- [Предл.] **Разброс** дают три источника, у каждого свой поток CounterRng: знание (hazard на FND/PRN и 10 ключевых узлах, #32), события (лицензия, перебой сплава) и ИИ (3 профиля по seed, годовой разброс приоритетов). В слоях способности и изделия RNG нет (#28).
- [Предл.] **Главный методический принцип (урок HYP-0001):** калибровка идёт только по микроякорям (коридоры Райта §8.2, срок освоения, CV открытий, окна поколений) на отдельных seeds. Доля смен лидера **не калибруется**: это внешний прогноз модели. Параметры ИИ замораживаются до калибровки.
- [Предл.] **Решение:** main — 1000 seeds (мощность ≈ 0,89 поймать долю 0,45 как чистый провал). Wilson CI и флаг «на грани» — как в EXP-0001. Каждый слой должен «заработать» свою сложность: его отключение меняет долю смен лидера на ≥ 0,10 **или** распределение лидера 1975 на TVD ≥ 0,15 (парный bootstrap). Иначе — `refutes`.
- [Предп.] Стоимость тика среза — десятки мкс; на весь эксперимент (~7600 прогонов) уходит несколько минут. Главный риск — калибровка, а не производительность.

## 3. Динамика сверх контракта
### 3.1 Знание (слой RR-0008 в объёме среза)
- **Фронтир** `F_a` — неизвестные узлы, у которых известны все `requires` (для `alt_group` — хотя бы один член).
- **Бюджет НИОКР** `S_a(t) = share_R(profile)·budget_a(t)`. Он делится по фронтиру с весами `w_n = prio(profile, type_n, ★)·j_{a,n,y}`. Множитель разброса `j ∈ [0,5; 1,5]` берётся из потока AI раз в год (§9). Веса нормируются.
- **Эффективная цена:**
  `c_eff = c_n · (1 − k_diff·known_elsewhere(n)) / ((1 + k_K·Kmix/K_ref) · (1 + Σ_{i∈informs, known} w_i))`.
  Здесь `Kmix = K_d[disc] + K_ind[disc]` для ENG/PRC (контракт §3, правило 1) и `K_d[disc]` для остальных типов. `known_elsewhere = 1`, если в снимке t узел знает другой актор.
- **Прогресс:** `prog[a,n] += S_a·w_n / c_eff` (доля от 1).
- **Детерминированные узлы** открываются при `prog ≥ 1`.
- **Hazard-узлы** (★, hz). После порога `prog ≥ θ_start`:
  - `y = prog − θ_start`, `h = h_max·y/(y + y_half)` (рационально, контракт §4.5);
  - открытие, если `U_know < h` (сравнение в целых, §9.2);
  - `prog` растёт дальше и ограничен `prog_cap`.
  Два соперника могут открыть узел в один месяц (RR-0008 §12 A).
- **`K_d`:** `ΔK_d = μ_K·(доля S_a в дисциплине d)/S_ref + k_node·[открыт узел дисциплины d]`. Забывания `K_d` в срезе нет. `K_ind` — по контракту §4.3 (с правилом v2.1 при `K_d = 0`).
- **Абляция «знание выкл.»** (§6) заменяет весь пункт расписанием (контроль C из EXP-0001).

### 3.2 Способность: что уточняется (формулы — контракт §4.1–4.2)
- `act[c] = min(1, granted_skilled[c] / required_skilled[c])`, `act_norm = 1`; `w[c] = w_a` (§1.1).
- `v_p = r_line·n_p·labour_p` — труд на **годные** единицы, без раздувания на `1/yc`. Так консервативнее для бюджета каналов §8.2 [Предл.].
- `report_output(site, p, units = r_line·n_p, labour_hours = v_p)`. Учебная серия (§4) — та же линия, но с темпом, который ИИ задаёт ради обучения.
- `tooling_M`: `ΔM = invest/cost_M(tier) − δ_M·M`. [Предл.] Своя оснастка не выше `1 + max tier` процесса MECH, который site ведёт при `yield > 0` (RR-0006 §4.5: «станки делают станки»). Импорта нет.
- `ramp(X) = λ0 + (1 − λ0)·X/(X + X½)` (RR-0006 §4.4), `X½ = X½(tier)`; лицензия даёт `X½·(1 − l_lic)`.
- `H_floor = φ_floor·Hcap[site,d]`; `Hcap` растёт с образованием (§1.1).

### 3.3 Изделие: что уточняется (формулы — контракт §4.4)
- **Проект.** Работа `W = W0·complexity/(1 + bureau_exp/E_B)` инженеро-месяцев. В тик t прогресс равен `granted` из t−1 (контракт §4.6).
- **Дефекты.** `D0 = d0·novelty·complexity/(1 + bureau_exp/E_B)`, где `novelty` — доля слотов с альтернативой, новой для актора. Испытания добавляют `test_rate` часов в месяц; выявление — по контракту §4.4; на исправление уходят `fix_hours` инженеров.
- **Серия.** Темп `r = min(line_capacity, бюджет закупок / unit_cost)`. Содержание парка оплачивается раньше закупок.
- **Когорты** — (проект, год выпуска). Списание в возрасте `service_life`. `readiness = min(1, оплачено/нужно)·q·(1 − ψ_D·D/D0)`.
- **`bureau_exp`:** +1 за завершённый проект; при простое убывает с `δ_B`.
- **ECONOMY** в `why_not` — по контракту §6, бюджет программы = доля закупок × 60 мес.

### 3.4 Бюджет (единственная экономика среза)
`budget_a(t) = budget_a(t−1)·(1 + g_a/12)` в Fx6 (экзогенно). Доли статей задаёт профиль ИИ (§4). Лицензия — перевод денег от покупателя продавцу. Инвариант — сохранение денег: сумма расходов ≤ бюджет, неизрасходованное сгорает.

## 4. Политика ИИ и события (контракт §9.2)
**Профиль на прогон.** На тике 0 у каждого актора профиль выбирается равновероятно, `⌊3·U_ai⌋` (§9). Профиль не меняется — это доктрина. Вероятности **не настраиваются** под результат.

| | P1 «качество» | P2 «массовость» | P3 «адаптивный» |
|---|---|---|---|
| Доли R / способность / закупки / QP | 0,35 / 0,20 / 0,40 / 0,05 | 0,20 / 0,30 / 0,50 / 0 (0,05 после триггера) | 0,28 / 0,25 / 0,42 / 0,05 |
| Вариант КБ | «превосходящий» | «технологичный» | больший `fleet_value` при равном бюджете (§5.5) |
| Покупка лицензии | никогда | всегда, если предложена | если `eta_months` узкого звена `null` или > 60 |
| Программа качества | с t0 и снова, если QC в топ-3 `why_not` | если `q < 0,7` у серийного проекта 24 мес. подряд | если первое звено `why_not` — `quality_control` |
| Приоритет НИОКР `prio` | ★ и ENG ×2 | PRC ×2 | все ×1 |
| Запуск серии | выявлено ≥ 60% `D0` | ≥ 30% | ≥ 45% |
| Учебная серия | на узком PRC, если узкое место — `H` | нет | если `eta` по `H` > 36 мес. |

**Ритм решений (детерминирован при seed):**
- раз в год (t mod 12 = 0): доли, приоритеты и `j`, выдача `Requirement` на новейшее известное APP без проекта;
- каждый месяц: темп линий, оснастка (бюджет способности идёт сначала в `invest_tooling_M` по узким местам `M`, затем в учебную серию);
- по событию: выбор варианта, запуск серии.

Команды ИИ считаются в compute по снимку t и применяются в начале t+1 (ADR-0006).

**События (поток EVT):**
- **Лицензия.** Раз в год для каждой пары (продавец, покупатель): продавец освоил двигатель поколения, которого у покупателя в серии нет → предложение с вероятностью `p_offer` (решение ИИ продавца, поток AI), цена `lic_price`. Покупатель решает по профилю.
  - [Факт, вторичный, в сессии не перепроверен] Rolls-Royce Nene продан СССР в 1946–47 гг. Значит, предложение «великой — великой» возможно.
- **Перебой сплава.** Помесячный hazard `p_dis·exposure_a`. Длительность 6–18 мес. (равномерно, поток EVT). Дефицит `deficit = 0,5`.

**Правило «не под результат»:** все числа этого раздела замораживаются **до** калибровки (§8.2) и не входят в калибруемый набор. Их изменение — только новым EXP.

## 5. Метрики
### 5.1 `tech_lead` (контракт §9.1)
- Считается каждый месяц среди GA, GB, GC по лексикографическому правилу контракта.
- «Освоен» = `yield ≥ 0,7` и `v ≥ v_min` 6 мес. подряд.
- «На вооружении» = в строю ≥ `n_service_min` (50) единиц проекта.
- `tech_lead_all` — то же по всем 5 акторам; нужен для критерия малой державы (§12, F5).

### 5.2 Смена лидера
- Смена засчитывается, если новый лидер начал лидировать в тике s ≤ 359 и удержал лидерство ≥ 24 мес. (до тика 383).
- **Главная метрика:** `chg` — доля seeds с ≥ 1 сменой.
- Печатаются также: число смен (p50/p95); время первой смены (гистограмма по годам); кто новый лидер (доли GB / GC); лидер на тике 359.

### 5.3 Малая держава и объём
- `small_lead` — доля seeds, где SM — `tech_lead_all` ≥ 24 мес. подряд в окне. MD печатается так же, без порога.
- `volume_lead` — по контракту §9.1, только печать (#27).

### 5.4 Время освоения ключевых процессов
По актору и ★-PRC: `t_known`, `t_first` (`yield > 0`, `v > 0`), `t_07` (`yield ≥ 0,7`), `t_mastered`. Цензура справа — тик 383, слева — освоено на старте (исключается). Печатаются p10/p50/p90 и доля цензуры. Это **калибровочный** якорь C2, а не тест.

### 5.5 `fleet_value` при равном бюджете (контракт §9.1; #34)
- Для актора a в тике t и проекта v, допущенного на его site:
  `n_v = max n` (шаг 10), при котором `Σ_{k=1..n} unit_cost_v(E + k) + n·upkeep_v·H ≤ B`.
  - `H` = 180 мес. (#34, параметр).
  - `B = fv_budget` (параметр, по умолчанию 24 медианных месячных бюджета закупок великих держав на t0).
  - `unit_cost` продолжает Райта по `line_E`, `production_profile` заморожен на t (консервативно и детерминированно).
- `FV_a = max_v n_v·readiness_v·perf_rel_v`. Печатается раз в год: отношения для пар великих держав и `FV(«технологичный»)/FV(«превосходящий»)` у каждого `Requirement`.
- Это чистая функция снимка; в тик не входит.

### 5.6 `why_not` — прокси читаемости (контракт §6)
Раз в год для каждого актора: цель — `requirement_id` новейшего известного APP, которое ещё не на вооружении. Пишется весь список. Метрики:
- (a) распределение слоя первого звена по классам акторов;
- (b) при `granted/n < 0,9` у КБ ≥ 6 мес. за год — доля актор-лет, где `ENGINEERS` в топ-3 (урок HYP-0001: ограничение действовало, а в объяснениях не появлялось);
- (c) доля `eta = null`;
- (d) соответствие рычагов сборке (валидатор).

### 5.7 Распределения и крайности
- По каждой метрике: p5/p50/p95, Wilson CI для долей.
- 5 крайних seeds (наибольшее число смен, наибольший отрыв лидера) — с помесячной лентой `tech_lead` и `why_not`.
- Разброс по источникам (§6.3).
- Дополнительно — «то же знание, другой выход» (RR-0006 §7 п.3): доля пар-лет великих держав, где обе знают фронтирный ★-PRC, а отношение `yield` ≥ 1,5.

## 6. Абляции и контроли (контракт §8; урок HYP-0001)
Все абляции идут на **тех же seeds**, что и main (seeds 1…400), чтобы сравнение было парным.

### 6.1 Слои выключены (контроли)
| Абляция | Заглушка через API контракта §5 | Аналог в EXP-0001 |
|---|---|---|
| `L_K` знание выкл. | `known_processes(a)` по расписанию: узел n известен с `T_n + lag_class`; `lag_class` 0 / 0 / 24 / 36 / 48 мес. (GA / GB / GC / MD / SM); `T_n` — середина окна поколения. RNG знания нет | контроль C (фиксированный лаг) |
| `L_C` способность выкл. | `production_profile`: `admitted = known`, `yield = 1`, `unit_cost_mult = 1`, `q = 1`; `culture_H`, `tooling_M`, `proc_X` не используются | контроль B (единый уровень) |
| `L_P` изделие выкл. | APP поколения g известно → через `T_design` мес. в строю канонический проект «превосходящий». Нет `line_E`, дефектов и вариантов. Цена = `Σ n_p·base_cost_p·unit_cost_mult` (способность сохраняется) | — |

**Что слой обязан показать [Предл., пре-регистрация].** Слой «зарабатывает свою сложность», если его выключение даёт хотя бы одно из двух:
- `|chg_full − chg_off| ≥ 0,10`;
- TVD распределения лидера на тике 359 (по GA, GB, GC) ≥ 0,15.

Это проверяется на точечной оценке, и 95% CI парного bootstrap (2000 повторов, фиксированный seed bootstrap) не должен включать 0. Метрики только «исходные» (кто лидирует и как часто). Внутренние подписи слоя (например, «время освоения = 0 при `L_C`») не засчитываются: они тавтологичны. Именно так в HYP-0001 контроль C показал, что модель A не нужна для заявленного эффекта.

### 6.2 Каналы (контракт §8.3)
- Сценарии: `α = 0`; `ramp ≡ 1`; `b = 0`; `η = 0`; `k_catch = 0`; `σ = 0`; плюс `k_diff = 0` [Предл.] — канал догоняния в знании.
- Для метрик контракта §8.3 и `chg` печатаются разложение и сравнение с коридорами §8.2.
- Решающими каналы не являются. [Предл.] Если `k_catch = 0` меняет p50 времени освоения у догоняющих (GC, MD, SM) больше чем на 30%, Orchestrator поднимает вопрос RR-0006 «Разногласия» п.1 (`access`).

### 6.3 Фиксированный seed источника (контракт §9.2)
- `FIX_K`, `FIX_E`, `FIX_A`: seed потока равен константе `0x5EED`, остальные потоки идут от seed прогона.
- Печатаются `chg` и энтропия лидера 1975 для каждого варианта. Доля разброса источника ≈ `1 − Var_fix/Var_full` для индикатора смены.
- Диагностика, не решение. Если `chg < 0,30` — это сигнал владельцу по #28. Повода добавлять шум в способность это не даёт.
- `FIX_ALL` — проверка детерминизма: все seeds обязаны дать одну траекторию.

### 6.4 Предусловие P0 (детерминированные тесты, до любых seeds)
- Тест разреженности (контракт §8.1).
- Бюджет падения цены на удвоение на эталонной линии (контракт §8.2): GB-подобный site, проект G2, постоянный темп; 4 прогона — полный, без канала выхода (`yield` заморожен на t0), без канала сборки (`b = 0`), без обоих. RNG не нужен.
- CI-фикстура «2 site» (контракт §8.4).
- Инварианты RR-0006 §4.14.
- Отсутствие RNG в `Core.Industry` и `Core.Products`.
- 4 сценария `why_not`, где первым звеном оказывается каждый слой по очереди (контракт §6).
- L1/L2.

Провал P0 означает, что EXP не запускается и модель исправляется. Это не исход гипотезы.

## 7. Правило решения (пре-регистрация)
**Прогоны:**
| Серия | Что | Seeds | Прогонов |
|---|---|---|---|
| main | полная модель | 1…1000 | 1000 |
| слои | `L_K`, `L_C`, `L_P` | 1…400 | 1200 |
| каналы | 7 сценариев §6.2 | 1…400 | 2800 |
| источники | `FIX_K`, `FIX_E`, `FIX_A` | 1…400 | 1200 |
| сетка | `k_catch × k_diff` ∈ {0,5; 1; 2}× заморожен. значения | 1…200 | 1800 |
| детерминизм | main, threads 1 / 4 / 8 | 1…20 | 60 |
| калибровка | только §8.2 | 10001…10100 | вне манифеста решения |

**Мощность [Факт: расчёт Wilson/нормальное приближение, скрипт сессии].**
- N = 1000 при истинной доле 0,35: CI [0,321; 0,380], точка в коридоре с вероятностью 0,999.
- Истинная 0,45 даёт чистый провал (CI целиком > 0,40) с вероятностью 0,89; истинная 0,25 (CI < 0,30) — 0,94. При N = 400 эти вероятности 0,50 и 0,59, поэтому main = 1000.
- Абляции, N = 400: разницу 0,10 видно с мощностью ≥ 0,84 даже без учёта парности; разницу 0,15 — 0,99.
- Малая держава: истинные 0,02 при N = 1000 дают верхнюю границу CI 0,031 < 0,05.

**Критерии:**
| # | Критерий | Проход | «На грани» | Провал |
|---|---|---|---|---|
| P1 | `chg` (main) в [0,30; 0,40] (#24) | точка в коридоре, CI внутри | точка в коридоре, а CI выходит за край, **или** точка вне коридора, а CI его пересекает | CI целиком вне коридора |
| P2 | `small_lead` ≤ 0,05 | точка ≤ 0,05, верхняя граница CI ≤ 0,05 | точка ≤ 0,05, верхняя граница > 0,05 | нижняя граница CI > 0,05 |
| P3 | необходимость слоёв (§6.1) для `L_K`, `L_C`, `L_P` | все три слоя показали эффект | эффект есть по точке, а CI включает 0 | точка ниже обоих порогов |
| P4 | читаемость (§5.6) | (a) ни один слой не первый > 70% актор-лет и каждый из 4 слоёв ≥ 5%; (b) ≥ 0,80 | в пределах 0,05 от порога | хуже |
| P5 | гладкость сетки | соседние точки сетки различаются по `chg` ≤ 0,20 | — | флаг `knife_edge` |
| S1 | цена превосходства | доля побед «технологичного» по `FV` — в [0,25; 0,75] (как H-A в RR-0007) | — | доработка, на исход не влияет |
| S2 | «то же знание, другой выход» | ≥ 20% пар-лет (RR-0006 §7 п.3) | — | доработка |

**Исход:**
- `supports` — P0 пройден; P1, P2, P3, P4 проходят; P5 без флага; «на грани» не больше одного из P1–P3.
- `refutes` — чистый провал P1 или P2, **или** провал P3 хотя бы для одного слоя. Тогда совместная гипотеза «три слоя дают…» отклонена в текущем виде, а итог указывает, какой слой не нужен.
- `inconclusive` — всё остальное (два и больше «на грани», флаг `knife_edge`, провал P4).
- Если P1 провален с `chg < 0,30`, к отчёту прикладываются результаты §6.3, и вопрос возвращается владельцу (#28).
- Итог формулируется с областью параметров: точка main и сетка.
- Любое изменение после заморозки манифеста — только новым EXP. Повторный EXP после провала P1 допускается только с решением владельца (§13 OQ3).

### 8.2 План калибровки
1. Калибровка идёт только на seeds 10001…10100, только полной моделью и только по якорям:
   - **C1** — коридоры контракта §8.2 (детерминированно, эталонная линия);
   - **C2** — p50 от `t_first` до `t_07` для tier-4 ★-PRC = 2–8 лет; у tier-5 — длиннее, чем у tier-4;
   - **C3** — CV времени открытия ★-узла при постоянных равных вложениях = 0,3–0,5 (отдельный стенд, один актор);
   - **C4** — окна поколений (мягкие) [Предп.]: первый G2 в строю у кого-либо в 1947–52, G3 — в 1954–61, G4 — в 1967–75, каждое в ≥ 50% калибровочных seeds;
   - **C5** — тест #30: после 10 лет простоя путь к `yield ≥ 0,7` короче, чем у новичка.
2. Метод — ручной перебор по сетке параметров «К», в порядке C1 → C3 → C2 → C4. Журнал перебора хранится в `lab/` (манифест калибровки), а не в `lab/results/`.
3. **Запрещено** смотреть `chg`, `small_lead`, `FV` и `why_not` на калибровочных seeds. Скрипт калибровки их не считает.
4. Затем параметры замораживаются, считается `manifest_hash`, проходит gate-ревью (critic + advocate), и только после этого идёт официальный прогон.
5. Если C1–C4 недостижимы, EXP не запускается, а вопрос уходит Orchestrator с данными.

## 9. Детерминизм
### 9.1 Потоки RNG (ADR-0004, `Singularity.Kernel.CounterRng`)
| Поток | `system` | `entity` | `n` | Что |
|---|---|---|---|---|
| KNOW | 1 | `actor·64 + node` | 0 | hazard открытия (#32) |
| EVT | 2 | `actor·8 + pair_or_kind` | 0 — наступление; 1 — длительность | перебой сплава |
| AI | 3 | `actor` | `kind·4096 + idx` | профиль (t = 0), `j` по узлам (t mod 12 = 0), предложение лицензии |

- У каждого потока свой экземпляр `CounterRng(seed_src)`, где `seed_src = seed` или константа (§6.3).
- `Core.Industry` и `Core.Products` не получают `CounterRng` (тест, RR-0006 §4.14).
- Порядок обхода на результат не влияет: значение — функция ключа.

### 9.2 Числовой путь
- Всё состояние хранится в `Fx6` (`long`), операции — через `Int128` (`Fx6.*`, `/`).
- `double` появляется только внутри `DetMath.PowFrac` (ADR-0012) и на её входе и выходе (`raw/10⁶` и `Fx6.FromDouble`).
- Проверка вероятности — без `double`: `(NextU64 >> 11) < ⌊p_raw·2⁵³/10⁶⌋` (Int128).
- Показатели — только целые `q10` из данных (ADR-0012 п.2): LR → `q10` поиском, `q10(1−β) = 1024 − q10(β)`.
- Забывание — `x·(1 − δ)`; насыщения и `ramp` — рациональные.
- Порядок merge: `report_output` по `(site_id, prc_id)`, `reserve_workforce` по `(site_id, cat, requester_id)` (контракт §4.6, §11). Открытия знания применяются в merge по `(actor, node)`, команды ИИ — в начале t+1.

### 9.3 Хеши
- Хеш состояния — годовой и финальный (как в EXP-0001, «Ревью» п.7).
- `golden_hash` — хеш набора финальных хешей main.
- Проверка L2: threads 1 / 4 / 8 на seeds 1…20.

### 9.4 Зависимость от ADR-0003 (FMA)
- Контракт считает ADR-0003 блокером. [Предл.] При правиле §9.2 в срезе нет выражений `a*b+c` над `double`: `PowFrac` — это только `sqrt`, `×` и одно деление (ADR-0012). Значит, FMA на результат не влияет.
- Предлагаю systems-architect подтвердить сужение блокера до «нет `double`-арифметики вне `DetMath`» с тестом-анализатором. Связано с TASK-0009 (FMA canary, REVIEW).
- Пока решения нет, срез ждёт ADR-0003.
- ADR-0004, 0005, 0006 — PROPOSED; срез на них опирается так же, как EXP-0001.

## 10. Стоимость тика (контракт §11)
| Часть | Объём в срезе | Операций за месяц [Предп.] |
|---|---|---|
| `culture_H`/`tooling_M` | 5 site × 4 кластера × 3 изм. = 60 ячеек × ~30 | 2·10³ |
| `yield`/`production_profile` | 5 × 20 PRC + ≤ 40 вызовов профиля | 10³ |
| `PowFrac` | ≤ 5·(4 линии + 4 проекта + upkeep) ≈ 60 вызовов × 50 нс | 3 мкс |
| знание | 5 акторов × ≤ 25 фронтирных узлов × ~5 рёбер | 10³ |
| изделие, когорты, ИИ | ~100 когорт, 10 КБ | 10³ |
| **итого** | | **≈ 10⁴ операций, 10–30 мкс** |

- Вне тика: `why_not` и `FV` раз в год. `FV` — до 2000 шагов `PowFrac` на проект; блоками по 10 это ~10 мкс × 10 проектов × 32 года ≈ 3 мс на прогон.
- Один прогон ≈ 10–20 мс счёта плюс ~0,15 с старта процесса .NET. ~7 600 прогонов при 14 процессах — около 2 мин, плюс анализ.
- Масштаб до 200 site и 2000 узлов ложится в оценку контракта §11 (3–5 мс на месяц): в срезе нет конструкций хуже O(site·PRC).

## 12. Расхождения с входными документами (FINDINGS)
- **F1 (высокая).** Узлы #32 (ТРД, жаропрочный сплав, точная ковка лопаток) при старте 1945 уже известны великим державам с прообразами США и Великобритании ([Факт, вторичный]: стендовые ТРД 1937, Nimonic 80 около 1941 — RR-0008 §12 A). Буквально применённый #32 даёт разброс только догоняющим. Я распространил hazard на аналоги следующих поколений (§1.3, 10 ★-узлов). Нужно подтверждение Orchestrator: это толкование #32, а не новое решение.
- **F2 (средняя).** Контракт §9.1 п.2 разрешает ничью по tier через `perf/unit_cost`. `unit_cost` падает от `line_E`, то есть от объёма, и в `tech_lead` проникает объём, который #27 вынес в отдельную метрику. Спецификация следует контракту. [Предл.] Анализ дополнительно печатает `tech_lead_perf` (ничья по `perf` проекта на вооружении) как чувствительность; уточнение контракта — за systems-architect.
- **F3 (средняя).** RR-0006 §7 описывает HYP-0002 как расширение toy-модели EXP-0001 (один кластер, 2 измерения, критерии β×γ и KS). Это расходится с #25/#29 (вертикальный срез). HYP-0002 нужно писать по этой спецификации; RR-0006 §7 считать устаревшим.
- **F4 (средняя).** Блокер ADR-0003 можно сузить для среза (§9.4).
- **F5 (низкая).** Контракт §9.1 определяет `tech_lead` «среди великих держав», а критерий малой державы требует сравнения по всем. Введён `tech_lead_all`.
- **F6 (низкая).** «2 КБ» (#25, контракт §10) истолкованы как 2 на страну.
- **F7 (низкая).** Лицензия в срезе не передаёт знание (контракт §10). Исторический случай Nene включал документацию, поэтому рычаг в срезе слабее исторического. Абляция покажет его вес; при необходимости — RR-0015.

## 14. Риски и ограничения
- [Предп.] Трёх источников разброса может не хватить для `chg ≥ 0,30` (контракт §9.2). Это измеряет §6.3.
- [Предп.] Стартовая асимметрия (у GA бюджет ×4 к GB) может сделать GA несменяемой. Тогда P1 проваливается снизу — это честный результат для владельца, а не повод менять старт после прогона.
