# ADR-0020 — Province storage, aggregation to regions and tick budget

> После ACCEPTED текст не меняется. Изменение решения — новый ADR с `supersedes`.
> Уровень: gate+research. Пункт 0.3 плана `development/milestones/MS-M1-economy-provinces-open-race.md`; снимает оговорку ADR-0016 §1 и требование ADR-0011 о регионах со смешанным владением. Ревизия 3: gate (`docs/reviews/adr-0019-0020-{critic,advocate,reviewer}.md`, `docs/reviews/adr-0020-deepseek.md`) и ответы владельца #348–#351.

## Краткий вывод
- [Предл.] Мир Kernel — несколько именованных таблиц: `actors` (строки заранее, колонка `active`), `regions`, `provinces` (провинции карты + территории без геометрии), `events` (`status`, `effective_tick`). Один формат хеша.
- [Предл.] Владение хранится только в `provinces`. **Границы регионов следуют каждой линии событий владения** (#350): у региона в любой день один `owner` и один `controller`. Контролёр региона — функция Core с мемо по версии `provinces` (кэш, не состояние).
- [Предл.] Экономика региона идёт **контролёру** (#349); совместная полития делит её поровну, доли из источника имеют приоритет (#351), раздел — `Apportion`.
- [Предл.] Доля провинций в бюджете M1 — **≤ 10 мс** из резерва ADR-0016; CoW и хеш — в `K_d`. При WARN K4 скорость сразу падает до пола 1 мес./3 с (#348).

## Контекст
- [Факт: ADR-0011 §1, §3, §5, табл. классов] Провинции 2000–5000, регионы 150–250 (5–15 на великую державу); `owner`/`controller` — `short`; `polities.yaml` — в `scenario_hash`, `map/*.yaml` — в `DataHash`, `map/*` запечатывается; класс B — «только владение, без геометрии» (Индия, колонии, кондоминиумы); центр Вены — совместная полития.
- [Факт: ADR-0016 §1, §3] Провинции не входят в полный масштаб; раздел: системы ≤ 100, `K_d` ≤ 50 (копия, swap, хеш), резерв 350 мс; правило `S + K_d + 19·P > 500` → ADR.
- [Факт: ADR-0017 п. 6] Кэш `LastHash` — пара `(version, hash)`; `Table.Version` растёт при swap открытых колонок и `Load`.
- [Факт: код, reviewer] Только `LongColumn`/`IntColumn`; хеш: `schema_version`, `n_rows`, колонки; `SliceWorld.SchemaFingerprint:403` пишет `i`/`l` по типу; `TickContext.Table`, `TickRunner._table`, `ChunkCountFor(Table.RowCount)` — одна таблица.
- [Факт: #312, #313, #325, #327, #328, #331, #333, #336–#338] Совместные политии; оккупация; события по дате; жертвуется скорость, пол 1 мес./3 с; K4 MS-M1 (#333). Тайвань — owner и controller ROC с 1945-10-25 (#338). Восток Одера–Нейсе — owner DEU, controller POL/SUN, переход владения по договору 1950, запасной 1970 (#337, #343).
- [Факт: #346, #348–#351] Срез M0 — git-тег; при WARN — сразу пол #331; экономика — контролёру; строгое совпадение границ регионов с линиями событий, Берлин и Вена — отдельные регионы; кондоминиумы — поровну, источник важнее.
- [Факт: `docs/game-design/scripted-events-conditions.md` §1, §4] Нужны `event_status`, `effective_date` в `StateHash`; `territories.yaml` для неевропейских наборов.

## Решение

### 1. Хранение и хеш
1. **Мир — список именованных таблиц** `World`. Система объявляет `ChunkTable` (по строкам которой режется на чанки) и свои колонки в любых таблицах.
2. **Запись между таблицами.** Один писатель на колонку (ADR-0019 п. 4). compute пишет только строки своего чанка своей `ChunkTable` в свои колонки; в строки других таблиц — только через буферы чанков, применяемые в своём merge в порядке чанков.
3. **`actors`:** строки всех политий, которые могут стать актором в сценарии (IND, PAK, IDN, FRG, GDR, …), создаются в t0; колонка `active` (`int`, 0/1) пишется только `ScenarioEventSystem`. Число строк постоянно → чанки и L2 от событий не зависят. Неактивные строки системы пропускают.
4. **`provinces`:** строка = провинция карты в ordinal-порядке `province_id`, затем территория без геометрии из `mods/core/map/territories.yaml` (`id`, `region`; `DataHash`, печать вместе с картой). Колонки `owner`, `controller` — `short`. Начальное владение — `owners.yaml` (`scenario_hash`). [Предп.] 2 × (5000 + ~300) × 2 Б ≈ 21 КБ — плотно.
5. **`events`:** строка = событие сценария в порядке `(nominal_date, event_id)`; колонки `status` (`int`: `due|deferred|fired|alt_fired|skipped|disabled`) и `effective_tick` (`int`, −1 = нет). Пишет только `ScenarioEventSystem`. Срок отсрочки — функция `nominal_date`, окна и `effective_tick` предшественника.
6. **`ShortColumn`** — новый тип Kernel (little-endian int16 в хеше). `SchemaFingerprint` — исчерпывающий `switch` по типу (`s`/`i`/`l`), неизвестный тип — исключение.
7. **Хеш мира** (частично заменяет ADR-0017, формат). Один формат для любого числа таблиц (срез M0 с прежним форматом — в git-теге, #346): `int32 table_count`, затем по каждой таблице в порядке списка: имя (UTF-8, `int32` длина), `int32 schema_version`, `int32 n_rows`, `int32 n_cols`, колонки в порядке регистрации. SHA-256 и расписание ADR-0017 не меняются.
8. **Версия мира.** `World.Version = Σ Table.Version` (версии монотонны → сумма меняется ровно при изменении любой таблицы). Кэш `LastHash` — пара `(World.Version, hash)`; остальное в ADR-0017 п. 6 прежнее.

### 2. Регион и его контролёр
9. **Строгое выравнивание (#350).** Для t0 и каждой даты таблицы событий: провинции и территории, меняющие `owner` или `controller`, — объединение целых регионов. У региона в любой день один `owner` и один `controller`. Исключений и весов провинций нет; один путь расчёта.
10. **Контролёр региона** — чистая функция Core `RegionController.Of(provinces, statics)` (контролёр любой его провинции), мемо — массив `region → polity`. Мемо считается в post при смене версии `provinces`, при сборке мира и после `Load`; compute читает его только на чтение. Это кэш, как `LastHash`: в хеш и сейв не входит (ADR-0013 п. 4 соблюдён). Система M2, меняющая `controller` (война), правки функции не требует.
11. **Бюджет актора (#330, #349):** выход региона `Y_r` целиком идёт его контролёру. Если контролёр — совместная полития, `Apportion(Y_r, w)` по `members`: `w = econ_shares` из `polities.yaml` (`scenario_hash`), если доли заданы с источником, иначе равные веса (#351). Σ бюджетов = Σ `Y_r` в raw точно. pull в compute актора, регионы по возрастанию индекса.
12. **Маркер смены для E1** — `events.effective_tick` (ADR-0019 п. 19); прежний контролёр, если нужен 2.9, хранится в колонках владельца E1 (решение 2.9).

### 3. Следствия для карты 1.1
13. **CI выравнивания:** нарушение п. 9 — красный CI с перечнем регионов и событий. Событие, чьи провинции ещё не на карте (1.1 идёт параллельно с 1.6a), — предупреждение `pending_map` до заморозки карты, после — ошибка.
14. **Сборщик карты 1.1** берёт линии разреза из таблицы событий 1.6a: каждый набор `set` события — граница регионов (ADR-0011 класс A). Берлин — 4 региона-сектора, Вена — 5 (4 сектора + центр); зоны Германии и Австрии, Корея (38°), Индокитай (16°), Пенджаб, Бенгалия, Одер–Нейсе — по линиям. Провинции нужны на уровне секторов Берлина и Вены.
15. **Число регионов** [Предп.]: разрезы добавляют порядка 15–30 регионов (Берлин +3, Вена +4, зоны Германии и Австрии, азиатские линии). Предел ADR-0011 150–250 держится, если база карты ≤ ~220; малые регионы-сектора к квоте «5–15 на великую державу» не относятся (их контролёры — оккупанты). R3 считает точно; превышение 250 — вопрос владельцу через ADR к ADR-0011.
16. **Валидатор:** `econ_shares` — сумма 1 000 000 и источник, иначе поле отсутствует; члены `joint` — политии-акторы, вложенные `joint` запрещены; у каждого региона один `owner`/`controller` на t0.

### 4. Совместные и оккупированные политии
17. DEU и KOR без правительства актором не являются — их регионы атрибутируются оккупантам. Восток Одера–Нейсе до договора 1950 — экономика у POL/SUN. Тайвань: controller ROC с t0, owner ROC с 1945-10-25 (#338). `owner` в M1 экономику не меняет.
18. Совместная полития (#312) может быть контролёром, не актор; раздел п. 11. Роспуск (`dissolve_joint`) — событие, меняющее `controller` регионов.

### 5. Бюджет тика (частично заменяет ADR-0016 §1, §3)
19. **Полный масштаб M1:** 200 акторов (строк — с запасом п. 3), 150–250 регионов, 2000–5000 провинций + территории, таблица событий.
20. **Раздел:** системы ≤ 100 мс; `K_d` ≤ 50 мс — **включая** CoW, swap и хеш всех таблиц; **провинции ≤ 10 мс** (`ScenarioEventSystem`, мемо, проверки K9) — из резерва; остаток резерва — E1 и прочее. Правило `S + K_d + 19·P + провинции > 500` → ADR (расширение правила critic M4).
21. Ожидание [Предп.]: проверка `due/deferred` — мкс в день; мемо при смене — O(провинций), десятки мкс; итого < 1 мс/мес. Пересмотр доли — на gate M2; система провинций заявляет цену на провинцию-день до кода.
22. **Исходы K4** — MS-M1 (#333). При WARN максимальная скорость **сразу** падает до пола #331 — 1 месяц за 3 с (#348); ступенчатой формулы нет. [Предл.] p95 ≤ 500 при медиане > 400 — WARN (закрывает пробел K4).
23. Число провинций — не рычаг бюджета (#327). K4 — на фактической карте; справочно 5000 синтетических провинций с событием каждый день.

### 6. Инварианты K9 (не зависят от `HashEveryTick`)
24. Флаг `CheckInvariants` (execution-only, по умолчанию включён, цена — мкс): в t0, после `Load` и в post каждого тика, где выросла версия `provinces` или `events` — индексы `owner`/`controller` действительны; у региона один `owner` и один `controller`; у `joint` есть члены; `fired` — с `effective_tick` ≤ текущего; `active` согласован с событиями создания.
25. «Смена не из таблицы событий — ошибка» обеспечивается структурно: единственный писатель `owner`/`controller` в M1 — `ScenarioEventSystem` (архитектурный тест ADR-0019 п. 4).

### Частично заменяет
- **ADR-0016 §1:** «провинции не входят» → п. 19. **§3:** строка «провинции ≤ 10 мс», уточнение `K_d`, правило п. 20. §4 (исходы M0) не меняется; исходы M1 — K4 MS-M1.
- **ADR-0017 п. 6 и формат хеша:** заголовок мира из таблиц (п. 7), кэш по `World.Version` (п. 8). Расписание прежнее.
- **ADR-0011:** «ячейка `(region, controller)` или столичная провинция» → строгое выравнивание п. 9; новый `map/territories.yaml` (`DataHash`), `econ_shares` в `polities.yaml` (`scenario_hash`). Предел 150–250 — проверка R3 (п. 15).
- **ADR-0013:** формат по таблицам прежний; `save_format_version` растёт; мемо не сохраняется.

## Рассмотренные альтернативы
| Альтернатива | Причина отказа |
|---|---|
| Провинции колонками в `actors` | ×200 памяти и хеша |
| Хранимые колонки атрибуции (ревизия 1) | Производное состояние; привязка к одному писателю ломается в M2 |
| Смешанные регионы с весами провинций (ревизия 2) | Заменено #350 |
| Ячейка `(region, controller)` с отдельным E1 | Строки E1 делятся при событиях |
| Атрибуция по `owner` | Отклонено #349 |
| Добавление строк `actors` при событии | Меняет `n_rows`, чанки, L2 |
| `share × выход` в Fx6 | Σ бюджетов ≠ выходу (floor) |
| Ступенчатая скорость `max(1 с, 2·p95, …)` | Отклонено #348 |
| Уменьшать провинции при превышении | Запрещено #327 |

## Последствия
- **Плюсы:** один источник владения; у региона один контролёр — E1 без долей; сумма бюджетов точна; хеш различает наборы таблиц.
- **Минусы:** Kernel под несколько таблиц меняет API `ITickSystem` всех систем Core (R2); карта 1.1 зависит от таблицы событий и получает 15–30 малых регионов; поздно добавленное событие с новой линией требует правки карты (до первого сохранения игрока миграция не нужна, ADR-0013 п. 7).
- **Обязательно:** один писатель на колонку; `Apportion` для разделов; строгое выравнивание в CI; `CheckInvariants` включён.

## Проверка
1. **Golden-вектор** хеша мира (фиксированные байты); перестановка таблиц или другое имя → другой хеш; таблица с 0 строк; `ShortColumn`: байтовый путь = быстрый путь; `SchemaFingerprint` для `short`.
2. **L2:** четыре таблицы, threads 1/4/8/16 × ChunkSize 1/8/32, разные `ChunkTable`, `HashEveryTick` — хеш каждого дня равен; день активации актора; два события в один день `(date, event_id)`.
3. **Версия:** изменение только `provinces` сбрасывает кэш `LastHash`; день без события — версии `provinces`/`events` прежние; `Load`/`Next` другой таблицы внутри тика — исключение.
4. **Save/load** в день события и на следующий → тот же хеш; мемо после `Load` = мемо без сохранения.
5. **Бюджет:** property — мемо = пересчёт с нуля после каждого события; Σ бюджетов = Σ выходов в raw; `joint`: равный раздел без `econ_shares`, раздел по источнику с ними; смена только `owner` не меняет экономику; роспуск `joint`.
6. **CI выравнивания** + отрицательный тест (событие режет регион → красный); `pending_map` до заморозки.
7. **Валидатор** п. 16; **K9** п. 24 при `HashEveryTick = false`.
8. **Бюджет тика:** K4 на фактической карте; 5000 синтетических провинций с событием каждый день; доля провинций по inclusive-профилю ≤ 10 мс.
