# Gate ADR-0021 — critic (2026-11-18)

3 high (key and schedule stability; p_roll precision with a weak test; the #342 boundary rests on an atom-name list), 5 medium. No one-writer violations.

- **high, §2 p. 6–7, §3 p. 9 (key and schedule).** `e` = ordinal row of the sparse network table; it enters the RNG key, slot `e mod period_days` and capacity `C`. A new, deleted or compacted network shifts keys and slots of later rows — unstable under ablation and counterfactuals. Fix: `entity` = permanent row id (issued once, never reused; for networks `o·M+t` with M fixed by the scenario); slot from the same id. Test: add/remove a domain row mid-run, other rows' rolls and slots unchanged.
- **high, R1, Проверка p. 5 (p_roll).** `Chance(Fx6)` with step 1e-6 distorts even `period_days = 7`: 0.1 %/year → ~19 raw, error up to ~5 %; 0.01 %/year → ~1.9 raw, up to ~50 %. `1−(1−h)^(7/Y)` via `DayRate` bisection in Fx6 subtracts near-1 values, no better than 1e-6. Property test p. 5 cannot catch it (h = 0.1 % on 10⁵ rows → ~100 cases, 3σ ≈ 30 %). Contradiction: daily rolls rejected for precision, yet `link.failure` has `period_days = 1`. Fix before ACCEPTED: `ChanceRaw(u, threshold53)`, Q53 threshold computed in Kernel via `−ln(1−h)·period/Y` in integers (Int128); deterministic unit test: for h ∈ {1e-5 … 0.5}, period ∈ {1, 7}, recovered annual risk within 0.1 % relative; statistical test only for large h.
- **high, §4 p. 13 (#342 and validator).** (1) The validator lets `stoch_*` atoms through in `branch: counterfactual` packs though question 2 is open — the owner's decision is pre-empted. Fix: ban everywhere until question 2 is answered. (2) A name blacklist misses indirect links [Предп.]: M2 brings `has_tech`/`has_institution`; chain `intel.expose` → `N` → technology theft → `has_tech`; later `war.surprise` → control → `controls`/`no_war`. Fix: a column dependency graph (taint from `stoch_today` through owner-written columns); the validator forbids an atom reading a tainted column. Keep the 20-seed run p. 7 as a secondary check.
- **medium, §3 p. 9.** Capacity `C` fixed at world build overflows on domain growth or `force`. Fix: `C` from the scenario's max domain size plus a force reserve; overflow is an error, not truncation; test.
- **medium, §6 p. 16, §7 p. 18.** "Golden M1 with off, #329 unchanged": new tables and `stoch_*` columns enter `StateHash` and change the M1 golden even with streams off. Fix: state that golden is reissued (ADR-0017, #346) or that tables are absent for an empty domain; a new stream adding `stoch_last_tick_<s>` to another table also bumps `save_format_version`.
- **medium, §7 p. 17.** The `force` list is not saved; a save before the forced day loses it; `extra[]` under force undefined. Fix: force list in the save manifest with a load check; `extra` given explicitly or rolled by the normal key.
- **medium, §2 p. 7.** 365/366 not divisible by 7: rows get 52 or 53 rolls a year, annual risk differs ~2 %; leap boundary inside a period undescribed. Fix: Y from the year of day D; accept and document 52/53; test across slots.
- **medium, §1 p. 3–4.** `pending` state and multi-day consequences (link down N days) undescribed for owners: who writes the columns, hashed, survives save/load? `stoch_last_tick` is written on `target_gone` too; cooldown cannot tell outcomes. Fix: list owner columns, add to p. 16 and Проверка p. 9.
- low, §2 p. 6: "otherwise later keys shift" is wrong — each case has its own `(stream, D, e)`; fixed `n_extra` keeps the meaning of `k`, not keys.
- low, §2 p. 5: no test that the stream registry only grows; no check that Flow/Decision ids < `0x5000_0000`. Fix: registry snapshot test and an id-range architecture test.
- low: ablation is `hazard_eff = 0` in the summary but "not rolled" in p. 8; one wording.

Missing tests: key/slot stability under domain change; deterministic p_roll threshold; `C` overflow and force; leap boundary; save with pending, force and multi-day consequence; taint validator; registry snapshot; paired on/off ablation on the same seeds.
Open: question 2 before the validator allows anything for branches; who writes the taint analysis (systems-architect or test-engineer).
