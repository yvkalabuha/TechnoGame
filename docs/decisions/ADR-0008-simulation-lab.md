# ADR-0008 — Simulation Lab: прогоны, хранение, анализ

> После ACCEPTED текст не меняется. Изменение решения — новый ADR с `supersedes`.
> Ревизия 2 (systems-architect, 2026-11-18): текст приведён к работающему Lab (TASK-0005, -0008, -0044, -0064; EXP-0001…0007). Ревизия 1 предлагала TOML, Parquet, DuckDB, polars; в коде JSON, CSV и Python stdlib.

## Краткий вывод
- Работает: один прогон — один процесс, `matrix` запускает дочерние `run`; манифест с SHA-256-хешем; `run.json` с provenance; `golden_hash` прогона и `golden_set_hash` матрицы; L2-сверка по потокам; `registry.py` требует полей воспроизводимости.
- Отличается от ревизии 1: манифест JSON (не TOML), метрики CSV (не Parquet), каталога DuckDB нет, анализ — Python stdlib со своим скриптом на эксперимент (не polars/DuckDB).
- Слабое место: CSV и stdlib упёрлись в память на EXP-0002 (3,7 ГБ, #264). Решено потоковым загрузчиком; формат хранения пересматривается по порогу, а не заранее.

## Контекст
- [Факт, код] `src/Singularity.Lab`: команды `run`, `matrix`, `hash`, `models`, `selftest`, стенды T12 и `bench` (ADR-0016). `MatrixRunner` запускает тот же бинарник дочерним процессом на каждую тройку (точка, seed, threads), до `--jobs` одновременно, с таймаутом. Формат — `docs/simulation/lab-cli.md`.
- [Факт, код] Манифест JSON schema 1 (`Manifest.cs`): `model`, `ticks`, `seeds`, `threads`, `chunk_size`, `params`, `series` со `sweep`, `data`, `meta`; неизвестный ключ — ошибка; `manifest_hash` — SHA-256 канонического JSON. Отклонение от TOML записано как пилотное (EXP-0001 «Ревью» п. 11). Манифесты в `lab/manifests/`.
- [Факт, код] `run.json`: `golden_hash` (`StateHash` Kernel), `core_commit`, `dirty`, `build_commit`, `manifest_hash`, `data_hash`, `params`, `runtime`, `os` и др. `matrix.json`: `thread_mismatch`, `golden_set_hash` (только если все прогоны ok). Метрики — CSV на метрику, объединение в порядке прогонов.
- [Факт, код] `tools/development/registry.py`: `REPRO_FIELDS = core_commit, data_hash, manifest_hash, seeds, threads, golden_hash, outcome` для экспериментов.
- [Факт] Анализ: `lab/analysis/exp0001.py`, `exp0002.py` и др. — Python stdlib, детерминированные bootstrap, KS, перестановки с фиксированными seed; тесты анализа в CI (`analysis` job). Пре-регистрация: скрипт замораживается, `script_sha256` в манифесте (EXP-0002, #258, #264).
- [Факт] #264: замороженный `exp0002.py` занял 22,5 ГБ RSS на 3,7 ГБ CSV; принят потоковый загрузчик с доказательством побайтного равенства JSON.
- [Факт] `lab/results/` в `.gitignore`. Исторические манифесты, которые не запускаются на текущей сборке, перечислены в `lab/manifests/README.md` с коммитом для воспроизведения.
- [Факт] Golden мира закреплены в тестах (`tests/Singularity.Session.Tests`, `ToyFunnelParityTests`) и гоняются CI на трёх ОС; EXP-0002-det — эталонный набор `golden_set_hash` (#316). Срез M0 после #228 хранится git-тегом (#346).

## Решение
1. **Процессы.** Один прогон = один процесс `Singularity.Lab run`. Параллелизм прогонов — процессами (`matrix --jobs`); внутри прогона — потоки `TickRunner` (`threads` манифеста).
2. **Манифест — JSON schema 1** в `lab/manifests/`, формат `docs/simulation/lab-cli.md`. Идентичность эксперимента — `manifest_hash` (SHA-256 канонического JSON). Числа передаются модели как десятичный текст (`GetFx6Raw` — точно).
3. **Provenance обязателен** в каждом `run.json`: `core_commit`, `dirty`, `build_commit`, `manifest_hash`, `data_hash`, `golden_hash`, runtime и ОС. Коммиты во время `matrix` запрещены (provenance разойдётся).
4. **Метрики — CSV** (одна таблица на метрику, колонка `run`, порядок прогонов не зависит от порядка завершения). Результаты — только в `lab/results/`, не в git.
5. **Анализ — Python** со скриптом на эксперимент в `lab/analysis/`, детерминированный (фиксированные seed у bootstrap и перестановок), с тестами в CI. Для пре-регистрированных экспериментов скрипт замораживается, его `script_sha256` пишется в манифест; правка — только отклонением в журнале эксперимента.
6. **Регрессия:**
   - точная — `golden_hash` прогона, `golden_set_hash` матрицы, `thread_mismatch = 0` (бесплатная L2-проверка);
   - статистическая — сравнение распределений (квантили, KS, bootstrap) в скрипте эксперимента по пре-регистрации, а не общим модулем Lab.
7. **В git:** манифесты, скрипты анализа, golden-хеши (в тестах и EXP-записях), выводы в EXP-файлах.
8. **Пересмотр хранения по порогу [Предл.]:** переход на Parquet (+ DuckDB/polars) — когда сырые результаты одного эксперимента превысят ~10 ГБ CSV или анализ — 30 мин; решение — новым ADR.

## Рассмотренные альтернативы
| # | Вариант | Плюсы | Минусы |
|---|---|---|---|
| **A** | **JSON + CSV + Python stdlib, скрипт на эксперимент (выбран, работает)** | без зависимостей; канонизация JSON уже есть; скрипты легко заморозить и проверить хешем | CSV объёмный и медленный; память при больших прогонах (#264) |
| B | Ревизия 1: TOML + Parquet + DuckDB + polars | компактно, быстрый анализ | 3 внешние зависимости в Lab и анализе; канонизация TOML; пока не нужно |
| C | Прогоны потоками в одном процессе | меньше накладных расходов на старт | общий процесс: утечка состояния между прогонами, падение одного убивает все |
| D | Общий статистический модуль Lab | одно место для KS/bootstrap | пре-регистрация привязана к скрипту эксперимента; общий модуль меняет прошлые анализы |

## Последствия
- Плюсы: каждый результат воспроизводится по `run.json` и манифесту; L2 проверяется каждой матрицей.
- Минусы: CSV-тяжесть; дублирование кода разбора между скриптами экспериментов.
- Обязательно: DONE-эксперимент имеет `REPRO_FIELDS`; манифест, который больше не запускается, попадает в `lab/manifests/README.md` с коммитом сборки.

## Открыто перед ACCEPTED (вопросы владельцу)
1. Закрепить JSON + CSV + Python stdlib как формат Lab и перенести Parquet/DuckDB в «пересмотр по порогу» (п. 8)? [Предл.] Да; порог 10 ГБ / 30 мин.
2. Делать ли малую golden-матрицу (например, 3 seeds EXP-0002-det-подобного набора нового мира M1) шагом CI, или достаточно закреплённых golden в тестах Session? [Предл.] Достаточно тестов: они уже идут на трёх ОС; матрица — перед закрытием milestone.

## Проверка
- `registry.py check` — `REPRO_FIELDS` у экспериментов.
- CI: `Lab self-test` (`selftest`: канонизация, golden при повторе, 1 vs 4 потока, чувствительность к seed, `data_hash`), job `analysis` (тесты `lab/analysis`).
- `matrix.json`: `thread_mismatch = 0` и непустой `golden_set_hash` — условие валидности прогона эксперимента.
