# ADR-0005 — Модель данных ядра: таблицы struct-of-arrays

> После ACCEPTED текст не меняется. Изменение решения — новый ADR с `supersedes`.
> Ревизия 3 (systems-architect, 2026-11-18): правки gate rev 2 (`docs/reviews/adr-0003-0005-0007-0008-critic.md`, `…-advocate.md`, `adr-0005-deepseek.md`) и решение владельца #374 (gate вместе с ACCEPTED ADR-0020; полная таблица слотов — отказ команды с `why_not`). Мир — `World` ADR-0020; набор типов колонок Kernel; категория «производный кэш». Финальная правка перед ACCEPTED (2026-11-18): решение владельца #388 (Q41) — освобождённые слоты переиспользуются со счётчиком поколения (п. 3), сужает #374.
> Ревизия 2 (2026-11-18): текст приведён к коду M0 и к ACCEPTED ADR-0013, ADR-0017.

## Краткий вывод
- Состояние мира — `World` (ADR-0020): упорядоченный список именованных таблиц Kernel. Колонка — плотный массив из набора типов Kernel (`long`, `int`, `short`), двойной буфер с copy-on-write (ADR-0017). ECS нет.
- Число строк каждой таблицы и набор таблиц фиксированы при сборке мира. Сущности с временем жизни занимают слоты с ёмкостью из данных; освобождённый слот переиспользуется (наименьший свободный индекс), ссылка — пара `(slot, generation)` (#388). Отказ команды с `why_not` — только когда заняты все активные слоты (#374, #388).
- Состояние — только в колонках. Вне таблиц допустимы `[Scratch]` и **производный кэш** (чистая функция `Current`, пересчитывается, не хешируется и не сохраняется).
- Строковые ID — в данных, сейвах и миграциях; в тике — только плотные индексы.

## Контекст
- [Факт] В grand strategy мало типов сущностей и много связей. RR-0002.
- [Факт] ADR-0020 (ACCEPTED, #354): `World` — список именованных таблиц (`actors`, `provinces`, `events`, далее `regions`); система объявляет `ChunkTable`; один писатель на колонку; запись в строки чужой таблицы — через буферы чанков в merge (п. 1–2); `ShortColumn` (п. 6); формат хеша мира (п. 7); `World.Version` (п. 8); контролёр региона — функция с мемо вне хеша (п. 10). Набросок API — `docs/architecture/notes/multi-table-api.md` (`World`, `ShortColumn`, `ColumnKind`, `WorldSchema.Fingerprint`).
- [Факт, код] `src/Singularity.Kernel/Table.cs`, `Column.cs`: `Table(rowCount)` с фиксированным `RowCount`; колонки в порядке регистрации; `Next` открывается на первое касание в тике (ADR-0017 п. 10–13), вне тика бросает `InvalidOperationException`; `Load` — вне тика; `FullCopyMode` — тестовый переключатель, не меняющий состояние и хеш. Срез M0 — одна таблица «строка = актор» (переход — задача миграции по ADR-0020; срез M0 хранится тегом, #346).
- [Факт, код] `ProductsLayout`: `max_designs` слотов на актора, новый проект берёт **наименьший никогда не занятый** слот; освобождённый слот не переиспользуется (код до решения #388; переход — задача по п. 3). Сценарий 1945: `max_designs: 12` (`mods/core/scenario_1945.yaml`). Отказ — `CommandRejection.DesignCapacity` (`src/Singularity.Core/Products/ProductsSystem.cs`).
- [Факт, код] Загрузчик модов (`Singularity.Core.Data.ObjectStore`): объекты по ID в `SortedDictionary` с ordinal; `ScenarioData`/`ProductsLayout` разрешают ID в номера один раз при сборке (`ImmutableArray`).
- [Факт] ADR-0013 (ACCEPTED): сейв — бинарный снимок колонок, порядок строк байт в байт (п. 3); состояния вне таблиц нет, кроме `[Scratch]` (п. 4); миграции по стабильным строковым ID; изменение `n_rows` — смена формата с миграцией (п. 7–8).
- [Факт, код] `ScratchTests` сканирует типы `ITickSystem` в Core: изменяемое поле — `[Scratch]` или запись в `PrecomputedFields` (`ProductsSystem._prcMemo` — мемо, `_mailbox`, конфигурационные `_p`, `FunnelSystem.<model>P`). Мемо `RegionController` ADR-0020 п. 10 — вне `ITickSystem`, тест его не видит.
- [Факт] Бюджет: `K_d` ≤ 50 мс, включая CoW, swap и хеш всех таблиц (ADR-0020 п. 20); полный масштаб ADR-0017 ≈ 8800 колонок × 200 строк ≈ 14 МБ, хеш 37,7 мс.

## Решение
1. **Мир — `World` по ADR-0020.** Упорядоченный список именованных таблиц; порядок задаёт хеш (ADR-0017 п. 1 + ADR-0020 п. 7: `table_count`, имя, `schema_version`, `n_rows`, `n_cols`, колонки в порядке регистрации) и сейв. Набор таблиц задаётся конструктором `World` и за прогон не меняется. Таблица — на тип сущности (акторы, провинции, регионы, события); подсущности с ёмкостью (проекты актора) — группы колонок или своя таблица со строкой = слот, выбор — в ADR слоя по бюджету `K_d`.
2. **Колонки — набор типов Kernel** (`ColumnKind`: `Long`, `Int`, `Short`; ADR-0020 п. 6). `Fx6` и `Rate` — как `Raw` в `LongColumn` с единицей в метаданных (ADR-0003 п. 1, п. 8). Новый тип — только в Kernel, с исчерпывающим `switch` отпечатка схемы и правкой формата хеша новым ADR.
3. **Фиксированное число строк и слоты.** `RowCount` задаётся при сборке из сценария и данных и в игре не меняется. Сущности с временем жизни получают ёмкость `max_*` из данных и слоты; таблица не растёт. Освобождённые слоты **переиспользуются со счётчиком поколения** (решение владельца #388, Q41):
   - **Колонка `generation`** (`int`) в группе слотов (или в таблице «строка = слот»), рядом с признаком занятости слота. Начальное значение 0. При каждом занятии слота `generation` увеличивается на 1 (`checked`; переполнение — исключение, на горизонте ~69 000 дней недостижимо). При освобождении слот помечается свободным, `generation` не меняется.
   - **Выбор слота:** новая сущность берёт **наименьший по индексу свободный** слот. Стек free-list не используется: его порядок зависит от истории освобождений.
   - **Handle** сущности — пара `(slot, generation)`; она хранится во всех ссылках (колонки, команды, `why_not`, UI). Голый индекс слота как ссылка на сущность с временем жизни не используется.
   - **Устаревший handle:** handle разрешается, только если слот занят и `generation` слота равна `generation` handle. Иначе ссылка устарела: читатель трактует её как «сущности нет» (без чтения чужих данных), команда с устаревшим handle отклоняется с причиной в `why_not`. Проверка пары — одна функция разрешения handle, общая для всех читателей.
   - **Отказ #374 сужен:** команда создания отклоняется с причиной в `why_not` (`CommandRejection.DesignCapacity` для проектов) только когда заняты все активные слоты — для проектов все 12 (`max_designs` сценария 1945); состояние при отказе не меняется.
   - **Детерминизм:** выбор слота — функция только `Current` (занятость по индексу), без зависимости от порядка потоков и истории; `generation` и занятость — обычные колонки, входят в хеш мира и снимок сейва ADR-0013 без изменения формата. Два прогона с одним seed и командами дают одинаковые handle.
   - Ёмкость `max_*` калибруется по худшему сценарию числа **одновременно** живущих сущностей и проверяется валидатором данных (ADR-0010).
4. **Связи** — индексы в колонках (тип по диапазону: `short` для политий, ADR-0020 п. 4; иначе `int`). Обратные индексы и смежность графов: неизменяемые массивы, собранные при загрузке, если граф статичен; **производный кэш** (п. 5), если зависит от состояния. Колонкой производный индекс не делается: второй источник истины.
5. **Только колонки хранят состояние.** Вне таблиц допустимы две категории:
   - `[Scratch]` — буферы тика, пусты на границе тика (ADR-0013 п. 4);
   - **производный кэш** `[DerivedCache]` [Предл. атрибут] — чистая функция `Current` (мемо `RegionController`, `ProductsSystem._prcMemo`): пересчитывается при сборке мира, после `Load` и в post при смене версии исходной таблицы (`Table.Version`/`World.Version`); compute читает его только на чтение; в хеш и сейв не входит. Владелец пересчёта — одна система (один писатель).
   - Конфигурационные неизменяемые массивы из данных — не состояние (`readonly`, заполняются в конструкторе).
6. **Один писатель на колонку** (ADR-0019 п. 4, ADR-0020 п. 2): compute пишет только строки своего чанка своей `ChunkTable` в свои колонки; запись в другие таблицы — буферы чанков, применяемые в своём merge в порядке чанков.
7. **Стабильные строковые ID** — в данных, сейвах (ADR-0013) и миграциях. Отображение ID → индекс строится один раз при загрузке в ordinal-порядке ID; в тике строки не ищутся по ID.
8. **Двойной буфер.** Системы читают `Current` (t) и пишут `Next` (t+1), `Next` открывается copy-on-write (ADR-0017); `Next` вне тика — исключение; `Load` — только вне тика (setup и загрузка); `FullCopyMode` не меняет состояние и хеш.
9. **ECS-фреймворк не используется.**

## Рассмотренные альтернативы
| # | Вариант | Плюсы | Минусы |
|---|---|---|---|
| **A** | **SoA-таблицы Kernel в `World`, фиксированные строки, слоты (выбран)** | плотная память, простой хеш и снимок (ADR-0013), детерминированный порядок | ёмкость задаётся заранее |
| B | ECS (Arch, DefaultEcs, Friflo) | сильнее при множестве однородных сущностей | слабее на связях; порядок архетипов и хеш сложнее держать детерминированными; внешний пакет в Core |
| C | Динамический `RowCount` | нет потолков ёмкости | меняет `n_rows` в заголовке хеша и сейва (ADR-0017 п. 1, ADR-0020 п. 7), границы чанков (L2) и индексы ссылок |
| D | Объекты-классы (AoS) | привычно | GC, нет простого снимка и хеша, легко спрятать состояние вне таблиц |
| E | Free-list (стек) с generational ID (RR-0002 §3.1) | ёмкость переиспользуется, выбор O(1) | порядок стека зависит от истории освобождений; принят вариант с поколением, но с «наименьшим свободным» вместо стека (п. 3, #388) |
| E′ | Слот не переиспользуется, «наименьший никогда не занятый» (ревизия 2, код M0) | просто, ссылка = индекс | ёмкость расходуется за игру: 12 проектов на страну за 1945–2100 кончатся, отказ — тупик поздней игры; отклонено #388 |
| F | Пересборка мира с большей ёмкостью при загрузке сейва | нет постоянного потолка | меняет `n_rows`, индексы и хеш — миграция формата (ADR-0013 п. 7–8) на каждую загрузку; отклонено #374 |
| G | Производный индекс колонкой | виден в хеше | второй источник истины; нужен писатель и порядок пересчёта в merge |

## Последствия
- Плюсы: хеш, снимок и COW — на уровне Kernel без знания домена; «нет состояния вне таблиц» проверяется тестом с двумя явными категориями исключений.
- Минусы: ёмкости — параметры данных, их надо калибровать; колонка `generation` на каждую группу слотов и проверка handle в каждом читателе ссылки (#388); выбор наименьшего свободного — линейный проход по ёмкости (≤ 12 для проектов); число колонок влияет на `K_d` (CoW, хеш) — новая группа колонок проверяется по бюджету ADR-0020 п. 20.
- Обязательно: каждая ёмкость `max_*` — в данных с проверкой валидатором и тестом на худшем сценарии; новый тип колонки — только Kernel и новый ADR формата.

## Проверка
- `tests/Singularity.Architecture.Tests/ScratchTests.cs` — нет состояния вне колонок (ADR-0013 п. 4). [Предл.] Тест распознаёт `[DerivedCache]` наравне с `[Scratch]`, сканирует не только `ITickSystem`, но и все типы Core/Session с изменяемыми статическими или экземплярными полями (мемо `RegionController`); `PrecomputedFields` сокращается до конфигурационных массивов.
- [Предл.] Property-тест производного кэша: кэш после `Load` = кэш без сохранения = пересчёт с нуля (ADR-0020 «Проверка» п. 4–5).
- `CoreArchitectureTests.CoreProject_PackageReferences_AreExactlyApproved` — в Core нет ECS-пакета.
- `tests/Singularity.Kernel.Tests` (`TableTests`, `StateHashTests`, `ColumnBufferTests`) — порядок колонок, COW, `Next` вне тика бросает, `Load` вне тика, `FullCopyMode` = COW по хешу. После миграции ADR-0020 — golden-вектор хеша мира и `WorldTests` (`docs/architecture/notes/multi-table-api.md` §5).
- Архитектурный тест (обязательный): в Kernel нет публичного API, меняющего `RowCount` или набор таблиц `World` после конструктора.
- Отказ #374/#388: тест `DesignCapacity` (`SliceChecks`) — команда при занятых всех 12 слотах отклоняется с причиной в `why_not`, состояние не меняется; при 11 занятых и одном освобождённом — принимается.
- Переиспользование #388: тест «освобождённый слот занят снова, `generation` вырос на 1, старый handle `(slot, generation)` не разрешается, команда с ним отклоняется с `why_not`»; тест «при нескольких свободных берётся наименьший индекс»; property-тест: одна последовательность команд при разном числе потоков даёт одинаковые handle и хеш мира (L2).
