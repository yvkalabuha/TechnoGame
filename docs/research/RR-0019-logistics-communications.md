# RR-0019 — Логистика, связь и инфраструктура

> Пометки: **[Факт]** — подтверждено источником; **[Предп.]** — предположение или не проверено; **[Предл.]** — предложение. Вход владельца — DECISIONS_LOG #262, #263 (читались также #256, #259–#261). Срез M0 не меняется. Внешние источники — только литература (оценки эффектов); абсолютные ставки и размеры ВПП в игру не импортируются, пока не найдены в PD/CC0/CC BY (ADR-0009). Рамка ревизии: ADR-0019 rev 3 (дневной тик, годовые ставки нарезаются по дню года #345, события применяются в merge D−1 #347, ИИ раз в неделю по очереди #344); ADR-0020 rev 3 (контролёр-экономика #349, строгие регионы #350, кондоминиум долями #351; 150–250 регионов + сектора).

## Вопрос исследования
Как дать логистике (ж/д, авто, море/река, авиа) и связи цену обслуживания, пропускную способность и качество, чтобы это (а) заменило линейную надбавку `m_d = m_1·d` (E1-model §14.2: цена привозной энергии `p_e,r` при диспетчеризации `loc_r/imp_r`; раздела «§импорт» в E1-model нет) осмысленным графом, (б) осталось региональным, детерминированным и дешёвым, (в) давало игроку выбор, а не микроменеджмент; и какое влияние связи на экономику, науку, войну и политику подтверждено доказательствами.

## Краткий вывод
1. [Предл.] **Масштаб исправлен.** 150–250 регионов в мире (E1-model §14.3, #171) + 15–30 секторов (ADR-0020): узлов ≈ 180–280, звеньев ≈ 600–1000 (не 4000). Пересчёт полного графа кратчайших путей по событию — порядка 1 мс [Предп., проверить Lab-микротестом]; не 10–50 мс.
2. [Предл.] Один тип состояния — **звено** `Link{mode, cap, upkeep, q, wear}`. Сухопутные (ж/д, авто) — между смежными регионами; море/река — порт–порт, воздух — хаб–хаб (не смежность ADR-0011; ограниченный список пар в данных). Случайности нет; случайные срывы — только из слоя событий (ADR-0021, в разработке).
3. [Предл.] Порядок цен между модами подтверждён литературой (Hummels, Индия); порядок **ёмкости и качества** — [Предп.], литературой не подтверждён.
4. [Предл.] **Две версии v1 (вопрос владельцу №1).** Вариант A (рекомендуется): `Φ` + доступ к рынку `MA_r` — без потоков и перегрузки; назначение потоков и перегрузка → E2/M2. Вариант B: потоки + перегрузка + `Allocate`. Оба сохранены ниже.
5. [Предл.] Связь — один уровень `comm[region]` 0–5. Эффекты упорядочены: сначала `k_diff` и `spec` (действуют на нынешнее ядро, наука — центр игры), затем `β` (после привязки к столбцу E1) и `c2` (после боевого слоя), `support` — только вход писателю (RR-0015).
6. [Предл.] «Бонус институтам» подтверждён только как **коллаборация**; v1 — множитель на `k_diff` и скорость `spec`, не на `out_d`.
7. [Предл.] Этапы: **M2** — ж/д, авто, море (cap/upkeep/q) + `Φ`; **M3** — `comm`, аэродромы, визуализация стройки. Трубы, энергосети, вертолёты, блокада, контейнерное событие, РЭБ — FUTURE.

### 2. Модель

**Агрегация.** [Предл.] Узел — регион ADR-0011 или сектор ADR-0020; ≈180–280 узлов, ≈600–1000 звеньев. Сеть по умолчанию строится из данных региона (порт + ж/д-магистраль + шоссе, **параметры по типу региона** до данных 1945). Игрок растит класс, не рисует линии.

**Правило контролёра (#349–#351).** [Предл.]
- Звено принадлежит и оплачивается **контролёром** региона-источника (не владельцем); содержание — статья «инфраструктура» контролёра.
- «Межстрановое» звено = звено между регионами с **разными контролёрами**; такое звено проходит через шлюз RR-0014 (тариф/эмбарго — политика `allowed`, транспортная часть — `Φ`, не считается дважды).
- Кондоминиум (#351): содержание делится по долям; звено в регионе с долями — на долю контролёра-источника.
- Смена контролёра (сценарное событие, merge D−1, #347) переносит сеть вместе с регионом и **инвалидирует кэш `Φ`** (версия сети +1). Западный Берлин — эталонный случай для теста.

**Состояние звена.** `cap` (годовая ёмкость), `q ∈ [0,1]`, `wear ∈ [0,1]`. **Дневная нарезка (#345):** годовые `upkeep`, `cap`, `spend_max` хранятся как годовые ставки; в тик берётся доля по дню года (`rate·days_in_slice/365`, остаток в последний срез, целые Fx6 — тот же шаблон, что ADR-0019). Износ: `wear += w0·util − repair(upkeep)` по дневным долям; `q = q_max(class)·(1−wear)^γ` (степень — таблица/`PowFracFx` ADR-0012; никаких exp/ln/double, E1-model §6).
- `q` → потеря `λ = (1−q)·λ_mode`, задержка `τ = τ0/speed + τ_q·(1−q)` (только в варианте B — нужны потоки).
- **Буфер дисперсии `β` — отложен**: в E1 нет столбца запаса у получателя, к которому его можно привязать; без столбца это фиктивная механика. Вернуть, когда E2 введёт запас CMP (колонка запаса `stock_cmp[r]`); до этого `β` и `ι` в v1 **не** входят.

**Управление сетью (#263).** Рычаги: ползунок `B_inf`, веса `p_mode`/`p_node`. Приоритетные коридоры (≤ 3) — [Предл.] **выводятся из кластеров #214**; ручной коридор — только для армии (M3, вместе с боевым слоем); ручного коридора в M2 нет (разногласие Р7). Ключ порядка `(−score, link_id)`, `score = p_mode·p_node·(size_a·size_b)·gap`; пол `floor_share` ≥ 10% остатка в хвост; содержание — первым. **Решения о распределении принимаются в недельном шаге ИИ/планирования (#344), исполнение — дневными долями.** Рост качества — `q ← q + (q_max − q)·T(spend/cost_q)`, где `T` — **хешируемая таблица данных** (вместо `1−e^{−x}`; версия таблицы входит в хеш данных). Строящееся звено работает на старом классе; ввод в эксплуатацию — событие, применяемое в merge D−1.

**Вариант A (рекомендуется): `Φ` + доступ к рынку.** [Предл.]
- `Φ[r,r']` — стоимость кратчайшего пути (по цене и потере, с `q`), кэш кратчайших путей; пересчёт в **post-фазе по версии сети** (мемо, как ADR-0020), не каждый тик.
- Заменяет `d(r)` в `m_d = m_1·d` E1 §14.2 → `m_d = m_1·Φ(r, hub)`. **Тест эквивалентности:** для сети по умолчанию `Φ ≡ m_d` с допуском (например ≤ 1% на регион) на всех 12 сценариях M1; иначе это изменение модели E1/M1-golden и требует повторной проверки HYP (#332/#334). Энергия получает от звеньев только цену/потерю, **не ёмкость** (иначе двойное ограничение E1 §14.2 + звенья).
- Доступ к рынку `MA_r = Σ_j Y_j·Φ_rj^{−θ}` (Donaldson–Hornbeck 2016, QJE [Факт; URL ниже]) — единственный путь, которым звено меняет доход региона. Потоков, перегрузки и `Allocate` нет. Игрок всё ещё решает, какие звенья растить.
- Совместимо с FINAL RR-0014/RR-0010 (в E3 — один коэффициент издержки, ёмкость — волна 3): поправки к ним не нужны.

**Вариант B: потоки + перегрузка.** [Предл.] E2 даёт межрегиональный баланс CMP (его сейчас нет — E1 их не хранит; это новая подсистема), груз идёт по обобщённой стоимости `c + v·τ`, `v` по `priority_class` **в порядке #213/RR-0011 P02: армия / гражданская / наука** (в ревизии 1 порядок был ошибочно изменён). Узкое место делит существующий `Allocate`, остаток уходит на следующую моду. Перегрузка: `util = flow/cap`, множитель `1 + a·util^p`, `p=4`; в Fx6 `util` ограничить сверху (`util ≤ 4`, иначе `util^4` переполняет — считать в Fx6 через два возведения в квадрат с насыщением); форма BPR (1964) — URL не проверен [Предп.]. Обратная связь перегрузки — **кэш Φ, пересчитываемый в фиксированный день недели/месяца** (не по событию): цена включает `util` снимка предыдущего окна (ADR-0006), колебаний периода 2 нет (тест RR-0011 §3). Нужны: поправка к RR-0014/RR-0010 (ёмкость из волны 3), класс `why_not` для «нет звена / нет ёмкости» — вводится **только с EXP и пересчётом golden** (RR-0011 G09). Бюджет: 10⁴ потоков × ≤5 звеньев ≈ 5·10⁴ операций/месяц [Предп.]; дневной бюджет всех систем ≈ 2,7 мс (RR-0011 §6), нужны ворота деградации (RR-0010 §5б).

**Детерминизм (общее).** Fx6, обход по индексам, сортировка путей `(стоимость, id)`; `util^4` и таблицы — см. выше; все таблицы данных хешируются; потоки — только после согласования с ADR-0006.

### 3. Связь и информация (M3)
**Канал.** [Предл.] `comm[r] = cov[r]×tier[r]`, `tier` 0..5 (курьер → телеграф → телефон/радио → ТВ → спутник → оптика/мобильный); агрегат страны `comm_c`. Развитие — через tech-узлы и проекты. Определения для эффектов: `comm_mil` = `comm` регионов с базами армии, взвешенный по численности (производный, не новое состояние); `air_connectivity` — число хабов `airfield_class ≥ 2` в пределах `reach` (производный, M3, позже `comm`).

**Порядок эффектов (по ценности для ядра):**

- Сила доказательств: сводка и таблица согласованы — для пропаганды «сильные, но контекстуальные»; для военного управления — средние/качественные.

### 4. Ценность для игрока
Выборы: сеть против узкого места (много слабых звеньев или один порт); связь против выпуска (деньги в `comm` или в `proc_E`/upkeep); рельсы против авто в M2 (цена/износ). Рельсы против «авиамоста» — после FUTURE-блокады. Риски: доминирующая мода (нужен спад ёмкости с длиной, узкие места на портах); микроменеджмент (игрок не трассирует); связь как «+X% ко всему» (запрещено); ловушка сильных стран.

**Метрики Lab для осмысленного выбора [Предл.]:**
1. разрыв качества `q` между крупными и малыми узлами за 30 лет игры (не растёт ли разрыв только из-за `size_a·size_b`);
2. меняет ли исход гонки при равном `B_inf` смена `p_mode` или коридора (если нет — решение декоративное; если всегда — чрезмерно);
3. доля потока/стоимости по модам (нет доминанты >60% ни в одном сценарии 1945–2100);
4. регрет: доля сценариев, где лучшая стратегия — одна и та же настройка `p_mode`;
5. чувствительность исхода к случайной экспозиции сети (владельцу: см. вопрос №3).

### 5. Связь со слоями и состояние
Читает/пишет: E1 (регионы, `m_d` → `Φ` при прохождении теста эквивалентности); E2 (баланс CMP — только вариант B); RR-0014 (шлюз, landed cost — транспортная часть из `Φ`); RR-0010 (`why_not`, только с EXP); RR-0012 (проекты, institutes); RR-0017 (`ci_eff`; видимость — не через `comm`); RR-0008 (`informs`); RR-0007 (парк, M3); RR-0015 (`support` — вход); RR-0018 (`c2`, блокада — FUTURE).
Новое состояние (M2): звенья (≈600–1000 × `cap, q, wear, state, progress`), статья бюджета «инфраструктура», кэш `Φ` с версией сети; (M3): `comm[r]`, `airfield_class[r]`. Параметры: ≈ +20 к **≈92** в E1-model v0.4 (§11, §15.9) — фиксировать «на класс звена». ### 6. Что ядро отдаёт клиенту (M3, вход для ui-art-director)
Требование #263: стройка видна на карте. Ядро отдаёт только данные; в хеш — состояния, не кадры.
- Звено: `link_id`, `mode`, `from/to`, `state ∈ {planned, building, active, degraded}`, `progress` (Fx6), `class_cur/next`, `q`, `util` (вариант B).
- Узел: `airfield_class_cur/next`, `comm_tier`.
- События журнала: `LinkCommissioned`, `LinkDegraded`, `AirfieldCommissioned`.
- Геометрия: нет PD/CC0/CC BY геометрии сетей 1945 → **схематичные отрезки между центрами регионов** (вопрос владельцу №4 не выносится отдельно: см. OPEN). Видимость чужой сети — разведка (I08/RR-0017).

## Рекомендации (PROPOSED)
1. [Предл.] M2: вариант A (Φ + MA) на ж/д, авто, море, три числа на звено, правило контролёра, тест эквивалентности; без потоков.
2. [Предл.] M3: `comm` (порядок k_diff → spec), `airfield_class`, визуализация. E2/M2+: вариант B, `β`, `c2`.

## Риски
- Распухание параметров (+~20 к ≈92) — фиксировать «на класс звена».
- Двойной счёт `comm` (TFP, `k_diff`, `intel_conf`, `support`): одна переменная на эффект.
- Данные 1945 — вторичные/отсутствуют; старт-асимметрия от «порт+ж/д+шоссе по умолчанию» (#329).
- Изменение `m_d` может сдвинуть исход M1 — защищено тестом эквивалентности.

## Вопросы владельцу (≤ 4, по критичности)
1. **Вариант A или B для v1 логистики?** A: `Φ` + доступ к рынку, без потоков и перегрузки (дёшево, совместимо с FINAL RR-0014/0010); B: потоки + перегрузка + `Allocate` (богаче, требует E2 и поправок к RR-0014/0010). Рекомендуется A, потоки → E2/M2 и бой.
2. **Заменять ли `m_d` на `Φ` в E1** при условии теста эквивалентности (допуск ≤1%), или оставить `m_d` до M3?
3. **Может ли сценарное событие или ветка #299 зависеть от случайной экспозиции сети** (#260 против #342)? Влияет на ADR-0021.
4. **Допустимы ли схематичные отрезки между центрами регионов** для анимации стройки (#263) в v1 при отсутствии PD/CC0/CC BY геометрии сетей 1945?
