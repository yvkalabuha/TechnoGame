# Gate: парк без замены — критик (2026-11-19)

Артефакт: `docs/game-design/notes/fleet-without-replacement.md`. Отчёт агента critic, сохранён Orchestrator.

## Краткий вывод
- Правило убирает обрыв «нет самолётов по возрасту», но в нынешней формулировке в основном переносит проблему: вечные парки и занятые слоты на верхнем поколении, двойной зачёт замены.
- Слова решения #431 «место падает постепенно» не выполнены: старение не входит в механику места.
- Два порога предложенного эксперимента выполняются по построению. Четыре замечания высокой важности, пять средних, два низких.

## Замечания
| # | Важность | Суть | Исправление |
|---|---|---|---|
| 1 | высокая | Замена считается по числу машин в строю (запас), а не по приходу новых: те же 400 новых машин дают 400 «замен» каждый месяц; «один к одному» не выполняется | Счётчик зачтённых замен по (актор, поколение) или учёт только прихода за месяц. Это новая колонка состояния: «поезд схемы», уровень gate+research |
| 2 | высокая | Слот проекта освобождается только при нуле машин (`ProductsSystem.cs:1641-1660`). Поколения в данных кончаются на G4: у парка G4 замены не будет никогда, слоты заняты до 2030; при 12 занятых слотах новые проекты получают отказ | Считать заменой более новый проект того же поколения с большей характеристикой, либо явное списание; мера — число отказов по ёмкости проектов |
| 3 | высокая | ИИ не может избавиться от перестарков (`FleetBook.cs:200` их не считает, правило требует замену). Парк SUN при 805 машинах в месяц растёт без предела, содержание растёт, доля оплаты и готовность падают | Включить перестарков в списание ИИ первыми; не требовать замены при высокой нагрузке содержания |
| 4 | высокая | В состоянии нет боевой ценности парка; вариант старения меняет только последний член ключа места. Это показатель на экране без механики. O-023 выбрал вариант (а) молча, хотя вопрос затрагивает #431 и #422 | Вынести владельцу; либо связать старение с местом: порог «в строю» считать по эффективным единицам (число × ценность) |
| 5 | средняя | Условие «ценность ниже 50 %» при нижнем пределе 50 % не наступает никогда | Порог выше предела |
| 6 | средняя | Эксплойт: 50 машин верхнего поколения держат место до 2030 года без закупок; игрок списывает остальное бесплатно, ИИ не может | Порог по эффективным единицам; одинаковые правила списания |
| 7 | средняя | Порядок зачёта: новые G3 расходуются на G1, G2 остаются; перестарки G2 засчитываются как «новые» для G1 | Зачёт сверху вниз, сначала ближайшему нижнему поколению; перестарки не считаются заменой |
| 8 | средняя | Утверждение «побитно до месяца 178» неточно: проекция ИИ смотрит на месяц вперёд (`PolicySystem.Fleet.cs:131`), новая колонка меняет хеш с месяца 0 | Сравнивать по месяц 176 и только общие колонки |
| 9 | средняя | Меры 1 и 5 эксперимента выполняются по построению или не обоснованы | Доля содержания в бюджете, число машин против бюджета, доля машин без возможной замены, отказы по ёмкости |
| 10 | низкая | В ключе места характеристика — максимум по проектам в строю, а не «лучшее поколение × средняя ценность» | Одно определение |
| 11 | низкая | Перезапись эталонов «вместе с G5/G6» — скрытая зависимость | Назвать задачу |
