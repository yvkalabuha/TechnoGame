На выходе YAML-таблицы для ядра (`mods/core/map/`) и бинарный файл общих дуг для клиента.
- [Предл.] Ядро видит только целые и строки: id, регион, соседство, площадь в км², центроид в микроградусах. Геометрии в ядре нет, `float` в состоянии нет. Владение — две колонки `short` в `Table`: входят в `StateHash` и в снимок ADR-0013 без изменения формата.

## 1. Модель
| Уровень | Число | Что несёт | Источник |
|---|---|---|---|
| Провинция | 2500–3500 суши [Предл.] (#195: 2000–5000) | полигон, `owner`, `controller`; позже война, логистика, заводы (#198) | производная NE admin-1 10m |
| Регион | 150–250, 5–15 на великую державу (#171) | экономика и политика; группа соседних провинций | ручная таблица группировки |
| Полития | ~70–90 на 1945 [Предп.] | владелец; тинт; подпись | сценарий |

- **Id.** `region_id`: `[a-z][a-z0-9_]*`, по географии, а не по владельцу (`silesia`, `east_prussia`, `bavaria`), потому что владелец меняется, а id стабилен (ADR-0005). `province_id = <region_id>.<suffix>`, где `suffix` имеет вид `[a-z][a-z0-9_]*` (`silesia.wroclaw`). Принадлежность провинции региону вшита в id и не меняется в прогоне. Перенос провинции в другой регион — смена данных и миграция ключа (ADR-0013 п. 7). `polity_id`: `[A-Z][A-Z0-9_]*`. Где сущность совпадает с NE `ADM0_A3`, берётся этот код, иначе код проекта, например `CCP` для освобождённых районов КПК. Валидатор не даёт кодам проекта пересечься с действующими `ADM0_A3`. Актор = полития с тем же id (`SUN`).
- **Почему владение на провинции.** Владелец хочет точнее, чем ~200 регионов (#308). Линии 1945 года (Одер–Нейсе, 38-я параллель, Дунай в Верхней Австрии, 16-я параллель, линия Моргана) режут бы регионы. Владение на регионе потребовало бы позже миграции «регион → провинция» в сохранениях. Цена — 2 × 5000 `short` = 20 КБ состояния, это пренебрежимо.
- **owner и controller сразу** (отступление от B8 «не резервировать controller»). Причина в данных t0: без `controller` нельзя честно записать оккупационные зоны, это ровно случай I09 (RR-0011). Клиент заливает по `owner` и штрихует цветом `controller`, если тот отличается (как штриховка оккупации в спайке, GLOBE_DIRECTION §2.1). Смысл и правила смены (война, договор) остаются за RR-0016/0018.
- **`status`** провинции на t0 (`core | colony | protectorate | mandate | condominium | occupied | leased`) — данные сценария, а не изменяемое состояние. Сейчас нужен только для подписи и легенды.
- **Регион со смешанным владением** допустим: границы сдвигаются в игре. Экономика позже считает ячейку `(region, controller)`; это решает ADR экономики E1, а не этот документ. На t0 валидатор выдаёт **предупреждение**, если у региона больше одного `controller`. Регионы проектируются так, чтобы таких случаев было мало.

## 2. Сборка (`tools/map/`, детерминированно)
1. **Источники** — `tools/map/sources.lock.yaml`: тег релиза `nvkelso/natural-earth-vector` (закреплённый), URL, SHA-256 для `ne_10m_admin_1_states_provinces` и `ne_10m_admin_0_map_units`. Это страны без admin-1, проверка admin-0 и острова. Кеш вне git, загрузка в пустой каталог; файлы читаются только как данные. [Предп.] В 10m admin-1 около 4500–4600 объектов, число зависит от версии. 50m admin-1 покрывает только около 9 крупных стран, поэтому основа — 10m, а упрощение для рендера делает сам инструмент.
2. **Спецификация** (ручная, в git, собственная работа проекта, ADR-0009): `tools/map/spec/<area>.yaml` с правилами `merge` (коды `adm1_code` в провинцию), `cut` (разрез объекта линией или полигоном из `spec/cuts/<id>.geojson`; у каждой линии есть `source` и `precision`), `subdivide` (крупный объект делится рекурсивной бисекцией по меридиану или параллели пополам по площади; детерминированно, позже можно заменить ручным разрезом), `assign` (провинция в регион).
3. **Геометрия**: NetTopologySuite, `PrecisionModel` фиксированный 1e-6°. Правила применяются в порядке «имя файла, затем порядок правила». Покрытие суши чистится (snap, без дыр и наложений). [Предп.] NTS — управляемый код без нативного GEOS, поэтому одинаковый вход даёт одинаковый выход. Проверяется побайтовым сравнением повторной сборки на Linux в CI, как golden в ADR-0013 п. 10.
4. **Вычисления**: площадь в км² (равновеликая проекция, `long`); центроид и точка подписи в микроградусах (`int`); признак `coastal`; соседство — общая граница ≥ 1 км (касание в точке не считается) плюс ручной `straits.yaml` (ADR-0011); граф регионов по E9.
5. **Проверки**: покрытие суши без щелей; каждая провинция в одном регионе; число провинций и регионов в диапазонах §1; полосы площадей §5; каждая линия `cut` имеет источник; полнота таблицы владельцев (§3).
6. **Выход** (`mods/core/map/`, список файлов в `mod.yaml`, входят в `DataHash`): `provinces.yaml` (id, area_km2, centroid, label, coastal, `ne_src` — список `adm1_code`), `regions.yaml` (id, `capital_province`), `adjacency.yaml` (отсортированные пары), `straits.yaml`. Геометрия для клиента лежит в `mods/core/map/geo/`: `arcs.bin` — общие дуги, квантованные int32 микроградусы, упрощение с сохранением топологии, у каждой дуги левая и правая провинция (−1 = море); `manifest.json` с хешами. Каталог `geo/` исключён из `DataHash` по тому же правилу, что `locale/` в ADR-0018 §2, поэтому правка геометрии не меняет хеш ядра. Бюджет `arcs.bin` ≤ 8 МБ [Предп.: проверить на первой сборке; если больше — LFS или генерация при сборке клиента, OPEN].
7. **Таблица владельцев 1945 пишется вручную**, а не генерируется: `mods/core/scenarios/1945/owners.yaml`. Значение по умолчанию задаётся на регион, исключения — по провинциям. Поля: `owner`, `controller`, `status`, `source`, `as_of` (≤ 1945-09-02, #130). Там же `polities.yaml`: id, `actor?`, вид. Инструмент проверяет, что каждой провинции досталось ровно одно значение.

## 3. Ядро (только слой владения; мировую экономику не делаем)
- `Singularity.Core.Map` (данные): `MapData` строится из YAML при загрузке. Плотные индексы — по ordinal-сортировке строк id (как `region_id` в E-предложениях). Соседство хранится в CSR (`int[] offsets`, `int[] targets`, отсортированы). Таблица только читается, входит в `DataHash` и `scenario_hash`.
- **Состояние**: таблица `provinces` в `Table` (Kernel без домена), колонки `owner: short`, `controller: short` (индекс политии). Инициализация — из `owners.yaml`. Изменение — только в merge по событию или команде (ADR-0006, 0014). Таких событий пока нет, поэтому в M-срезе колонки постоянны. `StateHash` и снимок ADR-0013 подхватывают таблицу без изменения формата, `save_format_version` растёт по п. 7.
- **Виды (Session)**: `MapLayoutView(ProvinceIds, ProvinceRegion, RegionIds, PolityIds, PolityActor)` строится один раз в `Create`. В `SliceView` добавляется `Ownership(ImmutableArray<short> Owner, Controller, ImmutableArray<int> Changed)`; без изменений передаётся тот же экземпляр массива. Ключи для текста: `-region-<id>` и подпись политии. Провинции в v1 без имён: при наведении показывается регион, поэтому новый вид ключа в ADR-0018 не нужен.
- **Сохранения**: стабильный ключ строки — `province_id`. Порядок строк = порядок индекса (ADR-0013 п. 3). Другая карта означает другой `DataHash`, и загрузка честно падает с ошибкой (#307, до первой публичной сборки без миграций).
- **Бюджет**: состояние около 20 КБ, хеш < 0,1 мс [Предп.]. На месячный бюджет p95 ≤ 500 мс (#269) не влияет.

## 4. Клиент
- ID-растр R16 провинций: equirect 8192×4096 (64 МБ, ≈ 4,9 км/px на экваторе) или куб 6×2048² (≈ 48 МБ). Выбирает спайк (GLOBE_DIRECTION §8 п. 1). Растр печётся из `arcs.bin` при сборке клиента и в git не попадает. Для выбора мышью остаётся CPU-копия.
- Шейдер: `id → LUT_prov(RG16: owner, controller) → tint[owner]`, штриховка при `controller ≠ owner`. Граница государства на Z0–Z1 — по разности **owner** соседних пикселей (`fwidth`), а не id. Граница провинции — `rule` 0,6 du только на Z2+.
- Вектор на Z2–Z3: ленты из дуг `arcs.bin`. Набор «граница государства» = дуги с `owner(L) ≠ owner(R)`. При смене владения пересобирается только он, это линейный фильтр по дугам. Береговая линия = дуги с −1.
- Провинции мельче ~2 px (сектора Берлина и Вены, зона канала, Танжер) на Z0 — по правилу «кружок» GLOBE_DIRECTION §2.1.
- Подпись: полития-актор подписывается `-actor-<id>`, остальные — `-country-<polity_id>` (ADR-0018 §5).

## 6. ADR
[Предл.] Гейт (critic + advocate + третий голос). Это **ревизия 2 ADR-0011** (PROPOSED). План:
1. Контекст: #195, #306, #308, E9, B8; лицензии (`map-1945-borders.md`).
2. Решение: уровни и id (§1); владение `owner`/`controller` на провинции; полития ≠ актор; файлы `mods/core/map/` и `geo/` вне `DataHash`; граф регионов и `d_max` (E9); инструмент и закреплённые источники; точность A/B/C.
3. Альтернативы: владение на регионе (отклонено #308); только `owner`, без `controller` (нечестно для зон); готовый исторический набор (лицензии); Python + Shapely/GEOS (нативная библиотека, второй язык сборки; запасной вариант); прямое использование вершин NE в ядре (float в ядре); растр как источник истины (теряет соседство и вектор).
4. Последствия: `-country-<id>` теперь = id политии (формулировку ADR-0018 §5 об `ADM0_A3` трактуем как частный случай; новый ADR не нужен, решает Orchestrator); B8 частично заменён.
5. Проверка: побайтовая повторная сборка в CI (Linux); валидатор покрытия, диапазонов и полноты владельцев; тест «геометрия `geo/` не меняет `DataHash`»; тест save → load с таблицей `provinces`; L1/L2 с колонками владения; архитектурный тест «Core не ссылается на NTS».
