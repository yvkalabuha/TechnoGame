## Время: дневной тик (#60, спец. v0.5 §2)
- Тик ядра = 1 день (ADR-0006). Эталон крутит **дневной цикл** `day = 0 … day_tick(24) − 1` (730 дней от 1945-09-01); месячные системы среза срабатывают в день 1 каждого календарного месяца, в остальные дни состояние не меняется (только часы: 706 «пустых» дней из 730). Это точное отображение: числа траектории бит-в-бит те же, что у прежнего месячного цикла (в `out/` при переходе добавились только поля `day_tick`, `date`, `calendar`).
- `rows[].tick` — **индекс месяца** `t` (так его называет спецификация), `rows[].day_tick` — тик ядра `d(t)`, `rows[].date` — дата. Ключи RNG и правила `t mod 12` берут индекс месяца, не день (спец. §9.1).
- `formulas.json` → `calendar`: таблица `t → d(t)` (месяцы 28/29/30/31 дн., високосный 1948, конец окна и горизонта: 360 мес. = 10 957 дней, 384 мес. = 11 688 дней, последний тик 11 687 = 1977-08-31). Календарь — целочисленный пролептический григорианский (`days_from_civil`), при каждом запуске сверяется с `datetime`.
- D10 для T8: `t → d(t)` из `calendar` совпадает точно; C#-прогон в дневных тиках даёт ту же траекторию, что и `trajectory.json`, в тиках `d(t)`.

## Соглашения формата
- Все числа `Fx6` в JSON — целые raw (`3500000` = 3,5). Целые без масштаба: тики, id, люди в `workforce_split`, `u`, `r`, `threshold`.
- Узел = индекс в ключе RNG (`entity = actor·64 + node`, спец. §9.1); актор траектории = 0 (A7).
- `formulas.json` — у каждого случая `input` и `output` с промежуточными величинами (`drive`, `maint`, `sat`, `g` по измерениям, `ramp`, `yc`…), чтобы T8 мог локализовать расхождение.
- `trajectory.json`: `setup` (решение ИИ тика 0, профиль из потока `AI`), затем `rows[t]`: `commands_applied` (решены на t−1), `knowledge` (вес, `alloc`, `c_eff`, `dprog`, `prog_new`, ключ/`u`/порог hazard), `merge_report_output` и `merge_discoveries` в каноническом порядке, `commands_issued` (применятся на t+1), `yield_used` (по снимку), `state_after` (включая служебные колонки `proc_v`, `proc_yield` «прошлый месяц», контракт §4.0; до тика 0 обе = 0 — условие фикстуры).

## Порядок тика в эталоне (контракт v2.3 §4.0, спец. v0.4 §3.5)
0. Инициализация: решения ИИ тика 0 (профиль из потока `AI`, доли, `j` года 0, темпы) действуют с тика 0 (спец. §3.5 A8).
1. Начало t: бюджет `budget(t) = budget(t−1)·(1 + ⌊g/12⌋)` (A12); применяются команды, решённые на t−1.
2. compute (читает только снимок t−1):
   - знание: `K_ind` по `proc_v`, `proc_yield` месяца t−1 и `K_d`, `K_ind` снимка (A10), в буфер; фронтир, `w_n = prio·j / Σ`, `alloc = S·w_n`, `prog += alloc/c_eff` (`Kmix` из снимка); детерминированный узел открывается при `prog_new ≥ 1`, hazard — по `prog_new` после `prog_cap` (A3b);
   - способность: `yield` по снимку `H`, `M`, `proc_X` → `proc_yield` (буфер), выпуск по действующему темпу; `culture_H` по `H` снимка и `proc_v` месяца t−1 (A3); `tooling_M` по `M` снимка [Предл.: фазу оснастки контракт не называет, на числа не влияет];
   - команды ИИ на t+1 (темп линий — каждый месяц, `j` года — при t mod 12 = 0, t > 0).
3. merge: `report_output` по `(site, prc)` → `proc_X += units`, `proc_v = labour_hours` (0 и забывание `proc_X` без сообщения); открытия по `(actor, node)`; `K_d += μ_K·amount_d/S_ref + k_node·opened_d`. Затем буферы compute становятся состоянием.
4. post: только инварианты.

Итог: выпуск месяца t влияет на `culture_H` и `K_ind` в compute t+1 и виден с t+2 (контракт §4.0).

Покрытие траектории (`coverage` в JSON, проверяется в `--check`): промах hazard до открытия (ENG: тики 9, 10 — промах, 11 — открытие), два `report_output` в одном тике (с 17), два открытия в одном тике (11: узлы 2 и 3), команда темпа `t → t+1` (решена 16, действует 17), годовая команда `j` (12 → 13), открытие APP (19). Seed 6 выбран перебором `--find-seed` как первый, дающий всё покрытие; это выбор фикстуры, а не результат модели.
