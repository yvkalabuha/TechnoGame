## 2. Ответы на вопросы

2. **Где спрос на сплав входит в `v_exp`/`prc_set`?** Он уже там: через `prc_set` горячей части (данные r4/r5, R-AK2). Плавка получает `v_exp` в П/О, а `proc_v`/`proc_X` — от линий двигателей (A23). ## 3. Предложение к v0.13
**Ф1 (A37 + контракт §4.1a, §5 `planned`; erratum по смыслу G4-2).** [Предл.]
- `planned(site, p)` = p входит в `prc_set` своего проекта в стадии П, О **или в стадии С с выпуском `rate(t−1) = 0`**.
- `v_exp(site, p)` = `proc_v` + `Σ (r_plan·n_p)·labour_p` по таким проектам, где `r_plan` = `r_ref/4` в П и `r_ref` в О и в «С без выпуска».
- Причина: формулировка «О без серии» опиралась на то, что у серии есть `proc_v`. Серия, запущенная (по допуску или досрочно) на недопущенном `prc_set`, выпускает 0 и оказывается хуже проекта в О: нет денег наладки, нет `eligible`, нет прохода 2 A39. Это ловушка без выхода у любого актора, в том числе у USA на G3.
- Двойного счёта нет: при `rate > 0` слагаемое исчезает, работает `proc_v`.
- Правка Core: `ProductsSystem.Planned`/`PlannedVolume` (+2 условия). Тест: серия с `rate = 0` даёт `planned`, `v_exp = r_ref·n·labour`, при первом выпуске слагаемое пропадает.

**Ф2 (A39 проход 2).** [Предл.] Цель `min(H + ρ_max, M_cap)` вместо `min(H, M_cap)`.
- Причина: план поднимает `M_dec` ровно до `H` снимка, а `H` в том же месяце растёт. В следующем месяце `M < H`, источник — `M`, `limiter = TOOLING`, `E_useful = 0`. Наладка получает деньги 1 месяц из 3 (цикл виден в трассе t=236–250).
- `ρ_max` — верхняя граница месячного роста `H`, поэтому через месяц `M ≥ H`.
- Цена ≈ `ρ_max·cost_M` на ячейку один раз. Побочный эффект: GBR растёт сильнее (окна 1–2: 276/561 → 395/1343). Это нужно оценить на распределениях (T8/T10), а не принимать по одному seed.

**Ф3 (ловушка культуры без выпуска) — нужно решение владельца.**
- Ф1+Ф2 не выводят SUN в серию. Переход «`H < r_d − 1` → первый выпуск» в C-B идёт только через `ℓ`, а равновесие `ℓ`-роста со спадом к `H_floor` лежит ниже порога допуска для процессов с `r_d − H_start` > ≈0,4. Это свойство временного правила C-B (RISK-0016; стенд `culture-round2.md` §10.2: «деньги без выпуска — до 16% разрыва, без освоения»), обострённое стартом SUN (R-H даёт нижний край 3,2 шкалы-заглушки, `δ_c = 0`).
- Варианты [Предл.]:
  - (а) Опытное производство: в П/О и «С без выпуска» `ṽ` для `c_p` берётся как `k_proto·r_plan·n_p·labour_p` при `k_proto` ≈ 0,1–0,25. Это правка контракта §4.1 (gate).
  - (б) Калибровать `ℓ` (сейчас «З», не калибровалось) в сетке C2 до 1,0. Контракт не меняется, но эффект слабый и поздний (табл. §1).
  - (в) Пересмотр R-H и стартовых `H` (research-scientist; data_hash, scenario_hash до заморозки).
  - (г) Принять: SUN без лицензии и без копирования в G1 не входит, это честный исход (#28). Тогда HYP-0002 фактически проверяет USA/GBR — нужна правка пре-регистрации.
- Моя рекомендация: (а) как кандидат для gate с абляцией `k_proto = 0`. (в) проверить параллельно, без подгонки к истории (RISK-0011).
