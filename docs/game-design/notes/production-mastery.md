## 1. Что видит и решает игрок (M-play, #422)
Игрок — министр технологической политики; линий не строит (принцип «условия, а не процессы»). Рычаги **только существующие**:
- «Наладка» (#112): фокус до 3 приоритетных процессов — именно они растят культуру проекта в Prototype.
- **Новое одно решение: «держать / форсировать серию».** По умолчанию серия ждёт ворот. «Форсировать» разрешает старт при `y_min ≥ y_start` и прогнозе выхода выше `y_prod`; ниже `y_prod` форсирование недоступно (`why_not`). Игрок не может обойти инвариант, он выбирает момент и цену.
- Что игрок видит (100 % кадров, #417): карточка проекта «серия закрыта: лимитер — кадры точности (min по активным измерениям, названо), ожидаемо 2029–2033»; полоса «что дальше»: «парк G4 перестанет считаться в 2031 (#435) — проект G5 успеет / не успеет»; журнал: «серия G5 отложена: процесс 52, 62 %», автопауза на «ворота открыты» и «линия-кандидат закрыта (причина)».
- Выбор остаётся настоящим: сфокусировать «Наладку» на узком процессе, дождаться ворот, форсировать позже, или признать, что поколение не наше (потолок `Hcap`, #24). Покупка старого поколения игроком из ред. 1 **убрана**: в M-play работает существующий бюджетный механизм закупок (замечание DeepSeek про `M_PLAY_LOOP`).

## 2. Правила (для simulation-engineer; константы — [Предп.])
1. **Ворота старта** (заменяют условие `yield > 0`, `:413`): `y_min ≥ y_start`, `y_start = y_prod = 0,5` [Предп.], по каждому активному измерению; не снижая `Requirement` (`y_min` = минимум по измерениям).
2. **Закрытие кандидата:** линия нового проекта с `y_min < y_prod` дольше `T_Ab` закрывается; место и способность возвращаются рабочей линии старого поколения. Повторная попытка — только после смены `limiter` или роста `Hcap`.
3. **Статическое предвидение** (`Foresight`, чистая функция снимка, без итераций прогноза): для каждого `p` проекта — `Hcap(a, d, m + T_look) > r_d` по активным `d`; оснастка `M ≥ r_d` достижима по плану A39. `T_look` = горизонт старения парка (порог `n_eff < 50`, #435–#436) / `T_Ab` — выбрать одно в реализации и записать.
4. **Гистерезис:** `Requirement` поколения `g` не снижается, пока проект `g` в Prototype. Мерцание из-за шума исключено (замечание critic 5). Правило одинаково в `RequirementVariants` (UI/`why_not`) и в `Decide`, иначе UI покажет `Requirement`, которому ИИ не следует (critic 13).
5. **Область:** правила действуют с 1978-01 либо доказано тождественны на 1945–1977 (G1–G4 не меняются), см. §5 п. 3 [Предл.].
6. **Парк:** пока нового поколения нет, ИИ не списывает последнее поколение (ред. 4 `fleet-without-replacement.md` §2.6).
7. **Детерминизм:** целиком Fx6, без RNG; новых колонок нет → `SchemaVersion` без изменения; эталоны меняются только для прогонов за 1977 (поезд схем, оркестрация §5).
[Факт, advocate] `Planned`/`GrowthNominal` берут (актор, процесс) через `world.Products`: слот не нужен. [Предп., не проверено] побочные эффекты удержания Prototype на бюро и бюджете (`StartPending`, ворота).

## 3. Инварианты, проверяемые на старом коде (тест падает без правки)

## 6. Отложено
Слотовая «Программа освоения» ред. 1 (`V_OC = x_prog·R_cap·labour`, 2 слота, `T_hand`, `T_max`, `B_prog`, `StartProgramme`) **не входит** в M-play. Возврат — только если проба §5 с #438 + пп. 1–3 покажет, что процессы 43/73 всё ещё блокируют G5/G6 в строю. Тогда владельцу — вопрос #127 в фактической формулировке (critic 3): «#127 касался стартовых данных; учебный номинальный вход I-OC уже в контракте. Разрешаете ли расширить его до платной программы с номинальным выпуском? А — да; Б — нет, тогда останется предвидение, а 43/73 у лидера без донора не освоятся». Тогда же учесть замечания, снятые сейчас: Mastered недостижим без выпуска (programme оканчивается на «готов к серии»), `E_useful`/лидерство ячейки, `T_max` против ETA, стоимость `D` (ΣE + остаток = D).
