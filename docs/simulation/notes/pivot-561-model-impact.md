## 1. KnowledgeSystem: «исследование только через слоты, один узел на слот»

### 1.1. Что есть сейчас [Факт, код]
- Бюджет `S = share_R · budget · BudgetFactor` (`KnowledgeInputsAdapter.ResearchBudget`); `BudgetFactor` = (1 − стройка − содержание)·(1 + мощность построенных институтов).
- Вес узла `w = Priority(тип, hazard, вес дисциплины) × J` (J — случайный множитель года); доля узла `S·w/Σw`; прогресс `Δprog = alloc / c_eff`.
- Цели институтов (`InstituteSystem.Goals`: приказ игрока, иначе выбор ИИ) превращаются в группы (`BuildGroups`: цель + её незнакомые требования); группы получают κ_eff × долю (`PlanOf`, `AllocOf`, ρ = 25 % остальным), сама цель ещё × (1 + 0,05·уровень).
- «Ускоренная программа» (`FundProgramme`) из резерва докупает прогресс узла до 1, убывающая отдача `1/(1+k)`.
- Узлы с риском (`hz`, `key`; 45 из 99) открываются случайно после `prog ≥ θ_start`.
- Лицензии (`lic_knows`) дают узлы без исследования; кража снижает цену (`StealShare`).

### 1.2. Предлагаемый режим `Slots` [Предл.]
| Что | Правило |
|---|---|
| Кто получает прогресс | только узел, на который назначен работающий (построенный) институт; один институт — один узел, один узел — не более одного института (`IsTaken` уже это обеспечивает). Остальные узлы фронтира: `Δprog = 0`, прогресс не теряется |
| Где может стоять слот | только на узле фронтира (требования известны). «Цель вдали» — удобство интерфейса: очередь слота, которую раскрывает `BuildGroups` в порядке пути (игрок видит каждый узел очереди) |
| Цена узла `C_eff` | нынешний `c_eff` без изменений: `c_money · ahead · (1 − max(диффузия, кража)) / ((1 + K)·(1 + Σinforms))` |
| Время узла `T_n` | новое: `T_n = TimeByType[тип] · TimeGen[поколение]` в `KnowledgeParams` (как `CostN`; без смены схемы данных `nodes.yaml`), позже — перекрытие на узел из данных. Скидки знаний [Предл.] действуют на цену, на время — ослабленно (например, `T_eff = T_n / (1 + 0,5·K/K_ref)`), чтобы опыт ускорял, но не обнулял срок |
| Ставка слота при полной скорости | `r_slot = C_eff / T_eff` в месяц |
| Деньги | `B = S − содержание − стройка` (без «мощности» +0,8 %: ценность института теперь — сам слот). Если `Σ r_slot ≤ B`: все слоты на полной скорости; иначе каждый слот × `B/Σ r_slot` (то же правило, что `OverloadScale`; детерминировано, без порядка слотов) |
| Прогресс | `Δprog = min(1/T_eff, m_slot / C_eff) × (1 + 0,05·уровень) × фокус`; бонус уровня остаётся (#493) |
| Фокус (#561) | столбец уровня фокуса на слот, `f ∈ {0, 1, 2}`: скорость × (1 + 0,25·f), ставка × (1 + 0,25·f)², то есть итоговая цена узла × (1 + 0,25·f) — сжатие срока выпукло дорожает. Числа — заглушки для Lab, не результат |
| Неизрасходованное | не сгорает молча: [Предл.] уходит в резерв (механика резерва с утечкой есть). Это изменение экономики — решение game-designer / economy-analyst (OPEN) |
| κ, ρ, группы | в режиме `Slots` не действуют (нечего «перетягивать» из общего котла); код остаётся для `Shares`, позже — в долг на удаление |
| Узлы с риском | без изменений: слот ведёт прогресс до `θ_start` и дальше, шанс открытия по `hazard`; слот на таком узле может «висеть» годами — нужен показ шанса в UI и право снять слот (прогресс сохраняется) |
| Ускоренная программа | только на узле, где стоит слот (иначе нарушится «без института — ноль»); не может сократить срок ниже `0,5 · T_eff`. Остаётся отдельной механикой разового вложения рядом с фокусом (OPEN для game-designer: не дублируют ли они друг друга) |
| Лицензии, кража, диффузия | без изменений (#561: все механики остаются); лицензия — единственный путь к знанию без слота |
| `K_d` (знания дисциплины) | растёт от реально потраченных денег по дисциплине, как сейчас |

### 1.5. Очередь института и цепочка до цели (#562) [Предл.]
- **Хранение.** Очередь — состояние мира (влияет на ход симуляции, сохраняется, входит в хеш): столбцы `inst.q.k.i` (номер узла, 0 = пусто) на слот `k` и позицию `i`, пишутся только командой между тиками, как `inst.order.k`. Нынешний `inst.order.k` = голова очереди.
- **Длина.** До 8 узлов на институт [Предп.: путь к G4 от 1945 г. — 11–15 узлов при глубине 5–6, §1.4; на два института этого хватает]. Больше — дороже по столбцам (16 слотов × 8 = 128 столбцов на актора) и почти не нужно.
- **Цепочка до цели.** Игрок выбирает дальний узел — клиент строит цепочку незнакомых требований (тот же обход, что `BuildGroups`; в `any_of` — участник с наименьшим остатком цены, игрок может заменить) в топологическом порядке и **показывает её до подтверждения**: каждый узел, его цена, `T_eff`, ожидаемая дата при нынешних деньгах. Подтверждение кладёт цепочку в очередь (длинная — на несколько институтов, по выбору игрока).
- **Какой узел работает.** Первый элемент очереди, который во фронтире и не занят слотом с меньшим номером (детерминированно: меньший слот побеждает, второй берёт свой следующий элемент). Узлы, ставшие известными иначе (лицензия, другой институт), выпадают из очереди сами.
- **Окончание узла.** В следующем месяце слот берёт следующий годный элемент; переходных потерь нет [Предл.: потеря месяца-двух на «переналадку» — возможная ручка баланса, не в v0].
- **Ни один элемент не во фронтире** (требование ведёт другой институт): слот **простаивает** и даёт уведомление «институт ждёт»; ИИ-советник предлагает узел. Автозаполнения у игрока нет (выбор вручную, #561), но есть переключатель «автоплан» по правилу ИИ (§2.1) — по желанию игрока.
- **Замена.** Перестановка и замена элементов — свободно; прогресс снятого узла сохраняется (S5), поэтому смена ничего не даёт даром и ограничение `ReassignMonths` = 12 мес. (rev 4 §4) [Предл.] снять в режиме `Slots`. Узел, снятый с середины, показывается в дереве как «начат, x %».
- **Пустая очередь.** Слот простаивает, уведомление; в инвариантах S2 «цель слота» = активный элемент очереди.

### 1.6. Узлы, ускоряющие исследования вообще (#562) [Предл.]
- [Факт] В `docs/game-design/NODE_EFFECTS_SCHEMA.md` такого эффекта нет: узел сегодня открывает вариант изделия, поколение или процесс. Ближайший существующий механизм — знания дисциплины `K_d` (удешевляют `c_eff` узлов той же дисциплины) — уже положительная обратная связь, но в пределах дисциплины и только по цене.
- **Вид эффекта.** Новый тип эффекта узла `research_speed`: `{scope: all | [дисциплины], value: 0,05…0,15}`. Действует **на время** `T_eff` узлов в области действия, не на цену (цена — деньги, их ускорять компьютером странно; время — то, что сокращают вычисления и моделирование).
- **Сложение.** Суммой, не произведением: `T_eff = T_n / (1 + min(Σ value, cap_scope))`, `cap` [Предп.] 0,5 на дисциплину и 0,3 для «всех». Произведение 6 узлов по +15 % дало бы ×2,3 и растущий отрыв лидера; сумма с потолком даёт не больше ×1,5 / ×1,3.
- **Риск самоусиления.** Знаешь больше → исследуешь быстрее → знаешь больше: лидер убегает, отстающий не догоняет. Противовесы [Предл.]: потолок выше; диффузия (`known_elsewhere` уже удешевляет узлы, известные другим); такие узлы — дорогие и поздние; кража и лицензии. Проверка в Lab: разрыв USA–SWE по году первого G_k с эффектом и без (ворота: разрыв не растёт больше чем на N лет — N задать в предрегистрации).
- **Где в коде.** Один множитель на (актор, дисциплину), считаемый из снимка известных узлов перед шагом (сумма по списку узлов-эффектов, без аллокаций) и входящий в `T_eff`. Данные — в `nodes.yaml` (поле `effects`), то есть смена схемы данных и хеша.
- [Факт] В срезе «реактивная авиация» нет вычислительных узлов (99 узлов: `aero`, `prop`, `metal`, `chem`, `mech`): эффект можно сделать и протестировать в v0, но содержательно он появится с шириной дерева M1 (электроника, ЭВМ) — данные от research-scientist.

## 2. ИИ: выбор узлов по слотам и стройка институтов

### 2.1. Выбор узла [Предл.]
- PATH (#559, `InstituteSystem.PickForFreeSlots` на ветке TASK-0171) уже выбирает **по одному узлу на свободный слот** из ступени 1 пути (узлы, нужные для следующего поколения изделия), самый весомый — в институт с наивысшим уровнем в его области. В режиме `Slots` меняется только смысл: раньше слот без цели означал «деньги идут всем», теперь — **простой слота**.
- Поэтому порядок: ступень 1 → ступень 2 (поколение g*+1, уже считается в `GoalPath`) → любой узел фронтира по весу `Priority` (военный уклон профиля) → простой только при пустом фронтире.
- Устойчивость: ИИ не снимает слот с начатого узла, пока тот на пути или прогресс > 0,5 (прогресс и так сохраняется, но частые смены выглядят хаотично в журнале).
- #561 «превосходство, сначала военное»: путь обобщается с «следующего поколения истребителя» на «следующее поколение каждого военного класса изделий» с весом угрозы (отставание от главного соперника по `G`). В срезе класс один — правило записать, мерить на M1.

### 2.2. Фокус [Предл.]
ИИ ставит фокус 1 на узел ступени 1 с наибольшим остатком срока, если соперник опережает его по `G` и запас денег после ставок ≥ 10 % `B`; фокус 2 — только при войне или угрозе (позже, с военным слоем). Снимает при недостаче денег.

### 2.3. Стройка институтов [Предл.]

### 3.3. Дымовой прогон живости (Lab, 10 seeds, 1945–2030, все акторы ИИ) [Предл.]
- Простой слотов ИИ при непустом фронтире ≤ 5 % слото-месяцев (цель — 0).
- Нет застоя: у каждого актора интервал между открытиями ≤ 36 мес. до исчерпания фронтира.
- Нет выжигания денег: неизрасходованное ≤ 20 % бюджета науки в медиане (иначе слотов мало или узлы дёшевы).
- Число институтов ≤ потолка; содержание ≤ `U_max`.
- Время прогона в пределах нынешнего (`timings`).

### 3.4. Полосы темпа (направление, не подгонка) [Предл.]
- Мир только ИИ, медианы по 10 seeds: первый G2 любого актора 1948–1962, G3 1952–1970, G4 1962–1985; у каждого актора G2 до 1975.
- Порядок: лидер по `G` в 1977 — USA или SUN в ≥ 7 из 10 seeds; SWE не лидирует до 1990.
- Разброс: p90 − p10 первого G4 ≤ 15 лет (страж от «рулетки»).
- Полосы пересматриваются только по решению владельца; выход за полосу — разбор, а не подкрутка параметра.

### 3.5. Новый замер, ради цели #561 [Предл.]
«Сила рычагов»: игрок-скрипт (а) весь фокус на военный путь, (б) стройка до потолка, (в) упор на лицензии против ИИ-базы той же страны. Метрики: выигрыш в годах до первого G_k, месяцы превосходства по `G` над главным соперником, цена (деньги, отставание мирных узлов). Плюс поиск выродившихся стратегий: стройка всех институтов в 1946 г. не должна доминировать (содержание, недостача денег). Это прямой замер того, ради чего меняется игра.
