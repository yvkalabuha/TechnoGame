## Краткий вывод

## 1. Правило
**Что такое «бюджет» в срезе.** [Факт, `docs/research/data/jet-slice/scenario_1945.md`, R-BUD] `budget_index` = `gdp_a/gdp_USA × (доля авиации_a / доля авиации_USA)`, доля авиации **одинакова** у всех (оценка: открытого ряда с лицензией нет).
Это индекс бюджета военно-авиационных программ, а не ВВП; при равной доле он пропорционален ВВП. Как это меняет чтение сходимости:
- [Предп.] Это не сходимость производительности (Solow; Barro–Sala-i-Martin 1992, https://doi.org/10.1086/261816, β ≈ 2 %/год; Mankiw–Romer–Weil 1992, https://doi.org/10.2307/2118477 — не открывались). Здесь `s_a` = относительный ВВП × относительная военная нагрузка,
  а доля расходов — политический выбор. Значит `s_a` — историческая оценка, не вывод модели. `λ` для GBR (0,025) близка к β ≈ 2 %/год; для остальных (0,06–0,08) это скорость восстановления после 1945 года.
- [Предп.] Военная нагрузка СССР в холодную войну заметно выше, чем у USA (оценки расходятся), поэтому `s_SUN` по ВВП (0,43) — нижняя граница для военного бюджета.

**Формула** (шаг — 1 месяц, `n` — месяцы с 1945-09):
```
F(t)     = max_b B_b(t-1)                  // снимок Column.Current; читается всеми строками, пишется только Next
g_m      = floor(g_pa / 12)                // как в BudgetMath.Next
lambda_m = floor(lambda_pa / 12)
B_a(t+1) = max(0, (B_a(t) + lambda_m * (s_a * F(t) - B_a(t))) * (1 + g_m))
```
- Лидер (`B = F`, `s = 1`) получает `B·(1+g_m)`: ряд USA совпадает с нынешним `BudgetMath.Next`; он же задаёт рост рубежа.
- Рубеж отдельно не задан: если страна обгонит лидера, рубежом станет она, а USA начнёт догонять (`s_USA = 1`). «Лидер» — состояние мира.
- Порядок акторов не влияет: строка читает только `Current` (в том числе максимум по 5 строкам) и пишет в свой `Next`; без аллокаций.
- Fx6: произведения через `Int128` (`Fx6.cs`), величины ≤ 1,3·10⁷ raw — переполнения нет с огромным запасом.
- Свойства: при `s ≤ 1`, `λ_m ≤ 1` и `B ≤ F` верно `B(t+1) ≤ F(t)(1+g_m)`, никто не обгоняет лидера; к `s·F` бюджет подходит монотонно.

## 4. Реагирует ли правило на действия игрока (#235: размер бюджета игрок не меняет)
Варианты для владельца (решения нет):
- **А. Не реагирует.** Бюджет — внешний фон; игра идёт через узлы и линии. Стоимость нулевая, у игрока и ИИ равные условия. Остаётся замечание «деньги почти не нужны» (`m-play-horizon-2030.md`).
- **Б. Успех повышает долю.** Страна с поколением на вооружении выше среднего получает до +20 % к `s_a`. Стоимость: обратная связь «успех → деньги → успех» (нужны потолок и лаг), чтение состояния Session по снимку прошлого месяца, около дня работы и новые эталоны.
- **В. Гонка вооружений.** `s_a` растёт, когда у соперника на вооружении поколение выше (условием, не датой — как #256; игрок видит причину роста). Стоимость как у Б плюс определение «соперника».
- **Г. Игрок выбирает долю на «другие технологии»** — отдельное решение (#235), в срез не входит.
- [Предп.] А — минимум; Б и В нужно ограничить масштабом: после 1990 года у игрока в срезе и так мало решений (`m-play-horizon-2030.md` §3).

## 5. Что не должно меняться
- [Факт] Эталоны 1945–1977 откалиброваны на старых бюджетах; USA остаётся бит-в-бит (формула лидера = `BudgetMath.Next`).
- [Предл., расчёт] Отклонение новых бюджетов от старых, 1960 / 1977: GBR −5 % / −6 %; SUN +6 % / −19 %; FRA +15 % / −27 %; SWE 0 % / −23 %.
  Монотонное правило не повторит старые SUN (доля 0,51 в 1977) и FRA (0,22): они выше долгосрочной доли `s`. Чтобы приблизиться к старым, нужно `s_SUN` ≈ 0,5, `s_FRA` ≈ 0,22 — тогда в 2030 году +160 % и +60 % к истории.
- Одной формулой нельзя совместить «как раньше до 1977» и «как в истории после»; выбор владельцу: (а) история — перезапись эталонов, (б) эталоны — завышенный 2030 год.
- [Предл.] Изменение бюджетов — один шаг «поезда схемы» (orchestration §5): перезаписать golden один раз, объяснить; сравнить факты 1945–1977 (места, поколения в строю, первые линии) до и после, а не только хэши.
- Места правки (по поиску): `BudgetMath.Next`, `PolicySystem.cs:209`, `PolicyLiveness.cs:96` (прогноз `factor` по `growthPerYear`), стенды C1/C5, `FleetRuleTests` (зависят от `GrowthPa`), стартовые варианты (`growth_pa` ×m), `scenario.schema.json` и `ScenarioData.Actors`, `scenario_1945.yaml`/`rhms_off`.
