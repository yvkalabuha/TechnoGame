## 1. Гипотеза и кандидаты
[Предл.] Если в правиле культуры C-B у процесса живого проекта или серии есть «канал внедрения» — рост культуры от денег наладки без серийного выпуска, — то новый tier-4 процесс выходит из ловушки низкого выхода (`yield` 0,02–0,04, `c2-diagnosis.md` §4) за горизонт среза, а C1 и различия стран сохраняются.

**Почему нет кандидата В3а диагноза.** [Факт: контракт §4.1a r4, #128; код `CbCultureRule.Eligible`] Процесс проекта в П/О/С уже `eligible` (`planned`) и получает деньги наладки с весом `v_exp`, но «деньги без выпуска не растут»: `c_p` = 0 при `v_p` = 0, `E_useful` ≤ `ℓ·E_full`. В3а уже действует и ловушку не снимает.

**Кандидаты** (параметр Lab `CULTURE_VARIANT`; отсутствует = C-B без изменений). Для каждого `ṽ_grow` заменяет `ṽ_p` в `x_V` роста (`t_p`, `t̂_p`, `E_useful`, `k*`) и `v_p` в шагах 4–5 `limiter`/`limiter₀`. Поддержание `m_p`, `maint_p` — по фактическому `ṽ_p` (G-5: деньги культуру не держат).
- **CB** — база: `ṽ_grow = ṽ_p`.
- **I-A `VEXP`** — `ṽ_grow = (1 + k_tr·lic_p)·max(v_p, v_exp(site, p))`; `v_exp` — §4.1a r4 (#128): `r_plan` = `r_ref`/4 в П, `r_ref` в О и С. Процесс проекта или серии налаживается в объёме плана.
- **I-C `VEXPC`** — то же, но вместо `v_exp` — `max(v_p, V_C(a, p))` на `home(a)`: только номинал серии (стадия С), без проектов П/О. Наладка на серийной линии, чей выпуск ограничен деньгами (`unit_cost` ∝ 1/`yield`), идёт как при номинальном темпе. Это В3б диагноза («`c_p` от собственной ставки линии»).
- **I-B `LAB`** — у процесса с `planned(site, p)` лабораторный потолок `gapL_p = max(0, r_d − H)` (без `ΔL`), шаг 4 — `v_p = 0` и `H ≥ r_d`. Это В3в.
- **Новых чисел нет:** `r_ref`, `r_ref`/4, `k_tr`, `ℓ`, `v_cap` уже есть в контракте и спеке.
- **Комбинация I-A + I-B не прогоняется:** при `v_exp` > 0 `c_p·gap` ≥ 0,65·`gap` > `ℓ·gapL` [вывод из формулы], лабораторная часть в I-A почти не выигрывает.
- **Новые числа истории** (доля «пилотной отладки» 5–20%, срок 1–4 года, `process-introduction-sources.md` [Предл.]) не используются: источников нет, это была бы подгонка.

### 11.6 Рекомендация по правилу ИИ «не закрывать линию осваиваемого процесса» [Предл.]
**До C2 не вводить.**
1. **Правило било бы не туда.** Во всех 24 случаях процесс выпадает из пути актора (новый кандидат без процесса 40). Чтобы «не закрывать», пришлось бы держать третью линию (F17b разрешает две) или откладывать запуск поколения 4 ради процесса, который актору больше не нужен.

3. **Цена.** Ещё одна правка ИИ меняет golden. Задержка поколения 4 у USA сдвигает `tech_lead` (HYP-0002).

**Вместо правила:**
- (а) В отчёте C2 печатать класс **«процесс брошен до `t_07`»** (выпал из всех живых проектов актора) и KM с цензурой в месяц закрытия рядом со статистикой спеки. Пре-регистрацию не менять.

- (в) Если владелец всё же хочет правило: самая узкая форма без новых чисел — «кандидат, чей процесс ★ с `yield` < 0,7 выпадает из нового состава, заменяется только при `yield` нового кандидата ≥ `y_prod`». Это отдельный эскиз с пре-регистрацией и новыми seeds, не часть C2.
