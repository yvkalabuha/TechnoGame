STATUS changes_requested: 1 high, 6 medium, 2 low

- [high] §6 and «Проверка»: `thread_mismatch = 0` declared an L2 check and a validity condition: lab-cli.md: `matrix` compares `golden_hash` of one (point, seed) only across the `threads` values present in the manifest, and `threads` is optional with default `[1]`. With one threads value `thread_mismatch` is 0 with nothing compared, so the stated validity condition and the claims 'бесплатная L2-проверка' / 'L2 проверяется каждой матрицей' are false for a default manifest. `chunk_size` — an explicit INVALID axis in ADR-0016 §4 (1/8/32) and in ADR-0017 §8 — is never varied by `matrix` at all, so the Lab regression path is weaker than the determinism policy it depends on.
- [medium] §3 provenance list vs what run.json actually records: lab-cli.md records `dirty_untracked_src` precisely because the SDK compiles all `*.cs`, so untracked source changes the binary without changing `core_commit`/`dirty`. The ADR makes provenance mandatory but omits that field (and `manifest_path`, `data_files`, `model_info`, `model_is_test`), so a run built from a source tree with untracked files would look reproducible under this ADR while the implementation flags it.
- [medium] §5/§7 pre-registration: `script_sha256` written into the manifest: Manifest schema 1 (lab-cli.md) has a closed key set where an unknown top-level key is an error, and the documented keys contain no `script_sha256`. The only possible place is `meta`, which is hashed — and lab/manifests/README.md documents that editing `meta` invalidates already-recorded `manifest_hash` values. The ADR also gives no mechanism proving the freeze happened before the run, and `registry.py check` enforces no script hash (REPRO_FIELDS has none), so the pre-registration claim has no verification.
- [medium] §6 statistical regression: no multiple-comparison correction: RR-0002 §7.4 requires a Benjamini–Hochberg correction 'для многих метрик' in the statistical regression path. ADR-0008 §6 lists only quantiles, KS and bootstrap, and the linked working script (exp0001.py) explicitly prints 'поправки на множественные сравнения (8 признаков) нет'. Adopting §6 as written codifies a method that the research report already identified as under-controlled.
- [medium] §8 storage-review threshold ~10 GB CSV / 30 min analysis: The cited failure (#264) occurred at 3.7 GB CSV with 22.5 GB RSS, and the fix was a streaming loader inside one script. At 10 GB the same memory blow-up recurs well below the trigger, and exp0001.py in the linked files still materializes every CSV row in memory (`_read_csv` returns a list of dicts). The 30-minute criterion is also not instrumented anywhere in lab-cli.md (runs record `elapsed_ms`; analysis duration is not recorded), so the threshold cannot be detected.
- [medium] Lab↔Session and test-model marking not carried from ADR-0014 / lab-cli: ADR-0014 requires that any world built from Core systems (including Lab runs over Core) be built only through Session, and records the residual risk that Lab prototypes are mistaken for Core behaviour, with the defence being architectural tests plus marking of Lab reports. ADR-0008, the Lab decision, contains neither rule; it also never mentions `model_is_test`, which lab-cli.md records in run.json and which is the marker for non-scientific models (e.g. `test.random-walk`).
- [medium] Matrix validity ignores `problems` and subset selection: lab-cli.md: matrix.json carries `problems` and can finish with provenance divergence ('provenance differs from matrix'); `--point`/`--seeds` select subsets, and `golden_set_hash` is computed over the runs actually produced. The ADR's validity condition (`thread_mismatch = 0` and non-empty `golden_set_hash`) can therefore be satisfied by a subset matrix that has recorded problems, which conflicts with §3's ban on committing during `matrix`.
- [low] §2 manifest description omits required keys and misstates one condition: The enumerated schema keys omit `schema` (required; absence is an error), `experiment`, `description`, and the per-series `seeds`. §Контекст also says `golden_set_hash` is emitted 'только если все прогоны ok', while lab-cli.md adds 'and no thread_mismatch'. Anyone implementing from the ADR text alone would produce an invalid manifest and a wrong expectation about matrix.json.
- [low] No rule mapping run.json/matrix.json to EXP `REPRO_FIELDS`; no rebaseline procedure: `registry.py` requires `seeds` and `threads` on a DONE experiment, while run.json records a single `seed`; nothing in the ADR says how these are derived (or that they must cover the whole matrix), so the 'DONE-эксперимент имеет REPRO_FIELDS' requirement is satisfied by hand entry. Separately, RR-0002 §7.4 requires an explicit rebaseline procedure with a changelog entry when golden hashes change, and §7 only says goldens live in git.
