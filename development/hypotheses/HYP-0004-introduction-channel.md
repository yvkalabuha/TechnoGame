# HYP-0004 — Канал внедрения: новый процесс выбирается из низкого выхода без серийного выпуска

> Постановка, пре-регистрация и результат эскиза — `docs/simulation/introduction-channel-sketch.md` (здесь не дублируются). Основание — #238 В3, `c2-diagnosis.md`.

## Гипотеза
[Предл.] Если в правиле культуры C-B у процесса живого проекта или серии есть «канал внедрения» (рост культуры от денег наладки без серийного выпуска), то новый tier-4 процесс выходит из ловушки низкого выхода за горизонт среза. C1 и различия стран при этом сохраняются. Кандидаты без новых чисел: I-A (`c_p` от `v_exp`, #128), I-C (`c_p` от номинала серии `V_C`), I-B (лабораторный потолок до `r_d`) — эскиз §1.

## Причина появления
[Факт: `c2-diagnosis.md` §4] Все каналы роста `yield` пропорциональны выпуску, а выпуск пропорционален `yield`. Это поглощающее состояние: C2 `d` = 1 во всех точках T12, петля «знание → производство» не работает для tier 4–5.

## Предполагаемый эффект
Эскиз §4 (ожидания записаны до прогона).

## Альтернативы
В1 (принят, #238), В2 (ИИ, по #238 — после В3), В4, В5 — `c2-diagnosis.md` §6; комбинация I-A + I-B и «исторические» числа пилотной отладки не рассматриваются (эскиз §1).

## Риски
Освоение станет «бесплатным» и сотрёт различия стран (HYP-0002). Деньги наладки перетекут с работающих линий. Возможна подгонка через выбор варианта. Правило C-B временное (RISK-0016). Защита — критерии эскиза §3.

## Способ проверки
Пре-регистрированный эскиз на реальном Core: вариант правила подставляется из Lab (`CULTURE_VARIANT`, по умолчанию отсутствует). `JetSliceCalib` в точке C1 + C3 (p00); решение — по seeds 30001–30100. Эскиз §2.

## Критерии успеха
E1 (без `t_first` ≤ 0,5), E2 (цензура `t_07` < 0,5), E3 (`yield` p50 через 48 мес. ≥ 0,25), G-C1 (`loss_C1` = 0), H1 (разброс доли `t_07` по странам ≥ 0,2), H2 (p10 `t_07 − t_first` ≥ 12 мес.) — эскиз §3.

## Результат эксперимента
[Факт: эскиз §5, 2026-11-15] **Эскиз не пройден ни одним вариантом.**
- I-A и I-C снимают ловушку культуры: E3 0,39 / 0,29 против 0,027 у C-B.
- Цепочка при этом рвётся ещё в двух местах:
  - вход в серию: E1 0,59 (I-A), 0,81 (I-C, C-B);
  - второй барьер — `ramp`: E2 0,73 / 0,54.
- H1 не пройден (0,19 / 0,14).
- I-B почти без эффекта.
- G-C1, G-golden, H2 пройдены.
- Побочный эффект I-A: снятий A40 `PROCESSES` 0 против 54.

## Код вариантов (developer)
Оба варианта экспериментальные, по умолчанию выключены. С флагами off все golden main и существующие golden не менялись (`dotnet test`: Architecture 97, Kernel 316, Core 1035, Lab 20, Session 337 — зелёные).
- **I-OC** (`CULTURE_VARIANT` = `VEXPOC`): только Lab, хук `IntroCultureRule` (Core не менялся). `V_C` + `V_O`: к стадии С добавлена стадия О (`DesignStage.Prototype`), та же формула `r_ref·n_p·labour_p`; П не входит. Колонки `run.*` нет (как у других `CULTURE_VARIANT`).
- **В2 «пилотный выбор»** (`PILOT_CHOICE` = `OFF` | `ON` | `ON_ADMITTED`): Core `ProductPresets.Compose` (P2 Mass и P3 adaptive; P1 не затронут), `PolicyParams.PilotChoice`, `SliceRunConfig.PilotChoice`, колонка `run.pilot` только при on. Правило: если выбранный пресет (producible) не повышает `g` и `superior` повышает, берётся `superior`.
  - **`g` композиции** = максимальное `gen` узла среди процессов её `prc_set`; текущее `g` актора = то же по его живым проектам (П/О/С/в строю, не снятым). Чтения «g = gen(d)» и «g = ранг альтернативы» проверены и отвергнуты: на seeds 1–5, 384 мес. они не меняли ни одной композиции (двигатель одинаков у superior и producible).
  - `ON_ADMITTED` добавляет условие «у всех процессов `prc_set` `superior` `yield` > 0» (буквальное прочтение §7). Для не освоенных процессов это условие почти всегда ложно, поэтому `ON` (без него) — вероятный рабочий вариант; выбор за simulation-engineer.
- `SliceSession.TestApiVersion` 4 → 5 (новое публичное свойство `SliceRunConfig.PilotChoice`), `session-surface.v5.txt`, `JetSliceModel.SurfaceVersion` 5.
- Тесты: `tests/Singularity.Session.Tests/PilotChoiceTests.cs` (off = без колонки; on меняет колонку и реальные композиции ИИ на seeds 1–5; L1/L2 для `ON` и `ON_ADMITTED`, потоки 1 и 4); `SliceChecks` «switches» — `PILOT_CHOICE` ON/ON_ADMITTED и `VEXPOC` меняют прогон seed 1.
- Не сделано: `SliceObserver` (печать выбранного варианта по профилю, строки ~867) не знает о пилотном выборе и при on покажет по профилю, а не по факту.
