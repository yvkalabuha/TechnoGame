# Gate scripted-events-conditions rev 2 — advocate (2026-11-18)

Keep the main decisions. One strong contradiction with #341, two moderate simplifications, one consequence of an owner decision as a question.

- **strong — §3 "N true, S failed ⇒ skip at once".** #341 says a transient failure defers. S can be transient: FRG/C03 and C09 use `controls_all`, Austria `not at_war`. A temporary S failure now skips instantly — diverges from #341. Proposal: classify S atoms by monotonicity like N (transient ⇒ defer, monotone ⇒ skip); the `defer_on_sufficient` flag becomes unnecessary.
- moderate — `after` (hard cascade) and `fired(pred)` in N are two mechanisms with one result (monotone `skipped(pred)` already fails N for good): two reason codes (`pred_skipped`, `necessary_permanent`) for one cause, risk of drift (C09 has both). Proposal: `after` sets only order and `lag_days`; causality via N atoms; GDR/C03 generalises; `soft_after` merges into `after`. Developer/systems-architect with game-designer.
- moderate — windows: the validator (p. 5) hard-requires 6/12 months by class; #341 sets only the 36 maximum, so per-event override is not forbidden. Without it a mod or branch with long negotiations (Austria 1945–55, Saar) cannot set a realistic window. Proposal: class default, allow `defer_months` ≤ 36 with a mandatory `window_reason`; remove `on_fail` from the template (derive from `flags`/`kind`, write only overrides) — ~153 rows make duplication an error source.
- moderate — DSL vs closed vocabulary: a full DSL loses (determinism, validation, i18n in `failed_atoms`); keep the vocabulary. Missing: named compound predicates (`conditions.yaml`, macros of atoms, no new semantics) for repeated N like "power holds the zones and is not at war"; otherwise the "≤ 8 atoms, depth 3" cap is bypassed by copy-paste.
- moderate — gap vs #366: #299 branches may depend on stochastic streams, but there is no atom like `stream_outcome(stream, id)`. Reserve the name, ban in base, allow in `branch: counterfactual`; account for the atom-registry version in the save (§6) now.
- weak — player levers in M2: designing them in M1 is premature. One condition: list the levers before freezing the M2 atom registry; pressure atoms (`consent_to_hold` etc.) must read states the player influences, otherwise the event stays a table.
- keep: no RNG (#342), `nominal_date`/`effective_date`, golden test "all fired, `lag_days = 0`", typed pressures instead of `metric(war_exhaustion)`.

Open: owner — consequence of #341: `skip` is final with no re-check. In M1 it shows only under ablation; in M2 with war, IND/PAK creation failing because of a 1947–48 war would leave India with GBR until 2100 unless an `alt` is hand-written. Keep final skip, or add a `dormant` status that becomes `due` again when N/S recover (no RNG, within the scenario)? Hand-written `alt` for ~153 rows is too expensive.
