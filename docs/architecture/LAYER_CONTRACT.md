# LAYER CONTRACT — знание → способность → изделие

Статус: **DRAFT** · 2026-11-02 · владелец: systems-architect · сводит RR-0008 (знание), RR-0006 (способность), RR-0007 (изделие).
Основания: решения владельца #19, #23–#26 (`docs/decisions/DECISIONS_LOG.md`), ADR-0003, `.claude/rules/csharp-core.md`.
Связанный черновик: `docs/decisions/ADR-0012-deterministic-math-functions.md` (PROPOSED).

## Краткий вывод
- [Предл.] **Tier ничего не открывает.** Можно ли выпускать изделие, определяет только `production_profile(site, prc_set).yield` по его процессам (#26). Отставание до одного уровня даёт малый выход и высокую цену, больше одного уровня — выход 0. Требуемый tier изделия — производная метка для UI (C1).
- [Предл.] **Ключ способности — `site`** (промышленный район). В MVP у каждой страны один site; схема и API с первого дня принимают `site_id`. Причина — 1945 год: зоны оккупации, демонтаж, вывоз специалистов (C2).
- [Предл.] **Одна таблица накоплений (§3).** У каждого запаса один владелец, один эффект и одно правило забывания. Опыт процесса влияет на выход и цену. Опыт линии изделия влияет только на трудоёмкость сборки. Брак производства — это `q` из RR-0006, скрытые дефекты конструкции — RR-0007. Обратная связь «промышленность → наука» — отдельный запас `K_ind` с потолком (C3, C4, C8).
- [Предл.] Рост культуры **взвешен по объёму выпуска**: одна «показательная» трудная линия почти не двигает цель кластера (F2). Насыщение `(1 − H/Hcap)` множит **все** положительные члены (F3).
- [Предл.] Детерминизм (F4): забывание считается как множитель за тик, насыщение — рационально, степени — через `DetMath.PowFrac` с двоичным показателем 1/1024 (ADR-0012). `Exp`/`Log` в состоянии мира не нужны.
- [Предл.] Читаемость (F6): один запрос `why_not(actor, target)` возвращает цепочку не длиннее 3 звеньев, сверху вниз по слоям. Каждое звено называет рычаг игрока.
- [Предл.] Срез «реактивная авиация» (#25) использует подмножество контракта (§10). Всё остальное помечено FUTURE.
- [Предп.] Стоимость — около 1 мс на страну-месяц суммарно для всех трёх слоёв. Риск — калибровка, а не производительность (§11).

Правила, которые закрывают дубли:
1. `culture_H` растёт только от производства, `school_H` и `K_d` — только от науки. Мост между ними один: `K_ind`.
2. Образование не является запасом в этом контракте. Оно даёт кадры, а кадры — `Hcap` и `w`.
3. `line_E` не влияет на `yield`, `q` и надёжность. LR линии задаёт класс изделия и `complexity` проекта, **не культура**: культура уже входит в цену через `unit_cost_mult`.
4. Брак производства (`q` из RR-0006) и скрытые дефекты конструкции (`defects_hidden`) имеют разные причины, разные ярлыки и разные рычаги. Готовность множится на оба, но формулы друг друга они не используют.

## 4. Динамика (формулы контракта)
### 4.1 Культура `culture_H` (правка RR-0006 §4.5; F2, F3)
```
v_p      = выпуск p за месяц в чел.-ч (yield_p > 0), s_p = v_p / Σ_{p∈c} v_p      # доля объёма кластера
drive    = Σ_p s_p · max(0, r_d(p) + 0.25 − H)                                   # цель и рост взвешены объёмом
catch    = Σ_p s_p · world_lead(p) · max(0, r_d(p) + 0.25 − H)
spill    = Σ_c' R[c,c'] · max(0, H[c',d] − H[c,d])
maint    = Σ_p s_p · r_d(p) · min(1, act[c] / act_norm)                          # уровень, который держит текущая работа; 0 без загрузки
ΔH⁺      = dt · sat · (α·act[c]·w[c]·drive + k_catch·catch + σ·spill)
ΔH⁻      = dt · δ_H · max(0, H − maint)
ΔH       = min(ΔH⁺, ρ_max·dt) − ΔH⁻
```
- [Предл.] **F2.** Линия с 1% объёма кластера даёт 1% тяги. Чтобы учиться, нужен массовый трудный выпуск, а он убыточен при низком выходе. В этом и состоит видимая цена освоения.
- `world_lead(p)` = 1, если в прошлом месяце какой-либо актор вёл p с `yield ≥ 0.7`. Значение считается в post-фазе и одинаково для всех.

### 4.2 Выход и цена (RR-0006 §4.4 без изменений, плюс агрегат по изделию; C1)
```
yield_p = Π_{d: r_d>0} g(c_d − r_d) · ramp(proc_X)     g = 0 (gap<−1); (1+gap)² (−1..0); 1 (≥0)
production_profile(site, prc_set) =
  admitted        = ∀p: yield_p > 0 ∧ p ∈ known_processes(owner)
  unit_cost_mult  = Σ_p n_p·base_cost_p / max(yield_p, ε)  /  Σ_p n_p·base_cost_p
  q               = min_p q_p ;  bottleneck = argmin_p yield_p → (dim, H|M), ничьи разрешаются по id
```
[Предл.] По #26 «фактически невозможно» = `g = 0`. Штучные опытные образцы при `gap < −1` отнесены к FUTURE (флагманы RR-0011).

### 4.3 Промышленность → наука (C8)
```
V_d   = Σ_{p: discipline(p)=d, yield_p ≥ 0.3} v_p
ΔK_ind = dt · η · V_d/(V_d + V_ref) · max(0, 1 − K_ind/(θ_ind·K_d))      θ_ind ≈ 0.25
```
Отдача убывает (`V/(V+V_ref)`). Потолок привязан к собственной науке: промышленность может дать не больше четверти научного запаса дисциплины и не заменяет НИОКР.

### 4.4 Изделие (RR-0007 §4–5 с правками)
```
assembly_hours(E) = h_floor + (h_first − h_floor) · PowFrac(1 + E, −b)     b = −log2(LR), квантуется до 1/1024 при загрузке
unit_cost(design, site) = materials_floor + assembly_hours(E)·wage + Σ_p n_p·base_cost_p/yield_p
detected(t)  = λ · PowFrac(test_hours + k·fleet_hours, β)                  β < 1
upkeep       = upkeep_base · PowFrac(complexity, α_u) / maintainability
```
Константы `log2(LR)` считаются офлайн при компиляции данных: `Log` в рантайме не нужен.

### 4.5 Детерминизм (F4)
| Выражение | Источник | Замена |
|---|---|---|
| `exp(−t/τ)`, забывание | RR-0005, RR-0006/0007 | множитель за тик `(1 − δ·dt)`, δ задаётся за месяц |
| насыщение, ramp | RR-0006 | рациональные формы `x/(x+h)` |
| `(1+E)^(−b)`, `h^β`, `complexity^α` | RR-0007 | `DetMath.PowFrac(x, q10)`, ADR-0012 |
| `(1+T/Tref)^γ·P^β·N^(1−β)` | HYP-0002 | `PowFrac`, значения β и γ на сетке, кратной 1/1024 |
| `log2(LR)` | RR-0007 | только офлайн, в компиляторе данных |

- [Предл.] MVP: у RR-0006 четыре пула на site. `Bureau` не владеет людьми: каждый месяц он вызывает `reserve_workforce(site, engineer, n)` и получает `granted ≤ n`. Специализацию КБ задаёт `bureau_exp[class]`, а не пулы по специальностям.

- Экипажи: в срезе только показываются (`crew_req`) и не списываются. Затем они берутся из пула `skilled`. Отдельный пул `military` — FUTURE (RR-0016).

## 6. `why_not(actor, target)` (F6)
`target` ∈ {`app_id`, `design_id`}. Чистая функция снимка, в состояние не пишет. Возвращает `Link[≤3]`, где `Link { layer, cause, subject_id, have, need, lever }`. Порядок проверки:
1. **Знание:** нет узлов на пути к APP. Звено — ближайший недостающий узел по цене. `lever` = приоритет института или лицензия.
2. **Способность:** `admitted = false` или `yield < 0.7` у узкого процесса. Звено — `(prc, dim, H|M, have, need)`. `lever` = учебная серия, импорт оснастки, программа качества или кадры.
3. **Изделие:** нет проекта, не хватает инженеров (`granted/n`), открыты `defects_hidden`, дефицит материала.

Берётся первый провальный слой и до двух причин из него или из следующего. Ничьи разрешаются по id. Пример: «Нет реактивного истребителя ← нельзя вести `s6.prc.precision_blade_forging` (выход 0) ← precision: культура 3,2 при требовании 4,5, станки 4,6».
Тест: для каждого из 3 слоёв есть сценарий, в котором первым звеном оказывается именно этот слой. Ответ полностью детерминирован.

## 7. Рычаги игрока на `culture_H` при гибриде #19 (F7)
| Решение | Механизм | Видимая цена |
|---|---|---|
| Учебная серия: массовый выпуск трудного процесса | растёт `s_p` → `drive` | убыток `(1/yield − 1)·cost` в месяц, занятые кадры |
| Импорт оснастки или лицензии | `tooling_M↑`, `X½↓`, `k_catch` работает | деньги, `import_share`, риск эмбарго |
| Программа качества или стандартизации (RR-0010) | `α↑` по `quality_control`/`process_control` на 5–10 лет; `ρ_max` и `sat` действуют | инженеры, отнятые у КБ, бюджет |
| Распределение кадров: армия, наука, промышленность | `w[c]`, `act[c]` | меньше армии или меньше науки |

Прямой «покупки уровня» нет: tier остаётся меткой (RR-0006 E17 REJECTED).

## 8. Абляции и проверка на двойной счёт (C3)
1. **Тест разреженности (CI, детерминированный).** Берём снимок, сдвигаем один запас на Δ, проводим один месячный compute и сравниваем выходы с таблицей §3. Если меняется выход, который запасу не принадлежит (например, `line_E` двигает `yield` или `q`), тест падает. Это прямая проверка «одного эффекта на запас».
2. **Абляция каналов (Lab, срез).** Сценарии: полная модель; `α = 0`; `ramp ≡ 1`; `b = 0`; `η = 0`. Для каждой метрики (время до `yield ≥ 0.7`, цена сотой штуки, `K_d` к 1955) ровно один канал должен давать вклад больше 70%. Кроме того, сумма одиночных эффектов на `log(unit_cost)` должна совпадать с полным эффектом в пределах ±15%.
3. **Коридор кривой.** Суммарное падение цены на удвоение выпуска на зрелой линии не должно превышать 30%: Wright 80% плюс ramp в пределах исторического диапазона. Выход за коридор — признак двойного счёта.

## 9. Старт 1945 (#23) и асимметрия (#24)
- [Предл.] Сохранность стартовой расстановки задают:
  - стартовые данные `culture_H`, `tooling_M`, кадры (RR-0005);
  - `ρ_max` (скорость догоняния);
  - `sat`/`Hcap` (образование);
  - `δ_H` (эрозия лидера без загрузки);
  - `k_catch`;
  - `σ` (перелив);
  - `θ_ind`.

  Больше ничего из контракта на это не влияет.
- [Предл.] Размер страны действует через **объём**: сколько линий и сколько `v` одновременно. Через уровень `H` он не действует. Малая страна может стать лидером в нише, но не по суммарной силе.
- [Предп.] В модели способности нет случайности. Значит, разброс между seeds дают RNG знания (FND) и события. Если разброс мал, ориентир 30–40% недостижим без шума в знании. Проверить в Lab.
- Критерий для совместной гипотезы (#25):
  - смена лидера среди великих держав за 1945–1975 — в 30–40% seeds (Wilson CI);
  - лидер определяется по `Σ` выпуска по tier ≥ 4 при `yield ≥ 0.7`;
  - малая держава обгоняет великую не чаще чем в 5% seeds.

## 11. Стоимость тика [Предп.]
Расчёт на месяц, 200 site в MVP:
- `culture_H` и `tooling_M`: 200·8·5 = 8·10³ ячеек × ~30 операций;
- `yield`: 3·10⁴ процессов;
- `PowFrac` на линиях и проектах: ~4·10⁴ вызовов × ~50 нс ≈ 2 мс;
- знание: ≈ 1,6·10⁶ операций (RR-0008 §11).

Итого ~3–5 мс на месячный тик, то есть ~0,15 мс на день в среднем. Бюджет RR-0002 — 8–45 мс на день.

Compute идёт параллельно по site. Merge собирает сообщения в порядке `(site_id, prc_id)`. Если пик месячного тика окажется заметным, системы разносятся по дням месяца.
