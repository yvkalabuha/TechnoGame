## 1. Словарь условий

Условие — дерево `all | any | not` над атомами, глубина ≤ 3, ≤ 8 атомов. Атом: `id` из реестра C# (`AtomId`), типизированные аргументы (polity, set, event, число fixed-point). Все атомы читают только состояние `World` (таблицы `provinces`, `polities`, `event_status`), вычисляются целыми числами, без `double`.

| атом | смысл | монотонность | M1 |
|---|---|---|---|
| `exists(P)` | политии `P` есть в таблице и `alive` | немонотонный (создание событием) | да |
| `absorbed(P)` | `P` была `alive` и стала `!alive` (нет провинций и территорий, нет преемника-события в ожидании) | **монотонный** (необратим) | да (после события) |
| `polity_free(P)` | `P` ещё не создана (для `create_polity`) | монотонный | да |
| `owns(P, set)` / `owns_all` / `owns_any` / `owns_share(P,set,≥ppm)` | `owner` провинций набора = `P` | транзитный | да |
| `controls(P, set)` (аналогично) | `controller` = `P`; для совместной политии `controls(ALLIED_VIENNA, set)` | транзитный | да |
| `at_war(A, B)` | активная война между акторами | транзитный | **константа false** |
| `war_over(set)` | идёт или завершилась война, чья цель/фронт включает набор | транзитный | **константа false** |
| `fired(E)`, `skipped(E)`, `deferred(E)`, `alt_fired(E, name)` | статус другого события | `fired`/`skipped` монотонны | да |
| `metric(P, name, op, k)` | порог из белого списка метрик (`gdp_index`, `legitimacy`, …), fixed-point | транзитный | **запрещён валидатором** |
| `has_tech(P, id)`, `trait(P, id)` | расширение для M2/веток, через тот же реестр | транзитный | нет |

- Набор территорий (`set`) — именованный список из `mods/core/scenarios/1945/sets.yaml`: id провинций, либо id «территорий без геометрии» (ADR-0011 §226, категория B: Индия, Алжир и др., так как карта M1 — только Европа, RR-0020 §3). [Предл.] Новый файл `territories.yaml` с владением без геометрии; без него `owns` для неевропейских событий не вычислить. Это зависимость 1.6b (systems-architect).
- `absorbed` определён строго: нет `alive` флага ≠ «потеряла территорию». Польша, потерявшая провинции, не поглощена. [CSD] проверить определение для политий-преемников и совместных политий.
- Условия вычисляются в слоте `ScenarioEventSystem` (ADR-0019 п. 11): на состоянии конца дня `D−1` плюс эффекты уже обработанных сегодня событий в порядке `(nominal_date, event_id)`. [Предп.] merge-слот первый в списке, поэтому читает свежекоммиченное; точное чтение (до или после merge) — за systems-architect.

## 3. Правила провала и умолчания

Каждое событие имеет `on_fail`. Атомы классифицированы: монотонный провал (`absorbed`, `skipped(pred)`, `fired(другое взаимоисключающее)`) = **постоянный**; транзитный провал = **временный**.

| провал | по умолчанию | пояснение |
|---|---|---|
| N, постоянный | **сразу** `alt` (если задан) иначе `skip`, reason `necessary_permanent:<atom>` | откладывать нечего |
| N, временный | **`defer`**, окно `window_months` (умолч. 6; `war-related`/деколонизация 12; максимум 36 [Предп.]), проверка каждый день | при истечении — `on_expire: skip` (умолч.) или `alt` |
| N выполнено, S провалено | **`skip`** сразу (умолч.) либо `alt`, если автор задал; `defer` только если явно `defer_on_sufficient: true` | причина не работает — не ждём |
| `after` предшественник отложен | событие ждёт, окно считается от `max(nominal_date, fired_date предшественника)` | |
| предшественник `skipped`/`disabled` | каскад: `skip`, reason `pred_skipped:<E>`; если у зависимого есть собственный `alt` — берёт его | |
| атомарная группа | все члены срабатывают в один день или ни один (одно решение на группу) | K9 |

- Окно в календарных месяцах: `deadline = AddMonths(nominal_date, N)` с обрезкой дня; целые дни, без времени суток. [Предп.]
- **Какая дата записывается.** Хранятся две: `nominal_date` (неизменна, из таблицы) и `effective_date` (день применения). Состояние провинции и цепочек использует `effective_date`; журнал и UI показывают оба и `lag_days`. История не «подгоняется»: отложенное событие не помечается задним числом.
- **Порядок в дне.** Ключ `(nominal_date, event_id)`: отложенное событие обрабатывается раньше новых событий дня, а при одинаковых датах — по id. Предшественник в цепочке имеет меньший ключ (проверка валидатора).
- **Цепочки.** Задаются `after: {event, lag_days}`; зависимое не может сработать раньше `predecessor.effective_date + lag_days` и не раньше своей `nominal_date`. Пример: C26 откладывается на 40 дней → C27/C28 срабатывает на `effective(C26)+90`, а не 1955-10-25.
- `excludes: [E…]`: срабатывание одного снимает другое (запасной путь Oder–Neisse).
- `alt` — именованный альтернативный эффект того же события (другой набор записей owner/controller, возможно другая политика-преемник), с собственным именем в журнале. Без `alt` провал приводит к `skip`: территория остаётся как есть.

## 4. Взаимодействие с гипотезой M1

- [Факт, MS-M1] В M1 нет войны, владение меняют только события. Поэтому единственные способы провала: абляция (S4, S5), моды, ошибки данных, каскад из пропущенной цепочки. [Предл.] Базовый прогон: все события `fired`, `lag_days = 0` — контрольный golden-тест; любое `deferred/skipped` в базе — блокирующий дефект.
- **Seed и #329.** [Предл.] Условия M1 не читают возмущённые стартовые значения (экономика, население, энергия): атом `metric` запрещён валидатором. Таблица владения не возмущается. Следствие: журнал событий идентичен для всех seeds и не создаёт скрытую связь «seed → сработало ли событие», а S4/S5 измеряют именно экономику vs скрипты (RISK-0011). Если владелец захочет пороги экономики — это отдельное решение с влиянием на S4 (вопрос 2).
- **RNG.** [Предл.] В условиях нет RNG. Вероятностные события (поворотные «могло случиться иначе») не вводятся; если нужны, то только как явный бросок отдельного потока с учётом в L2 — после решения владельца (вопрос 4).
- **Журнал для S4/S5.** Состояние `event_status ∈ due | deferred | fired | alt_fired | skipped | disabled` и `effective_date` входят в `StateHash` (L2) и сейв. Записи журнала (производный вывод, не хэшируется): `event_id`, `group`, `nominal_date`, `status`, `effective_date`, `lag_days`, `reason_code` (enum), `failed_atoms[]` (id атома и значение), `alt_name`, `affected_provinces`. Пишется при первом провале, при каждом переходе статуса и при срабатывании (не ежедневно).
- **S4**: события выключены = `disabled` (не `skipped`), чтобы причины не смешивались. **S5**: абляция по 5 группам; [Предл.] валидатор требует, чтобы рёбра `after` лежали внутри одной группы абляции либо явно помечены `cross_group`; иначе абляция группы тихо отключает чужое событие каскадом. Отчёт S5 дополнительно: число `deferred/skipped/alt`, средний `lag_days` по группам.
- Игровая ценность: «почему не сработало» — UI собирает причину из `failed_atoms` по шаблонам i18n (не из свободного текста): «Индия остаётся в составе GBR: не выполнено `owns(GBR, british_india)`».

## 5. Формат данных и валидатор

`mods/core/scenarios/1945/events/*.yaml`; одна запись на событие. [Предл.] Шаблон `kind` выдаёт N и дефолтный S, автор дополняет.

```yaml
- id: C09_FRG_SOVEREIGNTY            # unique, sort key (date, id)
  kind: transfer_controller          # transfer_owner | transfer_controller | create_polity | dissolve_joint | no_effect
  nominal_date: 1955-05-05           # chosen date from RR-0020 ("Rek."); signed/in_force/handover kept in `dates`
  dates: {signed: 1954-10-23, in_force: 1955-05-05, handover: 1955-05-05}
  group: germany_korea               # ablation group (S5), one of the 5
  flags: [disputed]                  # war_related | disputed | partial
  effects:
    - {set: germany_west, controller: {from: [USA, GBR, FRA], to: FRG}}
  after: {event: C03_FRG, lag_days: 0}
  necessary: {all: [{fired: C03_FRG}, {exists: FRG}]}
  sufficient: {controls_all: {polities: [USA, GBR, FRA], set: germany_west}}
  on_fail: {necessary_temporary: {defer_months: 6, on_expire: skip}, sufficient: skip}
  alt: {}                            # name -> alternative effects, optional
  source: {rr: RR-0020, row: C09, confidence: H}
```

Проверки валидатора (CI, `tools/` + тест в `tests/`):
1. Схема и закрытый словарь: неизвестный атом, неверные типы аргументов, глубина > 3, свободный текст — ошибка. `metric`/`has_tech`/`trait` запрещены в M1-пакете.
2. Ссылки: polity, set, event, `after`, `excludes`, `alt` существуют; `polity_free` — только у `create_polity`.
3. Граф: нет циклов `after`; ключ предшественника < ключа зависимого; `nominal_date` зависимого ≥ даты предшественника + `lag_days` (иначе предупреждение).
4. Эффекты: `from` соответствует `owners.yaml` на дату после всех более ранних событий (статический прогон по цепочке); K9: набор не делится между событиями одного дня без порядка; `owner ≠ controller ∧ status ≠ leased` согласовано (ADR-0011 §2.12).
5. Окна: `defer_months ≤ 36`, срок не выходит за конец сценария; `alt` задан для необратимых событий M2 (предупреждение).
6. Группы: рёбра `after` в пределах группы абляции или с `cross_group`.
7. Динамический тест (test-engineer): базовый прогон — все `fired`, `lag_days = 0`; для каждого события синтетически ломается по одному атому N и S, ожидается заявленный путь `defer/skip/alt` и детерминизм L1/L2 (повтор хэша).

## 6. Повторное использование: M2 и ветки #299

- **M2 (война).** Те же события, но атомы `at_war`, `war_over` становятся живыми; #336: `war-related` договоры заменяются реальной войной. [Предл.] Такое событие остаётся как `fallback`: срабатывает, только если `not war_over(set)` к концу окна; при реальной войне — `skipped`, reason `superseded_by_war`. Транзитные атомы дают естественное «отложить, пока идёт война, и проверять ежедневно». `metric` включается как белый список fixed-point метрик для S (например, `legitimacy`), с учётом в хэше.
- **Альтернативные ветки #299/#322.** [Предп.: содержание #299/#322 по строкам журнала, не перечитывалось] Ветка = событие с `alt` или с другим `nominal_date`/эффектом, помеченное `branch: counterfactual`; когда причина провалена (`absorbed(P)`, `has_tech`, `trait`), `alt` — готовая «развилка» вместо `skip`. Атомы расширяются через реестр без смены формата. counterfactual-analyst поставляет `alt`-исходы и «ранние» ветки; [CSD] решает, что считается национальной школой для `trait`.
- Совместимость сейва: версия реестра атомов в манифесте; новый атом = новая версия (SAVE/ADR-0020).
