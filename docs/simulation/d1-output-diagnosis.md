- [Предл.] Минимальные правки: **E1** — стартовый парк USA/GBR с действующей линией (спека A32/R-FL; erratum к K3); **R1** — `Requirement` «на замену», если у актора нет линии и нет проекта в П/О (правило ИИ, gate); **F17** — решение владельца (данные ниже); **C1** — калибровка C4 в T12 до любых выводов о K-SUN/FRA; **W1** — дефект `why_not` «ближайший узел» (указывает SUN на 19 вместо 48).

## 2. Симптом 1: USA/GBR без выпуска до ~1961
**Механизм [Факт: код `PolicySystem.Products.cs` `Decide`, спека §4, A32, A41].**
1. Стартовый парк (R-FL): 100 машин G1 `superior`, стадия «в строю», `D0 = 0`. Линии нет — выпускать нечем.
2. `Requirement` (§4, A41): годовой шаг, `g*` = новейшее известное APP; выдаётся, только если у `g*` нет проекта в П/О/С/В. Стартовый парк G1 — проект в В, поэтому G1 не заказывается, пока парк не списан (когорта 1945 → мес. 178).
3. G2 USA/GBR не знают до APP 59 (USA p50 126, GBR p50 286). Отсюда первый запуск USA = min(момент 59 + ~12–30 мес. проектирования, 181 + ~30) — мес. 138–212; GBR почти всегда 212 (новый G1 после списания парка).
4. Итог: 0 машин 1945–1957 у обеих стран во всех seeds. Историческая опора [Факт, вторичный, в сессии не перепроверен]: USA/GBR/СССР выпустили тысячи G1/G2 в 1946–1955 (F-80, F-84, F-86; Meteor, Vampire; МиГ-15).

**Классификация.** По букве спеки поведение задано (A32 + §4 = «b: пробел правила ИИ» + «a: так задумано»), но оно противоречит объявленной до прогона проверке K3 («USA/GBR сохраняют выпуск G1», §6.9 п.3) — значит, R-FL/A32 записан неполно, а не «так задумано».
- **E1 [Предл.; spec erratum к A32/R-FL, Orchestrator light, т.к. восстанавливает объявленный K3].** Стартовый парк держит линию: стадия С, `built_any = true`, `gate_opened = true`, темп `r_AI` с фазы A8. Новых параметров нет; когорты 1945 остаются. Следствие: USA/GBR выпускают G1 с t0, и правило «одна линия» (A41) уже обрабатывает замену при запуске G2.
- **R1 [Предл.; AI rule change, gate].** «Заказ на замену»: в годовой шаг, если у актора нет проекта в С и нет проекта в П/О, `Requirement` выдаётся на наибольшее `g ≤ g*`, для которого пресет собирает проект (иначе — ничего). Закрывает и случай «парк в В, линии нет» (после E1 он реже), и случай «серия снята ветками A40, а повтор по `g*` уже израсходован». Альтернатива без gate — только E1; тогда после списания стартового парка дыра повторяется у GBR (п.3).

## 3. Симптом 2: SUN, узел 48 и K-SUN
**Механизм [Факт: трасса `KnowledgeNodeStep`, seed 3].** Узел 48 — детерминированный PRC G1, `c_n` = 2 `S_ref`·год → `c_money` 2,4; `c_eff` ≈ 1,14 (×0,5 `known_elsewhere`, деление на `K`). Траты НИОКР SUN 0,064 → 0,11 в месяц; вес узла во фронтире из 10–11 узлов `w` = 0,07–0,13 (`j` годовой). `Δprog` ≈ 0,005–0,012 в месяц → ~125 мес. до `prog = 1`. По профилю: P2 (PRC ×2) 97–125, P3 123–150, P1 125–153.
- Далее путь до серии: ожидание годового шага (≤ 11 мес.), стадия П ~16 мес., О ~7 мес. → серия через 24–36 мес. после 48. Даже при 48 на t0 серия ≈ мес. 24–36: K-SUN (< 36) был бы на грани.
- Оценка «48 за 12–48 мес.» [`sun-start-data.md` §1.3, помечена «формула цены не проверена»] не учитывала деления бюджета по фронтиру. Это ошибка бумажной оценки, а не реализации: формула §3.1 исполняется как написана.
- Развилка SUN на G2 (печать §6.9): `t_known(30) < 48` — 1/20 = 0,05, у нижнего края объявленной полосы 0,05–0,95.

**Классификация: (c) темп знания до калибровки.** Тот же масштаб отставания у всех акторов (п.1, C4: G2 0/20 в окне). **C1 [Предл.; calibration item T12].** Калибровка C4 по `c_n` (и при необходимости `θ_start`/`h_max`) по §8.2 на seeds 10001…10100; K-SUN читать **после** неё как диагностику. Подстраивать `c_n` узла 48, `prio` или данные SUN под K-SUN — запрещено (§6.9). Если после C4 K-SUN всё ещё провален — это вопрос владельцу/research-scientist о стартовых данных SUN (как и записано в §6.9), не о параметрах.

## 5. Симптом 4: падение выпуска USA в конце
[Факт: месяцы 288–383, seeds 1…20] Падение до < 10% пика — в 16/20 seeds. Две причины по профилю:

| Профиль USA | seeds | месяцев без линии / линия с выпуском 0 / линия с выпуском > 0 | `upkeep/B_proc` |
|---|---|---|---|
| P1 «качество» | 9 | 6–53 / 43–90 / 0 | 0,05–0,41 |
| P3 «адаптивный» | 5 | 29–41 / 55–61 / 0–6 | 0,16–0,29 |
| P2 «массовость» | 6 | 0 / 33–58 / 38–63 | 0,74–0,82 |

- **P1/P3 — F17 + ловушка культуры tier 5.** Запуск серии G3/G4 по допуску дефектов закрывает рабочую линию (A41); `prc_set` G3/G4 содержит PRC 41/42/43 с требованием `H` 5,0 при `H` USA ≈ 3,6–3,7 (первое звено `CultureH … Effort`, `eta` нет). Выпуск 0, через 60 мес. ветка С снимает линию (37 закрытий линий без выпуска на 20 seeds, из них USA G3/G4 — 23), повтор G4 снова стоит. Это ровно сценарий F17 (§12), теперь с числами: USA теряет выпуск в 14/20 seeds.
- **P2 — насыщение парка.** Пресет `producible` берёт сталь + `eng_g1` на платформах G2–G4 (поколение изделия остаётся 2); содержание ×2,5 (`upkeep_mult`) и парк 8 600–9 900 машин съедают 75–82% статьи закупок; списания по возрасту до мес. ~400 нет, команды досрочного списания в контракте нет. Это следствие правил, а не дефект реализации.
- **Классификация.** F17 — **owner decision** (уже открыт, §13; данные выше — основа). Минимальный вариант [Предл.]: правило прокси игрока A41 «закрывать прежнюю линию, только если min `yield` новой ≥ `y_prod`» перенести в ИИ (gate, новых параметров нет). Насыщение P2 — **owner decision / game-designer**: принять как свойство (равновесие `N* = B_proc/upkeep`) или ввести добровольное списание устаревшего парка (новая команда контракта — gate+research). ## 6. Побочные находки
- **W1 [Факт; спека §5.6 / контракт §6 → systems-architect].** «Ближайший недостающий узел» по слоту выбирает самый дешёвый узел фронтира из всех альтернатив. У SUN на t0…120 первое звено G1 — `AltUnavailable` узел **19** (`turbojet_g2`, ★, считается до `θ_start` 0,6), хотя он ведёт к `comp_axial`, которому ещё нужны 36 и 50; реальная преграда — 48. Подсказка игроку неверна; D1 `eta_hit` и P4 это исказит. Предл.: считать цену до доступности альтернативы (сумма по недостающему замыканию), а не по одному узлу.
- **Годовой ритм `Requirement`** добавляет 0–11 мес. к каждому переходу (знание → проект). Так задано (§4); упоминаю, т.к. входит в сроки K-SUN и C4.
- **P2 и заменитель:** `producible` спускается к стали + `eng_g1` и на платформе G4 (`gen` = 2). По правилу #70 это допустимо, но «массовая» доктрина USA никогда не выходит за поколение 2 → для game-designer (печать K4b/«ловушка заменителя», §6.9).
- GBR: окна 197/411/459/521 совпадают побитно в 7 из 20 seeds (ещё 3 — 203/396/434/535) — у GBR одна линия G1 с мес. 212, траектория почти не зависит от RNG (G2 появляется после мес. 300). Разброс GBR даёт только знание узла 20/59.
