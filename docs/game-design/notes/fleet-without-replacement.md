## 2. Спецификация для реализации (TASK-0129)
Обозначения: `age(c)` — возраст когорты, мес.; `m(c) = max(0, age(c) − service_life)`; перестарок — `age ≥ service_life`; проекты одного актора упорядочены по ключу `(gen, Perf, номер слота)` по убыванию. Все числа — `Fx6`, умножение и деление с floor слева направо (как `ProductsMath.cs:13`); `double` в состоянии запрещён (ADR-0003 п. 12).

### 2.1 «Проект e заменяет проект d» [Предл.]
`gen(e) > gen(d)`, либо `gen(e) = gen(d)` и `Perf(e) ≥ 1,05·Perf(d)` (5 % — защита от шума, [Предп.]). Ключ места и `FieldedL` не меняются.

### 2.2 Состояние
| Колонка | Тип | Владелец | Смысл |
|---|---|---|---|
| `prd.replCredit.{d}` (на слот проекта d) | `LongColumn`, Fx6 raw, ≥ 0 | `ProductsSystem` | число единиц проекта d, которым уже «подготовлена замена» |

Больше ничего не хранится. `f(m)`, `n_eff`, срок «до перестаёт считаться» — производные, пересчитываются из когорт и не пишутся в состояние (иначе второй источник правды). Колонка входит в хэш; хэш меняется **с месяца 0**; обнуляется в `TakeSlot` (`ProductsSystem.cs:1674`) и при переходе слота в `Withdrawn`. Номера строк в `FleetBook.cs`, `ProductsSystem*.cs` взяты из ред. 3 и могли сместиться: developer сверяет.

### 2.3 Учёт замены по приходу
- **Начисление** (в месяце выпуска, на месте `Produce`, `ProductsSystem.cs:1632-1634`). Выпущенные в месяце `r` единиц проекта e — только новая когорта (возраст 0). Распределение сверху вниз по проектам, которые e заменяет (п. 2.1), по ключу по убыванию, ближайшему более низкому первым; доступно `room(d) = Whole(d) − replCredit[d]`; остаток переходит к следующему; остаток после всех **пропадает** (запаса нет). `Whole(d)` — число физических единиц проекта (без весов `f`): кредит считает машины, а не вес.
- **Расход** (шаг 0 месяца t+1, на месте нынешнего `Retire`). `leave(d) = min(единицы-перестарки d, ⌊replCredit[d]⌋)`; уходят самые старые когорты (`FleetRules.Take`); `replCredit[d] −= leave(d)`. Каждый месяц `replCredit[d] = min(replCredit[d], Whole(d))`.
- Следствия: 400 новых машин дают 400 замен один раз; одни и те же новые машины не засчитываются двум проектам; перестарок промежуточного поколения не служит «новой» заменой нижнему.
- **Возрастной обнуляющий выход убирается**: `AgeOut` (`ProductsSystem.cs:1077-1087`) и его зеркало (`FleetBook.cs:100-109`) не удаляют когорту по сроку. Когорта уходит только по расходу кредита, списанию (игрок, ИИ) или потерям.

### 2.4 Порог «в строю» по эффективным единицам
`n_eff(d) = Σ_c count_c · f(m_c)` (Fx6, floor после каждого умножения). Проект `fielded`, если `n_eff(d) ≥ n_service_min = 50` (`FieldedMasteredOf`, `UnitsBuiltMasteredOf`, `ProductsSystem.Fleet.cs:148-166`; сейчас целые единицы). Остальное в ключе места `(G, T, N, P)` не меняется (#143, #435). `FV_fleet = n_eff·готовность·perf^γ` — диагностика, в ключ не входит; `FV` контракта (гипотетический парк при бюджете B) от старения не зависит.

### 2.5 Команда игрока и вердикт [Предл. имена; сверить с `CommandRejection`]
- `retire_cohort` (`FleetBook.cs:170-183`) остаётся: самые старые первыми, разрешено **без замены** (#437).
- Новое поле команды `acknowledged: bool` (по умолчанию false). Если после списания лучшее поколение в строю (по `n_eff ≥ 50`) снизится, а `acknowledged = false`, команда **не исполняется** и возвращает вердикт `NeedsConfirmation` с данными `{ bestGenBefore, bestGenAfter }`. С `acknowledged = true` исполняется. Если поколение не снижается — исполняется сразу. Вердикт — не отказ ёмкости/денег: это отдельное значение, чтобы UI показал диалог.
- Запрос `retire_forecast` (только чтение, не команда): «лучшее поколение в строю станет G2; место страны может упасть». Точное место не пишется: прогноз не знает ключей соперников. 
- Прогноз срока (для экрана и журнала «почему упало место»): для каждого проекта — первый месяц `t'`, когда `n_eff < 50` при допущении «закупок, потерь и списаний нет, кредит не растёт»; монотонное сканирование ≤ 1020 шагов **на пути запроса, не тика**. Игрок видит «через N лет ваше G3 перестанет считаться (месяц/год)» ежегодно и в журнале.

## 3. Старение: выбранная кривая (#436)
**Формула.** `m = max(0, age − service_life)` месяцев; ценность когорты `f(m) = 2^(−m/60)` (за 60 месяцев вдвое меньше; `f(0) = 1`, пола нет). Для проверки: порог `N·f ≥ 50` нарушается при `y = 5·log2(N/50)` лет; 300 → 12,92 года; 2000 → 26,61 года; 100 → 5 лет. Совпадает с числами решения #436 (12,9 и 26,6). На месячной сетке: 156, 320 и 61 мес. (см. тест 3); отличие ≤ 1 мес. — шаг сетки, а не ошибка.

**Как считать (Fx6, без float) [Предл.].** Использовать таблицу, а не `PowFracFx`, и вот почему. `PowFracFx(x, q10)` даёт `x^(q10/1024)` (ADR-0012), показатель кратен 1/1024. Нужный показатель `m/60` не кратен 1/1024; округление `q10 = round(1024·m/60)` даёт ошибку показателя до 1/2048 (≈ 0,03 % значения) и сдвигает месяц порога непредсказуемо; для `m` до 1020 нужны разные `q10`, вызов на каждую когорту каждый месяц. Таблица из 60 целых констант `T[k] = round(2^(−k/60)·10^6)` и целочисленный сдвиг: 
`f(m) = T[m mod 60] >> (m div 60)` (Fx6 raw; один сдвиг, одно округление вниз).
`f(60) = 500000`, `f(120) = 250000` точны. Таблица (k = 0…59, Fx6 raw) лежит в данных (`ProductsParams`, константа, а не расчёт во время работы); вычислена вне игры с округлением к ближайшему и входит в `DataHash`:
```
1000000, 988514, 977160, 965936, 954842, 943874, 933033, 922316, 911722, 901250,
890899, 880666, 870551, 860551, 850667, 840896, 831238, 821690, 812252, 802923,
793701, 784584, 775572, 766664, 757858, 749154, 740549, 732043, 723635, 715323,
707107, 698985, 690956, 683020, 675175, 667420, 659754, 652176, 644685, 637280,
629961, 622725, 615572, 608502, 601513, 594604, 587774, 581023, 574349, 567752,
561231, 554785, 548412, 542113, 535887, 529732, 523647, 517632, 511687, 505810
```
Альтернатива `PowFracFx(2, −q10)` не рекомендуется по причине выше. Если архитектор всё же предпочтёт её, критерии теста 3 (месяцы 156/320/61) надо пересчитать и объяснить. Стоимость: целочисленный доступ к таблице и сдвиг, без аллокаций.

**Что меняется в месте (#435, #143).** Ключ `(G, T, N, P)` не меняется. `G` — поколение лучшего изделия на вооружении (#44); условие «на вооружении» теперь зависит от возраста через `n_eff`. Ценность парка в ключ не входит, возраст только участвует в тесте «в строю». Владелец это подтвердил: #435 уточняет #143.

Требования: (а) парк не исчезает на 15-м году; (б) не остаётся вечно значимым: 50 машин без закупок нарушают порог в первый месяц сверх срока; крупный парк держится дольше (300 — 13 лет, 2000 — 26,7 года сверх срока; общий возраст 28 и 41,6 года).

Фраза для экрана: «Каждые 5 лет сверх срока службы ценность парка вдвое меньше». Прогноз для игрока — §2.5. 

[Предп., важное следствие] После G4 нового содержания нет. Страна без работающей линии лучшего поколения потеряет G по сроку (в среднем 2010–2020 для когорт 1970-х): провалы «G = 0» вернутся, но **постепенно, с видимым сроком**. Закроют G5/G6 и модернизация.

## 4. Цель «догнать» и ранг
- Раньше страна проваливалась в G = 0 мгновенно. Теперь ценность падает, поколение перестаёт считаться по сроку, место падает на ступеньку; лучшее поколение уходит вниз на одно, а не сразу в 0, если есть парк предыдущего.
- Место 4–5 по-прежнему возможно. Причин три: (1) кончился срок (старение); (2) соперник вывел поколение выше (`G`); (3) соперник обогнал по `T` и `N`. [Предп.] `T` и `N` считаются по освоенным процессам, их вклад в смены места до 2030 не сверен. Третья причина не лечится парком: игрок должен видеть её отдельно.
- «Почему упало место»: (1) «ваше G3 перестало считаться 2011-03: парк 300 машин состарился на 13 лет сверх срока»; (2) «впереди FRA, SUN: G3 с 2011»; (3) «по T и N вас обошла FRA» (ответ — наука и освоение, не закупки); (4) что делать: серия нового поколения, закупка того же поколения лучшим проектом (2.1), модернизация (раздел 5, когда появится).
- [Предп.] Для GBR и SWE цель недостижима из-за бюджета (8–15 раз меньше); это вопрос бюджетов (#430, потолок отложен #433), не парка.
