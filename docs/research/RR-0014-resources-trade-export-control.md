## Вопрос исследования
Как смоделировать природные ресурсы, торговлю и экспортный контроль так, чтобы каждая механика давала игроку **осмысленное решение** и **читаемое «почему нельзя»** (`why_not`), не ломая детерминизм L2 (ADR-0002), бюджет тика и уже принятые решения: #165 (экспортный контроль на E1.5 на существующих предметах), #168 (деньги в постоянных ценах 1945 года, без валют и инфляции), #193/#198 (сеть предприятий), #203 (три слоя видимости).

## Краткий вывод
- [Предл., граница принята из RR10 §5в] **RR10 владеет физикой** (баланс, потоки, запасы, мощность, делёж внутреннего дефицита, `why_not` по цепочке). **RR-0014 владеет рынком и политикой**: цены, сделки, пошлины, эмбарго, санкции, лицензии, оснастка, канал догоняющего, платёжный баланс. Интерфейс — **шлюз страны по CMP** (`import/export[country,cmp]`) и ворота `allowed(from,to,item)`. Рёбер «предприятие ↔ предприятие» через границу нет.
- [Предл.] `allowed(from,to,item) = ¬export_control ∧ ¬embargo ∧ licence_ok` — **только булева политика** из данных и решений. Деньги импортёра (`NO_MONEY`, определение — §3) — **ограничение клиринга**, не ворота; мощность перевозки (`NO_CAPACITY`) — **FUTURE** (волна 3, RR-0019; в E3 транспорт — только коэффициент издержки, ревизия 2026-11-14); цена берётся из снимка t−1, поэтому цикла внутри тика нет. [Факт: #165, ENM §2.7] На E1.5 живёт только первый член — `export_control(from,to,item)` над существующими предметами среза (лицензия, компонент, сплав); это **вырожденная форма** ворот.
- [Предл.] Предмет торговли в E3: CMP и **ресурсы `RES`** (одни и те же ворота и шлюз, учёт как CMP), **компоненты** (изделие без проекта игрока), лицензии, оснастка. Знание и готовые системы — вне E3 (ENM §2.5; владелец — RR-0008/разведка).
- [Предл.] Рынок — **цена как функция мирового баланса CMP** без ордербука, деньги — постоянные цены 1945 года (#168): «цена» есть относительный множитель к базовой `p0`, валют нет.
- [Предл.] Три категории доступности из CE §6.6 отображаются на режимы данных: `OPEN`, `LICENSE_REQUIRED` (≈ RESTRICTED), `DENIED` (≈ CLOSED); по блоку, эре и классу предмета. Товар, передача технологии и производственная лицензия — **разные ворота** (CE T6).
- [Предл.] Канал догоняющего `catch` (RR6 разногласие 1) получает множитель `access(owner,p) ∈ [0,1]`: без него скидка действует под полным эмбарго и контроль неэффективен. **Это критерий gate E1.5** (формула — §4).
- [Предл.] Эмбарго не считается дважды: потеря выручки идёт **только** через доход и `B_a` (E3); `g_shock` — лишь для событийных шоков без денежного канала (граница `ε_cap` — #165/ENM §2.5, не #172); на E1.5 они не складываются (§4).
- [Предп.] Стоимость: E1.5 — несколько обращений к таблице за месяц; E3 — двухуровневый клиринг через пулы блоков, O(число стран) на CMP ⇒ ~10⁴–3·10⁴ операций `Fx6` (≈ 3·10⁴ при 200 × 150), **< 1 мс на месячный тик с накладными** (единая оценка; согласована с RR10 §5б и RR-0011 §6; замер — Lab-микротест, §7). Главный риск — данные 1945 (двусторонние потоки под ADR-0009 недоступны), а не CPU.
- [Предл.] Ключевой тест на каждую механику: решение игрока + читаемая причина отказа (таблица §«Ключевой тест»). Механики без обоих — не берём.

### 2. Ресурсы
- [Предл., RR6 §4.9, CE §6.5] 10 природных категорий: уголь, нефть, газ, железная руда, медь, бокситы, уран, редкоземельные, лес, легирующие металлы (Ni, Cr, Mn, W). Мощность добычи — данные региона; **истощения нет в v1** (ENM §2.4).
- [Предл.] Единица ресурса — стоимостная (как у CMP, RR10 §5г): 1 ед. = 1 тыс. $1945 по базовой цене; тонны — только показ.
- Правило: ценность месторождения нулевая, пока процесс-потребитель не в `known_processes` (RR6). Новая технология создаёт спрос на ранее неважный ресурс **данными процессов** (входы `PRC`), а не отдельным механизмом (CE §6.5: «пластик, высокочистые вещества, полупроводники»).
- Нефть ≠ пластик: природный ресурс никогда не подменяет материал; суррогат — только явный флаг данных (прецедент `alloy_free`, #131), общий механизм E14 — OPTIONAL.
- Энергоресурсы в E1 — три вида (уголь, нефть-газ, гидро) по регионам с `loss` 3–10% и надбавкой за расстояние (E1-model §14.2, #171). [Предл., правило] **До E2 носители энергии в `RES` не входят**: энергия E1 — собственный баланс E1 и не торгуется. В E2 уголь и нефть-газ становятся `RES`, а энергия E1 потребляет их **как входы `PRC`** (через тот же мост RR10 §5г); торговля ими идёт через шлюз. Двойного учёта (E1-энергия и `RES`-спрос) нет: на E2 `G_rt` для угля и нефти-газа заменяется на выпуск `RES`.

### 3. Рынок (E3)
- [Предл., ENM §2.5; правка 2026-11-14 по gate] **Цена по компоненте связности.** Рынок CMP строится отдельно на каждой компоненте связности графа `allowed` по этому CMP (ожидается 2–4 блочных рынка); порядок поиска компонент — по id (подтвердить systems-architect). `price_m,K = p0_m·(1 + k_m·dev_m,K)`, `dev = clamp((D − S)/S, −c_lo, c_hi)`; **защита деления:** `S = 0 ⇒ dev = c_hi`; в `Fx6` сначала умножение, потом деление. Цена берётся из **снимка t−1** (прошлого месяца) — цикла «цена ↔ клиринг» внутри тика нет. Без `exp` и степеней.
- **Реальный выпуск и деньги.** Реальный выпуск и баланс (RR10) считаются в единицах `p0` (постоянные цены 1945, #168). `price_m` влияет **только на `B_a`**. `B_a` — месячный поток, **не накапливается** (долга нет, #168).
- **Спрос неэластичен** (v1): цена не бывает причиной отказа в сделке, поэтому причина `PRICE` из `why_not` **убрана** (решение автора из двух вариантов; альтернатива — явная кусочно-линейная скидка спроса — отклонена как лишний параметр). Нехватка денег — `NO_MONEY`.
- **Клиринг двухуровневый** (§7): внутри блоковой компоненты — пулы блоков, затем раздача странам; деньги импортёра делятся между CMP **до прохода** пропорционально спросу; делёж — floor-долями по весу предпочтения, остаток по id; RNG нет (#28).
- Платёжный баланс — **один агрегат на страну**: `B_a = Σ экспорт·price − Σ импорт·price` (месячный поток, по **нетто**-цене без пошлины); валют, курсов, долга нет (#168). Инвариант: `Σ_a B_a = 0` на компоненту (с учётом `grant`, §4).
- **[Предл., ревизия 2026-11-14 по gate DeepSeek] Откуда деньги импортёра и что значит `B_a < 0`.** Резервов и кредита нет, поэтому покупка в месяце t оплачивается только из потоков **этого же** бюджета:
  - `M_imp,a(t) = X_a(t−1) + grant_a(t−1) + m_base_a·Y_a`, где `X_a(t−1)` — экспортная выручка прошлого месяца (снимок t−1), `grant` — полученная помощь, `m_base_a` — доля ВВП, которую страна может направить на импорт из **государственного бюджета** `budget_a = τ·s_prog·Y` (данные + решение игрока/ИИ; по умолчанию малая, `s_imp`). `M_imp,a` делится между CMP до прохода клиринга.
  - `B_a(t) < 0` означает: импорт превысил экспортную выручку, разницу покрыла строка `m_base_a·Y_a`, то есть **часть бюджета, потраченная на импорт**. Это не долг: ничего не переносится на следующий месяц, а `Σ_a B_a = 0` — не кредит (платёж идёт в том же месяце из бюджета покупателя; экспортёр получает выручку, а не «обязательство»).
  - Эффект на ECO: `s_prog_eff = clamp(s_prog − max(0, −B_a)/(τ·Y), s_lo, s_hi)` — расходы на импортный дефицит вычитаются из бюджета прогресса того же месяца (без лага, пол `s_lo`). Формула — предложение для E1-model §3 и RR-0011 A38 (контракт — systems-architect). Когда `M_imp` исчерпан, срабатывает `NO_MONEY`.
  - **Рычаг «сократить импорт» (T7):** импортная квота `import_cap[country,cmp]` (команда игрока/ИИ; снимает `NO_MONEY`-перерасход ценой выпуска, который эта поставка питала) и/или `m_base_a` (`s_imp`). Без квоты импорт определяется производственным планом и `M_imp`.
- Контракты (CE §6.6): долгосрочная поставка «объём × цена × срок» между двумя странами. Решение: надёжность поставки против гибкости цены; рвётся эмбарго или событием. EXPERIMENTAL (после ворот E3).
- Торговые блоки: блок задаёт **режим по умолчанию** `allowed` и вес предпочтения. **Членство — данные на t0 + состояние** `bloc_of[country]` (**владелец определения `Bloc` — RR-0014**; RR-0013 `T[bloc_i,bloc_j]` и RR-0012 ссылаются сюда; блок = `{id, режим по умолчанию по эре и классу, список}`; страна в одном блоке или нейтральна). Рычаги (#211/#213) [Предл.]: `join_bloc`, `leave_bloc` — команды игрока/ИИ; `w_pref[country,bloc]` — состояние: у не члена убывает на `k_w·доля_DENIED_со_стороны_блока` в месяц (пол `w_min`); при `w_pref < w_exit` ИИ нейтрала получает вариант `leave/не вступать` (автоматического выхода нет, решение — через очередь решений). Выход/вступление: блокировка `lock_bloc` месяцев и потеря предпочтения блока (цена по данным); так «`DENIED` всем вне блока» получает **моделируемую цену** (потеря объёма и `B_a` блока), а не декларативную. Матрица «блок × блок × класс предмета» (~10×10×**16**: 12 классов + `fissile`, `reactor`, `launcher_missile`, `satellite` из RR-0013 §2.7 — **владелец классов предметов RR-0014**, RR-0013 даёт только данные режимов) + список исключений, а **не** «страна × страна × предмет» (4·10⁴ × 16 ≈ 6·10⁵ ячеек).
- Транспорт: один коэффициент издержки (RR10 §5в); **мощности перевозки в E3 нет**; перерезанные пути, блокада и `NO_CAPACITY` — волна 3 (RR-0019, FUTURE).

### 4. Экспортный контроль, лицензии, оснастка, догоняющий
- [Факт: #165] **E1.5.** `export_control(from, to, item)` над существующими предметами среза; режимы `OPEN`, `LICENSE_REQUIRED`, `DENIED` по блоку и эре. Эффект на срез: отказ лицензии/компонента — корень `why_not` «контроль экспорта», а не «нет денег». Цена экспортёру: потеря `LicenceFlow`/`sale_income` или малый `g_shock` (≤ `ε_cap`; граница — #165/ENM §2.5; один канал на событие). Gate E1.5: контрфактуры «блок с контролем / без» в Lab; серебряной пули нет (замещение через собственную культуру C-B остаётся).
- Предметы и каналы (разные ворота) [Предл.]:
| Предмет | Что передаётся | Куда влияет | Ворота |
|---|---|---|---|
| CMP, ресурс | материал | баланс RR10, `f_M` | `allowed` (товар) |
| компонент | изделие без проекта | `component_stock`, #62: силу даёт, `tech_lead` нет | `allowed` + допуск |
| производственная лицензия | право вести PRC | `ṽ` в культуре, `X½·(1 − l_lic)` (RR6); деньги — `LicenceFlow` | `allowed` (лицензия) + цена |
| оснастка | станки | `M` растёт, `H` нет (правило RR6 §4.5/§4.14: импорт `H` не повышает) | `allowed` (оснастка); **только E3** — контракт §3 и RR6 §4.5 держат «импорт оснастки — FUTURE», поэтому перенос в E3 — **предложение поправки** для systems-architect; в E1.5 оснастка не торгуется |
| знание, готовые системы | — | — | вне E3 |
- **Канал `catch`; формула `access` на E1.5 (правка 2026-11-14 по gate).** `k_catch·catch·access(owner,p)`. **Отображение процесс → предметы [Предл., ревизия 2026-11-14 по gate DeepSeek]:** `allowed` определён на предметах, поэтому `items(p) = {tooling_class(p), component_classes(p), critical_CMP(p)}` из данных `ProcessDef` (станки процесса, ключевые компоненты, критичный входной CMP/ресурс). **Лицензионный предмет в `items(p)` не входит.** Уровень пары: `level(h→owner,p) = min_{i ∈ items(p)} lv(allowed(h,owner,i))`, где `lv`: `OPEN` = 1, `LICENSE_REQUIRED` = `s_lic` (ступень данных, по умолчанию 0,5), `DENIED` = 0. Итог: `access(owner,p) = max_{h ∈ holders(p)} level(h→owner,p)·min(1, share_h(p)/s_ref)`, где `holders(p)` — акторы с `Mastered(p)` (знание без производства держателем не делает: передать нечего), `share_h` — доля `h` в мировой освоенной мощности `p`, `s_ref` ≈ 0,2 [Предп., Lab]. Поэтому один малый нейтральный держатель **не обнуляет эмбарго** (его вклад ограничен долей), а при реальном крупном нейтральном держателе утечка — это уже `leak` (T13), а не `access`. Остальные члены (специалисты, торговый объём) — **FUTURE**. **Лицензия в `access` НЕ входит:** она действует через `ṽ` и `X½` (RR6, контракт §3, правило 5; двойной учёт и риск #158); пара **«лицензия × catch»** (владелец — RR6): выданная лицензия не меняет `access` (ворота лицензии отдельны, не в `items(p)`), `X½·(1 − l_lic)` действует отдельно — тест: при `access = 0` и выданной лицензии скидка `catch` равна 0, а `X½·(1 − l_lic)` применяется; формулировки RR10 §5в приведены в соответствие (эррата, ревизия 2026-11-14). **Тест монотонности:** добавление держателя или смягчение режима не уменьшает `access`; `access ∈ [0,1]`. Режим — ступени (основной), булев `s_lic ∈ {0,1}` — частный случай. **Критерий gate E1.5:** без `access` контрфактура «блок с контролем» не покажет эффекта выше шума (абляция `k_catch = 0` — RR6 §8.3).
- [Предл.] Санкции = набор эмбарго; **механизм** здесь, **политика** (кто кого, когда) — RR-0012/RR-0016.
- **Эмбарго не считается дважды.** В E3 потеря выручки экспортёра идёт **только** через доход и `B_a` (экспорт падает ⇒ `B_a` падает). `g_shock` — только для событийных шоков без денежного канала (например, блокада порта, авария). На E1.5 (до `B_a`): потеря `LicenceFlow`/`sale_income` и малый `g_shock` (≤ `ε_cap`) **не складываются** сверх границы `ε_cap` (#165, ENM §2.5; #172 — про производительность, не про шоки) — выбирается один канал на событие; Lab-проверка: суммарное снижение роста от одного эмбарго ≤ `ε_cap`. **Эррата ENM §2.5 (предложение):** «санкции = набор эмбарго через `allowed`/`B_a`; `g_shock` — только событийные шоки без денежного канала» (сейчас ENM включает `g_shock` в санкции — это двойной счёт; согласовать с RR-0011 D19).
- **Замещение у жертвы — FUTURE** (ревизия 2026-11-14 по gate DeepSeek). Историческое наблюдение (Япония 2010, §5) — **не** механика v1: рециклинг/снижение удельного расхода (RR6 E14) — OPTIONAL, `ProcessDef.inputs` фиксированы, а C-B растит культуру от денег наладки, которых у жертвы при потере выручки меньше. **v1 показывает только ценовые, доходные и выпускные эффекты эмбарго**; замещение не входит в критерии Lab (§Lab, п. 3). Единственный действующий канал — собственная культура `H` по C-B и `build(region,cluster,ΔK)` внутренних производителей CMP при росте цены (RR10), без отдельной механики «замещения».
- **Пошлина (T17, E3).** Коэффициент `tariff_{to,item} ≥ 0` на цену импорта; `B_a` считается по нетто-цене (без пошлины), доход пошлины — **отдельная строка `tariff_income_a`**, возвращается в `budget_a` государства-импортёра, `Σ B_a = 0` не нарушается. Эффект — через ограничение `M_imp`: при связывающих деньгах на единицу денег закупается меньше (объём падает), а не «перераспределение `B_a`». `TARIFF` — **уточнение к `NO_MONEY`** (модификатор, а не самостоятельный корень): при неэластичном спросе и несвязывающем бюджете пошлина объём не меняет. Рычаг количества — импортная квота `import_cap` (§3).
- **Отзыв лицензии `revoke_licence(owner_of_licence, recipient, p)` (#210) [Предл.].** Команда держателя: прекращает **будущие** `LicenceFlow` и поставки по этой лицензии; освоенные `H` и `M` получателя остаются; отзывающий теряет доход `LicenceFlow`; `X½·(1 − l_lic)` перестаёт расти с даты отзыва, накопленное остаётся. Повторная выдача — по общей цене.
- **Асимметрия режима (#211) [Предл.].** Умолчание блока (эра × класс) — данные. Ужесточить относительно нормы блока можно свободно (цена — потеря выручки, §«эмбарго не считается дважды»). Ослабить **ниже нормы блока** — с трением: `lock_loosen` месяцев блокировки обратного хода и снижение `w_pref` у союзников блока на `k_fr·(норма − новый уровень)`.
- **Утечка `leak` (T13, #209) [Предл., ревизия 2026-11-14 по gate DeepSeek].** Только E3. Механика в балансе: доля `ℓ ≤ ~0,1` экспорта эмбаргированного CMP идёт **как две записи** «экспортёр → нейтрал» и «нейтрал → жертва» с наценкой `μ`; нейтрал получает наценку как доход (`B_a` жертвы падает на `μ`, у нейтрала растёт), так что `Σ экспорт = Σ импорт` по `(cmp, компонента, месяц)` и `Σ B_a = 0` **сохраняются** (в инварианте утечка — явный сквозной поток нейтрала, а не потеря). Видимость: точное значение — слой 3 (RR-0017); **но слой 1 даёт сигнал** «аномалия торговой статистики нейтрала» (его импорт CMP из эмбаргирующего и экспорт жертве растут, публичная статистика с задержкой). Решение игрока: ужесточить (внести нейтрала в эмбарго — вторичная санкция, цена — потеря рынка и `w_pref`) или принять утечку. Корень `why_not`: `EMBARGO_LEAK(нейтрал)` («эффект эмбарго ослаблен»), у жертвы — подробнее, у остальных — по слою. Строка в «Ключевом тесте» добавлена; T13 **входит в E3 MVP** как малый скаляр (а не в E1.5).
- **Помощь (grant).** `grant(donor, recipient, amount)` без долга (E3, идея плана Маршалла): перевод в `B_a` и закупочную способность получателя, учитывается отдельной строкой баланса (`Σ B_a = 0` с учётом grant). Решение владельца (вопрос 5).

### 6. Видимость (#203) [Предл.]
Три слоя для торговли и контроля: (1) **показанное миру** — публичные эмбарго и режимы, торговая статистика с задержкой, видят все; (2) **публикуемое** — таблицы блоков и списки контроля (открытый слой, как FND/PRN), с задержкой; (3) **закрытое** — тайные поставки и обход через третьи страны, видит только разведка (RR-0017, волна 3), до неё скрыто. `why_not` игрока показывает причину **собственного** отказа полностью и причину чужого — на уровне видимого слоя. [Предл.] **Слой 3 в v1 пуст**, если обхода через третьих стран нет (вопрос 1, вариант «нет»): скрытых потоков не существует, поэтому пустота слоя — не ошибка; наполнение — только при утечке (`leak`) и разведке RR-0017.

## Разногласия
Gate 2026-11-14 (critic + advocate); итог — Orchestrator, вопросы — владельцу.
1. **`allowed` и деньги/транспорт.** Первая редакция включала `мощность ∧ деньги` в ворота — критик: цикл с ценой и смесь политики с клирингом. Принято: ворота только булевы, деньги и мощность — ограничения клиринга, цена из снимка t−1.
2. **`access` и лицензия.** Критик: лицензия в `access` — двойной учёт с `ṽ`/`X½` (#158). Принято: только `max` по держателям от `allowed`; лицензия не входит; добавлена пара «лицензия × catch» в инварианты. Нерешённое: форма ступеней по режиму — данные, калибровка Lab.
3. **Двойной счёт эмбарго.** Выручка идёт только через `B_a`, `g_shock` — только событийные шоки без денежного канала. На E1.5 один канал на событие (#172).
4. **Причина `PRICE`.** Спрос неэластичен ⇒ причина убрана; альтернатива (кусочно-линейная скидка спроса) отклонена автором как лишний параметр. Остаточное: возражение, что игрок хочет отказаться от дорогой сделки — решается пошлиной/квотой (T17), не ценой.
5. **Тик.** Первая оценка ~3·10⁵ операций пересчитана на 3·10⁴ через блоковые пулы; число проверить Lab-микротестом.
6. **Доминанта «DENIED всем вне блока».** Критерий добавлен в Lab; цена — потеря предпочтения нейтралов и выход из блока.
7. **Итог (решения владельца, 2026-11-14):** #209 — малая утечка только в E3, видна только в слое 3; #210 — отзыв лицензии прекращает будущие потоки, `H` и `M` остаются, отозвавший теряет доход; #211 — умолчания блока + асимметрия; #212 — `grant` без долга в E3; #217 — двусторонние потоки 1945 **вручную** для ~10 ключевых стран с источником на пару, против рекомендации автора («веса модели»; риск фальшивой точности остаётся — оценки помечаются `estimated: true`, Lab проверяет чувствительность), остальные страны — общий рынок.
