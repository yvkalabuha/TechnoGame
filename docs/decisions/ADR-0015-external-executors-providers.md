# ADR-0015 — Внешние исполнители и ревьюеры (DeepSeek, Codex)

> После ACCEPTED текст не меняется. Изменение решения — новый ADR с `supersedes`.

## Краткий вывод
- **Классы риска R0–R3.** Классы считаются по путям из одного файла `risk_paths.json`. Из этого же файла собирается `WRITE_FORBIDDEN`, и он содержит R2 и R3 целиком. Класс может только подниматься; неизвестный путь получает R2.
- **Роли.** Claude координирует, проектирует и делает первое ревью.
  - Codex — основной второй ревьюер (#175 b). Работает под bwrap и не читает ничего за пределами worktree.
  - DeepSeek — запасной второй ревьюер и третий участник ворот (#175 c). Он же исполняет шаги R0–R1 с обязательным ревью Claude.
  - Qwen выведен из работы (#174 e). `tools/llm_worker` остаётся инфраструктурой.
- **Режим исполнения.** Сейчас только узкий контракт `llm_worker`: модель отвечает JSON без инструментов, файлы пишет инструмент. Агентный режим откладывается.
- **Деньги.** Отдельного аккаунта DeepSeek нет, лимит $5 держит только наш ledger (#175 a). Ledger работает с резервом и `flock` и отказывает при любом сомнении. Перерасход над лимитом ограничен ошибкой оценки одного вызова.
- **Готовность.** Первый платный вызов возможен только после задач 1a–1c (§9). До этого `llm_worker` отказывает платному провайдеру.
- [Предл.] Ступеней доверия нет. Метрики выводятся разделом отчёта ledger, плюс одно правило отката (§7).

## Решение

### 1. Классы риска
Класс итогового диффа — максимум из двух значений: класса из контракта (поле `risk`, контракт v2) и класса, который `tools/llm_worker/risk.py classify` вычисляет по путям. Класс никогда не понижается.

| Класс | Глобы [Предл.] | Исполнитель |
|---|---|---|
| R0 | `docs/**`, кроме R2/R3; `tests/**`, кроме R2 | DeepSeek или Claude |
| R1 | `tools/**`, кроме R2/R3; `src/Singularity.Lab/**`; `mods/**`; `lab/**`, кроме `lab/results/**` | DeepSeek или Claude |
| R2 | `src/Singularity.{Kernel,Core,Session}/**`; `tests/Singularity.{Kernel,Core,Session,Architecture}.Tests/**` (там golden-хеши L1/L2); `**/*golden*`; `**/*.csproj`, `**/*.props`, `**/*.targets`, `**/Directory.Packages.props`, `**/nuget.config`, `**/global.json`, `**/*.runsettings`, `*.sln`; `tools/llm_worker/**`; `docs/architecture/**` | только Claude |
| R3 | `docs/decisions/**`, `docs/vision/**`, `development/**`, `CURRENT_STATE.md`, `tools/development/**`, `.claude/**`, `CLAUDE.md`, `AGENTS.md`, `.githooks/**`, `.github/**`, `.mcp.json`, `.gitignore`, `.git/**`, `lab/results/**`, `tools/llm_worker/risk_paths.json`, `tools/llm_worker/prices.json` | никогда внешний исполнитель |

- **Источник списка.** Глобы R2/R3 хранятся в `risk_paths.json`. `WRITE_FORBIDDEN` в `config.py` собирается из него и содержит R2 ∪ R3, поэтому два списка не могут разойтись. Файл `risk_paths.json` — R3: исполнитель не может ослабить свою же проверку.
- **Дифф** берётся командой `git diff --name-status --no-renames main...llm/<id>` (три точки). При переименовании в расчёт идут обе стороны.
- **Пути нормализуются:** убираются `..` и `./`, регистр сравнивается без учёта (Windows и macOS в CI). Путь вне репозитория — R3.
- **Содержимое.** Если дифф меняет во frontmatter поле `status`, `approved_by`, `approved_at` или `approval_ref`, шаг получает R3.
- **Неизвестный путь** получает R2.

### 2. Роли
| Работа | Claude | DeepSeek | Codex |
|---|---|---|---|
| Координация, дизайн, ADR, решения | да | нет | нет |
| Ворота: critic, advocate | да | третий участник (#175 c) | нет |
| Исполнение R0–R1 | запасной | основной: S → flash, M → pro; L сначала разбивается | нет (позже, агентный режим) |
| Исполнение R2/R3 | да | нет | нет |
| Первое ревью любого диффа (`reviewer`) | всегда | нет | нет |
| Второе ревью диффа Claude: R2 и `tools/**` | — | запасной (при `codex_limit`, сбое) | основной (#175 b) |
| Второе ревью кода DeepSeek | — | — | не требуется: первое ревью Claude уже от другого провайдера |

- Для `tools/**` второе ревью стало обязательным по advocate 7: Codex не тратит лимит $5.
- Для остальных R0–R1 второе ревью делается по выбору Orchestrator.

### 3. Режимы исполнения
- **(a) Узкий контракт `llm_worker` — принят.**
  - Пакет контекста собирается из объектов git (`git show <head>:<path>`), а не из рабочего дерева. Так неотслеживаемые файлы и `lab/results/` не могут в него попасть.
  - Модель отвечает одним JSON без инструментов и сети.
  - Файлы пишет инструмент, только в `allowed_paths`, в worktree `llm/<id>`.
  - Проверки идут в bwrap (§8).
  - Цикл «объясни → исправь» сохраняется.
- **(b) Агентный режим** (`claude -p` с endpoint DeepSeek, как `deepseek_ask` в devLLMex; Codex-исполнитель) — **отложен.**
  - Условия включения: фильтр исходящего трафика только на `api.deepseek.com:443` с тестом самопроверки, и не меньше 3 шагов R0–R1, которые не удалось выразить узким контрактом.
  - Включается отдельной задачей уровня gate.

### 4. Второе ревью
- **Вызов:** `python3 -m tools.llm_worker review --task TASK-NNNN --base <sha> --head <sha> [--provider codex|deepseek]`.
- **Вход:**
  - цель и критерии приёмки из задачи;
  - `git diff base...head`;
  - изменённые файлы из объектов git;
  - для R2 — `.claude/rules/csharp-core.md` и ADR-0002.

  Больше 1 MB — отказ `input_too_large`. gitleaks проверяет весь вход (§8).
- **Codex** запускается как `codex exec --sandbox read-only` внутри bwrap:
  - `$HOME` закрыт пустым tmpfs;
  - видны только чистый detached worktree на `head` и `~/.codex`;
  - системные каталоги — только на чтение;
  - `/var/www` и основной checkout не смонтированы.

  Сеть общая: она нужна для OpenAI API. Codex ничего не пишет; изменение worktree даёт `guard_violation`. Работает ли внутренняя песочница Codex внутри bwrap — проверить; если нет, границей остаётся bwrap.
- **DeepSeek** (запасной) — один API-запрос без инструментов.
- **Выход** — JSON по `tools/llm_worker/schemas/review.schema.json`:
  `{verdict: accept|changes_requested, summary, findings[{severity: high|medium|low, path, line, claim, evidence}]}`.
  - Правило «`accept` с `high` недопустим» проверяется кодом после схемы: `jsonschema_lite` его не выражает.
  - Нарушение даёт `schema_invalid`, ревью не засчитывается, но расход идёт в ledger.
- **Хранение.** JSON остаётся в `tools/llm_worker/runs/` (git-ignored) и в репозиторий не коммитится. Orchestrator вставляет в раздел REVIEW одну строку, которую печатает инструмент:
  `- [x] Второе ревью (codex, head a1b2c3d4) — changes_requested: 1 high; report sha256 <64 hex>`.
- **Устаревание.** Ревью действует только для своего `head`.
- **Находки.** Каждую `high` Claude либо исправляет, либо опровергает с доводом в REVIEW. Несогласие идёт в «Разногласия» задачи.

### 5. DeepSeek в воротах (#175 c)
- `python3 -m tools.llm_worker gate --item <path> --stance third` отправляет документ и связанные файлы из объектов git. Это один запрос без инструментов, ответ по схеме `gate.schema.json` (STATUS, SUMMARY, FINDINGS, OPEN).
- Находки `high` разбираются наравне с находками critic и advocate.
- Расход идёт в общий лимит $5.

### 6. Учёт и лимиты
- **Ledger** — `~/.local/share/singularity-llm/ledger.jsonl`, вне репозитория и вне `runs/`, только дописывается. Каждая запись и проверка идёт под `flock`.
- **Маркер инициализации.** `ledger init` создаёт файл-маркер. Если ledger или маркер отсутствует, вызов отклоняется: это не означает «потрачено 0».
- **Лимит $5** общий: исполнение, ревью, ворота (#174 b, #175 a). Поднять его может только владелец.
- **Резерв.** Перед каждым HTTP-запросом пишется резерв `worst_case`. Это относится и к повторам внутри `provider.complete`: их резервирует callback перед каждой попыткой.
  - `worst_case` = вход по оценке 1 токен на 2 байта (строже, чем `CHARS_PER_TOKEN = 3.5`) × пиковая цена входа без кэша + `max_tokens` × цена выхода.
  - Если `spent + worst_case > cap` — `cap_exceeded`, вызова нет.
  - После ответа резерв сверяется с фактическим `usage`. Если `usage` нет, остаётся списанным `worst_case`.
- **Граница перерасхода** — ошибка оценки одного вызова, а не ноль. Свести её к нулю нельзя: цену назначает провайдер.
- **Без двойной оплаты.** Сырые байты ответа сохраняются до `json.loads`. При возобновлении используется сохранённый `*_response.json`, нового запроса нет.
- **HTTP 402** (нет средств) и 401/403 останавливают весь прогон без повтора.
- **Пары попыток (#175 d).** Предел — 2 неудачи модели на пару (шаг, модель). Цепочка: `deepseek-flash → deepseek-v4-pro → Claude`. Для платного провайдера `max_candidates = 1`.
- **Сбои инфраструктуры** (`fault: infra`: сеть, 5xx, `sandbox_unavailable`) в неудачи модели не входят. Предел — 3 на задачу.
- **Лимит на задачу** `max_usd_task = 0.50` [Предп.] считается по ledger с ключом `task`.
- **Codex.** В USD не считается (подписка). Пишутся попытки и токены; `codex_limit` — переход к DeepSeek.

### 7. Метрики и откат
Ступеней доверия и `report --executors` нет. В отчёте ledger (`python3 -m tools.llm_worker report`) есть раздел метрик. Он вычисляется из ledger, прогонов и строк REVIEW:
- раунды до accept Claude;
- вердикт первого раунда;
- высшая тяжесть находок в принятом раунде;
- $ на задачу;
- подтверждённые находки второго ревьюера.

**Сбежавший high** — high, найденный позже в принятом коде DeepSeek. Его вручную отмечает Orchestrator ссылкой `fixes: TASK-…` в новой задаче; отчёт учитывает только эти ссылки.

**Правило отката.** После любого сбежавшего high DeepSeek получает только шаги, которые Orchestrator выбрал вручную, с записью причины. Вернуть прежний режим может владелец.

### 8. Безопасность данных
- **Что уходит наружу:**
  - только объекты git из `head`, файл задачи и дифф;
  - `CONTEXT_EXCLUDE` дополнен `.mcp.json`, `**/.mcp.json*`, `**/.git/**` и включает R3-путь `lab/results/**`.
- **gitleaks:**
  - проверяет весь вход каждого внешнего вызова, включая `error_lines` проверок в prompt повтора, а для Codex — ещё и его worktree;
  - находка → `secret_detected`, без вызова;
  - нет бинаря → `sandbox_unavailable`.
- **Ключ DeepSeek:**
  - файл `~/.config/singularity/deepseek-api-key`, права 0600, владелец — текущий пользователь;
  - читается только из файла, переменная окружения для DeepSeek отключена;
  - иной режим или пустой файл → `key_error`;
  - не попадает в argv, логи и прогоны; агенты его не читают.
  - Аккаунт общий (#175 a), поэтому защита от трат на стороне провайдера отсутствует, и ledger — единственная граница.
- **Песочница проверок** (`sandbox.py`). Монтирование в таком порядке:
  1. системные `/usr`, `/etc/ssl`, `/lib*` — только чтение;
  2. на `$HOME` — пустой tmpfs;
  3. `~/.dotnet` — только чтение;
  4. `~/.nuget/packages` — только чтение (на запись — только на шаге `restore`);
  5. worktree — на запись;
  6. `/var/www` не монтируется.

  `.mcp.json` лежит в корне репозитория, а не в `$HOME`, поэтому его закрывает именно отсутствие `/var/www`. Сеть отключена (`--unshare-net`), кроме шага `restore`.
- Ответы моделей — недоверенные данные, разбираются только по схеме.

### 9. Готовность к платному провайдеру
Флаг `paid_providers_ready` хранится в `prices.json` (R3). Пока он `false`, платный вызов получает `provider_not_ready`. Флаг включает Orchestrator, когда закрыты 1a–1c и выполнены их критерии:
- `test_cost_invariants.py` проходит без `expectedFailure` (DEBT-0022);
- DEBT-0023 и DEBT-0024 закрыты.

### 10. Контроль слияния `llm/*`
- `commit_all` обходит хуки (`--no-verify`), поэтому точкой контроля служит CI. Новый job `llm-worker` запускает:
  - `python -m unittest discover -s tools/llm_worker/tests` (тесты bwrap в CI пропускаются);
  - `risk.py classify` на ветках `llm/*`.
- `zone_check` для `llm/*` не используется, его заменяет `classify`.
- Класс выше R1 — слияния нет.

## Разногласия
| # | Тема | Позиции | Итог |
|---|---|---|---|
| 1 | Лимит на стороне провайдера (advocate 1) | advocate: нужен отдельный ключ или аккаунт с лимитом у DeepSeek; architect: желательно | Отклонено владельцем (#175 a): общий аккаунт, лимит держит ledger (§6) |
| 2 | DeepSeek как read-only агентный ревьюер (advocate 4) | advocate: дать DeepSeek `Read/Grep` для ревью | Снято: основной ревьюер — Codex (#175 b), DeepSeek-запасной отвечает одним запросом |
| 3 | Второе ревью `tools/**` (advocate 7) | advocate: обязательно; черновик: только R2 | Принято: Codex обязателен для `tools/**` R1, потому что не тратит $5 |
| 4 | Ступени доверия | черновик: ступени 0/1 по окну из 5 задач; critic и advocate: лишнее при таком масштабе | Убраны; остались метрики и одно правило отката (§7) |

## Рассмотренные альтернативы
- **Только Claude.** Противоречит #174 (c): ревью кода Claude осталось бы самопроверкой одной модели.
- **Codex — основной исполнитель.** `codex exec` — агентный режим. Ему нужна та же песочница, что и режиму (b); польза над узким контрактом не доказана.
- **Перенос `rp`** (акторы, `events.jsonl`, PR-поток). Это второй реестр рядом с `registry.py` ради одного разработчика. Взяты только идеи: классы по путям, пары попыток, схема ревью, лимит с отказом.
- **Агентный режим сейчас.** Нет egress-фильтра, а пилот показал, что узкий контракт справляется.
- **DeepSeek как основной второй ревьюер.** Тратит $5. Codex идёт по подписке (#175 b).
- **DeepSeek исполняет R2.** Ошибка L1/L2 дорогая и находится поздно; разрешены только R0–R1 (#174 c).
- **Коммитить JSON ревью.** Лишние файлы в репозитории. Строки с sha256 хватает, отчёт остаётся в `runs/`.
- **Отдельный `deepseek_ask`.** Дублирует worktree, bwrap, контракты и отчёт `llm_worker`.

## Последствия
- **Плюсы:**
  - у R2-кода и `tools/**` появляется независимое ревью другого провайдера бесплатно;
  - шаги R0–R1 уходят с Claude;
  - инфраструктура пилота переиспользуется.
- **Минусы:**
  - до первого платного вызова нужны три задачи;
  - ревью Claude каждого внешнего результата может съесть экономию;
  - $5 хватит примерно на 100–150 вызовов [Предп.].
- **Риски:**
  - общий аккаунт: ошибка в ledger не будет поймана провайдером. Защита — `flock`, резерв, маркер и тесты §Проверка;
  - Codex в общей сети может обратиться к локальным службам хоста. Его внутренняя песочница по умолчанию блокирует сеть для команд — проверить.
- **Обязательно:**
  - строка второго ревью в REVIEW для R2 и `tools/**`;
