## Вопрос исследования

Как устроить пространство в 1000–5000 узлов поверх модели C из RR-0003 (дисциплины как запасы, узлы-открытия, слой применений)? Что нужно решить: секторы, типы узлов и рёбер, специализация институтов, ценность фундаментальной науки, «открытие ≠ производство» (интерфейс к RR-0006), бюджет узлов, правило «у каждого узла есть функция», авторинг и валидатор, UI, стоимость тика, MVP. Входы: CONCEPT_EXPANSION §7.1–7.5, 8.1, 9, 9.11; ANALYSIS §2, T8; урок пилота EXP-0001.

## Краткий вывод

- [Предл.] Модель C сохраняется. Радиальная карта — только **раскладка** этой модели. 9 макросекторов на круге (соседи по кругу — те, кто чаще обменивается знаниями), внутри них ~34 дисциплины-клина. Радиус задаёт **слой узла**: в центре — фундаментальное, по краю — применения. Год виден по цвету и фильтру, а не по геометрии.
- [Предл.] **6 типов узлов**: FND (фундаментальное открытие), PRN (принцип), ENG (инженерное решение), PRC (производственный процесс), CMP (компонент/материал), APP (применение). Тип задаёт, какие эффекты допустимы и какие рёбра узел может иметь («грамматика графа»).
- [Предл.] **6 типов рёбер**: `requires` (жёсткое), `informs` (мягкое, с весом), `synergy` (междисциплинарное: работает только при пороге в нескольких секторах), `hidden` (скрытое/условное, с условием раскрытия), `alt_group` (альтернативные пути «одно из»), `retrofit` (новое знание улучшает уже выпускаемые изделия, CE §8.1).
- [Предл.] **«Открытие ≠ производство»** живёт в узлах PRC. Знать процесс ≠ уметь его вести. `complexity_tier` — только метка; допуск и выход определяет `production_profile(site, prc_set)` по `capability_req` (контракт §4.2, решение #26): отставание до одного уровня — малый выход, больше одного — выход 0. Интерфейс — §5 и контракт §5.
- [Предл.] Пилот показал: без накопления всё решает старт. Поэтому специализация институтов и школы (`school_H`) — **медленно накапливаемые запасы** с переливом знаний в соседние секторы. Мост «промышленность → наука» — отдельный запас `K_ind` (контракт §4.3). Догоняющим дешевле: знание с известным примером (диффузия, разведка) стоит меньше, чем знание на переднем крае. Это надо проверить в Lab, до контента.
- [Предл.] Целевой объём — **~2000 узлов**, а не 5000. Первый срез — «реактивная авиация», ~60 узлов, состав по контракту §10. MVP после среза — **~180 узлов**: три цепочки (реактивная авиация, микропроцессор, спутниковая навигация) и их опоры в 6 секторах. Валидатор с правилом функции и обязательными `cluster`/`discipline` — с первого узла.
- [Предп.] Стоимость тика мала (<1 мс в месяц), если считать только «фронтир» доступных узлов. Основной риск — контент и баланс, а не производительность.

### 3. Типы узлов
| Тип | Что это | Как «открывается» | Допустимые эффекты (функция) |
|---|---|---|---|
| FND | фундаментальное открытие | вероятность в тик от `K_d`, финансирования, приборов (ускоритель, лаборатория) | рост `K_d` и φ дисциплины; новая дисциплина или клин; престиж; приток учёных; ≥2 исходящих `informs` |
| PRN | технологический принцип («можно сделать X на основе Y») | вероятность; часто через `hidden` | открывает ENG; повышает веса направления |
| ENG | инженерное решение (схема, архитектура) | проект КБ/института (RR-0007), стоимость в инженеро-годах | параметр или компонент для конструкторов; `retrofit` |
| PRC | производственный процесс | изучение = знание; **освоение** — в слое способности (RR-0006, ключ `site`) | право вести процесс (`known_processes`); выход годных считает `production_profile` (контракт §4.2); `complexity_tier` — метка |
| CMP | компонент/материал | нужен PRC | вход для ENG/APP и конструкторов; модификаторы параметров |
| APP | применение (класс изделий/инфраструктуры) | нужны ENG + CMP + PRC | новые категории в конструкторах, экономике, армии, обществе |

[Предл.] Цепочка CE §8.1 ложится на типы так: открытие = FND, принцип = PRN, инженерное решение = ENG, затем проектирование и испытания — это **процессы над изделием** (RR-0007, не узлы графа), производство = PRC + CMP, эксплуатация — это парк изделий (RR-0007, vintage capital). Значит, граф знаний кончается на APP. Изделия и парк — отдельные сущности, граф лишь их подпитывает.

### 4. Типы рёбер и грамматика
| Ребро | Семантика | Механика | Ограничения валидатора |
|---|---|---|---|
| `requires` | без A узел B невозможен | логическое И; для ИЛИ — `alt_group` | без циклов; ≤3 на узел [Предл.]; FND→FND только для явной логики |
| `informs(w)` | A облегчает B | −стоимость / +вероятность, сумма весов с убыванием отдачи | циклы допустимы; w ∈ (0,1] |
| `synergy` | B требует сочетания секторов | бонус к вероятности, только если `K` в каждом из ≥2 секторов выше порогов | у ≥30% узлов ENG/APP есть synergy или inputs из ≥2 макросекторов [Предл.] |
| `hidden(cond)` | ребро (или узел) не видно, пока не выполнено условие | 4 вида: *concealed* (порог K: «не знаешь, чего не знаешь»), *classified* (чужая секретная программа; раскрывает разведка), *conditional* (условие мира: дефицит нефти → веса синтетического топлива растут), *serendipity* (малый случайный шанс) | у каждого `hidden` есть `reveal`; serendipity — с детерминированным RNG |
| `alt_group` | альтернативные пути к одной функции | достаточно одного; другие узлы группы дешевеют | ≥2 члена; общая цель |
| `retrofit` | ENG/CMP/PRC улучшает уже выпускаемые изделия | модернизация без нового проекта (CE §8.1; детали — RR-0007) | цель — параметр изделия, а не узел |

Грамматика [Предл.]: APP не может быть `requires`-предком FND; `speculative` не может быть hard-предком `historical` (RR-0003); у PRC обязательны `complexity_tier`, `capability_req`, `cluster` и `discipline` (§5). Рёбра `uses_material` / `uses_energy` из RR-0003 сводятся к входам CMP/PRC.

### 5. «Открытие ≠ производство»: интерфейс к слою способности
Слои, ключи и API заданы контрактом (`LAYER_CONTRACT.md` §1, §5); здесь — только то, что относится к графу. Граф отвечает за **знание** (ключ `actor`), слой способности — за **умение** (ключ `site`).

```
# статические данные узла PRC (граф -> способность)
ProcessDef { id, complexity_tier: int,            # шкала RR-0006 §4.3; только метка
  cluster: ClusterId,                             # ОБЯЗАТЕЛЬНО: MET|CHEM|MECH|ELEC|AERO|NUC|ENER|BASE
  discipline: DisciplineId,                       # ОБЯЗАТЕЛЬНО: одна из ~34 дисциплин графа (для K_ind)
  capability_req: { dim -> tier },                # разреженно, в единицах tier; имена измерений — RR-0006
  key_dims, learning_half, energy_per_unit,       # поля способности, контракт §2
  inputs: [cmp_id | resource_id | energy], workforce: { category: amount },
  outputs: [cmp_id | app_id], test_infra_req? }
known_processes(actor) -> bitset<prc>             # пишет граф
```
Граф читает из слоя способности только (контракт §5): `production_profile(site, prc_set)` и `capability_tier(site, cluster)` — для режима цели и UI (§10); `discipline_volume(actor, d)` (для `K_ind`) и `world_lead(prc, actor)` — в post-фазе. Прежние `capability(actor|enterprise, dim)`, `operable(actor, prc)` и `cumulative_output` **удалены**: их заменяют `capability_tier`, `production_profile` и `proc_X[site,p]` (контракт §2).

- [Предл.] Знать PRC без нужной возможности = «есть чертежи, нет фабрики». Пути — рычаги контракта §6–7: учебная серия, оснастка, лицензия, `simplified_variant` (более лёгкий `prc_set`, в т.ч. старый процесс из той же `alt_group`).
- [Предл.] **Промышленность → наука (CE §14) — только через `K_ind[actor,d]`** (контракт §3, §4.3). Растёт от объёма выпуска PRC своей дисциплины при `yield ≥ 0.3` с убывающей отдачей и потолком `θ_ind·K_d` (≈ четверть научного запаса). Действует **только** как добавка к `K_d` в цене узлов ENG/PRC; на вероятность FND/PRN не влияет. Без выпуска в d забывается (`δ_ind`, за месяц). `K_d` от производства напрямую не растёт.
- **Валидатор `cluster`/`discipline`** [Предл.]: у каждого PRC оба поля заданы; `cluster` ∈ 8 кластеров RR-0006; `discipline` есть в списке дисциплин и принадлежит сектору узла или соседнему (иначе — предупреждение); каждое измерение в `capability_req` известно для этого `cluster` (каталог RR-0006); `complexity_tier` в шкале RR-0006 §4.3. Узел без `cluster` не компилируется.

### 6. Фундаментальная наука как самостоятельная ценность
[Предл.] FND даёт ценность четырьмя путями, и ни один не требует немедленного применения:
1. **Запас и скорость:** открытие поднимает `K_d` и показатель φ в `dA/dt = δ·L^λ·A^φ` (RR-0003 §5.2), то есть ускоряет всю дисциплину.
2. **Опцион:** раскрывает `concealed`-узлы и целые клинья (например, физика ядра → сектор S4). Пока они не раскрыты, игрок не видит, что может потерять.
3. **Люди:** престиж науки привлекает учёных и студентов (миграция знаний, связь с RR-0010) и улучшает качество институтов.
4. **Сотрудничество и диффузия:** открытые публикации ускоряют всех, но первооткрыватель получает лаг-преимущество и престиж. Засекречивание (RESTRICTED/CLOSED, ANALYSIS T6) замедляет и себя.

Приборы (ускоритель, большой телескоп, химическая лаборатория) — это объекты-институты, а не узлы графа. Они открывают доступ к классам FND и умножают вероятность их открытия.

### 7. Специализация институтов и школы
[Предл.] У института есть вектор специализации `s_d` (сумма 1) и **накапливаемый** запас школы `school_H[inst,d]` (контракт §2–3; с производственной культурой `culture_H` не обменивается). Выход по дисциплине `d`: `out_d = base · (s_d + ε) · (1 + k_school·school_H[inst,d])`, где `ε > 0` — «не закрывает другие области» (CE §7.5). Перелив: `0.1–0.3 · out` идёт в соседние по кругу дисциплины, а по `synergy`-хордам — в связанные дальние. `school_H` растёт только от вклада института (наука, не производство), убывает на `δ_s` за месяц при недофинансировании и переносится с людьми (эмиграция школ). В первом срезе `school_H` — FUTURE (контракт §10).
- Против доминирования старта [Предп.]: (а) у `school_H` убывающая отдача и потолок; (б) догоняющим дешевле знание, уже известное в мире (отсылка к «преимуществам отсталости» по Гершенкрону; в этой сессии не проверено); (в) сдвиг парадигмы (keystone) обнуляет часть преимущества старых школ в секторе.
- [Предл.] Проверка: кандидат HYP «школы с переливом и скидкой догоняющему дают разнообразие траекторий» — в Lab на абстрактном графе ~50 узлов, по образцу метрик EXP-0001, **до** массового контента.

### 9. Авторинг в масштабе
- Формат (RR-0003, ADR-0009/0010): YAML по файлу на дисциплину → JSON Schema 2020-12 → скомпилированный бинарный граф. ID `<sector>.<type>.<name>` (например `s5.prc.zone_refining`).
- **Семейства** [Предл.]: шаблон поколений (сталь, реакторы, литография, ГТД) порождает N узлов с параметрами и автоматическими рёбрами `informs` и `alt_group`. Сгенерированные узлы проходят тот же валидатор. Генерация — инструмент для автора, а не runtime.
- Помощь AI-автору [Предл.]: черновик узла с историческим окном и источником → человек проверяет → валидатор. Поле `sources:` обязательно для `historical`.
- **Валидатор** (дополнение к RR-0003 §5.4): грамматика типов; правило функции; бюджеты секторов (предупреждение при превышении >20%); лимиты fan-in/fan-out; у `hidden` есть `reveal`; `alt_group` ≥2; у PRC есть tier, требования, `cluster` и `discipline` (правила — §5); доля межсекторных узлов; **исторический прогон**: N seeds «средней» страны-лидера, медиана года открытия historical-узлов должна попасть в `historical_window ± допуск`; анализ центральности и узких мест (узлы, через которые проходит >X% путей, — в отчёт); детерминизм (один seed → одна траектория).
- Экспорт в GraphML/DOT для ревью в Gephi/Cytoscape (RR-0003).

### 10. UI-навигация (высокий уровень)
- Масштабирование по смыслу: круг секторов (заливка — % освоения, полосы `K_d`) → клин дисциплины (кластеры-семейства) → узел.
- Поиск по имени, эффекту («что улучшает дальность самолёта»), тегу, году. Фильтры: тип, уровень, состояние (известно / доступно / изучается / освоено в производстве / известно о чужом), источник (своё / лицензия / разведка).
- **Режим цели**: игрок выбирает APP — граф показывает минимальный набор недостающих узлов и узкие места, включая PRC-разрыв («знание есть, возможностей нет»). Цепочку причин строит `why_not` (контракт §6); уровень кластера на site показывает `capability_tier(site, cluster)`. Это ответ на «альтернативные пути» и «автоматический анализ связей» (CE §7.2).
- Скрытые связи: «?»-заглушки с подсказкой о классе условия (порог дисциплины / разведка / событие) — без раскрытия содержимого.
- Управление [Предп.]: из-за косвенного управления (ANALYSIS T2) игрок задаёт **направления и приоритеты** институтам (как в Alpha Centauri), а узлы-цели — только для флагманских проектов. Решает владелец.

### 11. Производительность
[Предп.] Оценка: 200 акторов × 2100 узлов → состояние в bitset (~50 КБ на все узлы) плюс Fx-прогресс только по фронтиру (50–150 узлов у актора). Наука идёт на месячной частоте (мультичастотность, RR-0002). В месяц: 200 × 150 × ~8 рёбер ≈ 2,4·10⁵ операций, плюс `K_d` 200 × 34 и диффузия 200² × 34 ≈ 1,4·10⁶ (или по сети контактов). Итого ≪ 1 мс на ядро в месяц, против бюджета 8–45 мс на день (ANALYSIS T4). Пересчёт фронтира — инкрементально при открытии узла. Скрытые условия проверяются событиями, а не каждый тик. Счётный RNG (CounterRng) по (seed, actor, node, month) — детерминизм и параллельность.

### 12. Примеры междисциплинарных цепочек (иллюстрация, не контент)
Обозначения: `→` requires, `~w>` informs, `⊕` synergy, `?` hidden, `{a|b}` alt_group, `⟳` retrofit.

**A. Реактивная авиация (S7, S8, S5, S6)**
```
s7.fnd.brayton_cycle(XIX в.) ~0.6> s8.prn.gas_turbine
s8.fnd.boundary_layer ~0.5> s8.eng.compressor{centrifugal|axial}
s8.prn.gas_turbine → s8.eng.turbojet ← s8.eng.compressor{…}
s5.cmp.heat_resistant_alloy → s8.eng.turbojet      ⊕(S5 металлургия ≥ t1, S8 ≥ t2)
s6.prc.precision_blade_forging(tier высокий) → s8.cmp.turbine_blade → s8.eng.turbojet
s8.eng.turbojet → s8.app.jet_aircraft ;  s5.cmp.heat_resistant_alloy ⟳ (тяга, ресурс ГТД в парке)
```
[Факт] патент Уиттла — январь 1930; стендовые запуски: Уиттл — апрель 1937, фон Охайн — сентябрь 1937; He 178 — 27.08.1939; Gloster E.28/39 — май 1941 (один вторичный источник, migflug.com; нужно сверить). Вывод для механики: между PRN и APP прошло ~10 лет. Узкие места были в материалах и финансировании, а не в идее — это хорошо ложится на PRC/CMP и `capability_req`. [Предп.] Названия конкретных сплавов не проверены.

**Дисперсия открытий в срезе (контракт §9.2).** [Предл.] В слоях способности и изделия случайности нет (#28), поэтому разброс между seeds обязан давать RNG знания. Ключевые узлы среза: `s8.eng.turbojet` (ТРД), `s5.cmp.heat_resistant_alloy` (с его PRC), `s6.prc.precision_blade_forging`.
- Время открытия каждого ключевого узла случайно: после накопления порогового вклада узел открывается с месячной вероятностью (hazard), а не детерминированно по сумме. Это распространяет правило FND на ключевые ENG/CMP/PRC среза (см. «Разногласия»). Hazard — рациональная функция от вклада и `K_d` (без `exp`, контракт §4.5); RNG — CounterRng `(seed, actor, node, month)` на отдельном потоке знания (ADR-0004/0005).
- Цель [Предп., калибрует Lab]: коэффициент вариации времени открытия ключевого узла при равных вложениях ≈ 0,3–0,5 (порядка 3–5 лет на окне ~10 лет между PRN и APP). Предки (`s8.fnd.boundary_layer`, `s8.prn.gas_turbine`) тоже случайны, разброс складывается по цепочке.
- Ориентир: [Факт] Уиттл и фон Охайн независимо запустили стендовые ТРД в 1937 г. с разницей ~5 месяцев (тот же источник migflug.com, вторичный). Значит, одновременные открытия у соперников должны быть возможны, а не исключены.
- Lab: абляция «фиксированный seed потока знания» показывает вклад этого источника в разброс `tech_lead` (контракт §9.2).

## Риски
- Контент: даже 2000 узлов с источниками — это месяцы работы. Нужны семейства и AI-черновики, а валидатор обязателен (RISK-0001).
- Доминирование старта повторится, если специализация — множитель к капиталу без убывающей отдачи (урок EXP-0001).
- Историческая предопределённость: жёсткие окна превратят игру в «рельсы», слабые — дадут анахронизмы. Исторический прогон — только мягкое ограничение.
- Эксплойты: прямой «рывок» к цели через сумму `informs`, накопление бонусов специализации, фарм serendipity. Нужны убывающая отдача и потолки.
- UI-перегрузка при ~2000 узлах. Без режима цели и масштабирования по смыслу граф нечитаем.
- Интерфейс с RR-0006/0007 согласован контрактом v2. Остаётся риск, что FND RNG не даст разброса для ориентира #24 (контракт §9.2).
