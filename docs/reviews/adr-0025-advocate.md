# ADR-0025 — адвокат (2026-11-21)

- **high, альтернативы (нет варианта):** сузить вид клиента до показываемых акторов. [Факт] Клиент читает `Nodes` одного актора: `TechTree.cs:145` `View.Actors[_actor].Nodes`, `AudioDirector.cs:244`; остальное — статические `_host.Data.Nodes`. 6,42 из 6,94 МиБ строятся для читателя, которого нет. Режим вида (`SliceRunConfig.ViewMode` уже есть) или список подписанных акторов: блоки узлов только для играемого и выбранного (≈26 КБ каждый). [Предп.] ≈0,55 МиБ на снимок, п. 5 ADR-0014 сохраняется целиком, аренды, `StaleViewException`, `ViewsDropped` не нужны. Lab — кольцо на потоке владельца без аренд. Цена ≈1–1,5 дня вместо 2–3. Оценка: сильный.
- **moderate, §2 п. 5–6, §3:** если межпоточное кольцо остаётся — классическая тройная буферизация (один читатель, `Interlocked.Exchange` индекса слота) вместо счётных аренд; переполнение невозможно по построению.
- **moderate, последствия:** виды держатся между кадрами (`ActorPanel._lastView`, `TechTree._lastView`, `SimHost._lastWhyView`, `HostSnapshot.View`); по п. 8–9 чтение после N−1 публикаций бросит исключение в UI. Перечислить поля и правило.
- **moderate, `NodeList : IEquatable` (`NodeList.cs:75`):** при кольце равенство двух видов разных тиков в одном хранилище может молча сломаться; сравнение с поколением и тест.
- **low, R2:** как набор N публикаций назад приводится к актуальному — полная перестройка без аллокаций.
- **weak:** альтернативы 1 (настройки GC), 3 (полное кольцо) — отклонение верно; 4 (публикация по запросу) — как дополнение.
- **low, Проверка п. 4:** стресс-тесту нужна мутация (убрать перепроверку ссылки — должно появиться рваное чтение).
- **Вопрос владельцу (gate):** нужны ли в M1 клиенту блоки узлов всех акторов (экран сравнения соперников)? От этого зависит выбор.
