# ADR-0004 — Генератор случайных чисел без состояния

## Контекст
Общий генератор со состоянием ломает L2: порядок обращений зависит от потоков.

## Решение (предложение)
- Случайное число = hash(seed, tick, system_id, entity_id, n) — counter-based генератор (SplitMix64 как функция смешивания; Philox — если понадобится качество выше).
- `System.Random` в ядре запрещён.

## Уточнение: смысл поля `tick` (2026-11-03, решение #60)
- Тик ядра = 1 день (#60, ADR-0006), а системы работают со своей частотой (`Cadence`). Поле `tick` ключа — **индекс шага на частоте системы**, а не дневной тик ядра: для месячной системы — индекс месяца `t` от старта сценария, для годовой — индекс года, для дневной — дневной тик `d`.
- Индекс шага система получает из календаря Kernel по дневному тику (чистая функция без состояния); отображение `t ↔ d(t)` взаимно однозначно, поэтому ключ остаётся функцией времени и L1/L2 не страдают.
- Зачем: значение месячной выборки не зависит от длины предыдущих месяцев, даты старта и правила дня срабатывания; ключи совпадают с пре-регистрированными в HYP-0002 и эталоне EXP-0002. Источник: `docs/simulation/slice-jet-aviation.md` v0.5 §2, §9.1.
- Пересечений нет: системы с разной частотой имеют разные `system_id` («один поток — один смысл», срез §9.1).

## Последствия
Каждая система явно передаёт свой `system_id` и счётчик `n`.

## Проверка
Unit-тесты на эталонные значения; тест L2. Тест: выборка месячной системы с ключом `tick = t` одинакова при разных `start_date` сценария с тем же числом месяцев (ключ не зависит от дневного тика).
