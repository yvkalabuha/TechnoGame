## 3. Сцена и камера
### 3.1 Узлы: шесть силуэтов (C2)

|---|---|
| знание | треугольник вершиной вверх |
| принцип | ромб |
| инженерия | шестиугольник |
| компонент | пятиугольник (как этап 1, ⬠) |
| процесс | круг с вырезом-стрелкой (по часовой) |
| изделие | скруглённый квадрат со срезанным верхним углом |
- [Предп.] Этап 1 называет силуэт только для компонента; остальные выбраны здесь, привести в соответствие со stage1 перед реализацией.
- Силуэт — **плоский контур** с внутренним «кристаллическим» бликом (декор ≤ 1,6:1 к заливке); эмблемы институтов в силуэты узлов не вписываются (§7).
- Размер на экране: ближний план 40 du, не меньше **24 du** в дальнем (A2 ≥ 16, A10 ≥ 24); зона нажатия = max(32, размер + 8) du. Узлы ближе 28 du друг к другу сливаются в кластер «+N» (кольцо + число 14 du).
- Каждый узел лежит на плашке `deep.abyss` 85 % радиусом +4 du: контраст контура к плашке считается именно к ней, лента и свечение под узлом не мешают (C5, A4).
- Военный узел: двойной контур (как этап 1).

### 3.2 Модель камеры
- Параметры: цель T (точка мира), yaw, pitch, distance. Перспектива, вертикальный угол 40°.
- Мир: X = поток (ширина полосы 6 ед.), Z = год (1 ед. = 1 год, 1945 → 0, 2100 → 155), Y = высота стагера узлов (0–4 ед., считается при загрузке без случайности, стабильно по id, чтобы узлы одного года не пересекались).
- Пределы: yaw ±75°, pitch 15°–70° над плоскостью моря (под воду камеру не пускать), distance 8–220 ед., T внутри габарита узлов +10 ед.
- Вид по умолчанию «Сейчас»: T на год игры (Z(now)), yaw 0, pitch 35°, distance 70. «Весь океан»: distance по габариту, pitch 55°, yaw 0.
- Мышь: ЛКМ по пустому месту, перетаскивание ≥ 4 px = орбита (тянем сцену: вправо — сцена вращается вправо); ПКМ или СКМ или Shift+ЛКМ = сдвиг в плоскости вида; колесо = полёт по лучу к точке под курсором, шаг 12 % расстояния за деление (логарифмически; минимум 0,5 ед.); клик по узлу = выбрать (камера не двигается); двойной клик или F = навести на узел: T к узлу, distance = min(текущая, 30), 350 мс ease-out; клик по пустому = снять выбор. Тачпад: два пальца сдвиг, щипок полёт.
- Инерция: затухание не более 150 мс (A8 ≤ 200 мс). Прокрутка у края экрана не используется.
- Любое действие камеры отменяет перелёт в процессе. Выбранный узел вне кадра (например, из поиска) — камера переходит к нему автоматически.
- Желаемое: камера никогда не показывает «пустоту» целиком: при выходе T за габарит возвращается в предел без анимации.

### 3.3 Годы как глубина
- Три канала глубины: размер перспективы, туман (цвет линии стремится к `deep.fog` до нижнего предела контраста узла 3:1, подписи и значки в туман не уходят), линейка лет.
- Кольца-декады на «море» (Z = 1950, 1960, …) тонкие, 1 du, контраст к фону ≤ 1,6:1 (`deep.ring` #0E2A40 к ground ≈ 1,2:1, декор, под подписями нет). Кольцо «Сейчас» — единственное яркое: 2 du, `deep.command`, ≥ 3:1, плашка «Сейчас · 1978» 96x24 на кольце.
- **Метки лет только на линейке лет** (экранные координаты, левый край): ряд 1950, 1960, … 2100 по возрастанию вверх, позиция = проекция кольца на центральную ось вида; шрифт 13 du `deep.ink-2`; метки ближе 24 du друг к другу прореживаются через одну (оставляется «Сейчас» и ближайшие круглые 50 лет). Цифры считает код; вне 1945–2100 не рисуются. Подсказка при наведении на линейку: «Год на уровне курсора: ≈ 1983».
- Узел показывает год в подсказке и в инспекторе («≈ 1970»); на сцене год рядом с узлом только у выбранного и узлов маршрута.

### 3.6 «Меньше движения» (A8)
- Перелёты (двойной клик, F, автопереход, миникарта) — мгновенный скачок, без инерции; бег ряби, частицы, бег света по лентам, пульсация выбора отключены. Свечение статичное.
- В обычном режиме: бег света вдоль потока не быстрее 1 цикла за 4 с, не мигает, ≤ 3 вспышек/с исключены; пульсации выбора нет вообще (выбор — белое кольцо).

## 4. Потоки (направления)
- 13 направлений из этапа 1 §2; на эскизе 5 — при 13 лентах поле заполнится. [Предл.] Лента на каждое направление, но ширина 2–3 ед., тело ленты почти прозрачное, кромка 2 du несёт данные. - Направление потока (куда «течёт») — шевроны 8 du на кромке каждые 60 ед. (статично); бег света только в обычном режиме (§3.6).
- Узел в нескольких направлениях лежит на главном потоке; на остальных — тонкая связь и тег в подсказке.
- Маршрут к цели: линия 3 du `deep.ink` (светлая) с тёмным контуром 1 du, номера 1…N в квадратах 22x22; вне маршрута узлы тусклее (контур `deep.locked`), подписи убраны.

## 9. Технология и бюджет [Предл.; подтверждает systems-architect, ADR-0001]
**Рекомендация: 2.5D.** Позиции узлов (x, y, z) проецируются своим кодом (чистая функция `Project(camera, point) → (screen, scale, depth)` с юнит-тестами, общая для живого пути и фикстур, .claude/rules/ui.md); рисуют Control/_Draw (узлы, плашки), потоки — один предпостроенный `ArrayMesh`/`Polygon2D` на поток, свечение — готовая текстура на узле (аддитивное смешивание).
Причины: (1) подписи и значки остаются чёткими, пиксельно привязанными, с размерами в du и нижним пределом — 3D-подписи (Label3D) дают мерцание и сглаживание, трудно держать A1; (2) нажатие и клавиатурный выбор — просто круги в экранных координатах; (3) вся остальная клиентская UI и тема на Control; серые кадры и тест-мост `--shots` рендерят то же дерево; (4) не требует Forward+ и мощной видеокарты, работает на Compatibility; (5) бюджет в 300–400 узлов тривиален для CPU-проекции; (6) глубина читается 2.5D достаточно (размер, туман, ленты), настоящий обзор «из-под» не нужен — камера ограничена.
Минус: нет теней и освещения, эффект «ощущение объёма» слабее; снимается свечением и туманом. Настоящее 3D возвращаем, только если спайк S2.0 покажет, что 2.5D не даёт ощущения погружения (решает владелец по кадрам).
Бюджет [Предп., целевая машина не определена]: кадр ≤ 16,6 мс на 1920x1080 на встроенной графике; проекция и сортировка 400 узлов ≤ 1 мс CPU; draw calls ≤ 250; подписей на кадре ≤ 24 (пул Label, без создания в кадре); частиц ≤ 200 и 0 при «Меньше движения»; память под сцену ≤ 100 МБ. В `_Draw` никаких аллокаций (правило ui.md): массивы точек предвыделены, меши строятся при загрузке раскладки. Раскладка узлов считается один раз при открытии экрана (не в кадре), детерминированно по id. Пересчёт проекции только при движении камеры или смене данных.
