# Формат CSV и манифестов EXP-0002 (срез «реактивная авиация»; `lab/analysis/exp0002.py`)

> Статус: черновик v0.2 (#77: P2, P4) (simulation-engineer, 2026-11-03), часть T10 и T11 спецификации `slice-jet-aviation.md` v0.6 (дальше «спец. §N»). C#-моделей `JetSlice` и `JetSliceCalib` ещё нет; формат проверен только синтетическими данными (`exp0002.py --selftest`).
> Соглашения унаследованы от `exp0001-csv-format.md` и Lab (ADR-0008, `src/Singularity.Lab/RunExecutor.cs`, `MatrixRunner.cs`).

## Краткий вывод
- [Предл.] Lab пишет `runs.csv` (свои фиксированные колонки) и по одной таблице метрик на файл; первая колонка каждой таблицы — `run`. Lab склеивает CSV всех прогонов матрицы и **требует одинаковый набор файлов и заголовков у всех прогонов**, поэтому модель `JetSlice` всегда создаёт все 8 таблиц, а «тяжёлые» таблицы в сериях, где они не нужны, остаются с заголовком без строк (параметр `detail`, ниже).
- [Предл.] Время — индекс месяца `t` 0…383 (спец. §2), не дневной тик. Годовые строки — при `t mod 12 = 0` (`t` = 0, 12, …, 372).
- [Предл.] Числа `Fx6` пишутся **целым raw** (значение × 10⁶, `long`), без десятичной точки. Целые счётчики и месяцы — целые. Пустое поле — «не наступило к t = 383» (правая цензура); `−1` — «уже на старте» (левая цензура).
- [Предл.] Лента лидера — строка из 384 символов (индекс актора на каждый месяц), а не 384 строки CSV: так `summary.csv` для 12 440 прогонов весит ~15 МБ.
- [Предл.] Калибровочная сборка `JetSliceCalib` пишет **другой** набор таблиц, без колонок лидерства, FV, `why_not` и объёма (спец. §8.2 п.2). Тест T10 проверяет заголовки по списку запрещённых файлов и подстрок (ниже); тот же список проверяет `exp0002.py --calib` до любого расчёта.
- Запуск: `python3 lab/analysis/exp0002.py DIR [DIR …] [--config cfg.json] [--out report.md] [--json report.json]`; `--calib DIR` — таблицы контролей §6.1 и якоря C2, C4; `--dump-config` — все пороги; `--selftest [--quick]` — синтетические данные с известным ответом.

## 1. Общие правила
| Правило | Значение |
|---|---|
| Кодировка, разделитель | UTF-8 без BOM, `,`, первая строка — заголовок; порядок строк и лишние колонки не важны (как EXP-0001) |
| Акторы | id сценария: `USA`, `GBR`, `SUN`, `FRA`, `SWE`; индекс актора = порядок сценария, 0…4 (спец. §3.5 A7) |
| Великие державы | `USA`, `GBR`, `SUN` = индексы 0, 1, 2 в ленте `lead` |
| Узлы | номер 1…61 по таблице спец. §1.3 |
| Время | `t` — индекс месяца; `t = 0` — 1945-09; год сценария `y` = `1945 + (8 + t) div 12` |
| `Fx6` | целое raw (`yield` 0,7 → `700000`) |
| Пусто / `−1` | не наступило к 383 / известно или достигнуто на старте |
| Профиль ИИ | целое 1…3 = P1 «качество», P2 «массовость», P3 «адаптивный» (спец. §4) |
| Несколько каталогов | анализ принимает несколько каталогов результатов (разные манифесты); id прогона внутри анализа = `<номер каталога>:<run>`, так совпадающие id Lab (`p0-s1-t1`) из разных матриц не конфликтуют |

## 6. Что считает анализ (определения, которых нет в спец. дословно)
- [Предл.] **Засчитанная смена** (спец. §5.2): берутся максимальные отрезки ленты `lead`; отрезок нового лидера `X ≠ L` начинается в `s ≤ 359` и длится ≥ 24 мес. (может уходить в хвост до 383); `L` — последний **подтверждённый** лидер (старт — `lead[0]`). Короткий «скачок» < 24 мес. не смена и не сбрасывает `L`; возврат прежнего лидера после подтверждённой смены — новая смена.
- [Предл.] **Tenure**: от старта и от каждой засчитанной смены до следующей засчитанной смены, обрезка на 360.
- [Предл.] **`small_lead`**: отрезок `SWE` в `lead_all`, начинающийся в `s ≤ 359` и длящийся ≥ 24 мес. (тот же «хвост», что у смен; ключ `p2.tail_counts`, `false` — считать только месяцы ≤ 359).
- **P3**: `Δ` = `chg_main − chg_off`, парный перцентильный bootstrap (2000); `|Δ|`-нижняя граница = 0, если CI содержит 0. `TVD_bc` — по спец. §6.1 (перестановки меток внутри пары, 2000; bootstrap `TVD* − b`). Split-half: фиксированное разбиение 1…500 / 501…1000 печатается, решает p95 по 2000 случайным разбиениям 500/500.
- **P2**: «точка > 0,05, нижняя граница ≤ 0,05» — «на грани» (решение #77, спец. §7).
- **P4 (a)** — доли слоя первого звена по всем актор-годам с непустым `why_not` (5 акторов вместе); по классам — печать. Допуск «на грани» (#77): 0,05 у порога 70% (`p4.tol_max`), 1 п.п. у порога 5% (`p4.tol_min`). **(b)** — актор-годы с `eng_short_months ≥ 6`, допуск 0,05 (`p4.tol_b`); если таких нет, (b) = `n/a` («не применимо»), P4 решает (a), отчёт пишет это в примечании.
- **P5**: 54 пары соседних точек; флаг — `|Δchg| > 0,20` и `|Δ|`-нижняя граница CI парного bootstrap > 0,10.
- **Исход**: `refutes` — провал P1, P2 или P3; `supports` — P1–P4 проход/«на грани», «на грани» ≤ 1 среди P1–P3, P5 без флага; иначе `inconclusive`; нет нужной серии — `incomplete`. P0 анализ не проверяет: `p0_passed` в конфиге (`null` → к исходу дописывается «P0 not confirmed»).
- **D1**: все звенья с `eta ≠ null`; попадание — `closed_t − t ≤ 1,5·eta`; незакрытое при `t + 1,5·eta > 383` исключается. **D2**: единицы без звена `why_not` идут в «не закрыл» (буква спец. §5.9), их число печатается; «стал лидером» — засчитанная смена с началом в `(12y; 12y + 60]`.
- Таблицы контролей (`--calib`): `m`, `s` (выборочное, n − 1) по нецензурированным seeds, `half = ⌊√3·s + 0,5⌋`, `p_cens` в Fx6; `δ` и медианы `Y_k`, `U_k`, `T_design`, `ρ` — **нижняя медиана** (`median_low`), чтобы значение было целым и точным без округления; `ρ` raw = `⌊out·10¹²/proc_budget_raw⌋`. `control_tables_hash` = sha256 канонического JSON таблиц.
- Детерминизм анализа: каждый bootstrap/перестановка — свой `random.Random`, seed = sha256(`seed конфига | метка статистики`); результат не зависит от порядка расчёта (проверяется в `--selftest`).
