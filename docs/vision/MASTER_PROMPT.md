# PART II. GAME VISION

## 2. ОСНОВНАЯ КОНЦЕПЦИЯ

Рабочее название: PROJECT SINGULARITY.

Жанр: глобальный цивилизационный симулятор с элементами grand strategy, научно-технической стратегии, экономического и геополитического моделирования.

Временной диапазон: приблизительно 1910–2100 годы.

Главная идея:

Создать масштабную интерактивную модель развития человеческой цивилизации, в которой игрок формирует условия развития собственного государства, а научные, экономические, политические, социальные и военные процессы взаимодействуют между собой.

Главный акцент — исследования и технологическая эволюция.

Но исследования не существуют сами по себе. Они влияют на промышленность, экономику, военную мощь, общество, международные отношения и дальнейшее развитие цивилизации.

Игра должна моделировать не только то, что делает игрок, но и то, что происходит без его непосредственного вмешательства.

**Игрок управляет условиями и стратегией развития государства, а не каждым отдельным процессом.**

Государства, организации, политические институты, промышленность, научные учреждения и общественные группы должны обладать собственной логикой поведения.

Игровой мир должен продолжать развиваться независимо от действий игрока.

## 3. РОЛЬ ИГРОКА

Основная модель — вариант цивилизационного симулятора.

Игрок:
- Формирует стратегические приоритеты государства.
- Влияет на политическую систему.
- Определяет государственную экономическую политику.
- Распределяет ресурсы и бюджет.
- Развивает образование и науку.
- Формирует условия для технологического развития.
- Влияет на промышленность.
- Определяет внешнеполитический курс.
- Принимает решения по вопросам безопасности и обороны.
- Управляет долгосрочными национальными программами.

При этом игрок не должен быть всемогущим.

Решения проходят через государственные институты, экономические механизмы, политические ограничения, общественные интересы и доступные ресурсы.

Необходимо исследовать подходящие модели:
- Косвенного управления.
- Государственного планирования.
- Рыночной экономики.
- Смешанной экономики.
- Политических ограничений.
- Институциональной инерции.
- Автономии организаций.
- Влияния общества и групп интересов.

Не фиксируй окончательную модель до исследования.

Игрок может столкнуться с ситуациями, когда:
- Правительство не может реализовать задуманную политику.
- Промышленность не заинтересована в определённых проектах.
- Научные учреждения развиваются независимо от государственных приоритетов.
- Общество сопротивляется реформам.
- Частный сектор обгоняет государственные предприятия.
- Технологическое развитие приводит к непредвиденным последствиям.

Это не недостатки симуляции, а потенциально важные игровые механики.

# PART IV. IDEA AND RESEARCH PROCESS

## 8. СИСТЕМА РАБОТЫ С ГИПОТЕЗАМИ

Введи отдельный реестр игровых и технических гипотез.

Любая существенная новая идея должна иметь статус:

- IDEA
- HYPOTHESIS
- UNDER_RESEARCH
- EXPERIMENTAL
- VALIDATED
- REJECTED
- DEFERRED

Пример:

**EXP-0001 — Зависимость науки от промышленности**

Гипотеза:

Научное лидерство не должно автоматически приводить к промышленному превосходству.

Проблема:

Государство может обладать сильной фундаментальной наукой, но не иметь возможности создавать передовую технику.

Предполагаемое решение:

Разделить научный потенциал, инженерные возможности и производственные мощности.

Эксперимент:

Создать несколько государств с различными сочетаниями науки, кадров, промышленности и ресурсов.

Критерий успеха:

Разные условия приводят к разным результатам развития. Ни одна модель не получает автоматического превосходства.

Каждая гипотеза должна иметь:
- ID.
- Название.
- Описание.
- Причину появления.
- Предполагаемый эффект.
- Альтернативные варианты.
- Связанные системы.
- Риски.
- Способ проверки.
- Критерии успеха.
- Результат эксперимента.
- Итоговое решение.

Не превращай все гипотезы в обязательные механики.

## 9. ПРОТОКОЛ АНАЛИЗА ИДЕЙ

Для существенных идей используй цикл:

1. IDEA — регистрация.
2. CONTEXT — определение проблемы.
3. RESEARCH — исследование аналогов и источников.
4. ANALYSIS — анализ вариантов.
5. ADVOCACY — поиск преимуществ альтернатив.
6. CRITIQUE — независимая критика.
7. DESIGN — формирование решения.
8. REVIEW — проверка совместимости.
9. APPROVAL — моё утверждение.
10. IMPLEMENTATION — реализация.
11. TESTING — тестирование.
12. VALIDATION — проверка гипотезы.
13. INTEGRATION — интеграция в игру.
14. RELEASE — фиксация результата.

Для простых задач используй упрощённый цикл.

Для фундаментальных решений используй полный.

Разногласия агентов должны фиксироваться, а не скрываться.

# PART V. SIMULATION LAB AND GAME BALANCING

## 10. ОТДЕЛЬНОЕ СИМУЛЯЦИОННОЕ ЯДРО

Это одно из важнейших архитектурных требований.

Исследуй возможность создания независимого от графического интерфейса симуляционного ядра.

Оно должно позволять запускать полноценную модель мира без отображения карты и визуальных элементов.

Цель — автоматизированное исследование игровых механик и балансировки.

Возможности:
- Запуск исторических сценариев.
- Запуск альтернативных сценариев.
- Симуляция нескольких десятилетий.
- Симуляция большого количества государств.
- Массовые повторные запуски.
- Изменение стартовых условий.
- Изменение параметров механик.
- Сбор статистики.
- Сравнение результатов.
- Выявление аномалий.
- Поиск доминирующих стратегий.

Предусмотри Simulation Lab.

### Simulation Lab должна поддерживать:

1. Batch Simulations — массовые запуски.
2. Scenario Testing — проверка конкретных сценариев.
3. Parameter Sweeps — перебор параметров.
4. Monte Carlo Experiments — статистические эксперименты с вариативностью.
5. Regression Simulations — сравнение с предыдущими версиями.
6. Balance Analysis — анализ баланса.
7. Performance Benchmarking — измерение производительности.

Каждый эксперимент должен сохранять:

### Анализ баланса

Проверяй:
- Не возникает ли технологического застоя.
- Не получает ли одна страна необоснованное преимущество.
- Не разрушается ли экономика при определённых условиях.
- Не становится ли война единственным эффективным способом развития.
- Не существует ли доминирующей экономической стратегии.
- Не возникают ли бесконечные циклы роста или упадка.
- Не становится ли научная система слишком линейной.
- Не возникает ли технологическое преимущество без необходимых ресурсов.
- Не приводят ли отдельные события к необратимому разрушению симуляции.

Баланс должен оцениваться не только по средним результатам, но и по распределениям, вариативности и крайним сценариям.

Не подгоняй все результаты под историческую хронологию.

Альтернативная история и разнообразие результатов являются частью концепции.
