# ADR-0020 — Province storage, aggregation to regions and tick budget

> После ACCEPTED текст не меняется. Изменение решения — новый ADR с `supersedes`.
> Уровень: gate+research. Пункт 0.3 плана `development/milestones/MS-M1-economy-provinces-open-race.md`; снимает оговорку ADR-0016 §1 («провинции не входят») и требование ADR-0011 «до кода E1 — решение о регионах со смешанным владением».

## Краткий вывод
- [Предл.] Провинции — **отдельная таблица Kernel** (`provinces`, 2000–5000 строк, колонки `owner`, `controller`), регионы — своя таблица (`regions`, 150–250 строк). Kernel получает мир из нескольких таблиц; мир из одной таблицы хешируется прежними байтами (golden M0 и `SliceLegacy` целы).
- [Предл.] Провинция — единственный источник владения. Регион хранит **производную атрибуцию**: до 4 пар `(polity, share)`, пересчитываемых из провинций только в merge дня события. Это и есть «dirty flag»: в другие дни колонки не открываются (CoW = 0).
- [Предл.] Экономика региона атрибутируется по **`controller`** (де-факто). Регионы со смешанными контролёрами допустимы **только по явному списку** `mixed_regions` с весами провинций из источников; иначе граница события обязана совпадать с границей региона — проверка в CI на всей таблице событий.
- [Предл.] Совместная полития (#312) не актор: её доля делится между членами по `econ_shares` из `polities.yaml` (по умолчанию поровну), раздел точный (`Apportion`, ADR-0019).
- [Предл.] Доля провинций в бюджете — ≤ 100 из 500 мс; ожидание M1 [Предп.] < 5 мс/мес. При превышении `T` жертвуется скорость до пола 1 мес./3 с (#327, #331), число провинций не трогается.

## Контекст
- [Факт: ADR-0011 §1, §3] Провинции 2000–5000 (жёстко), регионы 150–250; `owner`/`controller` — колонки `short` на провинции с t0; полития `kind: state | joint`, `government` (DEU, KOR — false); владение меняется только в merge; «до кода E1 — решение ADR о регионах со смешанным владением: ячейка `(region, controller)` или атрибуция по `controller` столичной провинции».
- [Факт: ADR-0016 §1] Полный масштаб без провинций; для систем провинций нужен новый ADR бюджета. ADR-0011 оценивает слой владения [Предп.] < 1 % `K_d`.
- [Факт: код `Table.cs`, `TickRunner.cs`, `StateHash.cs`] Kernel держит **одну** таблицу с общим числом строк (сейчас 200 акторов; узлы знания — колонки, ≈ 8800 × 200 ≈ 14 МБ). Колонки — только `long` и `int`. Хеш: заголовок `schema_version`, `n_rows`, затем колонки.
- [Факт: ADR-0013 п. 1] Формат сохранения уже описан «по каждой таблице: name, schema_version, row_count».
- [Факт: ADR-0017] CoW по колонкам; хеш в игре — только в точках старт/save/load/конец replay; `Table.Version` растёт при swap открытых колонок и `Load`.
- [Факт: DECISIONS_LOG #312, #313, #325, #327, #328, #331] Совместные политии; оккупация (owner без правительства, controller — оккупант; Тайвань owner JPN, controller ROC); сценарные смены владения строго по дате, широкий список (Германия, Корея, Индия/Пенджаб/Бенгалия, Палестина, Индонезия, Индокитай, деколонизация); при превышении бюджета жертвуется скорость, пол 1 мес./3 с.

## Решение

### 1. Хранение
1. **Мир из нескольких таблиц.** `World` в Kernel — упорядоченный список `Table` с именами: `actors` (как сейчас), `regions`, `provinces`. Каждая система объявляет таблицу, по строкам которой режется на чанки (`ITickSystem.ChunkTable`, по умолчанию первая). Чанки — по `ChunkSize` этой таблицы; правило L2 прежнее.
2. **`provinces`:** строка = провинция в ordinal-порядке `province_id` (ADR-0011 §3). Колонки состояния: `owner`, `controller` — `short` (индекс политии). В Kernel добавляется `ShortColumn` (little-endian int16 в хеше). Статика (регион провинции, вес `w_p` для смешанных регионов, CSR соседства) — неизменяемые массивы `Singularity.Core.Map`, в `DataHash`, не в `Table`.
3. **Плотные колонки, не разреженные.** [Предп.] 2 × 5000 × 2 Б = 20 КБ; разреженное хранение (RISK-0006, «10⁴») не нужно, пока провинции несут только владение. Пересмотр — когда у провинций появятся системы M2 (война, логистика).
4. **`regions`:** E1 (ADR и спецификация E1) плюс производная атрибуция `attr_polity_0..3` (`short`, −1 = пусто) и `attr_share_0..3` (Fx6, сумма = 1,000000 точно). Не больше 4 контролёров на регион — правило валидатора.
5. **Хеш мира.** Если таблица одна — байты как сейчас (golden M0, `SliceLegacy`, ADR-0019 п. 19). Если таблиц больше: `int32 table_count`, затем по каждой таблице в порядке списка `int32 schema_version`, `int32 n_rows`, колонки в порядке регистрации. Алгоритм SHA-256 и расписание ADR-0017 не меняются.

### 2. Агрегация провинция → регион
6. Регион владельца не хранит (ADR-0011). Атрибуция региона — функция `controller` его провинций и статических весов: `share(r, c) = Σ_{p ∈ r, controller(p)=c} w_p / Σ_{p ∈ r} w_p`, раздел точный (`Apportion`, ADR-0019 п. 6), пары упорядочены по убыванию доли, затем по индексу политии.
7. Для региона не из списка `mixed_regions` веса не нужны: валидатор гарантирует одного контролёра, атрибуция — `(c, 1,000000)`.
8. **Пересчёт только в дни событий.** `ScenarioEventSystem` (первая в списке, ADR-0019 п. 11) в merge дня события пишет `owner`/`controller` в `provinces.Next` и пересчитывает атрибуцию **только затронутых регионов** в `regions.Next`. В дни без событий она не обращается к `Next`: колонки не открываются, CoW и `Version` не меняются. Отдельного флага-состояния нет.
9. Почему колонки, а не кэш вне таблиц: кэш, живущий между тиками, — исключение из ADR-0013 п. 4 (нет состояния вне таблиц) и требует пересборки после load. Колонки сохраняются и хешируются как всё остальное; цена — 8 колонок × 250 строк.
10. Инвариант post (K9): в день события и при `HashEveryTick` каждый день — атрибуция каждого региона равна пересчёту по п. 6; у провинции ровно один `owner` и `controller`; смена не из таблицы событий — ошибка.

### 3. Регион с несколькими контролёрами
11. **Правило выравнивания (CI).** Для t0 и каждой даты таблицы событий 1.6a: множество провинций, меняющих `controller`, — объединение целых регионов, и у каждого региона один контролёр — **кроме** регионов из `mixed_regions` (`mods/core/map/regions.yaml`, поле `mixed: {weights_source, as_of}`, веса `w_p` у его провинций). Нарушение — красный CI с перечнем регионов и событий.
12. **Ожидаемый список** [Предп.; составляет research-scientist с картой 1.1]: Берлин (4 сектора), Вена (4 сектора + центр, #312), регионы, рассечённые линиями зон Германии и Австрии, где регион по географии не разделён. Пенджаб, Бенгалия, Корея (38°), Индокитай (16°) — **выравниваются** разделением регионов по линии (ADR-0011 §6 класс A), а не входят в список.
13. Физическое состояние смешанного региона (люди, энергия, мощность) — общее; атрибутируются только выходы (деньги, вклад в бюджет актора) по долям. [Предп.] Для 5–10 малых регионов искажение мало; это проверяет 2.9.
14. Новое событие, режущее регион вне списка, — либо правка карты (разделение региона; до первого сохранения игрока миграция не нужна, ADR-0013 п. 7), либо запись в `mixed_regions` с источником весов. Выбор — game-designer и research-scientist, фиксируется в задаче.

### 4. Атрибуция: controller, совместные и оккупированные политии
15. Экономика региона идёт **контролёру** (де-факто). Оккупированные политии без правительства (DEU, KOR) актором не являются — их регионы атрибутируются оккупантам. Тайвань до передачи — ROC. `owner` в M1 экономику не меняет (притязания, легитимность — M2).
16. **Совместная полития** (#312) может быть контролёром; она не актор. Её доля делится между `members` по `econ_shares` (`polities.yaml`, Fx6, сумма 1,000000, по умолчанию поровну; иной раздел — с источником). Раздел — `Apportion` в порядке `members`.
17. Бюджет актора (#330) = Σ по регионам `share(r, a)` × выход региона + доли через совместные политии; pull в compute актора, регионы по возрастанию индекса (ADR-0019 п. 17).

### 5. Бюджет тика
18. **Доли** [Предл.; уточняет диагностический раздел ADR-0016 §3 для M1]: системы способности ≤ 100 мс; Kernel + Session ≤ 50 мс; **провинции ≤ 100 мс**; E1 (E1a + E1b + H/M) и прочее — из оставшихся 250 мс. Ожидание M1 по провинциям [Предп.]: дневная проверка событий — мкс; день события — O(провинций региона); хеш 20 КБ (≈ 15 мкс) только в точках ADR-0017; view `Ownership` переиспользует массивы без изменений (ADR-0011 §3). Итого < 5 мс/мес; остаток доли — запас под системы провинций M2.
19. **Исходы K4** (#269, #327, #331): ядру — половина стены месяца, поэтому максимальная скорость = 1 месяц за `max(1 с, 2 × T_p95)`.
    - PASS: p95 ≤ 500 мс и медиана ≤ 400 мс — скорость 1 мес./с.
    - WARN: 500 < p95 ≤ 1500 мс — максимальная скорость снижается до 1 мес. за `2 × T_p95` (пол 3 с); подмена #269 записывается в DECISIONS_LOG; раунд оптимизации по ADR-0016 §4.
    - FAIL: p95 > 1500 мс — вопрос владельцу (#331).
20. **Число провинций — не рычаг бюджета** (#327). Его задаёт карта (2000–5000, ADR-0011). Бенчмарк K4 идёт на фактической карте и справочно на синтетических 5000 провинциях с событием каждый день (худший случай слоя).
21. Новая система провинций (M2) заявляет удельную цену на провинцию-день до кода; превышение доли п. 18 — gate.

### Влияние на другие ADR
- **ADR-0011:** тип `short` и место владения не меняются; «ячейка `(region, controller)` или столичная провинция» → атрибуция по долям п. 6 со списком `mixed_regions` (п. 11). Добавляется поле `mixed` в `regions.yaml` и `econ_shares` в `polities.yaml` (`DataHash`, валидатор).
- **ADR-0013:** формат не меняется (по таблицам уже); `save_format_version` растёт.
- **ADR-0016 §1:** оговорка «провинции не входят» снята этим ADR; полный масштаб M1 = 200 акторов, 150–250 регионов, 2000–5000 провинций.
- **ADR-0017:** CoW и расписание без изменений; `Table.Version` — на таблицу, кэш `LastHash` сравнивает вектор версий.
- **ADR-0002:** без изменений.

## Рассмотренные альтернативы
| Альтернатива | Причина отказа |
|---|---|
| Провинции колонками в таблице акторов (5000 × 2 колонки × 200 строк) | ×200 памяти и хеша, бессмыслица строк |
| Разреженные колонки провинций | Не нужны при 20 КБ; вернуться в M2 |
| Строгое выравнивание без исключений | Берлин и Вена дают 4–5 регионов-секторов каждый из 150–250 (#171) |
| Ячейка `(region, controller)` с отдельным E1-состоянием | Строки E1 появляются и делятся при событиях: перенос людей и мощности, миграция строк; объём 2.9 растёт кратно |
| Весь регион — контролёру столичной провинции | Западный Берлин уходит SUN; ошибка порядка 40 % региона [Предп.] |
| Веса `w_p` у всех провинций (общий раздел по долям) | Оценки населения 1945 для 2000–5000 провинций — объём research (#168) без пользы для выровненных регионов |
| Атрибуция по `owner` | DEU и KOR без правительства — экономика «ничья»; Тайвань у JPN после капитуляции |
| Агрегат как кэш вне таблиц с флагом версии | Исключение из ADR-0013 п. 4, пересборка после load |
| Уменьшать число провинций при превышении бюджета | Запрещено #327 |

## Последствия
- **Плюсы:** провинция — единственный источник владения; в обычный день слой ничего не стоит; E1 работает с одной ячейкой на регион; правило выравнивания ловит ошибки таблицы событий в CI.
- **Минусы:** Kernel получает мир из нескольких таблиц (чанки, хеш, save, CoW, версия) — изменение Kernel до кода 1.3; карта 1.1 зависит от таблицы событий 1.6a (CI выравнивания); общий физический пул в смешанных регионах — приближение.
- **Обязательно:** `mixed_regions` с источником весов; `econ_shares` с суммой 1; ≤ 4 контролёра на регион; атрибуция пересчитывается только в merge `ScenarioEventSystem`.

## Проверка
1. **Хеш одной таблицы:** golden M0 и `EXP-0002-det` (`824f4ded…`) без изменений после изменения Kernel.
2. **L2 мира из трёх таблиц:** threads 1/4/8/16 × ChunkSize 1/8/32, разные `ChunkTable`, `HashEveryTick` — хеш каждого дня равен.
3. **Save/load:** три таблицы, save в день события и на следующий день → load → продолжение даёт тот же хеш (ADR-0013).
4. **CoW:** в день без события `provinces.Version` и `regions.Version` не меняются; в день события — меняются.
5. **Атрибуция:** property-тест — после каждого события атрибуция = пересчёт с нуля; сумма долей = 1,000000; бюджеты акторов + доли совместных политий = сумме выходов регионов в raw.
6. **CI выравнивания** (п. 11) по t0 и всем датам таблицы событий; отрицательный тест: событие, режущее регион вне списка, валит сборку.
7. **Валидатор:** ≤ 4 контролёра на регион; `mixed` регионы имеют веса у всех провинций; `econ_shares` у каждой `joint`.
8. **Бюджет:** K4 на фактической карте; справочно 5000 синтетических провинций с событием каждый день; доля провинций по inclusive-профилю ≤ 100 мс.

## Research до ACCEPTED
- **R1. Замер слоя** в Lab-прототипе: 5000 провинций, 250 регионов, событие каждый день и раз в месяц — мс/мес на пересчёт атрибуции, CoW, хеш трёх таблиц.
- **R2. Изменение Kernel под несколько таблиц:** набросок API (`World`, `ChunkTable`, вектор версий) и проверка, что одна таблица даёт прежние байты хеша (`EXP-0002-det`).
- **R3. Список `mixed_regions`:** research-scientist по черновику карты 1.1 и ядру событий 1.6a — сколько регионов не выравнивается и есть ли у них источники весов (PD/CC0/CC BY).
- **R4. `econ_shares`** для Англо-Египетского Судана, Новых Гебрид, Танжера, центра Вены — есть ли источник для неравного раздела.

## Вопросы владельцу (критичные первыми)
1. **Смешанные регионы.** [Предл.] Границы регионов совпадают с границами событий (проверка в CI), кроме короткого списка (Берлин, Вена и немногие другие), где выход региона делится между контролёрами по весам провинций. Альтернативы: строгое совпадение без исключений (Берлин и Вена — по 4–5 регионов) или раздел по весам для всех провинций (большой объём оценок населения 1945).
2. **Кому идёт экономика.** [Предл.] Контролёру (де-факто): зоны Германии и Кореи — оккупантам, Тайвань — ROC. Альтернатива — владельцу (де-юре); тогда у DEU и KOR без правительства экономика ничья.
3. **Кондоминиумы.** [Предл.] Выход совместной политии делится между членами поровну, если у research-scientist нет источника на другой раздел. Согласны?
4. **Правило скорости.** [Предл.] При WARN максимальная скорость = 1 месяц за удвоенное p95 тика (ядру — половина стены, #269), но не медленнее 1 мес./3 с; доля провинций — до 100 мс, из них M1 [Предп.] < 5 мс, остальное — запас под войну и логистику M2.
