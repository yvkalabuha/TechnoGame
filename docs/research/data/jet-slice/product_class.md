**`eng_gen` (r5, G4-9)** — [Предл.] поколение двигателя, используется в `gen(d) = min(g_p, eng_gen(engine) + 1)` (#70); обязательное поле только у слота `engine` (у остальных слотов нет), `1 ≤ eng_gen ≤ G_max = 4`. Задано явно, не выводится из `rank`. Обоснование (одно на альтернативу):

Обоснование `af_mach2`:
- [Факт] Планеры класса M2 появились в 1954–59 гг.: XF-104 — первый полёт 04.03.1954; F-104 — первый истребитель США в строю, достигавший M2 (NASM). YF-105A — 22.10.1955, F-105D — 09.06.1959 (NMUSAF). F-4 — 27.05.1958 (P1 `product_inputs.md`). Ценовой и DAPCA-якорь G4 в данных — F-105D (2 240 км/ч, `product_inputs.md` §2, §7). Значит, G4-платформа данных — планер класса M2.
- [Факт] Планер F-105D стоит ×3,1 к планеру F-100D в $ 1950: 1 472 145·24,07/29,575 = 1,198 млн против 448 216·24,07/28,09 = 0,384 млн (Knaack через P1, CPI P2). Этим подтверждается большой множитель блока планера G4 (§14).
- `requires_nodes` = 29, 32: узел 29 уже требует (24 | 25) и 26 (`nodes.csv`), титан 32 — как у `af_titanium`. Кумулятивно (F-PC1).
- `prc_set` = как у `af_titanium`: отдельного PRC для конструкции M2 (химфрезерование, сотовые панели, горячая конструкция) в `nodes.csv` нет. Последствия — F-PC4.
- `perf_mult` 1,8 [Предп.]: шаг ×1,125 к титану. Это параметр, а не историческое отношение скоростей (F-105D / F-100D = 2 240 / 1 487 = 1,51 по скорости).
- Время: узел 29 и APP G4 (61) имеют один якорь (F-15, 1972), а APP G4 требует 29. Порог по `af_mach2` не задерживает G4 сверх уже существующего (риск окна C4 был и раньше).

## 3. Расхождения со спецификацией
- **F-PC1** — в §1.4 у альтернатив планера перечислены только «свои» PRC, а «+ титан» читается как добавка. Принято кумулятивное толкование (стреловидный планер тоже требует проката и обшивки). Решает simulation-engineer.
- **F-PC2** — правило «технологичного» варианта не задаёт ничью между слотами с равным tier. Предложен фиксированный порядок слотов.
- **F-PC3** — для G1 у каждой альтернативы нет более лёгкой, поэтому требование §1.4 «`prc_set` различаются всегда» невыполнимо. [Предл.] Для G1 разрешить совпадение вариантов (один проект) или считать «технологичным» тот же набор; решает simulation-engineer.
- **F-PC4 (средняя, r4)** — `af_mach2` и `af_titanium` имеют один `prc_set`. Освоив титановый планер, актор сразу производит планер M2 с тем же `yield`. Разница в цене (×3,4 блока планера) держится только на множителе `af_class`, а не на процессах. [Предл.] Добавить PRC tier 5 «конструкция M2» (например, `s8.prc.mach2_hot_structure`, якорь ≈ 1955–58) и пересчитать §14 `product_inputs.md`. Это меняет граф и `data_hash`, решает Orchestrator.
- **F-PC5 (высокая, r4)** — у всех рангов двигателя одни PRC (54, 44). Поэтому смена `eng_g(r)` на `eng_g(r+1)` при том же остальном составе не дороже по процессам, сплаву и часам. Она только поднимает `perf`, то есть слот двигателя не даёт компромисса (#82). До r4 (немонотонный `proc_scale_eng`) такая замена была даже **дешевле** (−96 raw на G1-наборе, −148 raw на G3-наборе). [Предл.] → simulation-engineer / game-designer: собственная стоимость альтернативы двигателя, например `n_p` PRC 54 или вес по массе двигателя (726 / 1 123 / 1 700 / 1 700 кг).

**Проверка r5 (`gen = min(g_p, eng_gen + 1)`):**

| g | `eng_gen` (оба варианта) | `g_p` | `gen` |
|---|---|---|---|
| G1 | 1 | 1 | min(1, 2) = **1** |
| G2 | 2 | 2 | min(2, 3) = **2** |
| G3 | 3 | 3 | min(3, 4) = **3** |
| G4 | 4 | 4 | min(4, 5) = **4** |

Технологичный вариант меняет только hot_section, двигатель тот же, поэтому все 8 эталонов дают ожидаемое `gen = g`. Смешанные случаи контракта (§4.4a): G3 `af_titanium` + `eng_g1` → min(3, 2) = 2; + `eng_g2` → min(3, 3) = 3; G2-платформа + `eng_g4` → min(2, 5) = 2. Все совпали. `g_p` по `rank(airframe)` 1/2/4/5 ≥ `platform_min_rank` 1/2/3/5 взято из контракта, здесь не пересчитывалось.
