## 3. Предложения для ADR (PROPOSED, оформить в PHASE D по шаблону ADR)

Объединено из RR-002 и RR-003; дубли убраны.

1. ADR-0001 — Стек: C# ядро + Godot позже (D1).
2. ADR-0002 — Уровни детерминизма (D2).
3. ADR-0003 — Численная политика: int64 fixed-point для денег, запасов, населения; f64 для поведенческих моделей; без FMA-сжатия и fast-math; свои sin/exp/ln. **Перед утверждением:** проверить поведение .NET JIT по FMA.
4. ADR-0004 — RNG без состояния: ключ (seed, tick, system, entity, n), SplitMix64 или Philox.
5. ADR-0005 — Модель данных ядра: таблицы struct-of-arrays, плотные целые ID внутри, стабильные строковые ID в данных и сохранениях. Без ECS-фреймворка.
6. ADR-0006 — Модель тика: 1 тик = 1 день, мультичастотные системы, фазы compute → merge → post; ввод только через команды.
7. ADR-0007 — Запрет коллекций с нестабильным порядком обхода в состоянии мира.
8. ADR-0008 — Simulation Lab: процесс на прогон, TOML-манифест, Parquet + DuckDB, анализ на Python; golden-hash и сравнение распределений.
9. ADR-0009 — Политика лицензий данных (D4).
10. ADR-0010 — Формат данных и моддинг v0: YAML или JSON + JSON Schema 2020-12; базовая игра = мод `core`; патчи по ID (define/override/patch/delete); громкие ошибки.
11. ADR-0011 — Представление карты: векторные полигоны → компилируемый граф провинций. Для M0 нужен только граф.

ADR по модели графа технологий (RR-003, «модель C») и инженерии — не архитектура, а game design. Переносятся в PHASE F как гипотезы.
