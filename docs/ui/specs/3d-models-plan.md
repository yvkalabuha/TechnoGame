# Трёхмерные модели в игре: план и пилот

Статус: [Предл.] для решения владельца (2026-11-25). Ничего не реализовано. Автор: ui-art-director.

## Краткий вывод
- [Предл.] Брать 3D как **инструмент производства иллюстраций**, а не как живую 3D-сцену. Лучшее соотношение пользы и риска: **(a) параметрический генератор самолёта из слотов дизайна, отрендеренный офлайн в 2D-чертёж/гравюру** (3 вида). Он честно показывает, чем одно поколение отличается от другого, детерминирован, весит килобайты и ложится в бумажный стиль «Фолио».
- Ранжирование: **(a)** генератор в 2D спрайты, затем **(b)** маркеры институтов/заводов/аэродромов на глобусе, затем **(d)** иллюстрации узлов, затем **(c)** живая вертушка в Godot (дороже всего, ценность наименьшая).
- Лицензии чистые: меши свои, процедурные, никаких чужих моделей (кроме CC0 при явном решении). ADR-0009 соблюдён; ADR-0026 (ИИ-картинки) к мешам не относится, Gemini даёт только референсы-концепты, в игру они не идут.
- Данные рисуются кодом (`.claude/rules/ui.md`). Спрайт самолёта = иллюстрация формы, а не прибор: подписи, числа, поколение рисует `Label`. Спрайт строго соответствует слотам (инженерная правда), поэтому он не «картинка для настроения», а читаемый признак.
- Пилот: 6 истребителей G1–G6 из слотов, стиль чертежа, 3 вида; ориентир 1–2 дня работы Claude через Blender MCP плюс приёмка. Решение «идти ли дальше» принимается после просмотра кадров.
- [Предп.] Производственные единицы целиком (корабли, танки) не берём: пока в линии только реактивные истребители (O-054).

## 1. Исходные данные [Факт: mods/core/product_classes.yaml]
Слоты дизайна истребителя: `engine` (eng_g1…eng_g6, eng_g6_adaptive; поколение 1–6), `compressor` (центробежный/осевой), `airframe` (af_straight, af_swept, af_milled, af_titanium, af_mach2, af_fbw, af_composite, af_lo_composite; класс af_class 1–6), `afterburner` (ab_none/ab_on). Число двигателей в слотах **не найдено** (только поколение): [Предп.] «один или два» задаёт игра/дизайнер; генератор принимает `engine_count` как параметр, но пилот делает 1 двигатель и один двухдвигательный вариант G5–G6 (вопрос game-designer в OPEN).
Что видно на виде: класс крыла (прямое, стреловидное, дельта/«талия» по правилу площадей, трапеция Mach 2, с утками для fbw), воздухозаборник (носовой круглый для G1–G2, боковой/подфюзеляжный G3–G4, прямоугольный с клином G5+), сопло (круглое, с форсажным раструбом, плоское/вектор тяги G6), фонарь, оперение (двухкилевое с G4), малозаметность (грани вместо кривых, af_lo_composite). Вес дизайна на вид не влияет.

## 2. Где 3D даёт ценность (по убыванию)
### (a) Генератор самолёта в чертёж/гравюру
- Игрок получает: в окне «Линия производства» (`levers-windows.md` §4) у модели есть силуэт-портрет; видно, что G3 стреловиднее G1, у G5 боковые воздухозаборники. Выбор слота сразу меняет рисунок (превью дизайна, когда дойдём до окна проекта). В карточках узлов «Фолио» (`design-pass-2-tree-science.md`, окно картинки #466) — вариант C: деталь узла показывается на чертеже самолёта (двигатель, крыло) вместо одинаковых код-схем.
- Конвейер: `tools/models3d/aircraft.py` (bpy, запускается `blender -b -P`; через Blender MCP — для интерактивной отладки) читает JSON параметров, строит меш из примитивов (лофт сечений фюзеляжа, профиль крыла, заборник, сопло), рендерит Freestyle-контуром (ортографика: вид сбоку, сверху, спереди; фон прозрачный, линия без заливки или с лёгкой штриховкой-тенью). Выход: PNG 3 вида (+ при желании SVG-контур через Freestyle SVG, [Предп.] требует аддон из поставки Blender, проверить). Godot импортирует PNG как `Texture2D`, никакого 3D в клиенте.
- Параметры из данных: скрипт `tools/models3d/params_from_yaml.py` читает `product_classes.yaml` и делает JSON на каждую комбинацию слотов; таблица «слот → геометрия» лежит в `tools/models3d/geometry_map.yaml` (правило: ничего не зашито в код скрипта).
- Стиль: бумажный «Фолио» (`UI_DESIGN_SYSTEM.md`): линия цвета чернил токена, без градиентов; толщина линии 2 px при 512 px по длинной стороне, тонкая штриховка в тени; раскраска только одним акцентом (поколение), не цветом как единственным носителем (A5). Подписи видов («Сбоку», «Сверху», «Спереди») — `Label` в шрифтах `UI_DESIGN_SYSTEM.md`.
- Бюджет: меш ≤ 20 тыс. треугольников (офлайн, в игру не идёт); PNG 3 вида по 512×256 ≈ 30–60 КБ каждый, на модель ≤ 200 КБ; полный каталог 8 рамок × 7 двигателей ≤ ~60 комбинаций реально нужных ≈ 12 МБ. [Предп.] Рендерим только достижимые комбинации.
- Лицензия: свой процедурный код и меши (авторские права проекта); в `ATTRIBUTION.md` — строка «процедурно, Blender (GPL, как инструмент; вывод не GPL)» [Предп., проверить формулировку у systems-architect].
- Кто: Claude пишет и запускает bpy-скрипты; Gemini — только референс «как выглядел Hawker Hunter сбоку» (концепт для сверки пропорций, не в игру, не копируем формы конкретных самолётов); ui-art-director — приёмка; developer — подключение PNG и тест на соответствие слотов; test-engineer — тест «одинаковые слоты → одинаковый хеш PNG».
- Риски: (1) сходство с реальными самолётами (форма Hunter/F-4); смягчение: обобщённые пропорции, без эмблем и номеров. (2) Фотореализм сам собой не появится: цель — чертёж, это дёшево. (3) Детерминизм рендера между версиями Blender: закрепить версию 5.3 и хеш при каждом ресете; результат — закоммиченные PNG, не рендер в рантайме.

### (b) Низкополигональные метки на глобусе (институт, завод, аэродром)
- Игрок получает: объекты читаются на карте и отличаются по типу без чтения подписи; видна стадия (стройка, действует).
- Конвейер: bpy-скрипт строит 3–4 типа × 2–3 стадии, экспорт glTF (.glb), Godot импортирует как `Mesh`; либо, надёжнее, офлайн-рендер в иконку-спрайт 64–128 px (изометрия 30°) и билборд на глобусе. [Предл.] Начинать со спрайта: глобус сейчас плоско-векторный (стиль «Атласа»), вставка 3D-меша ломает единый язык и критерии C5 (декор не мешает данным).
- Стиль: плоская заливка тремя тонами токенов + контур; никаких текстур.
- Бюджет: ≤ 500 треугольников на метку, ≤ 100 меток на экране, ≤ 2 МБ всего.
- Риски: плотность меток на экране (читаемость вблизи границ государств), мерцание на вращении; доступность: тип должен читаться и в сером (A5), значит форма силуэта разная.
- Лицензия: процедурно; CC0-наборы допустимы (Kenney и аналоги) только по отдельному решению и записи в ATTRIBUTION.

### (d) Иллюстрации узлов дерева
- Игрок получает книжность «Фолио» без одинаковых схем. Но данных об узле картинка не несёт, и по ADR-0026 этим занимаются ИИ-гравюры. 3D даёт: для ≈ 70+ узлов слайса [Предп.] ручная сборка слишком дорога; применимо только к узлам-машинам (двигатель, компрессор, крыло). Рекомендация: брать модели из (a) как «деталь самолёта» для узлов s8, остальные — вариант A (код-схема) или ИИ-гравюра.
- Бюджет и лицензия как в (a).

### (c) Живая вертушка в Godot
- Игрок получает: вращение и осмотр дизайна. Ценность мала при цене: `SubViewport`, свет, меш glTF до ≈ 20 тыс. треугольников на дизайн (~1 МБ на глубину), вращение должно уважать «Меньше движения» (A8) и иметь клавиатурный доступ (A6). Три статичных вида из (a) закрывают 90 % задачи. [Предл.] Откладываем после M-клиента; пересмотр после пилота.

## 3. Производственные единицы и «правда конструкции»
Сложность: у модели должны совпадать число и тип двигателей, форма крыла, форсаж. Решение в (a): геометрия — функция слотов, а не художественный выбор; таблица `geometry_map.yaml` проверяется тестом (каждый `id` слота имеет запись). Новые классы изделий (корабль, танк) — отдельные генераторы, не раньше решения game-designer.

## 4. Пилот (предложение)
- Что: 6 истребителей G1–G6 из слотов (G1: eng_g1 + af_straight, ab_none; G2: eng_g2 + af_swept; G3: eng_g3 + af_milled/дельта + ab_on; G4: eng_g4 + af_mach2; G5: eng_g5 + af_fbw/composite; G6: eng_g6 + af_lo_composite), 3 вида, стиль чертежа, фон прозрачный, подписи кодом.
- Приёмка (мои критерии):
  1. Отличимость: на кадре 1920×1080 при 100 % силуэты G1–G6 различимы за 2 с (проба «показать две и спросить»); в сером различимы (A5).
  2. Соответствие слотам: тест превращает слоты в параметры и сверяет с `geometry_map.yaml`; изменение слота меняет хеш PNG.
  3. Детерминизм: два запуска дают одинаковые PNG (хеш).
  4. Стиль: контур токена-чернил, нет градиентов; сверка с «Фолио» и «Атласом» по §12; толщина линии 2 px после масштабирования не пропадает на 100 %.
  5. Размер: ≤ 200 КБ на модель, всего ≤ 1,5 МБ; без лишних аллокаций в `_Draw()` (текстура кэшируется).
  6. Нет узнаваемой копии чужого самолёта, эмблем, текста в картинке.
  7. Мнение Gemini на кадрах (#450), расхождения записаны.
- Кадры: (1) окно «Линия производства» с G1–G6 в списке моделей, 1920×1080; (2) сетка 6×3 видов; (3) пара G2 против G5 рядом (читабельность разницы); (4) серый кадр; (5) карточка узла с врезкой двигателя (если делаем).
- Критерий «стоп»: если через 2 дня силуэты G3–G5 различимы хуже, чем простые 2D-силуэты, нарисованные кодом (`_Draw`, полилиния по параметрам), — остаёмся на 2D-коде: 3D не окупается.
- Сравнение подходов для важного экрана (§5 брифа): (1) офлайн 3D в чертёж; (2) вектор по параметрам прямо в Godot `_Draw` (без Blender, живой, меняется с данными, но плоский и без теней, нужно рисовать три вида вручную через код). Рекомендую (1), если пилот покажет выигрыш; (2) — запасной.

## 5. Открытые вопросы

- systems-architect: формулировка лицензии вывода Blender в ATTRIBUTION; место скриптов (`tools/models3d/`) и хранение отрендеренных PNG (в `mods/core/art/` или `client/`).
- Владелец: готов ли смотреть пилот G1–G6 до выбора между (a) и (b)? Платных сервисов не требуется.
