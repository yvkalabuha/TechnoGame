### 2.2 Канал кражи в единицах `CEff` (gate п. 1, 2, 11)
Сейчас: `num = c_money·(1 − KDiff·known)`. [Предл.] Станет: `num = c_money·(1 − max(KDiff·known, s_steal))`, `s_steal = min(s_max, σ·eff_ot)`, где `eff_ot` = `N·maturity(A)` сети вора на цель (RR-0017), `σ` — множитель канала (ранее `ε` ≈ 0,2–0,3 [Предп.]). Всё Fx6, `max` точный, порядок «слева направо, floor» не нарушается; знаменатель (`Kmix`, `Σw`) не меняется.
1. **Единицы.** `s_steal` — скидка с денежной стоимости узла, как `KDiff`. «Скорость кражи» в годах не вводится: годы получаются из `CEff`, значит прибавки к `m_dev` нет и двойного счёта нет.
2. **Когда есть эффект.** При `s_steal ≤ KDiff` `max` даёт старое значение: механика нулевая. [Предл.] Разведка нужна только там, где зрелая сеть даёт `s_steal > 0,5`; `s_max` ≈ 0,7 [Предп., Lab]. Тогда пол цены узла — `0,3·c_money`: остальное — своя работа и знаменатель. Свой потолок вне ±15 %, но не выше `s_max`.
3. **Условия** [RR-0017]: у вора есть все прямые предшественники; узел известен цели (`known` по цели, не только «где-то»; для канала нужен `known_target`, иначе красть нечего); вне `dir` — `leak` = 0,1 от `s_steal`; смена `dir` — раз в N мес., сброс 50 % `A`. Экспортный контроль (RR-0014) обходится.
4. **`max`, не сумма.** Диффузия (`KDiff`) и кража — один `max`. Лицензия (`LicenceShare`) — процесс в Industry, не узел знания, в `max` узла не входит. Лицензия и кража сходятся только для краденого know-how (FUTURE): там `max` по `yield`-бонусу.
5. **`s_cap` и `T_abs` убраны** (gate п. 11): потолок даёт `s_max`, затухания освоения нет — кража узла действует сразу, как диффузия. Вернуть их можно только после Lab-доказательства, что `σ·eff·s_max` не хватает.
6. **Нет мастерства:** `yield` нового процесса — по кривой своей культуры; `H`, оснастка не растут (#47, #104, #322).
7. Жертва знания не теряет. Её следствия — раздел 3 (сигнал контрразведки).
8. `why_not`: «стоимость узла снижена разведкой на X % (диффузия — 50 %)».
9. **Траектория (#460, gate п. 5).** Правило ИИ по умолчанию (приоритет целей, «красть» при отставании, `security` «обычная») входит в базовый прогон. Калибровка `v_base`/годов открытий (#457/#458) идёт с каналом кражи; исторические кражи в неё включены. Проверка устойчивости: сдвиг годов открытий при `σ` ∈ {0,5; 1; 1,5}·базовое ≤ `Y` (INST 6.3).

## 3. Контрразведка, раскрытие, дезинформация (по RR-0017 §2)
- **Контрразведка (gate п. 9):** `ci_eff = sat(ci_budget/GDP_t)` ∈ [0,1]. Рост чужой сети: `× (1 − k·ci_eff)`, `hazard`: `× (1 + g·ci_eff)`; при `ci_eff = 1` равновесный `N*` и скорость падают ≥ 50 %. Игроку нет отдельной ручки: `ci` — часть доли `security` (раздел 6). **Сигнал и польза жертве:** каждая пойманная сеть — событие в журнале («поймана сеть SUN, цель — реактивный сектор»); накопитель «следа» `trace[t→o]` растёт от чужой активности и даёт слова «следов нет / есть / много» (без числа); при «много» жертва получает право реакции (усилить, предупредить, подставить ложные данные). Польза защиты видна: «потеряно чужих сетей: N», число узлов у жертвы, по которым `s_steal` у вора упал. Без этого защита доминируема.
- **Раскрытие (ADR-0021, gate п. 6):** на годовом горизонте риск `P_year[o,t] = 1 − Π(1 − hazard_m)` ограничен: слово «высокий» ≤ 25 %/год (потолок `p_max` пересчитывается из него, `p_max` ≈ 0,02–0,03/мес вместо 0,15 [Предп.]). `hazard = clamp(a0·eff·(act_obs + act_steal + act_dis)·(1 + g·ci_eff), 0, p_max)`; наблюдение рискованно, безопасного режима нет. Игрок видит **накопитель следа** `trace[o,t]` и тенденцию словами («растёт / стабильно / падает»); бросок определяет только *дату* раскрытия внутри месяца-года, не «будет ли»: накопитель, превысив порог, делает раскрытие неизбежным в окне 1–12 мес. [Предл., проверить в Lab: не должно убирать RNG, 5 % мест решает случай]. Потери: `N ·= 0,25`, `A ·= 0,2` в merge D−1; (#261(4): частичная, но сильная).
- **Дезинформация (gate п. 7).** В UI режим называется **«ложные следы»** (не «дезинформация»); механика — порча источников наблюдения цели: `φ = min(1, dis·κ)`, `c = floor(φ·s + ½)` из `s = floor(S_max·N)` (`S_max` = 6). Если `s − c ≥ 2`, порченые отбрасываются, иначе `bias_eff = b·c/s`. **Видимый исход (обязателен для UI среза):** строка журнала «оценка <цель> разошлась с вашей: расхождение источников / ложная уверенность» и в карточке цели слово «данные цели искажены». Если исход нельзя показать в срезе — режим скрывается в UI (остаётся в Core, #364). Прямого эффекта на скорость нет.
- **Обращённые сети** (`mode = turned`, `taint`): `turned` — в v1 по #364, `p_detect_turn` = 0,05/мес, поток `intel.turn`; `taint` — FUTURE (RR-0017). Для игрока в срезе — только событие «обратить / разоблачить» у ИИ, без ручки.
- **Показ уверенности (gate п. 10, #68, #260, #261).** Одно представление: **диапазон** `[x(1−w), x(1+w)]`, `w = max(0,1; 1 − intel_conf)`; `intel_conf = conf·sens(node)`, `conf = 1 − (1−q)^s`, `q = maturity(A)`. Проценты #260 — это *производная от числа независимых источников* `s` (#261(2)), доступная в справке карточки («достоверность ≈ 70 %, 4 источника»), но не вместо диапазона и не как точный проценты мощи цели. Видимость слоя при `intel_conf ≥ 0,3` [Предп.]. STATE_WORDS согласуются (правка — game-designer вместе с кодом).
- Доминирующей стратегии быть не должно: T2 RR-0017 (кража у порога `hazard` теряет сеть с ожидаемой частотой).

## 8. Детерминизм и идентификаторы (gate п. 8)
- RNG только в `StochasticEventSystem`; потоки **регистрируются в реестре ADR-0021**: `intel.expose`, `intel.turn`, `intel.poach` (для вымышленных, FUTURE). Ключ: `(seed, day, stream, (o,t))`; `intel.poach` — `(o,t,person_id)`.
- День броска: `D(o,t) = stable_hash("intel", o, t) mod days_in_month(m)` — не «mod 30» (в феврале день 29–30 не существует), `stable_hash` — именованная функция Kernel с фиксированной раскладкой, не `GetHashCode`.
- Рост сетей, `steal` (`s_steal`), `ложные следы`, `maturity`, `conf`, `trace` — Fx6 без RNG, без `e^x`, `floor`/round-half-up.
- `o`, `t` — **стабильные `actor_id`**; порядок обхода `(o,t)` по возрастанию; узлы — по `node_id`; люди — `Personality.id` (INST §9). Раскол/поглощение — RR-0017 §2 (Apportion, T8).
- Новое состояние (`Net`, `trace`, `ci_budget`, седьмая доля) меняет формат сохранения и хэш: erratum goldens, один поезд (§5, ADR-0013). L1/L2: тесты T6 RR-0017.
