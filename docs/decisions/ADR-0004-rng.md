# ADR-0004 — Генератор случайных чисел без состояния

## Контекст
Общий генератор со состоянием ломает L2: порядок обращений зависит от потоков.

## Решение (предложение)
- Случайное число = hash(seed, tick, system_id, entity_id, n) — counter-based генератор (SplitMix64 как функция смешивания; Philox — если понадобится качество выше).
- `System.Random` в ядре запрещён.

## Уточнение полей ключа (2026-11-03, решение #60, gate-ревью)
- **`tick` — индекс срабатывания по частоте системы, которая делает выборку**, а не дневной тик ядра. Это номер срабатывания `Cadence` этой системы, считая от первого срабатывания на тике ≥ 0 (оно имеет индекс 0). Для месячной системы это индекс месяца `t`, для годовой — индекс года, для дневной — дневной тик `d`. Выборки фазы инициализации перед тиком 0 (ADR-0006) берут `tick = 0`.
- **`start_date` сценария выровнена по границе частоты**: для месячных систем — 1-е число месяца, для годовых — 1 января. Загрузчик сценария отклоняет невыровненную дату громкой ошибкой. Поэтому индекс 0 всегда означает «первый полный период».
- Индекс срабатывания система получает из календаря Kernel по дневному тику (чистая функция без состояния). Отображение `t ↔ d(t)` взаимно однозначно, поэтому ключ остаётся функцией времени и L1/L2 не страдают.
- **`entity_id` — стабильный id сущности из данных** (отдельная колонка, ADR-0005), **никогда не индекс строки**. Тогда выборка не зависит от порядка строк в таблице, а инвариант порядка строк ADR-0013 нужен только для порядка merge.
- Зачем так: значение месячной выборки не зависит от длины предыдущих месяцев и от правила дня срабатывания. Ключи совпадают с пре-регистрированными в HYP-0002 и в эталоне EXP-0002. Источник: `docs/simulation/slice-jet-aviation.md` v0.5 §2, §9.1.
- Потоки не пересекаются: у систем с разной частотой разные `system_id` («один поток — один смысл», срез §9.1).

## Последствия
Каждая система явно передаёт свой `system_id`, свой индекс срабатывания, стабильный id сущности и счётчик `n`.

## Проверка
- Unit-тесты на эталонные значения; тест L2.
- Тест: при двух разных выровненных `start_date` с тем же числом месяцев выборка месячной системы с ключом `tick = t` одинакова.
- Тест: перестановка строк таблицы при тех же стабильных id не меняет выборки.
- Тест: загрузка сценария с `start_date` не на границе частоты — громкая ошибка.
