# ADR-0018 — Localization: keys, locale files in mods, EN and RU

> После ACCEPTED текст не меняется. Изменение решения — новый ADR с `supersedes`.
>
> **Ревизия 2 (2026-11-17).** Учтены гейт (`docs/reviews/adr-0018-gate.md`: critic, advocate, DeepSeek) и решение владельца #297. Формат строк — Project Fluent (`.ftl`) вместо YAML ревизии 1. Ревизия 1 есть в истории git.

## Краткий вывод
[Предл.] Все видимые строки хранятся в Project Fluent: `mods/<mod>/locale/<lang>/*.ftl`, по #297. Каталоги загружает сборка `Singularity.Localization` (.NET 10) через библиотеку Linguini.Bundle (MIT OR Apache-2.0). Идентификаторы Fluent однозначно выводятся из id данных: `node-s8-eng-turbojet_g1` с атрибутами `.name`, `.short`, `.anchor`. Страны и регионы — термы с падежами и родом. Формы множественного числа — CLDR, встроенные в Linguini. Числа и даты форматируют собственные детерминированные функции `NUMBER` и `DATE`. Ядро текста не видит: `ModLoader` не читает `locale/`, а `StateHash`, сохранения и golden от языка не зависят. `anchor.event` переносится из данных Core в локализацию: `DataHash` меняется один раз, `golden_set_hash` EXP-0002-det остаётся прежним. Клиент Godot вызывает фасад `Loc`, `TranslationServer` не используется. В `dotnet test` проверяются полнота EN+RU, сироты, плейсхолдеры, формы множественного числа, бюджеты длины, покрытие глифами, устаревшие переводы и моды.

## Решение

### 1. Идентификаторы Fluent [Предл.]
- **Грамматика.** `<kind>-<seg>(-<seg>)*`. `kind` берётся из закрытого списка (ниже) и дефиса не содержит. `seg` — `[A-Za-z0-9_]+`. Поля сущности — атрибуты Fluent (`.name`) из закрытого списка вида. Сегменты ui и fmt задаются вручную по той же грамматике.
- **Отображение id данных.** Каждая `.` в id данных заменяется на `-`. Это биекция, потому что в id данных нет `-`. Загрузчик `Singularity.Localization` требует, чтобы каждый id, который выводится в ключ, подходил под `[A-Za-z][A-Za-z0-9_]*(\.[A-Za-z0-9_]+)*`; иначе громкая ошибка. [Предл.] В той же задаче добавить такую же проверку id узлов в `NodeTable` (Core).
- **Продукция без двусмысленности.** Id класса, слота и альтернативы не содержат ни `.`, ни `-`, поэтому позиции сегментов фиксированы: `pc-<class>`, `pc-<class>-slot-<slot>`, `pc-<class>-alt-<slot>-<alt>`. Ключ узла всегда начинается с `node-`, поэтому пересечься с `pc-` не может.

| Вид | Id | Сущность Fluent | Атрибуты (обяз. — **жирным**) |
|---|---|---|---|
| Узел знания | `node-<node_id>` | сообщение без значения | **`.name`**, **`.anchor`**, `.short`, `.desc` |
| Класс, слот, альтернатива | `pc-<class>`, `pc-<class>-slot-<slot>`, `pc-<class>-alt-<slot>-<alt>` | сообщение | **`.name`**, `.short`, `.desc` (только класс) |
| Сценарий | `scenario-<id>` | сообщение | **`.name`**, `.desc` |
| Актор (государство сценария) | `-actor-<id>` | **терм** | значение — имя; RU: селектор `$case` с вариантами `nom gen dat acc ins loc` и `*[nom]`, **`.gender`** (`masc fem neut plur`); `.short`, `.adj` |
| Страна мира (подпись карты), регион | `-country-<ADM0_A3>`, `-region-<id>` | **терм** | как у актора |
| Кластер, дисциплина, тип узла | `cluster-<name>`, `discipline-<name>`, `node_type-<name>` (имена из `DataNames`) | сообщение | **`.name`**, `.short` |
| Перечисление для показа | `enum-<enum_name>-<value_name>` | сообщение | значение; `.short`, если требует бюджет |
| Событие (когда появится) | `event-<id>` | сообщение | **`.title`**, **`.body`**, `.opt-<opt_id>` |
| Интерфейс | `ui-<screen>-<element>[-<role>]` | сообщение | значение; `.short`, `.tip` |
| Форматы, единицы, месяцы | `fmt-*`, `unit-<id>`, `date-month-<case>` | сообщение | значение |

- **Перечисления — по именам данных, не по C#.** `<enum_name>` и `<value_name>` берутся из стабильной таблицы имён: `DataNames` для данных; для перечислений Session (`Stage`, `Profile`, `BadLicence`, `LineCloseReason` и т. п.) — из тех же имён, что идут в протокол и журнал ADR-0014. Если такой таблицы нет, её заводят в той же задаче. Переименование члена C# ключ не меняет. Тест перебирает таблицу, а не `Enum.GetValues`.
- **Падеж и род (известный предел).** Падежи есть только у термов-сущностей, которые встают в предложения: акторы, страны, регионы. У узлов и продуктов падежей нет: шаблон строится вокруг именительного падежа («Освоено: { … }»). В предложение сущность передаётся как переменная типа `DataRef`, а не литералом. Для этого есть пользовательские функции: `NAME($actor, case: "ins")` форматирует терм `-actor-<id>`; `GENDER($actor)` возвращает `.gender` для селектора (как в RobustToolbox). Статическая ссылка `{ -actor-SUN(case: "gen") }` тоже допустима. В EN `$case` игнорируется, `.gender` = `neut`.
- **Пример (`mods/core/locale/ru/data.ftl`):**
  ```ftl
  node-s6-prc-centrifugal_impeller_machining =
      .name = Механообработка центробежных крыльчаток
      .short = Центр. крыльчатки
      .anchor = …
  -actor-SUN = { $case ->
     *[nom] СССР
      [gen] СССР
      [ins] СССР
     }
      .gender = masc
  ui-lever-licence_bought = { GENDER($buyer) ->
      [fem] { NAME($buyer) } купила лицензию
     *[masc] { NAME($buyer) } купил лицензию
     }
  ```

### 2. Файлы, моды, переопределение [Предл.]
- Путь `mods/<mod>/locale/<lang>/*.ftl`. `<lang>` — тег BCP 47 (`en`, `ru`, `pt-BR`). У `core`: `data.ftl`, `ui.ftl`, `fmt.ftl` на каждый язык. Внутри `locale/<lang>/` допустимы только `*.ftl` и `_sources.tsv` (§3.4); любой другой файл — ошибка. Файлы грузятся в ordinal-порядке имён.
- **Правило для `ModLoader` (явное).** Подкаталог `locale/` зарезервирован за локализацией. `ModLoader` и `Provenance.DataFiles` (Lab) читают и хешируют только файлы из `mod.yaml`, а в `locale/` не заходят. `mod.yaml` не меняется. Тест: удаление или правка `locale/` не меняет `DataHash`.
- **Конфликт модов — как в ADR-0010** (`ObjectStore`), отдельно для каждого языка и каждого id сообщения или терма.
  - Первое появление id — определение.
  - Позже мод может заменить сущность целиком (значение вместе со всеми атрибутами), только если транзитивно зависит от каждого мода, который уже менял этот id.
  - Внутри одного мода и языка id встречается один раз, в том числе по разным файлам.
  - Удаления нет.
  - Нарушение любого пункта — громкая ошибка загрузки.
  - Конфликты разрешаются на уровне AST до сборки бандла, поэтому поведение не зависит от того, как Linguini обрабатывает дубли.
  - Тесты: два независимых мода переопределяют один ключ → ошибка; зависимый мод → замена; дубль внутри мода → ошибка.
- Новый язык мод добавляет без правки данных (например `mods/lang_de/locale/de/`, зависимость `core`).
- Лицензии (ADR-0009): переводы, в том числе машинные, — собственная работа проекта; пометка ИИ не нужна (#297). Импортированные списки имён (Natural Earth, PD) записываются в `ATTRIBUTION.md`. Описания из CC BY-SA (Википедия) не копируются. Комментарии `#` к сущностям Fluent — заметки для переводчика; Weblate показывает их как описания.

### 3. Загрузка и проверки [Предл.]
Сборка `Singularity.Localization` (net10.0) ссылается на Core (`ModManifest`, порядок модов, `GameData`, `DataNames`) и на Linguini.Bundle. На неё не ссылаются Kernel, Core, Session и Lab. Для каждого языка строится свой `FrozenBundle`, `UseIsolating = false`: RTL вне рамок, а метки изоляции дали бы «тофу».

**3.1 Цепочка запасных и ошибки.** Выбранный язык → `en` → маркер `[[id]]` и одно предупреждение в лог на id. Глифы маркера проверяет §3.5. Громкие ошибки (`LocaleLoadException`):
- синтаксис Fluent;
- id вне грамматики §1;
- неизвестный атрибут для вида;
- конфликт модов (§2);
- `<lang>` каталога, который не разбирается как BCP 47.

**3.2 Проверки полноты.** Для `core` они в тесте; для сторонних модов в рантайме — предупреждения, кроме синтаксиса.
- **L1:** каждое видимое поле каждой сущности — все обязательные атрибуты из таблицы §1 для каждого объекта `GameData` и каждой записи таблиц имён перечислений — есть в EN и RU. Необязательный атрибут, заданный в одном базовом языке, обязателен и в другом. Фасад клиента принимает только поля из этой таблицы (типизированный `Field`), поэтому видимого поля вне L1 не бывает.
- **L2, сироты:** id `node-*`, `pc-*`, `actor-*` и т. п. без объекта в `GameData`. В тесте `core` это ошибка. В рантайме — предупреждение и пропуск: мод мог удалить узел (ADR-0010).
- **L3:** набор переменных `$x` и функций одинаков во всех языках сущности; селекторы могут различаться.
- **L4, множественное число:** для каждой переменной, по которой RU выбирает форму числа (`[one] [few] [many]`), есть вариант по умолчанию `*[other]`; ключ категории существует для языка (CLDR через Linguini). Это проверяется на числах 0–200 и на дробях: ни одна строка не падает и не уходит в `[[…]]`.
- **L5, ссылки из клиента:**
  - литеральные id в вызовах фасада `Loc.T("…")`, `Loc.A("…", "…")`, `Loc.Name(…)` (regex по именам методов фасада, сверенный с его исходником) существуют;
  - в `*.tscn` и `*.tres` клиента нет непустых `text =`, `tooltip_text =`, `placeholder_text =`;
  - динамические id строятся только типизированными помощниками (`Keys.Node(id)`, `Keys.Enum(table, value)`).
- **L6, бюджеты длины.** Роль строки задаёт суффикс `-<role>` в `ui-*` (`-btn` 24, `-btn_cost` 18, `-tab` 16, `-sheet_title` 40, `-inset_title` 28/40, `-stamp` 20, `-signal` 12, `-tag` 24, `-scale` 14, `-menu` 40). У данных роль задаёт атрибут: `.short` = 12, место сигнального поля. Слова-состояния `enum-state_word-*`: RU ≤ 16, EN ≤ 18 (§13.1 п. 8, без +30%).
  - Правило §13.2: `ceil(1,3 · max(len_en, len_ru)) ≤ бюджет`; иначе нужен `.short`, который проходит то же правило.
  - Длина считается в графемах (`StringInfo.LengthInTextElements`) и берётся максимальной по всем вариантам селекторов.
  - Подстановка: `NAME(...)` — по фактическому максимуму `.short` или имени этого вида в данных; `NUMBER` — 8.
  - Таблица ролей — код теста со ссылкой на §13.2; тест сверяет, что все строки §13.2 в ней есть.
  - Графемы — грубый фильтр, это не пиксели. Пиксели проверяют скриншоты RU, EN и `xx` при 100% и 125% (§13.3, test-engineer).

**3.3 Числа и даты.** Пользовательские функции, детерминированные и без `CultureInfo`. [Предп.] Данные ICU различаются по ОС, это ломает сравнение скриншотов. Подключаются через `AddFunctionOverriding`.
- `NUMBER($x, minimumFractionDigits, maximumFractionDigits, useGrouping, style: "decimal" | "percent", notation: "standard" | "compact")`.
  - Разделители и знаки — сообщения локали: `fmt-number-decimal` (RU `,`, EN `.`), `fmt-number-group` (RU U+00A0, EN `,`), `fmt-number-minus` (U+2212 в обоих).
  - Процент: `fmt-percent` (RU `{ $n } %` с U+00A0, EN `{ $n }%`) [Предл.: RU-норму подтверждает research-scientist].
  - Компактная запись: `fmt-compact-thousand / -million / -billion` (RU «12,5 тыс.», «3,1 млн», «2 млрд»; EN «12.5K», «3.1M», «2B»).
  - Результат сохраняет операнды отформатированного числа (`v`, `f`), поэтому форма выбирается по видимому числу: «1,0» → `other`.
- `DATE($date, format: "dmy" | "my" | "y")`. Даты только игровые: год, месяц, день (ADR-0006). Месяцы с падежами — сообщения Fluent с селектором `$month`: `date-month-nom`, `date-month-gen`. Например, `fmt-date-dmy = { $day } { date-month-gen } { $year }` [Предп.: ссылка на сообщение видит аргументы вызывающего — проверка S1(б)].
- Числа и даты в строки попадают только через `NUMBER` / `DATE`. Голая числовая переменная форматируется через `FormatterFunc` тем же форматтером.

**3.4 Устаревшие переводы (#297).** Исходный язык — `en`: смысл сначала правится в EN. Рядом с каждым неисходным языком лежит `locale/<lang>/_sources.tsv`, строки вида `<id>\t<hash>`. `hash` — первые 16 hex от SHA-256 исходной EN-сущности: текст без комментариев, хвостовые пробелы убраны, переводы строк LF.
- Перевод устарел, если хеш не совпадает или строки нет.
- Для RU в `core` это ошибка теста; для остальных языков — предупреждение.
- Отметку ставит команда `l10n stamp <lang> [id…]` после проверки перевода, человеком или агентом. Пометки ИИ нет.
- Формат-сайдкар выбран потому, что Pontoon и Weblate комментарии в `.ftl` переписывают, а `_sources.tsv` не трогают [Предп.].

**3.5 Покрытие глифами.** Тест читает таблицы `cmap` (формат 4/12) у TTF из #294 — Golos Text, PT Mono, Jura, Literata (`src/Singularity.Client.Spike/assets/fonts/`) — собственным мини-парсером без зависимостей.
- Все символы всех вариантов всех строк EN, RU и `xx` должны быть в Golos Text и Jura (интерфейс, заголовки и кнопки).
- Строки `fmt-*`, цифры и знаки `NUMBER`/`DATE` — в PT Mono.
- `-country-*`, `-region-*`, `-actor-*` — в Literata (подписи карты).
- Маркер `[[…]]`, U+00A0, U+2212, скобки и диакритика псевдолокали — во всех четырёх шрифтах.
- Если символа нет, меняется строка или знак псевдолокали, а не шрифт.

**3.6 Псевдолокаль `xx`.** Строится из AST более длинной версии (EN или RU): к тексту +30%, скобки `⟦…⟧` (если §3.5 их не пропустит — `[!…!]`), диакритика. Переменные, функции и селекторы не трогаются. В клиенте это обычный язык `xx` в переключателе; встроенная псевдолокализация Godot не используется.

### 4. Ядро не видит текста [Предл.]
- `GameData` не содержит текста для показа. `anchor.event` удаляется из `nodes.yaml` и `NodeTable` (`AnchorEvent`). Поле становится неизвестным, и строгий загрузчик выдаёт ошибку, если оно встретится. Текст переходит в `node-<id>.anchor` (RU — текущий текст, EN — перевод). `anchor.source` (id источника `S32`) остаётся.
- `DataHash` меняется **один раз**, в коммите миграции.
  - Замороженные манифесты и записи EXP не правятся.
  - Пару old→new `DataHash` записывает в DECISIONS_LOG Orchestrator.
  - Коммит миграции прогоняет EXP-0002-det и показывает, что `golden_set_hash` не изменился: динамика та же.
- Код, который читает `AnchorEvent`, переносится в том же коммите:
  - сверка `CoreNodesTests.cs:55` (`row["anchor_event"]`) переходит в `Singularity.Localization.Tests` (RU `.anchor` = `anchor_event` из CSV TASK-0011);
  - `TechTree.cs` берёт текст через `Loc.A(Keys.Node(id), Field.Anchor)`;
  - Lab `SynthWorld.cs:380` перестаёт писать `event:`, `SynthChecks.cs:72` перестаёт его сравнивать.
- `StateHash`, сохранения (ADR-0013), replay и golden от языка и от `locale/` не зависят. Session (ADR-0014) отдаёт id и коды. Исход команды для игрока — `enum-<reason_table>-<code>`; `Message` — английская диагностика для логов и harness. Lab, ошибки загрузчиков и логи — только на английском.

### 5. Клиент Godot [Предл.]
- Фасад `Loc`: `T(id, args)`, `A(id, field, args)`, `Name(DataRef, field, case)`, `Number`, `Date`, `SetLanguage(lang)` с событием `LanguageChanged`. Внутри — бандлы `Singularity.Localization`, которые загружаются с диска при запуске; моды работают без импорта Godot.
- `TranslationServer` и `auto_translate` не используются (`auto_translate_mode = disabled` у корня). Текст ставит только код через `Loc`. L5 проверяет, что сцены текста не содержат. Подписи карты при смене языка пересчитываются (§13.3).
- **Миграция CSV TASK-0070** (отдельная задача после ACCEPTED). Скрипт-конвертер переводит `ui.csv` и `data.csv` в `mods/core/locale/{en,ru}/{ui,data}.ftl`:
  - `ui.tree` → `ui-tree`; `status.*` → `ui-status-*`; `actor.USA` → `-actor-USA`; `node.<короткий id>` → `node-<полный id>.name`; `country.<имя NE>` → `-country-<ADM0_A3>`;
  - позиционные `{0}` вручную становятся именованными `{ $x }`, склейки — шаблонами (`ui-simerror = Simulation error: { $message }`);
  - удаляются `locale/*.csv`, загрузчик CSV в `Loc.cs`, вызовы `TranslationServer`, строки CSV в `LICENSES.md` и README;
  - `Names.RuOfActor`, `Stage`, `Profile`, `Short()` заменяются ключами.
- **`Names.CountryOfActor`:** ключ — код ADM0_A3, а не имя NE. Полигон, принадлежащий актору, подписывается термом актора. Так SUN в 1945 году — «СССР» / «USSR», а не «Россия». `-country-*` подписывают только полигоны без актора. Исторические границы — ADR-0011.

## Рассмотренные альтернативы
- **YAML-каталоги (ревизия 1).** Свой формат и своя библиотека, падежи и род пришлось бы изобретать заново. Отклонено владельцем (#297).
- **gettext `.po`.** Хорошая поддержка в инструментах, но падежей и рода в выражениях нет, а `msgid`-как-ключ плохо сочетается с выводом из id. Отклонено (#297).
- **CSV + `TranslationServer` (TASK-0070).** Нет форм множественного числа и падежей; импорт Godot работает только в редакторе, моды им не загрузить. Отклонено, мигрируется (§5).
- **Godot `TranslationServer` как рантайм поверх Fluent.** Второй путь к строкам и `auto_translate` в обход проверок L5. Отклонено.
- **Имена прямо в YAML данных.** Текст попадает в `GameData` и `DataHash`, новый язык требует `patch` каждого объекта. Отклонено.
- **ICU MessageFormat** (например, через ICU4N или ICU рядом с приложением). Падежи выражаются хуже, форматы ICU зависят от версии данных. Отложено: если понадобятся правила CLDR вне Linguini, это путь через новый ADR.
- **Свой парсер подмножества Fluent.** Меньше зависимостей, но это повтор зрелой библиотеки. Отклонено; остаётся запасным планом, если Linguini перестанут сопровождать (см. «Проверка библиотеки и инструментов»).
- **Форматирование чисел через `CultureInfo`.** Вывод зависит от ICU на ОС [Предп.]. Отклонено.

## Последствия
- Плюсы:
  - падежи, род и формы множественного числа выражаются в самом языке строк;
  - один источник для данных, UI и модов; новый язык — отдельный мод;
  - хеши и ядро от языка не зависят;
  - формат открывают Pontoon и Weblate.
- Минусы:
  - зависимость от библиотеки одного автора: версия закреплена, всё за фасадом, исходники можно взять себе;
  - одно изменение `DataHash`;
  - на сущности падежи только у термов; узлы — известный предел;
  - сайдкар `_sources.tsv` нужно поддерживать командой `stamp`.
- Обязательно:
  - в коде и сценах клиента нет видимых литералов;
  - каждый новый вид данных, перечисление для показа и экран приносят EN и RU в DoD;
  - смена бюджета §13.2 правит таблицу ролей в том же коммите.
- Вне рамок: RTL; падежи узлов и продуктов; имена, меняющиеся со временем (СССР → Россия по событию), — отдельный ADR вместе с картой.
