**Закономерности (общие для случаев, [Предп.] кроме двух датированных выше):**
1. Передаётся **набор для воспроизведения** (чертежи, оснастка, специалисты, комплекты), а не способность: качество и выход зависят от страны-покупателя (FRA/SWE свои двигатели начали серийно строить после 1952).
2. Лицензию покупают на **ту часть**, где отставание максимально: двигатель (FRA/SWE), планер — свой или тоже по лицензии (Mistral).
3. Первая серия — после 2,5–5 лет; ступени «комплекты → местные узлы» растягивают путь, но дают выпуск раньше.
4. Деньги — взнос плюс платеж за единицу (роялти); поэтому бедный покупатель мог войти в лицензию.

## 2. Что есть в модели сейчас и чего не хватает
[Факт, спека A43, контракт §3.1, §4.1, §4.2]
- Лицензия A43: данные `lic_gen/lic_seller/lic_mask/lic_start`; даёт `LicenceShare` = 0,5 на известные PRC маски → `X½·(1−l_lic)` и `ṽ = 2v` в культуре; знания не даёт (#47); проекта продавца не передаёт.
- Допуск: `admitted = ∀p: yield_p > 0 ∧ p ∈ known_processes(owner)`. `fielded` — только выпуск на **своём** `site` + `mastered` для всех PRC (#62, #70).
- Проект покупателя возможен только через `compose_design(requirement_id, …)`, то есть при известном APP (узел 58 для G1).

**Три разрыва**, которые должна закрыть механика: знание (нет `Requirement`/PRC), деньги (цена > бюджета SWE), культура (`v = 0` → канал #104 равен нулю).

## 3. Общие правила для всех вариантов
[Предл.; числа — параметры «З» (не калибруются), объявлены до прогона]
- **Снимок состава.** При покупке в колонки политики покупателя пишется **снимок** состава проекта продавца: `lic_alts[5]` (по слотам), `lic_gen`; ссылки на проект продавца нет (A43.1: слот может быть переиспользован).
- **Цена — две части** (как исторически): взнос `fee_up = 0,35·lic_price` (E1, G1: 7 256 raw ≈ 0,0073, SWE способен: `ProcurementBase` 0,0096) + роялти `ρ = 0,10·unit_cost_floor` за каждую **собственную** единицу, выпущенную покупателем по лицензии (платится ежемесячно по выпуску t−1 через `LicenceFlow`; предел `≤ 0,2·ProcurementBase`, остаток переносится). `Σ_a LicenceFlow = 0` (L-M1) сохраняется. Деньги идут по A42: `u`, `sale_cap`, `LineRate` считают от `ProcurementBase`, роялти их не искажает.
- **Знание «на производство».** Для PRC маски лицензии, не известных покупателю, `known_processes` засчитывает их **только для допуска и выпуска по лицензии** (не добавляет узлы в граф исследований, не открывает проектов на их основе). Это точное отличие от «передачи знания» RR-0015/#47 и требует решения владельца (раздел 8, В1).
- **Поколение и срок.** Лицензия на `gen(d_s) ≤ g_b + 1`; при большем отставании `yield` = 0 по правилу #26. Срок A43.4 (#152) действует **на канал культуры**: когда у покупателя своя серия более позднего поколения двигателя, `LicenceShare` = 0. **Уже идущая лицензионная линия не закрывается**, роялти продолжается (исторически выпуск шёл десятилетиями).
- **Нет свободного обеда.** Лицензия не даёт: узлов, `Requirement`, культуры, оснастки, сплава (материалы — по `alloy_kg`/снабжению покупателя), КБ-опыта в полном объёме. Покупатель платит и взносом, и роялти; выход считается по его же `H`, `M`.
- **Видимость для игрока** (STATE_WORDS): «Лицензия получена», «Сборка из комплектов», «Местные узлы: 3 из 5», «Полностью свой выпуск»; в `why_not` — новое звено «замена импорта по слоту X» (рычаг `localize`), причина при недопуске — по F25.

## 4. Варианты механики

### LP-1. Проект-лицензия (простейший)
- **Состояние.** К A43.1 добавляется `lic_alts[5]` и флаг «проект-лицензия получен». Новая колонка проекта: `licensed = true` (в `design` §3.1) — для печати и `fielded`.
- **Команда** `start_licensed(slot)` (после `take_licence`, с t+1): создаёт **собственный** проект покупателя `d_L` с составом из снимка; стадия «О» сразу (чертежи и доведённые дефекты переданы): работа `W_L = 0,25·W`, скрытые дефекты `D_hidden = 0,3·D0`, КБ покупателя занято на `W_L` (опыт `bureau_exp` не начисляется). Далее — обычные `start_series` (A41, F17) и своя линия на своём `site`.
- **Допуск/выход/культура.** Как для любого проекта: все PRC проекта должны иметь `yield > 0` по **культуре покупателя**. Лицензия работает через #104/#107 лишь после первого выпуска.
- **Деньги.** Раздел 3. **Эффект на `fielded`/`tech_lead`:** считается как собственный выпуск (≥ `n_service_min` на своём `site` + `mastered`). Ключ `K` равен ключу продавца (одинаковые `G`, `P`): ничья не меняет держателя лидерства (контракт §9.1), поэтому асимметрия #24 не ломается; `G_front` не растёт.
- **Ловушка культуры.** **Не ломает честно** (раздел 5): FRA стартует с `yield(54)` ≈ 0,0003 и выпуском ≈ 0.
- **ИИ.** P1 — никогда (A43.3); P2 — покупает первое предложение, `start_licensed` сразу, `start_series` как только допуск; P3 — покупает по звену `why_not` (A43.7), запускает серию, когда `yield_if_fixed ≥ 0,2` (иначе ждёт, F17).
- **Детерминизм.** Выборок нет, кроме `EVT_LIC`; `design_id` по порядку команд; `max_designs` исчерпан → отказ `BAD_LIC` **до** списания взноса.
- **Сложность** низкая: 1 команда, 1 колонка проекта, 4 колонки политики.

### LP-2. Ступени «комплекты → местные узлы» (рекомендуется)
- **Состояние.** К LP-1 добавляется `local_mask` проекта `d_L` (бит на слот, 5 бит). Слот с `local = 0` — **импортный комплект**: PRC этого слота в `prc_set_eff(d_L)` не входят.
- **Старт.** По умолчанию локальны слоты с минимальным `max r_d` PRC (сборка планера и систем); `engine`/`hot_section` — импорт (`local_mask` задаётся при `start_licensed`: исторически Mistral начинался со сборки комплектов).
- **Команды.** `localize(d_L, slot)` — перевести слот в местные: допустима, если для PRC слота `yield ≥ y_min = 0,15` и они известны (по маске). Разовая плата оснастки `loc_fee = 0,1·lic_price` из бюджета; `ToolingInvest` обычный. `import_back(d_L, slot)` — вернуться к комплектам (если `yield` упал; убирает зомби-линию).
- **Выпуск комплектов.** Импортная часть единицы закупается «у мира» по `kit_price = 1,3·unit_cost_floor(слот)` через внешний поток (`ext_total`, как продажи `sale_income` наоборот); продавец получает только взнос и роялти — его линия и `u` не затрагиваются (**не вводим** перераспределение когорт между акторами: ограничение сложности, сравни F27).
- **Допуск/выход/культура.** `admitted` и `unit_cost_mult` считаются по `prc_set_eff`. У местных слотов PRC с малыми `r_d` (сборка) `yield` > 0 даже при `H` ≈ 3,0–3,25, значит, `v_p > 0` → `maint` держит `H` на `max(r_d·a_r, H_floor)` и не даёт упасть ниже `req_54 − 1`. Рост выше `r_d + 0,25` (потолок `gap_p`) даёт только выпуск PRC с большим `r_d` — то есть **локализация двигателя** (PRC 54, `r_qc` = 4,0). Канал #104/#107 (`ṽ = 2v`, `X½` ×0,5) усиливает именно этот рост. Свободного скачка нет: пока `H < 3,5`, `yield(54) < 0,25` и цена слота ×4+.
- **Эффект на `fielded`/`tech_lead`.** Единицы с импортным `engine` в `fielded` **не входят** (нет `mastered` для PRC 54, #62: двигатель должен быть освоен страной). Они идут в отдельную метрику `licensed_units` (объём, без ориентира, как #27). `fielded` > 0 появляется после `localize(engine)`. Так «выпуск комплектов» не превращается в «технологическое лидерство».
- **ИИ.** P2: `localize` слота, как только `yield ≥ y_min`, по порядку «дешёвый → дорогой»; P3: когда `local_cost ≤ 1,5·kit_price` (экономика); P1 — нет. Все — по снимку месяца t, команда с t+1.
- **Детерминизм.** `local_mask` — колонка проекта; `kit_price`, `loc_fee` — `Fx6` floor на каждом `·`; порядок слотов — по индексу.
- **Сложность** средняя: +2 команды, +`local_mask`, `prc_set_eff` в `production_profile`, внешний поток комплектов.

### LP-3. Лицензия только на узел двигателя
- **Состояние.** Маска лицензии применяется к альтернативам слотов `engine`/`hot_section`: они становятся **доступными** (`avail`) покупателю без `requires_nodes` (знание на производство, как в разделе 3) для **его собственного** `compose_design`.
- **Результат.** Покупатель собирает свой проект со своим планером (Ouragan на Nene, Saab 29 на Ghost) — историческая схема. Но `compose_design` требует `Requirement` (узел 58): FRA получает его мес. 248–337, SWE — никогда (0/20). Без решения темпа знания (T12) LP-3 **для G1 бесполезна**.
- **Культура/деньги/`fielded`.** Как LP-1, но свой планер → полноценная производная в `fielded` с собственным `P`, возможна смена лидера (риск для #24 больше, чем у LP-1).
- **Использование.** Расширение для G2+ после T12: меняет «страна строит чужое» на «свой проект на чужом двигателе» (разнообразие исходов).

## 5. Расчёт на бумаге: ломает ли каждый вариант ловушку
[Факт: параметры A43.8 и `fra-swe-zero-diagnosis.md`: FRA `H` 3,04 → дрейф до 2,904; `yield(54)` на t0 = 0,00034; SWE `qc` 3,37, `g_qc` ≈ 0,137.] Расчёт — [Предп.], точный прогон — Lab.
- **FRA, LP-1.** Серия стартует рано (допуск есть: `yield` > 0 при `H` 3,04), цена единицы ≈ ×3 000 → выпуск ≈ 0,007 шт./мес. `x_V ≈ 0`, `c_p` ≈ 0, `m_p` ≈ 0 → дрейф `H` продолжается, мес. ≈ 116 `yield(54)` = 0. Любой дробный выпуск обнуляет счётчик A40: линия не снимается, `fielded` < `n_service_min`. **Результат: не пробивает** (E-FRA сохраняется).
- **FRA, LP-2.** Местные слоты (сборка) имеют `yield` порядка 0,5+ при `H` 3,04 (`r_d` ≈ 3,0, [Предп.]: значения PRC планера — из данных, не просматривались). Выпуск комплектов — единицы в месяц → `x_V` заметно > 0, `maint` ≈ 3,0–3,25 → `H` выше 3,0 держится; `gap_54` = 4,0 + 0,25 − H ≈ 1: рост идёт от выпуска PRC 54 после `localize(engine)` при `yield ≥ 0,15` (то есть `H ≥ 3,39`). **Узкое место:** путь `H` от 3,25 до 3,39 идёт только от сборочных PRC (потолок `r_d + 0,25`) — если у планерных PRC `r_qc` ≤ 3,0, потолок 3,25 недостаточен → тупик на уровне комплектов. Это не ошибка расчёта, а честный исход: рычаг — `quality_programme` (поднимает `α_eff`) и `r_d` PRC планера. **Проверка в Lab до прогона: потолок `r_d + 0,25` по PRC планера FRA ≥ 3,39?** Если нет — LP-2 для FRA даёт комплекты, а не `fielded` (исход «страна собирает, но не строит»; исторически близко к Mistral на комплектах).
- **SWE, LP-1/2.** `H` не в ловушке; нужны деньги (взнос 0,0073 ≤ 0,0096) и знание на производство. `yield` ≈ 0,137 (двигатель) → цена ×7. Выпуск ≈ 1 шт./мес. на старте → до `n_service_min` = 50 — 4–5 лет после серии.
- **LP-3.** Не меняет ничего без узла 58.

## 8. Риски и вопросы владельцу
1. **В1. Знание на производство vs #47.** #47 — диагностика «лицензия передаёт знание» вне main. Решение владельца нужно: допускаем ли знание **только на выпуск** по маске лицензии (рекомендация) либо лицензия ничего не знает и тогда варианты невозможны для SWE (узел 17).
2. **В2. Выпуск комплектов в `fielded`?** Рекомендация: нет, до локализации двигателя (#62). Альтернатива: считать `fielded` по планеру — даёт FRA/SWE якоря, но размывает #62/#70.
3. **В3. SUN (#127).** Знание на производство не должно открывать SUN горячую часть (никель кованый): допуск требует `alloy_kg` покупателя и `H`. Если Lab покажет сдвиг SUN вперёд > 12 мес. — механика сужается маской без PRC 49 или откладывается.
4. **Риск «спредшит»:** 5 слотов × `localize` × 3 профиля — игроку нужна одна строка состояния и одно звено `why_not`, не таблица.
5. **Риск зомби-линий** (выпуск ≈ 0, но сбрасывает A40): `import_back` и печать зомби; A40 не менять без решения.
6. **Вне объёма:** покупка лицензии игроком (спека: нет), санкции и отказ продавца, обратные лицензии, шпионаж.
