### 1.1 Кандидаты [Предл.]
Общее для обоих: `spill`, `H_floor`, `sat`, `α_eff`, `ΔH⁺`, `ΔH⁻`, `H'` — по контракту §4.1. `drive`, `catch`, `maint` — максимумы, как у R1 (`culture-rule-selection.md` §1.1). Арифметика — `Fx6` по §4.0: floor на каждом `·` и `/`, слева направо, процессы по возрастанию `prc_id`, `max` и `min` точны, деления на ноль нет (ветка `= 0`).
```
ΔH⁺ = sat · ( ((α_eff · act[c]) · w[c]) · drive + k_catch · catch + σ · spill )
ΔH⁻ = δ_H · max(0, H − max(maint, H_floor))
H'  = H + min(ΔH⁺, ρ_max) − ΔH⁻
```

#### 1.1.1 C-A: R1c с исправлением измерения
Правило — ровно §8.1 `culture-rule-selection.md`: `u_p = (x·x)·(3 − 2·x)`, `x = min(1, v_p/(r_full·labour_p))`; `drive = max_p u_p·gap_p`; `catch = max_{p: world_lead} u_p·gap_p`; `maint_p` по G-5, `u_m` = 0,5; `r_full = r_ref/4` = 6,25. Параметры не двигаются. Лицензия у C-A на культуру не действует, как в контракте: она меняет только `X½·(1 − l_lic)`, то есть `ramp`, а не `g_H`. Отличие от hold-out — только поправка измерения F-1 (§1.5). Она применяется **к обоим** кандидатам.

#### 1.1.2 C-B: культура от усилия (M1 + M3′, поддержание от выпуска)
Входы ячейки `(site, c, d)` из снимка t−1: `v_p = proc_v[site,p]`, `E_p = proc_E[site,p]` (деньги доводки, индекс бюджета в месяц, `PROCESS_DEVELOPMENT.md` §2.1), `lic_p = licensed(owner, p)` ∈ {0, 1}, `world_lead(p, owner)`. Учитываются процессы кластера c с `v_p > 0` или `E_p > 0` и с активным измерением d.
```
v_cap(p)  = r_cap  · labour_p          # потолок «материала для экспериментов», шт. процесса/мес. × труд (единицы §7.5)
v_keep(p) = r_keep · labour_p          # выпуск, при котором поддержание полное
x_V   = (v_cap = 0) ? 0 : min(1, ((1 + k_tr·lic_p) · v_p) / v_cap)
c_p   = LIN:    x_V
        SMOOTH: (x_V · x_V) · (3 − 2·x_V)
U_p   = E_full · c_p                   # = E_useful(site,p) до поправки на «нечего доводить» (§1.2)
x_E   = min(1, E_p / E_full)
e_V   = min(x_E, c_p)                  # M1: min(E, E_useful)/E_full
e_L   = (ℓ = 0) ? 0 : min(x_E, ℓ)       # M3′: лабораторная часть
gap_p  = max(0, r_d + 0.25 − H)
gapL_p = max(0, (r_d − ΔL) − H)        # лабораторный потолок r_d − ΔL
t_p   = max(e_V · gap_p, e_L · gapL_p)
m_p   = (v_keep = 0) ? 0 : min(1, v_p / v_keep)
maint_p = H_floor + (max(r_d·a_r, H_floor) − H_floor) · m_p
drive = max_p t_p;   catch = max_{p: world_lead(p,owner)} t_p;   maint = max(H_floor, max_p maint_p)   # пусто → 0 / 0 / H_floor
```
Почему такая форма (все пункты — [Предл.], опора в источниках указана):
1. **M1, а не M2.** Квота опытных партий — это доля производственного потока [E4]. Излом `min` даёт одну точку `E_useful`, которую можно показать игроку и в которую ИИ «наливает» деньги (`PROCESS_DEVELOPMENT.md` §2.3). У M2 две степени свободы и нет естественной точки «сверх этого — впустую». M3 без потолка источники не поддерживают (`culture-effort-evidence.md` §4.2).
2. **Две формы потолка `c`, обе в сетке.** LIN — буквальный M1: опытных партий ∝ выпуску. SMOOTH — мощность эксперимента по размеру выборки имеет S-образную форму: при малой выборке улучшение почти не отличить от шума [Предп. по E7, E4: вероятность пропустить улучшение на 3% > 20%, S/N растёт с выборкой]. [Факт, `culture-rule-selection.md` §3 п.4] При полном усилии LIN совпадает по `drive` с линейным R1 при `r_full = r_cap`. У того K2b и K4c не выполнялись одновременно (`r_full` 10 — ровно граница). LIN оставлен как контроль M1, а не как фаворит.
3. **Поддержание — только от выпуска**, линейное, со своим порогом `r_keep`. Документы и штат знание не держат: FOGBANK, Astute (`culture-effort-evidence.md` §3). Поэтому `E` в `maint` не входит. Порог отдельный от `r_cap`, чтобы обрыв поддержания (§7.6 и §9.2 hold-out: `u_m` вместе со smoothstep) не был привязан к форме роста.
4. **Перенос знания (#100) поднимает `E_useful` при том же выпуске**, а не лабораторный потолок. Лицензия даёт документацию и чужой опыт: «знаешь, что искать», и каждая партия учит больше (Pisano: обучение до производства работает при сильной теории [E15]). Это множитель `(1 + k_tr)` на выпуск в `x_V`. Почему не потолок: при `ΔL` = 0,5 потолок закрывает только часть разрыва, и освоение без серии осталось бы невозможным, а #100 требует освоения при малой серии. Перенос через `world_lead` остаётся каналом контракта (`k_catch·catch`) и **`E_useful` не меняет**. Поэтому K2 при `W` проверяется так же, как в hold-out.
5. **`E = 0` → рост от усилия 0** (P6): `t_p = 0`, значит `drive = catch = 0`. Остаются `spill` и поддержание. Догоняние без своих инженеров не работает.
6. Лабораторная часть идёт только до `r_d − ΔL`. Выше этого уровня без выпуска роста нет (P1).

### 1.2 Функции снимка C-B (требование `PROCESS_DEVELOPMENT.md` §2.3) [Предл.]
Все функции чистые и читают только снимок t−1. Процесс p, site s. Узкое измерение `d*` выбирается так: наибольшее `r_d − H` по активным d; ничья — канонический порядок; ячейка `(s, c(p), d*)`.
- `E_useful(s,p)` = 0, если `limiter₀ ∈ {NONE, TOOLING, SATURATION, LAB_CEILING}`. Иначе — `U_p` при `v_p > 0` и `E_full·ℓ` при `v_p = 0` (стенд). `limiter₀` — `limiter` при `E = 0`.
- `limiter(s,p)` — первое совпадение, порядок фиксирован:
  1. `NONE` — `gap_p(d*) = 0`: доводить нечего.
  2. `TOOLING` — `M[s,c,d*] < H[s,c,d*]`: культура выше станков выхода не даёт (`c_d = min(H, M)`, A5).
  3. `SATURATION` — `Hcap[s,d*] ≤ r_d*`: целевой уровень недостижим, `sat` его не пустит.
  4. `LAB_CEILING` — `v_p = 0` и (`ℓ = 0` или `H ≥ r_d* − ΔL`).
  5. `VOLUME` — `v_p > 0`, `E_p ≥ U_p` и `U_p < E_full`: деньги есть, выпуска мало.
  6. `EFFORT` — во всех остальных случаях (в том числе `E = 0`, «в полную силу», а также стенд без серии ниже лабораторного потолка).
- `dH_forecast(s,p,E)` = `min(ΔH⁺, ρ_max)` ячейки `(s, c(p), d*)` по формуле §1.1.2, где `E_p` заменено на `E`, остальное — из снимка. Не убывает по `E`; при `E = 0` вклад усилия равен 0, остаётся `σ·spill`.
- **Деление `E` актора по site** (`PROCESS_DEVELOPMENT.md` §1.2): `E_{s,p} = (E_{a,p} · v_{s,p}) / Σ_s v_{s,p}`, floor. Остаток от floor идёт site с наибольшим `v`, при ничьей — меньшему `site_id`. Если `Σ v = 0`, всё получает меньший `site_id`. `Σ_s E_{s,p} = E_{a,p}` точно.

### 1.3 Заглушка распределения ИИ (C-B; фиксируется до прогона) [Предл.]
Это `PROCESS_DEVELOPMENT.md` §5 на стенде, профиль P3 (множители доктрин ×1). Расчёт идёт раз в месяц по снимку, деньги тратятся в следующем месяце.
1. Бюджет `D_a = 0,4·CapShare·budget_index_a` в месяц.
2. Кандидаты — `p` с `limiter₀(s,p) = EFFORT`. Пояснение: `VOLUME` возникает только при `E ≥ U`. Для распределения ограничитель берётся при `E = 0`, и тогда процессы, упирающиеся в выпуск, получают ровно `E_useful`, но не больше. Это читается так: «ИИ не платит сверх того, что сработает».
3. Вес `w_p = v_exp(p) · gap_H(p)`, где `gap_H` — наибольшее по активным измерениям `max(0, r_d − H)`. На стенде `v_exp` — плановый темп линии: `r·n_p·labour_p` (у линии стенда темп постоянный).
4. Налив: `alloc_p = (D_left · w_p) / Σ w`, floor, суммы по возрастанию `prc_id`. Затем `min(alloc_p, E_useful_p)`. Излишек раздаётся заново между неупёршимися, пока остаток > 0 и есть неупёршиеся; число итераций не больше числа кандидатов. Остаток уходит в оснастку (на стенде — в бюджет оснастки того же месяца).
5. Детерминированно, без RNG. Два прогона дают один хеш.

Режимы усилия на стендах C-B: **AI** — заглушка; **MAX** — `E_p = E_full` у каждого работающего процесса, без бюджета (худший случай для «тлеющего цеха», лучший для малой страны); **FIX** — `E_p = E_useful_p` у каждого работающего процесса, без бюджета; **ZERO** — `E ≡ 0`. У C-A режимов нет.

### 1.7 Ожидания до прогона [Предп.] (для честности отбора, не критерии)
1. **K2b и `α` до 0,15.** У R1c в hold-out K2b был 0,248 при `α` 0,08 (запас 0) и рос с `α`: норма упирается в `ρ_max` и `sat` раньше символического цеха. C-B SMOOTH с `r_cap` 6,25 при MAX имеет тот же `drive`, что R1c. Вероятно, K2b провалится у C-A и у части C-B на `α` ≥ 0,10.
2. **1,25 против 2 шт./мес.** K2b требует малого `e(1,25)`, HK8 (b) — достаточного `e(2)` при переносе. Без переноса это требует локальной эластичности по темпу ≈ 2 и выше; у SMOOTH она ≤ 2, у LIN — 1. При LIN перенос `k_tr` = 1 даёт `x_V(2)` = 4/`r_cap` (0,8 / 0,64 / 0,4), поэтому HK8 у LIN вероятен, а K2b при MAX — под угрозой. У C-A лицензия культуру не меняет: при 2 шт./мес. `u` = 0,24 < `u_m`. Вероятно, C-A провалит HK8 (a) — обрыв поддержания, §7.6 старого документа.
3. **F-1 закрывает только 90 из 168** сбоев K2a N·B у C-A. 78 сбоев (FRA/SUN × 38, 53, 44 — «тлеющий цех» у пола, §9.2) остаются, правило не меняется. Вероятно, C-A провалит HK2.
Эти ожидания не меняют ни критерии, ни сетку. Они записаны, чтобы потом нельзя было выдать провал за неожиданность или подогнать объяснение задним числом.

### 1.8 Правило прохождения и выбора
1. Вариант **проходит**, если выполняет все жёсткие критерии §1.5 при всех условиях, парах и режимах из таблицы (с D-1, D-3, D-4, F-1), на всём своём окне `α` × 3 `δ_H`. Кандидат проходит, если проходит хотя бы один его вариант.
2. **Выбор между кандидатами:**
   - проходят оба → C-B: только он выполняет #99 (рычаг с эффектом, P7, P8). Запасы обоих печатаются рядом;
   - проходит только C-B → C-B;
   - проходит только C-A → `needs-decision`: выбрать C-A значит оставить рычаг #99 без влияния на культуру, а это решение владельца.
3. **Внутри C-B** среди прошедших: (1) наибольший худший нормированный запас `min` по K2a `(0,9 − g*)/0,9`, K2b `(0,25 − r*)/0,25`, K4c `(2 − q5)/2` и `(1,5 − q10)/1,5`, HK8 (b) `(3 − q)/3`; запасы, различающиеся меньше чем на 0,01, считаются равными; затем (2) шире окно `α`; (3) LIN раньше SMOOTH (меньше операций, буквальный M1); (4) `ℓ` = 0 раньше 0,1; (5) больший `r_cap`; (6) больший `r_keep`.
4. **Если не проходит ни один кандидат:** формулу не правят, параметры не двигают, новый кандидат не придумывают (#80, #95). Статус — `needs-decision`. Владелец получает таблицу «критерий × условие × режим × вариант» и худшие случаи. Вопросы готовятся по фактическому узору провалов. Если провал совпадёт с §1.7, вопросы будут такими: (а) что важнее при 1,25 и 2 шт./мес. — #79 или #100, или K2 проверяется только в режиме AI; (б) где верх `α` по K2b; (в) `act` < 1 и обрыв.
5. Неисполнимые пункты и ошибки определения записываются в результатах как отклонения с причиной. Если результат по исходному определению можно посчитать, он печатается рядом.
