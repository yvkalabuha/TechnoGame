# ADR-0011 — Представление карты

> После ACCEPTED текст не меняется. Изменение решения — новый ADR с `supersedes`.
>
> **Ревизия 3 (2026-11-18).** Учтены гейт ревизии 2 (`docs/reviews/adr-0011-r2-critic.md`, `adr-0011-r2-advocate.md`, `adr-0011-r2-deepseek.md`) и решения владельца #311–#313. Основа ревизии 2 — `docs/architecture/notes/map-provinces-1945.md`. Ревизии 1 и 2 есть в истории git.

## Краткий вывод
[Предл.]
- **Уровни.** Провинции (2000–5000, #195) внутри регионов (150–250, #171). Плотность неравномерна: в Европе и Восточной Азии провинции мельче, в пустынях крупнее.
- **Id.** Иерархичные: `province_id = <region_id>.<suffix>`. Каждый id записан в спецификации явно, рядом стоит якорная точка. Поэтому id не зависят от порядка операций и правок геометрии.
- **Владение.** Хранится на провинции: `owner` (де-юре) и `controller` (де-факто), обе колонки с t0 (#310).
- **Политии.** Владельцы — политии. Среди них есть совместные (кондоминиумы, #312) и оккупированные без правительства (Германия, Корея, #313). Старт и `as_of` — 1945-10-01 (#311).
- **Сборка.** NetTopologySuite (BSD-3-Clause), версии закреплены, LGPL-модули запрещены проверкой графа пакетов. Natural Earth GeoJSON и объекты OHM (только CC0 и CC BY) закреплены по SHA-256 с указанием лицензии и даты. Площадь считается своей формулой на аутентической сфере.
- **Хеш.** Таблицы ядра коммитятся; CI пересобирает их и сравнивает diff. Производные атрибуты (площадь, центроид, соседство) хешируются; сырая геометрия (`geo/`) — нет. `geo/` всегда генерируется при сборке; в git лежит только `manifest.json` с SHA-256 и хешем привязки к таблицам. Несовпадение — громкая ошибка.
- **Моды.** В v1 `map/*` запечатаны. Моды меняют политии и владение сценария либо заменяют карту целиком.
- **Клиент.** ID-растр R16 и два LUT; граница ищется по 4 соседям. Бюджет памяти растров — ≤ 160 МБ.

## Решение

### 1. Уровни и id [Предл.]
| Уровень | Число | Что несёт |
|---|---|---|
| Провинция | жёстко 2000–5000 (#195); 2500–3500 — ожидаемый итог сборки, не цель | полигон, `owner`, `controller`; позже — война, логистика, заводы (#198) |
| Регион | 150–250, 5–15 на великую державу (#171) | экономика и политика |
| Полития | ~70–90 [Предп.] | владелец, тинт, подпись |

- **`region_id`** — `[a-z][a-z0-9_]*`, по географии, не по владельцу (ADR-0005).
- **`province_id`** — `<region_id>.<suffix>`, где `suffix` — `[a-z][a-z0-9_]*`, длина ≤ 48. Регион вшит в id. Перенос провинции в другой регион — смена данных и миграция ключа (ADR-0013 п. 7).
- **Правило именования (стабильно к правкам).**
  - Id **не вычисляются** из геометрии или порядка операций. Каждая провинция объявлена в `tools/map/spec/ids/<area>.yaml` записью `{id, anchor: [lat_µdeg, lon_µdeg]}`.
  - Каждый кусок итоговой геометрии получает id той записи, чей якорь лежит внутри куска. Ноль или больше одного якоря в куске — ошибка сборки. Якорь без куска — тоже ошибка.
  - Так `merge`, `cut` и `assign` не меняют id соседей, а правка линии разреза не переименовывает куски, пока якоря остаются по своим сторонам.
  - `subdivide` (§2 п. 3) объявляет `parts: n` и базу. Id кусков — `<base>_<k>`, `k = 1..n` в порядке (широта убыв., долгота возр.) итоговых семян; якоря для них сборщик пишет в `spec/ids` сам при первой сборке, дальше они правятся как ручные. Смена `n` — смена данных и миграция.
  - Первичная разметка: команда `bootstrap` один раз пишет `spec/ids` из `adm1_code` и точек подписи NE. Дальше файл правится только вручную.
- **`polity_id`** — `[A-Z][A-Z0-9_]*`. Если сущность 1945 года совпадает с кодом NE `ADM0_A3`, берётся этот код, иначе — код проекта. Валидатор запрещает коду проекта совпадать с действующим `ADM0_A3`. Окончательные коды (например, ROC против `CHN`/`TWN`) выбирает research-scientist в T4. Актор — полития с тем же id. В `polities.yaml` хранятся:
  - `kind: state | joint`; у `joint` — список `members` (≥ 2 политии, порядок — данные, он задаёт цвета штриховки) (#312);
  - `government: true | false` — `false` для DEU и KOR (#313);
  - `actor?` — связь с актором.

  `polities.yaml` входит в `scenario_hash`. Миграции сопоставляют значения по `polity_id`, а не по индексу.

### 2. Сборщик (`tools/map/`) [Предл.]
1. **Замок источников** — `tools/map/sources.lock.yaml`. В каждой записи: `id`, `url`, `sha256`, `license`, `retrieved` (дата), `kind`.
   - **NE**: GeoJSON `geojson/ne_10m_admin_1_states_provinces.geojson` и `geojson/ne_10m_admin_0_map_units.geojson` из `nvkelso/natural-earth-vector` по закреплённому тегу, `license: public-domain`. Shapefile не используется.
   - **OHM**: точечный источник линий разреза, не базовый слой (advocate 2). Запись `ohm:<type>/<id>@v<version>` указывает на снимок объекта (GeoJSON) с SHA-256 и значением тега `license`. Валидатор принимает только CC0-1.0 и CC-BY-*; при отсутствии тега — CC0 (правило OHM). Каждый CC BY объект записывается в `ATTRIBUTION.md`.
   - Загрузка идёт в пустой кеш вне git; файлы читаются только как данные. Если хеш не совпал, сборка падает.
2. **Спецификация** (`tools/map/spec/`, собственная работа проекта, ADR-0009) — **только геометрия, без владельцев**:
   - `merge` — объединить `adm1_code` в провинцию;
   - `cut` — разрезать объект одним из способов:
     - `{parallel: φ, within: [...]}` или `{meridian: λ, within: [...]}` — договорные параллели как параметры: 38° с. ш., 16° с. ш., 50° с. ш. (advocate 8);
     - `{line: spec/cuts/<id>.geojson}`;
     - `{ohm: <ref>}`;
   - `subdivide` — разбить на части;
   - `assign` — отнести провинцию к региону.

   У каждого `cut` обязательны `source`, `as_of`, `precision` (A/B/C), у класса A — ещё `ref` (карта или договор). Порядок применения: имя файла, затем порядок правила.

   **Слияния по владению** (IND+PAK+BGD, колонии к метрополиям) — не геометрия. Они задаются только в `owners.yaml`.
3. **`subdivide`** по умолчанию — Вороной (advocate 1):
   - n семян из последовательности Холтона (основания 2, 3) в равновеликих координатах ограничивающего прямоугольника объекта; точки вне объекта отбрасываются;
   - затем 10 итераций Ллойда на фиксированной сетке выборки;
   - ячейки обрезаются по объекту.

   Запасной метод — бисекция пополам по площади по меридиану или параллели (`method: bisect`).
4. **Геометрия.**
   - NTS с фиксированным `PrecisionModel` шагом 1e-6°.
   - Покрытие суши без щелей и наложений.
   - Объекты режутся по антимеридиану (Чукотка, Фиджи).
5. **Площадь — своя явная формула.** Модель Земли — аутентическая сфера WGS84, `R = 6 371 007,181 м`. Формула — сферический избыток кольца по Chamberlain & Duquette (2007): `A = R²/2 · |Σ (λ_{i+1} − λ_{i−1}) · sin φ_i|`, дыры вычитаются.
   - Результат — км², `long`, `MidpointRounding.ToEven`.
   - Центроид и точка подписи — в микроградусах (`int`).
   - NTS площадь не считает.
   - Валидатор предупреждает, если значение лежит в пределах 1% от порога любой полосы (critic 3).
6. **Соседство.**
   - Общая граница ≥ 1 км (касание в точке не считается), плюс ручной `straits.yaml`.
   - Регионы-острова без пролива помечаются в `regions.yaml` как `isolated: true` (§3).
7. **Полосы площади** (плотность неравномерна):
   - 5–150 тыс. км² в населённых районах;
   - до 500 тыс. км² в пустынях и тундре.
   - **Исключения по правилу, а не по списку имён** (critic 5): провинция меньше полосы допустима, если она:
     - (а) целиком admin-0 map unit;
     - (б) остров или архипелаг без сухопутного соседа;
     - (в) кусок `cut` класса A (сектора Берлина и Вены, Данциг, Триест).
8. **Детерминизм сборки** (critic 3).
   - `tools/map` закрепляет SDK (`global.json`) и пакеты (`packages.lock.json`, `RestoreLockedMode`).
   - **Таблицы ядра коммитятся** как канонический выход. CI (Linux) пересобирает их и сравнивает побайтово; diff — красный CI.
   - Авторитет — CI на Linux. Расхождение на другой ОС у разработчика не ошибка данных.
9. **Проверка графа пакетов** (critic 8). CI запускает `dotnet list tools/map package --include-transitive`. Совпадение с `NetTopologySuite.IO.ShapeFile*`, `*CoordinateSystems*` или `ProjNet*` — красный CI.
10. **Валидатор.**
    - Покрытие суши.
    - Диапазоны: провинции 2000–5000, регионы 150–250, 5–15 регионов на актора — великую державу.
    - Полосы площади и исключения из них.
    - Якоря id.
    - Каждый `cut`: `source`, `as_of`, `precision`, `ref`.
    - Лицензии OHM.
    - `owners.yaml`:
      - ровно одна запись на провинцию;
      - `as_of = 1945-10-01`;
      - `source` у каждой строки;
      - id политий существуют;
      - у `joint` ≥ 2 членов.
    - Связность графа регионов.
    - Коллизии `polity_id` с `ADM0_A3`.
11. **Выход для ядра.** `mods/core/map/{provinces,regions,adjacency,straits}.yaml` перечислены в `mod.yaml`.
    - `provinces.yaml`: `id`, `area_km2`, `centroid`, `label`, `coastal`.
    - `regions.yaml`: `id`, `capital_province`, `isolated`.
    - Происхождение (`ne_src` — список `adm1_code`, ссылки OHM) пишется в `geo/manifest.json` и не хешируется (critic 10).
12. **Стартовое владение** — `mods/core/scenarios/1945/{polities,owners}.yaml`, ручная таблица.
    - Значение по умолчанию задаётся на регион, исключения — по провинциям.
    - Поля: `owner`, `controller`, `status`, `source`, `as_of: 1945-10-01` (#311).
    - `status` ∈ `core | colony | protectorate | mandate | leased`. «Под оккупацией» **не хранится**, а выводится как `controller ≠ owner ∧ status ≠ leased` (advocate 7a); валидатор проверяет согласованность. Кондоминиум выражается совместной политией (#312), а не статусом.
13. **Обновление NE** (critic 10).
    1. Сменить тег и SHA-256 в замке.
    2. Собрать и получить отчёт diff: исчезнувшие и новые `adm1_code`, изменения площадей > 1%, изменения соседства.
    3. `adm1_code` без записи в `spec`, якорь вне всех кусков и коллизия id — громкая ошибка.
    4. Пару old→new `DataHash` записать в DECISIONS_LOG.
    5. Перепроверить `owners.yaml`.

    Старые сохранения становятся несовместимыми (#307).

### 3. Ядро: владение и граф [Предл.]
- **Статические данные.** `Singularity.Core.Map`: плотные индексы по ordinal-сортировке id; соседство провинций — CSR (отсортированные `int[]`). Граф регионов **не хранится в файлах**: он строится при загрузке из соседства провинций и `straits.yaml`, тоже в CSR. Матрица `d(r, r')` (≤ 250², `short`) считается BFS при загрузке.
  - `d = D_INF = short.MaxValue` между несвязанными компонентами. Системы считают `d ≥ d_max` недостижимым.
  - `d_max` — параметр сценария (`map.d_max`); его значение задаёт E1.
  - Валидатор требует, чтобы каждый регион вне главной компоненты был помечен `isolated: true` (critic 7). Неотмеченный изолированный регион — ошибка.
  - Всё перечисленное входит в `DataHash` и `scenario_hash`. Геометрии и `float` в ядре нет.
- **Состояние.** Таблица `provinces` в `Table` с колонками `owner: short`, `controller: short` (индекс политии). На t0 они заполняются из `owners.yaml`.
- **Время изменений** (ADR-0006, ADR-0014):
  - внешняя команда применяется в начале следующего тика;
  - событие системы пишется в merge своего тика;
  - системы читают снимок предыдущего тика, поэтому изменение видно в t+1;
  - вид публикуется после тика.

  Смысл и правила смены задают RR-0016/0018 (гейт). Пока таких событий нет, колонки постоянны.
- **Регион своего владельца не хранит.** Смешанное владение внутри региона допустимо. **Зависимость от E1 (RR-0011 G07):** `H/M`, `K`, `N_r` живут на уровне региона. До кода E1 нужно решение ADR или спецификации E1: ячейка `(region, controller)` или атрибуция по `controller` столичной провинции. На t0 валидатор предупреждает о регионах с несколькими `controller`, и список таких регионов печатается в отчёте сборки.
- **Виды Session.**
  - `MapLayoutView(ProvinceIds, ProvinceRegion, RegionIds, PolityIds, PolityKind, PolityMembers, PolityActor)` — один раз.
  - `Ownership(Owner, Controller, Changed)` — на каждом непустом тике; без изменений передаётся тот же экземпляр массивов.
  - Повышается `test_api_version` (ADR-0013 п. 2), добавляются тесты видов.
  - Провинции в v1 без имён.

### 4. Хеш, привязка и моды [Предл.]
- **Граница `DataHash`.** Хешируются таблицы `map/*.yaml`, включая **производные атрибуты геометрии**: площадь, центроид, `coastal`, соседство. Не хешируется **сырая геометрия** `map/geo/`: её не читают `ModLoader` и `Provenance.DataFiles`, по правилу `locale/` из ADR-0018 §2. Правка вершины, которая не меняет производных атрибутов, не меняет `DataHash`; правка, которая их меняет, меняет.
- **Привязка geo ↔ данные** (critic 1). `manifest.json` и заголовок `arcs.bin` содержат `data_binding` — SHA-256 канонических байтов `provinces.yaml`, `adjacency.yaml` и `regions.yaml`. Клиент сверяет его при загрузке; несовпадение — громкая ошибка с понятным сообщением. Тест: правка `provinces.yaml` без пересборки `geo/` приводит к ошибке.
- **Моды в v1** (critic 2, DeepSeek):
  - Объекты `map/*` запечатаны: `override`, `patch` или `delete` по ним — ошибка загрузки (ADR-0010).
  - Моды меняют `scenarios/*/polities.yaml` и `owners.yaml` обычными операциями ADR-0010.
  - Мод, меняющий набор провинций, заменяет карту **целиком**: все четыре таблицы, `spec/` и свой `geo/manifest.json`, связанные `data_binding`. Частичный патч геометрии не поддерживается.

### 5. Клиент [Предл.]
- **`geo/` всегда генерируется** при сборке клиента из замка и `spec` (advocate 4, critic 12). В git лежит только `manifest.json` с SHA-256 ожидаемых `arcs.bin` и растра, `data_binding` и версией формата. CI пересобирает файлы и сверяет SHA-256. Правило размера ревизии 2 отменено: при генерации оно не нужно.
- **`arcs.bin`** (little-endian):
  - **Заголовок:** магия, версия формата, `data_binding`, число дуг, провинций и колец.
  - **Дуги:** id = индекс в порядке сортировки по `(min(L,R), max(L,R), lat0, lon0)`. У дуги указаны левая и правая провинция (левая — слева по направлению обхода; −1 — море) и вершины в int32 микроградусах, дельта-кодированные. Упрощение одно на дугу, поэтому щелей нет.
  - **Кольца:** у провинции — список колец; кольцо — список id дуг со знаком (минус — обход в обратную сторону). Внешнее кольцо идёт против часовой стрелки, дыры — по часовой. Кольца упорядочены по убыванию площади.
- **ID-растр R16.** Развёртка — equirect 8192×4096 или куб 6×2048², выбирает спайк. Растр печётся из `arcs.bin`, CPU-копия хранится для выбора мышью. Бюджет растров вместе с копией — ≤ 160 МБ [Предл.] (critic 12).
- **LUT.**
  - `LUT_prov` (RG16: owner, controller) обновляется по `Ownership`; `LUT_tint` хранит тинт каждой политии.
  - Заливка — по `owner`. Если `controller ≠ owner`, поверх идёт штриховка цветом `controller`.
  - У совместной политии — двухцветная штриховка цветами первых двух членов в порядке `members` (#312) [Предп.: для 4 членов, как в центре Вены, достаточно; иначе ui-art-director].
- **Границы.** Граница государства на Z0–Z1 — выборка `owner` у 4 соседей (`texelFetch` ±1), а не `fwidth` (critic 12). Граница провинции — на Z2 и ближе. На Z2–Z3 — ленты из дуг: граница государства — дуги с `owner(L) ≠ owner(R)`, при смене владения пересобирается только этот набор. Береговая линия — дуги с −1.
- **Подписи** (ADR-0018 §5 по #310): полития-актор подписывается `-actor-<id>`, остальные (включая совместные и оккупированные) — `-country-<polity_id>`. Регионы подписываются `-region-<region_id>`.

### 6. Точность, ручные разрезы, проверка истории [Предл.]
Классы ошибки положения линии по сравнению с 1945-10-01:
- **A** — договорные и демаркационные линии: ≤ 10 км. У каждой линии хранится `ref`. Если линия есть в OHM, сборщик записывает в отчёт расстояние Хаусдорфа до неё; больше 10 км — предупреждение. Параллели задаются параметром, поэтому точны.
- **B** — линии, совпадающие с современными административными: точность NE 10m.
- **C** — зоны контроля без точных линий: 100–200 км, `precision: approx` в данных и в легенде.

**Политика оцифровки класса A** (advocate 8):
- источники — тексты договоров, OHM (CC0 или CC BY), PD-карты [Предп.: карты US Army Map Service 1940-х — федеральная работа США, значит PD; проверяет research-scientist];

## Влияние на другие ADR
- **ADR-0013: формат не меняется.** `provinces` — обычная таблица снимка; `save_format_version` растёт по п. 7; ключ строки — `province_id`. Если карта другая, `DataHash` другой, и загрузка честно падает с ошибкой (#307).
- **ADR-0016 (ACCEPTED): не меняется, но в силе его оговорка.**
  - Полный масштаб ADR-0016 «без провинций» относится к **системам** провинций.
  - Слой владения — таблица 2 × ≤ 5000 `short` (≤ 20 КБ) без систем. Он входит в `K_d` (копия, хеш, снимок) и в следующем замере `T` обязателен в синтетическом мире полного масштаба (задача Orchestrator; `tick-benchmark-m0.md`). [Предп.] Его вклад меньше 1% доли `K_d`.
  - **Системы провинций (война, логистика, экономика по провинциям) до своего кода требуют нового ADR бюджета**, как требует ADR-0016 §1.
- **ADR-0018 (ACCEPTED): текст не меняется.** По #310 ключ `-country-<…>` §5 читается как `-country-<polity_id>`. Правило кода — §1 этого ADR: `ADM0_A3`, если сущность совпадает, иначе код проекта без коллизий. Политии и регионы становятся объектами `GameData`, поэтому на них распространяется проверка L1 (§3.2): `-country-*` для каждой политии-не-актора, `-actor-*` для актора, `-region-*` для каждого региона, EN и RU с падежами и `.gender`. **Последующая задача:** расширить перечислитель L1 в `Singularity.Localization.Tests` на политии и регионы. Вид `province` не нужен, пока у провинций нет имён.
- **ADR-0010:** запечатывание `map/*` в v1 (§4) — частное правило загрузчика в рамках операций ADR-0010.
- **ADR-0006, ADR-0014:** время изменений владения — §3.
- **B8** (`contract-proposals-wave1.md`) заменён. **RR-0011:** нужен erratum в строке 80 (`region_id/NNN` → `<region_id>.<suffix>`) и в G07/I09 (владение на провинции, `owner` + `controller`, #310) (OPEN, автор RR-0011).

## Рассмотренные альтернативы
- **Владение на регионе.** Отклонено решением #308.
- **Только `owner`.** Отклонено решением #310.
- **Кондоминиум как `status` с основным владельцем.** Отклонено решением #312.
- **Готовый исторический набор (CShapes, historical-basemaps, COW).** Отклонено по лицензиям (ADR-0009).
- **Python + Shapely/GEOS или GDAL.** Отклонено: нативные библиотеки делают воспроизводимость зависимой от их версии, и это второй язык сборки. Запасной путь для общих дуг — mapshaper (MPL-2.0, Node), только если покрытие NTS не пройдёт проверку T2.
- **Id из `adm1_code` или из порядка операций.** Отклонено: правка спецификации или обновление NE переименовали бы ключи сохранений (DeepSeek high).
- **Вершины NE прямо в ядре.** Отклонено: в ядро попал бы `float` (ADR-0002).
- **Растр как источник истины.** Отклонено: нет точного соседства и нет вектора для Z3.
- **Коммит `geo/` или Git LFS.** Отклонено: вместо этого генерация с SHA-256 в манифесте (§5).
- **Векторные тайлы.** Отклонено: формат рассчитан на плоский Меркатор и потоковую подгрузку, а тайлы рвут общие дуги и фильтр `owner(L) ≠ owner(R)` (advocate 5).
- **~1000 провинций.** Отклонено решениями #195 и #308.
- **Бисекция как основной метод `subdivide`.** Отклонено: режет Сибирь, Сахару и север Канады на полосы. Остаётся запасным методом.

## Последствия
- **Плюсы:**
  - точность 1945 года на уровне провинций;
  - смена границ без перепечки растра;
  - ключи сохранений стабильны к правкам спецификации;
  - сборка воспроизводима и проверяется в CI.
- **Минусы:**
  - много ручной работы: якоря id, разрезы, таблицы политий и владения с источниками;
  - линии класса C приблизительны;
  - для сборки клиента нужен закреплённый NE (кеш);
  - в v1 моды не правят карту по частям;
  - id провинции навсегда привязан к региону.
- **Обязательно:**
  - каждый `cut` и каждая строка владения несут `source` и `as_of`;
  - владение меняется только в merge;
  - Core, Session и клиент не ссылаются на NTS;
  - до кода E1 — решение о регионах со смешанным владением;
  - до кода систем провинций — ADR бюджета.

## Разногласия
Ревизия 3 по гейту ревизии 2. Отклонено или изменено против рецензии:
1. **DeepSeek: «нет механизма модов для бинарной геометрии».** Частичный патч геометрии модом отклонён в v1. Принято только «замена карты целиком» (critic 2). Причина: частичный патч требует пересборки общих дуг на стороне игрока, то есть сборщика в рантайме. Вернуться к вопросу при первом реальном моде карты.
2. **Advocate 4, вариант «оставить (а) коммит и (в) генерацию».** Выбран один путь — всегда генерировать (тот же advocate 4, первый вариант; critic 12). Вариант (б) ревизии 2 снят.
3. **Critic 3, «коммитить канонический выход»** — принято только для таблиц ядра. Для `geo/` вместо коммита — SHA-256 в манифесте (п. 2 выше).
4. **Записка research-scientist (`map-1945-borders.md`)** допускала COW и CShapes как чтение для сверки фактов. По замечанию DeepSeek они исключены и из сверки. Автор записки это не подтверждал: разногласие открыто, решает Orchestrator.
5. **Advocate 8, PD-статус карт AMS** — не принят как факт, остаётся [Предп.] до проверки research-scientist.
6. **RR-0011 G07** (advocate RR-0011: «owner на регионе, controller на провинции»). Этот ADR кладёт оба поля на провинцию (#308, #310). Неделимость `H/M` ниже региона перенесена в зависимость E1 (§3), а не решена здесь.
