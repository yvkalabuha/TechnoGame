## 3. Компетенция и скорость (ограниченно)

[Предл.] Для приоритетного узла `r` области `d`, закреплённого за институтом `i` с уровнем `c(i,d) ∈ 0..4`: `m_inst(i,r) = 1 + clamp(0,05·(c(i,d) − c_ref(a,d,t)), −0,10, +0,10) + e_lead`, где `c_ref` — уровень **лучшего** института области на траектории ИИ (нормировка IP2 6.1: ИИ-траектория даёт `m = 1`, калибровка #457/#458 не меняется), `e_lead ∈ [−0,04; +0,04]` (#461). «Бонус института» из #487 понимаю как этот `m_inst`.
- Проверка потолка (#462): `|m−1| ≤ 0,10 + 0,04 = 0,14 < 0,15` при любых `c`, `c_ref`; клип по `c−c_ref ∈ [−4; +2]` даёт −10 % (непрофильный, #488) … +10 %. Рывок денег ×1,5 (разд. 5) в `m` **не входит**: потолок 15 % относится к множителю скорости, как в IP2 6.2. Затухание у границы по годам Y = 3 (IP2 6.3) остаётся.
- Узлы вне приоритета: `m = 1` (общий фон страны). Доля IP2 «ступень 6 + профиль 5 + руководитель 4» заменяется на «уровень 10 + руководитель 4» (#489: ступени и профиль заменены уровнями по областям; IP2 разд. 2, 3, 6.2, 8, 11, 13 нужно привести в соответствие, это правка IP2 — Orchestrator/владелец).
- Для узла пути приоритетной цели берётся компетенция назначенного института **по области самого узла** пути (слабая область замедляет путь).
- [Предп.] Значения 5 %/ступень и 0,14 — проектный выбор [Предп.] как и 15 % (#462).

### Как растёт компетенция
[Предл., #192/#488/#489: специализация меняется медленно] (а) **опыт**: за каждый завершённый приоритетный узел области, назначенный институту (в том числе непрофильному, #488), растёт `exp`; порог на +1: 0→1 ≈ 3 узла, далее ≈ 8, 15, 25 [Предп.]; (б) **проект «углубить область»** (национальный проект, остаётся из #192): +1 к уровню в одной области за ≈ 5 лет, ≈ 3 % бюджета науки в год [Предп., economy-analyst]; (в) **забывание**: без работы в области 20 лет −1 [Предп.]. Максимум один рост на область за 10 лет; предел 4. Непрофильный институт становится профильным через ≈ 3 узла опыта, то есть за 10–20 лет игры.

## 4. Назначение приоритетного узла
1. Игрок выбирает **узел** в дереве (точечный выбор, #485) → кнопка «Назначить институту» → список институтов страны: имя, компетенция в области узла (точки), занят/свободен, поправка скорости («−5 %», «0», «+5 %»).
2. **Правило покрытия (#488).** Назначить можно любой институт, в том числе без опыта в области (уровень 0): узел идёт на ≈ 10 % медленнее (−10 %), опыт института в этой области растёт со временем (разд. 3). Показывается пометка «не профильный».
3. **Свободный слот.** Один институт — один приоритетный узел. Занятый слот можно **переназначить** (прогресс узла не теряется, штрафа нет — как в A1 п. 3г — но пауза **12 месяцев** до следующей смены этого слота, чтобы не микроуправлять) [Предл.].
4. **Узел вне фронта.** Если выбран узел за непройденными предпосылками, его **путь во фронте** (узлы замыкания, уже доступные к изучению) входит в приоритетную группу и получает деньги первыми (разд. 5). Узлы пути серые «нужно для цели»; слотов не занимают.
5. При завершении узла слот освобождается, автопауза «Институт N свободен» ≤ 1 в игровой год на страну.
6. Сколько слотов: `N_slots = число институтов страны` (#485), потолок по данным.

## 5. Финансирование: деньги первым (численно)

Обозначения по коду (`KnowledgeSystem.ProgressRate`, `ComputeFull`): `S = ResearchBudget(a,t)`; фронт `F`; `w_r = Priority(a,r,t)·J(a,r,t)`; `wsum = Σ_{r∈F} w_r`; `CEff(r)` включает множитель опережения.
Сейчас: `Δprog_r = S·(w_r/wsum)/CEff_r`.

**Новое** (приоритеты по порядку списка игрока `k = 1..K`, `K ≤ N_slots`):
- Группа `G_k` = узлы фронта, входящие в замыкание цели `k` (сама цель, если во фронте; узел, уже занятый более ранней группой, остаётся там). `W_k = Σ_{r∈G_k} w_r`.
- Естественная доля: `nat_k = S·W_k/wsum`. Спрос: `dem_k = κ·nat_k`, **κ = 1,5** (#487) [значение владельца; остальные константы Предп.].
- Выделено: `A_k = min(dem_k, S − Σ_{j<k} A_j)`; внутри группы `alloc_r = A_k·w_r/W_k`.
- Остаток: `R = S − Σ A_k`; остальной фронт: `alloc_r = R·w_r/(wsum − Σ W_k)`. Если остальных нет, остаток тратится по правилу ядра (сгорает, §3.4 спецификации).
- Скорость: `Δprog_r = alloc_r·m_inst(i,r)/CEff_r` (`m=1` вне приоритета).

Пример (пересчитан): `S = 100`, 10 узлов фронта с равным весом, 3 приоритетных узла (по одному в группе), κ = 1,5. `nat = 10`, `A = 15×3 = 45`; остаток 55 на 7 узлов: **7,86 вместо 10** (−21 %). Приоритетные узлы получают в 1,5 раза больше денег; скорость узла `1,5 × m_inst`: у лучшего института 1,5; максимум 1,5 × 1,14 ≈ 1,71; у непрофильного 1,5 × 0,90 = 1,35 (всё ещё быстрее обычного). Дорогое опережение уменьшает выигрыш через `CEff`. В прежней версии при κ=2 было 5,7 (−43 %).

Свойства [Предл.]: (1) `Σ alloc ≤ S` (инвариант I4); (2) при κ=1 и `m=1` результат совпадает с текущим бит-в-бит (проверка P-1); (3) при отсутствии приоритетов — бит-в-бит как сейчас (ИИ-мир не меняется); (4) приоритет **не** берёт деньги сверх `S`, поэтому «другим направлениям» достаётся то, что осталось: это (#484) и есть «перераспределение», без отдельного штрафа; (5) при дефиците денег (`S` мало) приоритетные узлы первыми «выбирают» деньги по порядку списка. Реализация в ядре: один проход по фронту + K групп, O(|F|·K) в месяц — копейки.

## 6. Что видит и нажимает игрок

```
Опережение эпохи на 5 лет: цена узла ×1,5
Остальные направления: «Радар» ≈ +4 мес., «Материалы» ≈ +2 мес.
```

- Серые кнопки (#471): «Свободных институтов нет», «Институт переведён недавно: ещё N мес.», «Уже изучено», «Чужая держава».
