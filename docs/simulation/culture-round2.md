#### 1.1.2 C-B: культура от усилия (M1 + M3′, поддержание от выпуска)
Входы ячейки `(site, c, d)` из снимка t−1: `v_p = proc_v[site,p]`, `E_p = proc_E[site,p]` (деньги доводки, индекс бюджета в месяц, `PROCESS_DEVELOPMENT.md` §2.1), `lic_p`, `world_lead(p, owner)`. Учитываются процессы кластера c с `v_p > 0` или `E_p > 0` и с активным измерением d.
```
v_cap(p)  = r_cap  · labour_p          # потолок «материала для экспериментов» (единицы §7.5)
v_keep(p) = r_keep · labour_p          # выпуск, при котором поддержание полное
x_V   = (v_cap = 0) ? 0 : min(1, ṽ_p / v_cap)          # ṽ_p — канал лицензии §1.1
c_p   = LIN:    x_V
        SMOOTH: (x_V · x_V) · (3 − 2·x_V)
x_E   = min(1, E_p / E_full)
e_V   = min(x_E, c_p)                  # M1: min(E, E_useful)/E_full
e_L   = (ℓ = 0) ? 0 : min(x_E, ℓ)       # M3′: лабораторная часть
gap_p  = max(0, r_d + 0.25 − H)
gapL_p = max(0, (r_d − ΔL) − H)        # лабораторный потолок r_d − ΔL
t_p   = max(e_V · gap_p, e_L · gapL_p)
m_p   = (v_keep = 0) ? 0 : min(1, v_p / v_keep)          # без лицензии
maint_p = H_floor + (max(r_d·a_r, H_floor) − H_floor) · m_p
drive = max_p t_p;   catch = max_{p: world_lead(p,owner)} t_p;   maint = max(H_floor, max_p maint_p)   # пусто → 0 / 0 / H_floor
```
Почему такая форма (все пункты — [Предл.], опора в источниках указана):
1. **M1, а не M2.** Квота опытных партий — доля производственного потока [E4]. Излом `min` даёт одну точку `E_useful`: её можно показать игроку, и в неё ИИ «наливает» деньги (`PROCESS_DEVELOPMENT.md` §2.3). M3 без потолка источники не поддерживают (`culture-effort-evidence.md` §4.2).
2. **Две формы потолка `c`, обе в сетке.** LIN — буквальный M1: опытных партий ∝ выпуску. SMOOTH — мощность эксперимента по размеру выборки S-образна [Предп. по E7, E4]. [Факт, `culture-rule-selection.md` §3 п.4] При полном усилии LIN совпадает по `drive` с линейным R1 при `r_full = r_cap`; у того K2b и K4c одновременно не выполнялись. LIN — контроль M1, а не фаворит.
3. **Поддержание — только от выпуска**, линейное, со своим порогом `r_keep`. Документы и штат знание не держат (FOGBANK, Astute; `culture-effort-evidence.md` §3). Поэтому ни `E`, ни лицензия в `maint` не входят.
4. **Лицензия** — общий канал §1.1. `world_lead` даёт только `catch` (канал контракта), `E_useful` не меняет и переносом не считается (#102).
5. **`E = 0` → рост от усилия 0** (P6): `drive = catch = 0`, остаются `spill` и поддержание.
6. Лабораторная часть работает только до `r_d − ΔL`. Выше без выпуска роста нет (P1).

### 1.2 Функции снимка C-B (интерфейс `PROCESS_DEVELOPMENT.md` v0.2 §2.3) [Предл.]
Все функции чистые и читают только снимок t−1. Процесс p, site s.
- **R2-4: выбран вариант (a) `lead`, а не деление по ячейкам.** Ведущий процесс ячейки `lead(s,c,d)` — процесс с наибольшим `t̂_p` при полном усилии. `t̂_p = max(c_p·gap_p, ℓ·gapL_p)`; при `v_p = 0` `c_p` = 0. Берутся процессы кластера c с активным d. Ничья — меньший `prc_id`; если все `t̂_p = 0`, ведущего нет. От `E` выбор не зависит. Почему (a): формула §1.1.2 и инварианты I1–I3 (неразбавление) остаются как есть, меняются только функции снимка и ИИ. Деление по ячейкам (сумма вместо `max`) снова вводит разбавление — тот самый недостаток R0, который `max` убрал в раунде 1 — и меняет формулу после gate.
- `d*(p)` — узкое (наибольшее `r_d − H`) измерение среди ячеек, которые ведёт p. Если p не ведёт ни одной ячейки, `d*` — узкое среди всех активных измерений p. Ничья — канонический порядок.
- `E_useful(s,p)` = 0, если p не ведёт ни одной ячейки или если `limiter₀ ∈ {NONE, TOOLING, SATURATION, LAB_CEILING}`. Иначе `E_useful = E_full · k*`, где `k* = ℓ`, если `ℓ·gapL_p > c_p·gap_p`, и `k* = c_p` в противном случае (ячейка `(s, c(p), d*)`). Это точка излома `t_p` по `E`. Исправление r1: там при `v > 0` стояло `U_p` и терялась лабораторная часть при `ℓ > c_p`.
- `limiter(s,p)` — первое совпадение, порядок фиксирован. Если p не ведёт ни одной ячейки, его `limiter` равен `limiter` ведущего процесса ячейки `(s, c(p), d*)`. Новое значение не вводится (PD v0.2 §2.3 п.2).
  1. `NONE` — `gap_p(d*) = 0`.
  2. `TOOLING` — `M[s,c,d*] < H[s,c,d*]` (A5).
  3. `SATURATION` — `Hcap[s,d*] ≤ r_d*`.
  4. `LAB_CEILING` — `v_p = 0` и (`ℓ = 0` или `H ≥ r_d* − ΔL`).
  5. `VOLUME` — `v_p > 0`, `E_p ≥ E_useful` и `k* < 1`.
  6. `EFFORT` — во всех остальных случаях.
- `limiter₀(s,p)` — `limiter` при `E_p = 0`. От `E` не зависит; по нему ИИ выбирает кандидатов (§1.3).
- `dH_forecast(s,p,E,v)` = `min(ΔH⁺, ρ_max)` ячейки `(s, c(p), d*)` по §1.1.2. В формулу подставляются `E` вместо `E_p` и `v` вместо `v_p` (в `ṽ_p`, `x_V`, `m_p`), остальное берётся из снимка. Не убывает по `E` и по `v`. При `E = 0` вклад усилия 0. Если p не ведёт ячейку, вклад его `E` равен 0. Подставленный `v` нужен для показа цены по #101 («при серии `r_ref` — …»). Это только UI, на прогон не влияет. Проверка — I10.
- **Деление `E` актора по site** (`PROCESS_DEVELOPMENT.md` §1.2): `E_{s,p} = (E_{a,p} · v_{s,p}) / Σ_s v_{s,p}`, floor. Остаток floor получает site с наибольшим `v`; при ничьей — меньший `site_id`. Если `Σ v = 0`, всё получает меньший `site_id`. `Σ_s E_{s,p} = E_{a,p}` точно.

### 1.3 Заглушка распределения ИИ (C-B; фиксируется до прогона) [Предл.]
