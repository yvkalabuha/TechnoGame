# Политические механики стран «собственного пути» (КНР, Франция)

Статус: черновик дизайна. Основания: решения #255–#257, #256 (условия вместо дат), #224 (нет коридора историчности), #28 (RNG не в слоях способности и изделия). Срез M0 не меняется. Факты по КНР — из `docs/research/notes/prc-catch-up-1949-1977.md`; по Франции — общие знания [Предп.], заметка `france-own-path-1945-1980.md` не читалась. Исторические даты ниже — основания и ориентиры для Lab, не скрипт.

## Краткий вывод
- [Предл.] Событие = данные: `Event { id, scope, predicate, hysteresis, decisions[], effects[] }`. Предикат — булева функция снимка мира t−1 (ADR-0006), без дат и без RNG. Историчность появляется как следствие стартового состояния (патрон, зависимость, легитимность), а не как расписание.
- [Предл.] Решения принимают и игрок, и ИИ по одному контракту: `Option { id, gate, cost, effects }`; ИИ выбирает детерминированно: `argmax(utility_a(option))` по доктрине страны из данных, ничья — по id. RNG нужен только для появления людей (#28, слой событий) и для «шума сигнала»; в этом документе он не нужен нигде.
- [Предл.] Нужно ровно четыре новых состояния: `Alignment[a]` (блок, патрон, зависимость), `Colony[c]` (владение: ресурс и бремя), `Regime[a]` (легитимность, жёсткость), `CadrePipeline[a]` (поток инженеров). Каждое связано с существующими слоями через уже имеющиеся рычаги (лицензия, культура, бюджет, `support`), без новых валют.
- [Предл.] Милестоун КНР+Франция — 5 шагов, ~20–30 недель одного разработчика [Предп., грубо]; минимум — система событий + `Alignment` + `CadrePipeline` + 2 события на страну; колонии и режим можно сузить до 1 числа каждый.
- Главный риск — сценарий, переодетый в условия (§4).

## 1. Система событий по условиям

### 1.1 Структура
```
Event {
  id, scope: pair(a,b) | actor(a) | world
  predicate      : DAG из атомов над снимком t-1 (только чтение)
  hold_months    : N   // условие держится N месяцев подряд (гистерезис, защита от дребезга)
  once           : bool  // повторяемое событие требует cooldown
  decisions      : per-side Option[]   // игрок и ИИ — тот же список
  default_option : что происходит, если игрок не ответил (автопауза #196, затем default)
  effects        : запись в t+1 только в свои поля
  why            : текст-цепочка «какие атомы сработали» (для UI и `why_not`)
}
```
Атом предиката — сравнение числового поля мира с порогом: `dependence(a,patron) > x`, `legitimacy(a) < y`, `T(pair) > z`, `share_of_exports_to(patron) > w`. Паттерны условий [Предл.]:
- **Накопление напряжения:** `friction = f(идеологическое расхождение, цена зависимости, обиды)` растёт, событие — при пересечении порога.
- **Асимметрия:** патрон сокращает помощь, когда его собственный интерес падает (`aid_value < aid_cost`), а клиент растёт (`self_sufficiency > s`).
- **Шок + слабость:** внешний провал (`defeat`) при низкой `legitimacy` у режима.
- **Окно возможности:** требуется наличие базы (узлы знания, мощность) — иначе вариант решения закрыт (`gate`), а не недоступен «по сценарию».
- **Исключение:** взаимные блокировки (`blocks: [event_id]`), чтобы не наступали несовместимые повороты.

### 1.2 Решения и ветвление
Каждый `Option` имеет `gate` (что нужно иметь), `cost` (деньги, `support`, время, потеря отношения) и эффекты. Ветвление — **дерево глубиной ≤ 2**: ответ меняет поля и открывает/закрывает последующие события через их предикаты (а не через флаги «ветка 2.3»). Так цепочка выводится из состояния, поэтому два пути к одной ситуации ведут к одной реакции.

Как решает ИИ [Предл.]: у страны в данных есть доктрина — вектор весов `w` над целями (`autonomy, security, growth, ideology_bloc, stability`). `utility(option) = Σ w_i · Δgoal_i` по заранее вычисленным эффектам из таблицы события (ИИ не симулирует вперёд; это O(options) на событие). Лидер (Personality, #206) сдвигает `w` в пределах ограниченной доли; ничья — по id. Для патрона и клиента одно и то же событие рассматривается дважды (две стороны), результат — пара ответов, исход — в таблице исходов.

### 1.3 Детерминизм и RNG
- Предикаты читают снимок t−1, события упорядочены по `(tick, event_id, side_id)`; нет сравнения float на границах (пороги — в фиксированной точке / целых), L1/L2 сохраняются.
- RNG оправдан только: (а) появление и уход персон (уже в #28), (б) шум наблюдения (ИИ видит `dependence` оппонента неточно) — FUTURE, N14. Исход решений детерминирован.
- Ожидания «неопределённости» делаются скрытым состоянием и неполной видимостью, а не броском кубика.

### 1.4 Как не получить скрипт
- Нет полей `date`, `year`, `after_event_X` в предикатах; тест Lab — `grep` по данным: календарная переменная в предикате = ошибка (инвариант).
- Каждое событие должно иметь ≥ 2 различимых начальных состояния, при которых оно не наступает (тест на «ложное отсутствие»), и ≥ 1, при котором наступает раньше/позже исторического (тест «дрейф дат»).
- Метрика Lab: распределение времён наступления по семейству стартов с вариацией параметров; если окно < 12 месяцев при всех вариациях — событие скрипт.
- Исторические даты — ориентир для калибровки стартового состояния (#224), не критерий приёмки.

## 2. Разобранные примеры

### 2.1 Раскол СССР–КНР
Основания [Факт, prc-catch-up note §2]: 1960 отозвано ≈1390 советских специалистов, расторгнуто ≈600 контрактов, остановлено ≈200 проектов; но MiG-21 передан в 1962 — не обрыв, а ухудшение качества.
- Предикат (`pair(PRC, USSR)`): `dependence(PRC,USSR) > d0` ∧ `friction > f0` держится 12 мес. Где `friction` растёт от `ideology_gap` (линия на детант, ревизионизм), `status_gap` (КНР считает себя достойной ядерной помощи), `aid_value` (СССР отказывает в образце бомбы — [Предп.]).
- Решения КНР: A) терпеть (меньше трения, зависимость сохраняется); B) ускорить локализацию (`localize_share ↑`, платит бюджетом и временем); C) публичный разрыв (`support` у внутренних сил, но срезает лицензии).
- Решения СССР (ИИ): A) выдержать помощь; B) сократить `aid_level` на шаг; C) отозвать специалистов (убирает `cadre_transfer` и ухудшает качество документов: `doc_completeness ↓`, а не лицензия в ноль).
- Ветви: (B,B) → медленное расхождение; (C,C) → разрыв: `Alignment` сбрасывается, лицензии переходят в `degraded` (EVT_DIS), поток кадров из СССР = 0; (B,C) — КНР с высокой локализацией переживает дешевле. Ловушка культуры (A43.8) делает последствие зависящим от накопленной культуры, а не от даты.
- Что видит игрок: рост `friction` как сигнал за 2–3 года, а не письмо «раскол через 6 месяцев».

### 2.2 Выход Франции из военной организации НАТО (1966)
[Предп., общие знания]: де Голль, требование «тройного директората», вывод из объединённого командования, вывод баз США; страна остаётся в Альянсе.
- Предикат: `nato_member(FRA)` ∧ `autonomy_pref(FRA) > p` ∧ `nuc_capacity(FRA) ≥ strike_threshold` ∧ `control_share(FRA in alliance) < q` ∧ `regime.legitimacy ≥ L` (режим достаточно сильный, чтобы делать риск). Без ядерной базы вариант «выйти» закрыт (`gate`) — исторически он зависит от force de frappe.
- Решения: A) остаться в структуре и торговаться (платёж `support`, шанс получить «директорат» — детерминированно из `T` и вклада); B) выйти из командования, остаться в договоре (теряет часть системы раннего предупреждения и поставок, `bloc_trade_friction ↑`, получает `autonomy ↑`, рост `support` дома); C) выйти полностью (редко; дорого).
- ИИ США/НАТО: уступить / игнорировать / ввести торговое трение. Ответ — по доктрине и по `T` (при высокой `T` блок прощает меньше).
- Ветви: B открывает ветку национального проекта «независимое сдерживание» (дублирующий контур), закрывает часть лицензий США на высокие технологии. Это «чьё плечо держать и когда отпустить» (catch-up note) в режиме Франции.

### 2.3 Ядерное решение Франции после Суэца (1956)
[Предп.]: Суэцкий кризис — унижение, уход США и СССР; решение о программе ускорено; первое испытание 1960.
- Предикат: `defeat_event(FRA)` или `patron_defection(ally = USA)` ∧ `nuc_knowledge(FRA) ≥ k1` ∧ `reactor_base ≥ 1` ∧ `dependence_on_US < δ`. Не «Суэц = 1956», а «союзник не поддержал при кризисе».
- Решения: A) не строить (остаться под зонтиком, дёшево); B) запустить национальный проект бомбы (стадии: реактор/Pu → обогащение/испытательный полигон → носитель; цена — деньги + кадры + `support`, RR-0012); C) совместная программа (если патрон готов; уступка — контроль). Проект включается в `NationalProject` (стадии, детерминированный срыв от `D_hidden`).
- Ветви: B повышает `T` по паре с блоком патрона только после демонстрации (#222), создаёт долгий расход и открывает решение 2.2; A сохраняет зависимость и закрывает ветку собственного пути. Колонии влияют на источник урана/полигоны [Предп.] (Сахара; см. §3.2).

### 2.4 Алжирская война и кризис 1958
[Предп.]: колониальная война, расходы и потери, политический кризис 1958, падение Четвёртой республики, возврат де Голля, затем уход из Алжира (1962).
- Предикаты цепочки (три события, не одна дата): 
  1. `colonial_war(c)`: `independence_pressure(c) > u` ∧ `garrison < needed` → начинается как состояние; расход бюджета `burden(c)` ежемесячно.
  2. `regime_crisis(FRA)`: `legitimacy < L1` ∧ `burden/budget > b1` ∧ `military_political_gap > g` (армия против гражданской власти).
  3. `decolonize(c)`: `legitimacy_new ≥ L2` ∧ `net_value(c) < 0` ∧ `war_weariness > w`.
- Решения (игрок, режим): удерживать / реформировать колонию (дорого) / сменить режим (конституционная реформа: `Regime.executive_power ↑`) / уйти. Эффекты: `executive_power` даёт больше пространства для решений, но снижает «согласие» пока; уход снимает `burden` и теряет ресурс (`net_value`), но поднимает `legitimacy`.
- Ветви различимы: удерживать до конца → затяжное падение легитимности и риск повторного кризиса; сменить режим → нужен лидер (Personality) и цена в `support`. Ни одной даты в предикатах.

### 2.5 Реформа КНР 1978
[Факт: рывок после 1978, Maddison 2023 — GDP pc КНР 799 → 1583 за 1950–77, относительный уровень 5,2% → 5,7%, prc note]; причины и механизм — [Предп.].
- Предикат: `growth_gap(PRC) > g` (долгая стагнация относительно мира) ∧ `regime.shock_exhaustion` (последствия ряда политических шоков: большой скачок, культурная революция — шок культуры) ∧ `leadership_turnover` ∧ `open_window` (отношения с рынком: сниженное `T` с торговым блоком, либо возможность получать лицензии с Запада).
- Решения: A) продолжать модель; B) частичная реформа (хозрасчёт и специальные зоны: растёт `FDI`/`localize_share`, рискует легитимностью у консерваторов); C) широкая реформа и открытие (максимум темпа, максимум риска `Regime`).
- Ветви: B/C открывают лицензионные цепочки с несколькими блоками (одновременно) и поток кадров за рубеж. Темп роста — результат вложений в `CadrePipeline` и культуры, а не слайдер. Если игрок сделал B/C раньше «по истории», предикат выше позволяет; цена — слабая база, значит откат.

## 3. Новое состояние

### 3.1 Блоки и зависимость от патрона
`Alignment[a] { bloc_id, patron_id, dependence_vec: {tech, finance, security, market}, aid_level, autonomy }`. Напряжение — `T` по парам блоков (RR-0013, #222). Зависимость — не число-награда, а сумма вкладов: доля лицензий патрона в узлах (`licence_share`), доля поставок, доля кадров (`cadres_from_patron`), кредитный долг. `aid_level` — данные политики патрона, меняется событиями (§2.1).
- Связи: **лицензии** (EVT_LIC/EVT_DIS уже в срезе) — вход зависимости; **знание** — ассимиляция снижает `dependence` через `bureau_exp` и культуру; **бюджет** — платежи/долг; **нац. проекты** — «параллельный контур» как этап, снижающий зависимость; **культура** — при `g_qc = 0` дополнительная лицензия бесполезна (A43.8).
- Игрок управляет условиями (платежи, локализация), не патроном (catch-up note).

### 3.2 Колонии: ресурс и бремя
`Colony[c] { owner, resource_vec, garrison_cost, independence_pressure, net_value }`. Ресурс — запись в пул сырья/рынка владельца (через ключи региона, RR-0011); бремя — месячный расход бюджета и `support`. Давление растёт от идей и от слабости владельца, снижается от инвестиций и репрессий (репрессии — `Regime.legitimacy ↓` вне страны). Колония = отдельный регион с детальной картой только если стратегически значима; иначе 1 агрегат на 1 колонию.
- Связи: **бюджет** (война), **ресурсы/торговля** (E3), **политика** (легитимность), **ядерный проект** (полигон/уран, [Предп.]).
- [Предл.] В v1 колония — 1 агрегированный объект, без отдельной механики управления.

### 3.3 Режим и легитимность
`Regime[a] { legitimacy ∈ [0,1], executive_power, coercion, elite_split }`. `legitimacy` питается успехами (рост, престиж = `support`, #208/#223 — второй валюты нет, `legitimacy` остаётся индексом, а не расходуемым ресурсом) и расходуется провалами, бременем, шоками. Это не «счастье», а допуск к решениям: `gate` у рискованных `Option`.
- Связи: **бюджет** (вывод ресурса на силовые), **нац. проекты** (стоимость срыва ↑ при низкой легитимности), **культура** (политические шоки — шок `culture` в районах, §6 prc note), **личности** (смена лидера, шок/возможность).
- Риск дубля: `support` и `legitimacy` — разные величины: `support` — ресурс, тратится; `legitimacy` — состояние, не тратится. [Предл.] Вопрос владельцу, нужна ли вторая величина вообще (OPEN).

### 3.4 Образование и кадры
`CadrePipeline[a] { schools_tier, enrolment, graduates/yr, abroad_share, brain_drain, cat_mix }` — поток новых людей в 4 категории (#194), а не склад. Входы — бюджет и `school_H` (EXPERIMENTAL после EXP-0002; в v1 `Hcap` от образования = 0, F-SC3). Выход — когорта в `reserve_workforce` и рост `h_r` через год.
- Связи: **знание** — кадры повышают ёмкость диффузии (`Hcap`); **культура** — когорта с практикой только после лага; **лицензии** — передача кадров патроном (отзыв = `cadre_transfer = 0`, §2.1); **бюджет** — налог на будущее (образование vs наладка, catch-up note); **нац. проекты** — резерв людей на этапы.
- Тест двойного счёта: D10 (один человек в `h_r` и `reserved`).

## 4. Ценность для игрока и режимы отказа
Выбор значим, если [Предл.]:
- Имеет цену в разных валютах (деньги, время, `support`, зависимость), а не «+X к росту»; и отложенную: плата сейчас, результат через 5–15 лет.
- Ветви различимы по последствиям в состоянии (ядерная страна ≠ зависимая), а не по числу.
- Сигналы видимы заранее (рост `friction`, снижение `aid_level`), причина читаема (`why`).
- Нет доминирующей ветви: тест Lab — каждый путь выигрывает хотя бы в одном стартовом состоянии (по дисперсии параметров). Ориентир: ни одна опция не доминирует в >70% прогонов [Предп.].

Режимы отказа:
- **Скрипт в маске условий:** пороги подобраны так, что событие всегда наступает в окне истории. Лечение — тест §1.4.
- **Каскад:** события провоцируют друг друга (разрыв → кризис → реформа); нужен `cooldown` и взаимные блокировки.
- **Паралич решений:** слишком много автопауз; лимит ≤ N решений в год на игрока, остальные — политики-по-умолчанию (`standing_orders`).
- **Нет «хорошей» ветви:** выбор между злом без выхода — flavour, не игра.
- **Один «сверхинститут»/путь** (H-INST-2): сильная опция «всё в образование».
- **Кальибровочная ловушка:** ИИ всегда выбирает исторически, потому что доктрина записана с хвоста истории — доктрины должны быть описаны интересами, не результатами.
- **Двойной счёт и потеря причинности:** `dependence` считает лицензию и кадры; проверять D10/D01-подобные дубли.
- **Историчность под давлением:** владелец увидит «неисторичный» мир — #224 снимает требование, но UI должен показывать «почему», иначе читается как ошибка.

## 5. Предложение по составу и порядку milestone [Предл.]
Порядок и зависимости (размер — недели одного разработчика, [Предп.]):
1. **Система событий** (Event/Option/predicate, автопауза, `why`, ИИ по доктрине): ядро, зависимость — ничья, но нужны `COUPLED` Economy и снимки мира. 4–6 нед.
2. **`Alignment` + блоки + `T`:** зависит от торговли E3 (RR-0013 §7) и лицензий среза. 3–5 нед.
3. **`CadrePipeline` и образование:** зависит от EXP-0002/`school_H` и демографии; без него КНР — слайдер (catch-up note). 4–6 нед.
4. **Макроэкономика (ВВП, бюджет `COUPLED`)** — экономист; в этом оценка не даётся (граница). Блокирует «полный рывок» (#255).
