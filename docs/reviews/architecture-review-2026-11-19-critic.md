# Независимый разбор архитектуры (critic, 2026-11-19)

> Сохранено Orchestrator из отчёта агента critic (у него нет права записи). Сводка и решения — `docs/reviews/project-review-2026-11-19.md` §2.

Блокирующего в Kernel не найдено. Находки по убыванию важности:

1. **Высокая. Цена дневного тика M1 не измерена.** [Факт] В EXP-0007 «дневной» T — месячные системы плюс пустой зонд (П9 п. 3). По ADR-0019 п. 1–3 Flow-системы идут каждый день, Decision — раз в 7 дней на актора (около 4,3 решения ИИ в месяц вместо 1). Прототип R2 (ADR-0019 «Research») не найден; #353 принят под это условие. [Предп.] При полном проходе Flow цена растёт в 30 раз. Предложение: R2 до кода #228; дневная работа — O(изменившегося).
2. **Высокая. Замер M0 мерит масштаб вне M1.** [Факт] Точка A — 2000 синтетических узлов; в `mods/core` 61 узел. Сетка D, 200 × 180: 78/88 мс. Предложение: точку исхода K4 и EXP-0008 перенести на реальный масштаб M1.
3. **Высокая. Вывод о многопоточности недоказуем.** [Факт] t1 = 626 мс и t8 = 394 мс сняты при 25 % времени в GC. `TickRunner` режет только таблицу акторов: 25 чанков на систему, merge и post последовательны. Предложение: L2 оставить; новых вложений в параллелизм не делать, пока t1/t8 не даст ≥ ×2,5; серии Lab — t1 на процесс, параллельно по seed.
4. **Высокая. Сохранения нет.** [Факт] Нет `CreateSave/LoadSave/TableSnapshot`, нет `IReadOnlySession/ITestSession`, хотя ADR-0013 и ADR-0014 приняты. Новые кэши: `RegionController`, `_prcMemo`, `NodeBlockCache`, memo проектов. Предложение: до #228 — `TableSnapshot` в Kernel и тест «прогон до K → save → load → продолжение = непрерывный прогон».
5. **Средняя–высокая. Сущности как семейства колонок на таблице акторов.** [Факт] `CommandState.cs:43-70`, `PolicySystem.Fleet.cs:27-29`, 41 динамический `Add*` в `ProductsSystem.cs`, `KnowledgeSystem.cs:108-123`. Ёмкость слотов зашита в схему. Предложение: при миграции на World (ADR-0020) вынести проекты, когорты и очереди команд в свои таблицы с колонками `actor` и `generation`. Gate.
6. **Средняя. `[ThreadStatic]` вне стража.** [Факт] `ScratchTests.Systems()` сканирует только `ITickSystem`; `EffortAllocator.cs:19` и `ToolingPlan.cs:140` держат `[ThreadStatic]` без `[Scratch]`. Предложение: IL-тест на static-поля; тест «два мира попеременно на одном пуле потоков»; тип `DesignHandle`.
7. **Средняя. Снимок видов на каждом непустом тике.** [Предп.] После #228 около 200 МиБ мусора в месяц. Предложение: ADR о кольце буферов до кода #228; клиент получает снимок не чаще кадра, Lab — на границе месяца.
8. **Средняя. Лишнее для проекта одного человека.** Четыре ADR о правилах замера, EXP-0008 с калибровкой чужой нагрузки; TCP-транспорт ADR-0014 п. 7 описан раньше потребителя. Предложение: заморозить харнесс; решающий замер — один K4 на мире M1.
9. **Низкая. Core — фундамент, но ADR-0019 меняет семантику тика.** [Предп.] Цена — около 4,6 тыс. строк систем. `Session` целиком называется `Slice*`: нужен общий интерфейс сессии до клиента M1.
10. **Низкая. Документы расходятся с кодом.** [Факт] `ARCHITECTURE.md` называет принятые ADR предложенными. В `gen2-structural-analysis.md` §3 оценка «колонка 2000×200 в LOH» расходится с `Column.cs:61-62` (длина колонки = число строк, 200): вывод про LOH перепроверить.

Не проверено critic: поломка L2 через `[ThreadStatic]` найдена только в коде, в документах её нет.
