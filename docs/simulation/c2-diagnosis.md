## 4. Механизм (корневая причина)
- [Факт, код] Компоненты:
  - `yield = Π g_d · ramp`;
  - `g = (1 + gap)²` на [−1; 0);
  - `ramp = λ0 + (1 − λ0)·X/(X + X½)` (`IndustryMath`);
  - C-B (`CbCultureRule.Parts`): `t_p = max(min(xE, c_p)·gap, min(xE, ℓ)·gap_L)`, `gap_L = max0(r_d − ΔL − H)`. Без выпуска лаборатория поднимает `H` только до `r_d − 0,5`, то есть `g` ≤ 0,25.
  - Выпуск линии (`ProductsSystem.Purchases`): `r = min(rate, alloy/alloy_kg, money/unit_cost)`, `unit_cost` растёт как 1/`yield`. Отчёт процесса — `units = r·n_p`, `v = units·labour`; без отчёта `X` забывается.
- [Предп., согласуется со всеми таблицами] **Петля:** низкий `yield` → дорогая единица → `r` мал (деньги) → `v`/`v_cap` ≪ 1 → `c_p` ≈ 0 и `X` почти не растёт → `yield` остаётся низким. У ИИ та же петля: P2/P3 не берут процесс с `yield` < 0,5, а без проекта процесс не `eligible`, и его ячейку ведёт другой процесс. Выход из петли есть только у пар с большим бюджетом и ранним знанием (USA, SUN по 49): в p23 p90 `yield` через 96 мес. = 0,07, p90 максимума до горизонта = 0,41.
- [Факт] Такой же механизм описан в §8.2 п.9 для C1 («ловушка культуры: нет выпуска → нет роста `H`»). Решение #231 обошло его в стенде, начав «освоение» с культуры, при которой весь `prc_set` допущен с `yield` ≥ 0,25. В полной модели этого обхода нет.
- **Что это не:** [Факт] не темп знания (k меняет в основном долю А, и в R2 при k 4 цензура 0,83); не `DESIGN_CAPACITY` (0 во всех точках T12); не ошибка разбора (хост совпадает со сборкой). Дефектом кода это тоже не выглядит [Предп.]: каждое звено соответствует контракту v2.4 §4.1, A40, A41. Это свойство композиции правил, которое ни один стенд не видел (стенды стартуют с выпуском `r_ref` или с допущенной культурой).
