# ADR-0011 — Представление карты

> После ACCEPTED текст не меняется. Изменение решения — новый ADR с `supersedes`.
>
> **Ревизия 2 (2026-11-18).** Основа — записка `docs/architecture/notes/map-provinces-1945.md` и решения #195, #306, #308, #310. Ревизия 1 (2026-11-02) есть в истории git. Ниже указано, что из неё остаётся в силе, а что заменено.

## Краткий вывод
[Предл.]
- **Уровни.** Карта двухуровневая: 2500–3500 провинций внутри 150–250 регионов.
- **Id.** Иерархичные: `province_id = <region_id>.<suffix>` (#310).
- **Владение.** Хранится на провинции в двух колонках состояния: `owner` (де-юре) и `controller` (де-факто), обе с первого дня (#310). Владеет полития. Актор — полития, которую симулирует срез.
- **Сборка.** Карту собирает инструмент C# на NetTopologySuite (BSD-3-Clause, без LGPL-модулей) из Natural Earth 10m, закреплённого по SHA-256. Слияния и разрезы по линиям 1945 года задаются ручной спецификацией.
- **Ядро.** Получает только целые числа и строки. Геометрия лежит вне `DataHash`.
- **Клиент.** ID-растр R16 по провинциям, LUT «провинция → owner/controller» и LUT «полития → тинт». Смена границ не требует перепекать растр.

## Контекст

Владелец хочет точности выше ~200 регионов, поэтому провинции переносятся раньше волны 3. #130: старт 1945-09. #171: 150–250 регионов, 5–15 на великую державу. #195: два уровня, иерархичные id. #310: `owner` и `controller` с первого дня, разделитель `.`; ключ `-country-<polity_id>` в ADR-0018 §5 (решение Orchestrator).
- [Факт] `contract-proposals-wave1.md`: B8 предлагал `province_id = <region_id>/<suffix>` и не резервировать `controller`; E9 вносит граф регионов и `d_max` в этот ADR до его принятия.
- [Факт] Клиент-спайк сейчас растеризует Natural Earth admin-0 50m в ID-растр R8 с LUT на 256 значений (`src/Singularity.Client.Spike/Main.cs`). GLOBE_DIRECTION §2.1 и §8: заливка по ID-текстуре; на Z2–Z3 границы рисуются векторными лентами.
- [Факт] NetTopologySuite: ядро под BSD-3-Clause; модули `NetTopologySuite.IO.ShapeFile` и `CoordinateSystems` — под LGPL (https://github.com/NetTopologySuite/NetTopologySuite.IO.ShapeFile/issues/81 , https://secure.software/nuget/packages/nettopologysuite/2.5.0 , доступ 2026-11-18). [Предп.] Файл LICENSE основного репозитория перепроверяется в первой задаче.

## Решение

### 1. Уровни и id [Предл.]
| Уровень | Число | Что несёт |
|---|---|---|
| Провинция | 2500–3500 на суше (в пределах #195: 2000–5000) | полигон, `owner`, `controller`; позже — война, логистика, заводы (#198) |
| Регион | 150–250, 5–15 на великую державу (#171) | экономика и политика; группа соседних провинций |
| Полития | ~70–90 на 1945 год [Предп.] | владелец, тинт, подпись |

- `region_id` имеет вид `[a-z][a-z0-9_]*`. Имя берётся по географии, а не по владельцу (`silesia`, `bavaria`): владелец меняется, а id стабилен (ADR-0005).
- `province_id` имеет вид `<region_id>.<suffix>`, где `suffix` — `[a-z][a-z0-9_]*` (#310; заменяет `/` из B8). Регион провинции вшит в id и в прогоне не меняется. Перенос провинции в другой регион — это смена данных и миграция ключа (ADR-0013 п. 7).
- `polity_id` имеет вид `[A-Z][A-Z0-9_]*`. Если сущность совпадает с кодом NE `ADM0_A3`, берётся этот код, иначе — код проекта. Валидатор запрещает коду проекта совпадать с действующим `ADM0_A3`. Актор — полития с тем же id (`SUN`), связь `polity.actor` задаётся в данных сценария.
- Граф регионов (E9): два региона соседние, если соседствуют хотя бы две их провинции; к этому добавляется ручной список проливов. `d(r, r')` — длина кратчайшего пути по рёбрам (BFS), считается при загрузке. `d_max` — параметр сценария. Граф и `d` входят в `scenario_hash`. В тике поиска пути нет.

### 2. Сборщик (`tools/map/`) [Предл.]
1. **Источники.** Файл `tools/map/sources.lock.yaml` хранит тег релиза `nvkelso/natural-earth-vector`, URL и **SHA-256** для `ne_10m_admin_1_states_provinces` и `ne_10m_admin_0_map_units`. Если хеш не совпал, сборка падает. Кеш хранится вне git. Загрузка идёт в пустой каталог; содержимое читается только как данные.
2. **Спецификация** — ручная, хранится в git, это собственная работа проекта (ADR-0009). Файлы `tools/map/spec/<area>.yaml` содержат правила:
   - `merge` — объединить `adm1_code` в провинцию;
   - `cut` — разрезать по линии или полигону из `spec/cuts/<id>.geojson`; у каждого разреза обязательны `source`, `as_of` и `precision`;
   - `subdivide` — рекурсивная бисекция по меридиану или параллели пополам по площади;
   - `assign` — отнести провинцию к региону.

   Правила применяются в порядке «имя файла, затем порядок правила в файле».
3. **Геометрия.** Используется **NetTopologySuite** (BSD-3-Clause). LGPL-модули `IO.ShapeFile` и `CoordinateSystems` запрещены, данные читаются как GeoJSON. `PrecisionModel` фиксированный, шаг 1e-6°. Покрытие суши проверяется: без щелей и наложений. Инструмент — консольный проект в `tools/`, на него не ссылаются Kernel, Core, Session и клиент.
4. **Вычисляемые величины:**
   - площадь в км² (`long`, равновеликая проекция);
   - центроид и точка подписи в микроградусах (`int`);
   - признак `coastal`;
   - соседство: общая граница не короче 1 км, касание в точке не считается; плюс `straits.yaml`.
5. **Выход для ядра.** Файлы `mods/core/map/{provinces,regions,adjacency,straits}.yaml` перечисляются в `mod.yaml` и входят в `DataHash`.
6. **Выход для клиента.** Файлы `mods/core/map/geo/arcs.bin` и `manifest.json` (§4).
7. **Стартовое владение пишется вручную, а не генерируется.** Файлы `mods/core/scenarios/1945/{polities,owners}.yaml`. Значение по умолчанию задаётся на регион, исключения — по провинциям. Поля: `owner`, `controller`, `status` (`core | colony | protectorate | mandate | condominium | occupied | leased`), `source`, `as_of ≤ 1945-09-02` (#130). Валидатор проверяет, что каждая провинция получила ровно одно значение.

### 3. Владение в ядре [Предл.]
- `Singularity.Core.Map`. Статические данные: плотные индексы по ordinal-сортировке id, соседство в CSR (отсортированные `int[]`). Эти данные только читаются и входят в `DataHash` и `scenario_hash`. Геометрии и `float` в ядре нет.
- **Состояние.** Таблица `provinces` в `Table` с колонками `owner: short` и `controller: short` (индекс политии). Значения на t0 берутся из `owners.yaml`. Меняются колонки только в merge, по событию или команде (ADR-0006, ADR-0014). Смысл и правила смены задают RR-0016/0018 (гейт). Пока таких событий нет, колонки постоянны.
- **Регион своего владельца не хранит**, владелец выводится из провинций. Смешанное владение внутри региона допустимо. На t0 валидатор предупреждает, если у региона больше одного `controller`. Экономика (E1) потом решает, нужна ли ячейка `(region, controller)`.
- **Виды Session.**
  - `MapLayoutView(ProvinceIds, ProvinceRegion, RegionIds, PolityIds, PolityActor)` строится один раз.
  - `Ownership(Owner, Controller, Changed)` публикуется при каждом непустом тике; если владение не изменилось, передаётся тот же экземпляр массивов.
  - В v1 у провинций нет имён: при наведении показывается регион.

### 4. Геометрия вне `DataHash`; клиент [Предл.]
- **Исключение из хеша.** Каталог `mods/core/map/geo/` не читают `ModLoader` и `Provenance.DataFiles`, по тому же правилу, что `locale/` (ADR-0018 §2). Правка геометрии не меняет ни `DataHash`, ни `StateHash`.
- **`arcs.bin`.**
  - Общие дуги с упрощением, сохраняющим топологию.
  - Координаты квантованы в int32 микроградусах.
  - У каждой дуги указаны левая и правая провинция; −1 означает море.
  - Формат little-endian, с версией в заголовке.
- **ID-растр.**
  - Канал R16, индекс провинции.
  - Печётся из `arcs.bin` при сборке клиента и в git не попадает.
  - Развёртка — equirect 8192×4096 (≈ 64 МБ) или куб 6×2048² (≈ 48 МБ). Выбирает спайк (GLOBE_DIRECTION §8 п. 1).
  - Для выбора мышью клиент держит CPU-копию.
- **LUT.**
  - `LUT_prov` (RG16, owner и controller, ~5000 текселей) обновляется при изменении `Ownership`.
  - `LUT_tint` хранит тинт каждой политии.
  - Шейдер заливает по `owner` и штрихует цветом `controller`, если тот отличается от `owner`.
  - Граница государства на Z0–Z1 рисуется по разности **owner** соседних пикселей (`fwidth`).
  - Граница провинции (`rule`) рисуется только на Z2 и ближе.
- **Вектор на Z2–Z3.** Ленты строятся из дуг. Граница государства — дуги с `owner(L) ≠ owner(R)`; при смене владения пересобирается только этот набор. Береговая линия — дуги с −1.
- **Подписи.** Полития-актор подписывается `-actor-<id>`, остальные политии — `-country-<polity_id>` (#310).
- **Правило размера `arcs.bin`.** Бюджет — ≤ 8 МБ после упрощения.
  - (а) Файл ≤ 8 МБ — он коммитится в git.
  - (б) Файл больше 8 МБ — сначала сильнее упрощается для Z0–Z2. Детали Z3 при этом уходят в отдельный файл `arcs_z3.bin`, который генерируется при сборке клиента из закреплённого NE и в git не попадает.
  - (в) Если и после (б) основной файл больше 8 МБ — весь `geo/` генерируется при сборке. Git LFS не используется.

  Какой из случаев сработал, записывает задача сборщика.

### 5. Точность и ручные разрезы [Предл.]
Ошибка положения линии по сравнению с 1945 годом:
- **A** — договорные линии Европы и Кореи: ≤ 10 км;
- **B** — линии, совпадающие с современными административными: точность NE 10m;
- **C** — зоны контроля Китая, Ирана, Африки: 100–200 км; такие линии помечаются `precision: approx` в данных и в легенде.

Площадь провинции — 5–150 тыс. км² в населённых районах и до 500 тыс. км² в пустынях и тундре. Исключения: Берлин, Вена, Данциг, Триест, зона Панамского канала, Гонконг, Макао.

## Влияние на другие ADR
- **ADR-0013: не меняется.** Таблица `provinces` — обычная таблица снимка; `save_format_version` растёт по п. 7. Стабильный ключ строки — `province_id`. Если карта другая, отличается `DataHash`, и загрузка честно падает с ошибкой (#307).
- **ADR-0016 (ACCEPTED): не меняется.** Его масштаб «без провинций» относится к системам провинций: войне и логистике. Слой владения — 2 × ~3500 `short`, около 14 КБ, без систем. Он входит в `K_d` (копия, хеш, снимок) и замеряется в следующем замере как часть `T`. [Предп.] Его вклад меньше 1% от доли `K_d` в 50 мс. Системы провинций по-прежнему требуют нового ADR бюджета, как записано в ADR-0016. `tick-benchmark-m0.md` дополняется строкой о слое владения (Orchestrator).
- **ADR-0018: не меняется.** Ключ `-country-<polity_id>` установлен решением #310. `-region-<id>` уже есть в таблице видов. Вид `province` не нужен, пока у провинций нет имён.
- **B8 (`contract-proposals-wave1.md`)** заменён в части разделителя и резерва `controller`.

## Рассмотренные альтернативы
- **Владение на регионе.** Отклонено решением #308: линии 1945 года режут регионы, и позже понадобилась бы миграция сохранений с региона на провинцию.
- **Только `owner`.** Отклонено решением #310: оккупационные зоны так не записать честно.
- **Готовый исторический набор (CShapes, historical-basemaps, COW).** Отклонено по лицензиям (ADR-0009, `map-1945-borders.md`).
- **Python + Shapely/GEOS.** Отклонено: нативная библиотека и второй язык сборки. Остаётся запасным вариантом.
- **Вершины NE прямо в ядре.** Отклонено: в ядро попал бы `float` (ADR-0002).
- **Растр как источник истины.** Отклонено: нет точного соседства и нет вектора для Z3.
- **Git LFS для `geo/`.** Отклонено правилом размера в §4: лишняя инфраструктура для одного файла.

## Последствия
- **Плюсы:**
  - точность 1945 года на уровне провинций;
  - смена границ без перепечки растра;
  - хеш ядра не зависит от геометрии;
  - сборка воспроизводима из закреплённых источников.
- **Минусы:**
  - много ручной работы: спецификация, разрезы и таблица владельцев с источниками;
  - линии класса C приблизительны;
  - id провинции привязан к региону навсегда.
- **Обязательно:**
  - каждый `cut` и каждая строка владения несут `source` и `as_of`;
  - изменение владения идёт только через merge;
  - Core не ссылается на NTS.

## Проверка
- CI (Linux): повторная сборка `tools/map` из закреплённых источников даёт побайтово тот же выход.
- Валидатор проверяет:
  - покрытие без щелей;
  - диапазоны чисел и площадей §1 и §5;
  - каждый `cut` имеет источник;
  - полноту `owners.yaml`;
  - отсутствие коллизий `polity_id` с `ADM0_A3`.
- Тест: правка `geo/` не меняет `DataHash` и `StateHash` после N тиков.
- L1/L2 (ADR-0002): хеш с колонками владения одинаков при 1 и N потоках; save → load → продолжение даёт тот же хеш (ADR-0013).
- `Singularity.Architecture.Tests`: Kernel, Core, Session и клиент не ссылаются на NetTopologySuite.
- Ревью истории: research-scientist, затем critic.
