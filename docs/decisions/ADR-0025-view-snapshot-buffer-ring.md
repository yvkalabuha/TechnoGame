# ADR-0025 — View snapshot buffer ring

> После ACCEPTED текст не меняется. Изменение решения — новый ADR с `supersedes`.
> Уровень: gate (меняет контракт видов ADR-0014 п. 5; модель потоков не меняется). Шаг 3.6 этапа 3 `development/PLAN.md`; находка A7 `docs/reviews/project-review-2026-11-19.md`; DEBT-0057. Черновик, ревизия 1, до gate. Новых замеров нет (бенчмарки заморожены): только существующие числа с источниками.

## Краткий вывод
- [Предл.] **Гибрид: кольцо только для блоков узлов.** Блоки узлов (`NodeBlock`, массивы `ProcessView[]`) — 93 % байт снимка. Они берутся из кольца N предвыделенных наборов (по умолчанию N = 3) на сессию. Остальная часть вида (≈ 0,5 МиБ) строится заново, как сейчас.
- [Предл.] **Владение — аренда.** Поток клиента держит вид только через `ViewLease` (счётчик `Interlocked` на наборе). Поток симуляции никогда не пишет в арендованный набор и никогда не ждёт клиента.
- [Предл.] **Переполнение — пропуск публикации**, не блокировка и не копия. Вид остаётся прежним (его `Tick` это показывает), счётчик `ViewsDropped` растёт, публикация повторяется на ближайшей границе тика со свободным набором. Для потока-владельца (Lab, тесты) переполнение — исключение.
- [Предл.] Кольцо — исполнение, не состояние: не входит в хеш, сохранение и `SchemaVersion`; поле экземпляра сессии, никаких static и `ArrayPool.Shared`.
- [Предп.] Эффект: мусор пути снимка ≈ 0,5 МиБ на снимок вместо ≈ 6,9; после дневного тика ≈ 15 МиБ/мес. вместо ≈ 200; живой снимок перестаёт кормить gen2. Стоимость ≈ 2–3 дня developer + тесты, `TestApiVersion` +1.

## Контекст
- [Факт: ADR-0014 п. 5] Поток симуляции собирает неизменяемый вид после post непустого тика и публикует его одной атомарной записью ссылки, без блокировок. Клиент читает только виды.
- [Факт: DEBT-0057, `docs/simulation/debt-0057-gen2.md`] Свежий снимок в точке A (200 акторов, 2000 узлов) — 6,94 МиБ, из них блоки узлов 6,42 МиБ (93 %): 651 `ProcessView` (40 Б) × 200 акторов. Живой снимок держат `SliceSession.View` и `NodeBlockCache` до следующей публикации; сборки gen1 переводят его в gen2 по 8,5–9 МиБ за раз; это основной источник установившегося gen2.
- [Факт: TASK-0107] Путь тика без снимка — 0,49–0,69 МиБ/мес.
- [Факт: ADR-0023 п. 2.2, 2.6] Порог пути снимка — ≤ X = 8 МиБ на снимок, 0 LOH, ни одного ссылочного объекта на узел. Снимков в месяц 1–2 сейчас, до ~30 после #228; частоту снимков после #228 должен решить отдельный ADR. ADR-0019 (разногласие 6) снял `ViewPublish OnRequest` из #228.
- [Факт: ADR-0024, «Контекст»; записка `docs/architecture/notes/gen2-structural-analysis.md` §1] Причина gen2 — контракт «новый объект на каждую публикацию, живёт до следующей» (объекты среднего возраста); устраняет её кольцо буферов. Конфигурация GC только сдвигает порог (`DOTNET_GCgen0size` 64 МиБ убирает установившийся gen2, но это недокументированный рычаг).
- [Предп.] После #228 непустой каждый день: ≈ 30 × 6,6 МиБ ≈ 200 МиБ мусора в месяц (A7). На максимальном темпе клиента (30 тиков/с, `SimHost.TicksPerSecond`) это ≈ 200 МиБ/с реального времени.
- [Факт: код] `ProcessView` — `readonly record struct` без ссылок; `NodeList` — `readonly struct` над `NodeBlock`; `NodeBlockCache` уже переиспользует блоки на тиках, не писавших их колонки (R2, TASK-0103). Клиент (`SimHost`, `ActorPanel`, `TechTree`, `AudioDirector`) держит `SliceView` по ссылке неопределённо долго (на паузе — сколько угодно); Lab (`JetSliceModel`, `SliceObserver`) держит два вида — прошлый и текущий.

## Решение

### 1. Что кольцуется
1. Кольцо — массив из N **наборов блоков** (`NodeBlockSet`): у набора `NodeBlock[actors]`, поколение `long Generation` и счётчик аренды `int Leases`. Наборы выделяются при создании сессии; каждый массив внутри < 85 000 Б (ADR-0023 п. 2.2; сейчас `ProcessView[651]` ≈ 26 КБ). Один общий массив на все акторы запрещён.
2. Остальная часть вида (`SliceView`, `ActorView`, `DesignView`, `Inputs`, `Step` …) остаётся неизменяемыми записями, которые строятся заново. [Предп.] Это ≈ 0,52 МиБ на снимок (6,94 − 6,42, DEBT-0057).
3. **Правило роста.** Часть вида, которая на актора больше 16 КиБ или в точке A больше 1 МиБ на снимок, идёт в набор кольца, а не в свежие объекты. Решает systems-architect при ревью поверхности (ADR-0014 п. 6).
4. N — исполнительный параметр `SliceRunConfig.ViewRing` (по умолчанию 3, минимум 2), не хешируется и не пишется в сохранение. Потребитель, который держит k видов одновременно, требует N ≥ k + 1.

### 2. Владение и передача
5. **Поток симуляции** — единственный писатель наборов. Перед сборкой он захватывает свободный набор: `CompareExchange(Leases, -1, 0)` (−1 — «пишется»), не текущий опубликованный. Пишет, ставит `Leases = 0`, новое `Generation`, публикует `SliceView` атомарной записью ссылки, как в ADR-0014 п. 5. Неизменившийся набор (R2) публикуется снова без захвата нового.
6. **Поток клиента** читает вид только через аренду: `using ViewLease l = session.AcquireView();`. Захват — увеличить `Leases` CAS-циклом, только если `Leases ≥ 0`, затем перепроверить, что опубликованная ссылка та же; иначе отпустить и повторить. Освобождение — `Interlocked.Decrement` с любого потока. Аренда не блокирует поток симуляции.
7. **Поток-владелец** (тот, что вызывает `Step`: Lab, тесты, `SimHost` внутри своего потока) может читать `session.View` без аренды. Вид действителен, пока не прошло N − 1 следующих публикаций.
8. **Проверка поколения.** `NodeList` хранит поколение набора; каждый доступ сверяет его с набором. Расхождение — `StaleViewException` (Debug и Release: одно сравнение `long`). Тихого чтения чужих данных нет.
9. Что держится дольше — копируется значениями потребителем (как `TechTree._nv` сейчас). Кэшировать `ActorView` или `NodeList` между кадрами без аренды запрещено.

### 3. Переполнение
10. Свободного набора нет (все N − 1 непубликуемых арендованы) → **публикация пропускается**: `View` остаётся прежним, `ViewsDropped` +1, флаг «публикация должна». Поток симуляции не ждёт и не выделяет память.
11. Должную публикацию поток симуляции делает на ближайшей границе тика (и в `Step(0)` / цикле хоста на паузе), когда набор освободится; хеш и состояние от этого не зависят.
12. У потока-владельца (п. 7) переполнения нет по построению; если поток-владелец получает `StaleViewException`, это ошибка размера кольца в его конфигурации, а не пропуск.
13. `ViewsDropped` пишется в манифест замера и в отладочный оверлей клиента. [Предл.] Ненулевое значение в замере — нарушение P8 «пропуск вида» (ADR-0023 п. 2.5, без влияния на исход).

### 4. Связи
14. **Детерминизм (ADR-0002).** Вид — наблюдение. Сборка вида не пишет колонки и не использует RNG (ADR-0014). Хеш L1/L2 не зависит от N, от пропусков и от того, строятся ли виды вообще (`SkipViews`).
15. **Сохранение (ADR-0013, TASK-0124).** Кольцо не сохраняется. После загрузки сессия выделяет кольцо заново и строит первый вид, как конструктор сейчас. Вид после загрузки равен виду непрерывного прогона на том же тике.
16. **Два мира в процессе (TASK-0125).** Кольцо — поле экземпляра `SliceSession`; нет static-пулов, `[ThreadStatic]`, `ArrayPool.Shared` для наборов. Наборы двух сессий не пересекаются.
17. **GC (ADR-0023 п. 2.2–2.4, ADR-0024).** Наборы живут всю сессию в gen2 и не содержат ссылок (`ProcessView` — значение), запись в них не нагружает таблицу карт [Предп.]. Живая куча растёт на (N − 1) × 6,42 ≈ 13 МиБ при N = 3 [Предп.]. Пусковой gen2 (DEBT-0057) кольцо не устраняет — его покрывает прогрев ADR-0024.
18. **Частота публикаций (ADR-0023 п. 2.6).** Этот ADR частоту не меняет: каждый непустой тик, как в ADR-0014 п. 5. Ограничение частоты кадром клиента — отдельный light-пункт после R2 ADR-0019, если профиль покажет нужду.

### Частично заменяет
- **ADR-0014 п. 5:** «неизменяемый снимок» → неизменяемы записи вида; блоки узлов неизменяемы, пока действительна аренда (поток клиента) или не прошло N − 1 публикаций (поток-владелец). Атомарная публикация ссылки и «без блокировок» не меняются.

## Последствия
- **Плюсы:** мусор пути снимка ≈ ×13 меньше; живой снимок больше не кормит gen2; порог X = 8 МиБ выполняется с запасом и после #228; поток симуляции не ждёт клиента.
- **Минусы:** поток клиента обязан брать аренду (правка `SimHost`, `ActorPanel`, `TechTree`, `AudioDirector`); `StaleViewException` — новый класс ошибок; +≈ 13 МиБ живой кучи; на переполнении клиент видит вид с прошлого тика.
- **Обязательно:** каждый массив набора < 85 000 Б; наборы без ссылочных полей; кольцо — только поле экземпляра сессии; `TestApiVersion` +1 (`AcquireView`, `ViewLease`, `ViewsDropped`, `ViewRing`).
- **Стоимость миграции [Предп.]:** Session (`NodeBlockCache` → кольцо, аренда, проверка поколения) ≈ 1,5 дня; клиент (аренда в `SimHost`, отпуск при смене `HostSnapshot`) ≈ 0,5 дня; тесты ≈ 1 день. Делается до кода #228, отдельной задачей; golden и `SchemaVersion` не меняются.

## Проверка
1. **Аллокации пути вида:** в точке A после прогрева свежий снимок выделяет ≤ 1 МиБ (порог теста; [Предп.] ожидание ≈ 0,52), 0 байт в блоках узлов (`GC.GetAllocatedBytesForCurrentThread` вокруг `Nodes`), 0 LOH. Тест падает, если вернуть `new NodeBlock` в `ViewBuilder.Nodes` (мутация).
2. **Переполнение:** N = 3, клиентский поток держит 2 аренды, поток симуляции делает 10 непустых тиков → `View` не меняется, `ViewsDropped` = 10, ни одна арендованная `NodeList` не изменилась (сверка с копией). После отпуска одна граница тика публикует вид текущего тика.
3. **Поколение:** поток-владелец держит вид дольше N − 1 публикаций → доступ к `Nodes` бросает `StaleViewException`; при N − 1 — читается верно.
4. **Гонка:** стресс 2 потока (симуляция дневным тиком, клиент берёт и отпускает аренды случайно), 10⁵ публикаций: ни одного рваного чтения (контрольная сумма блока при записи = при чтении), ни одного исключения у арендатора.
5. **Детерминизм:** хеши каждого дня равны при N ∈ {2, 3, 8}, `SkipViews`, с клиентом, держащим аренды; L2 по матрице ADR-0019 «Проверка» п. 5.
6. **Эквивалентность:** JSON каждого опубликованного вида с кольцом = JSON вида без кольца (эталонная полная сборка) на прогоне с командами и дневным зондом.
7. **Сохранение:** продолжение TASK-0124 — после загрузки на тике K вид тика K + m равен виду непрерывного прогона.
8. **Два мира:** тест TASK-0125 с видами включёнными; IL-тест static-полей покрывает новые типы.
9. **Порог P8:** CI-проба `alloc` пути снимка по ADR-0023 «Частично заменяет» (база + 5 %, ≤ X) — без изменений правил, с новой базой.

## Открытые вопросы
- [Предл.] N по умолчанию 3 — по числу видов, которые держит Lab (2). Подтвердить после правки клиента.
- [Предп.] Не проверено, что запись в наборы gen2 без ссылок не даёт заметной цены GC; проверяет замер M1 (ADR-0024), не этот ADR.
- Нужно ли публиковать должный вид на паузе без тика (п. 11) — решает задача реализации вместе с `SimHost`.
