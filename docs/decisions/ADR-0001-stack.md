# ADR-0001 — Стек: ядро на C# / .NET 10, визуализация на Godot позже

> ACCEPTED: текст не меняется. Изменение — новый ADR с `supersedes`.

## Контекст
Нужен язык ядра симуляции и способ визуализации. Владелец — PHP-разработчик без опыта геймдева; код пишет AI, владелец проверяет логику. Требования: headless-ядро, многопоточность, детерминизм, Windows/Linux/macOS, моддинг. RR-0001.

## Решение
- Ядро — отдельные библиотеки C# на .NET 10 LTS без зависимостей от движка.
- M0 — консольная Simulation Lab, движка нет.
- После M0 — клиент на Godot 4 .NET, который подключает ядро как библиотеку.
- Пересмотр решения — если бенчмарки M0 покажут нехватку производительности.

## Рассмотренные альтернативы
- Rust-ядро (+ Godot gdext или Bevy): безопасность гонок на этапе компиляции, но код труднее проверять владельцу.
- C++-ядро (+ GDExtension): производительность, но выше риск ошибок памяти и сложнее ревью.
- Unity: история с Runtime Fee, закрытый движок. Unreal: тяжёл для 2D-карты и UI данных, роялти.

## Последствия
- Правила детерминизма надо соблюдать дисциплиной и тестами (ADR-0002..0007).
- Godot сейчас на `net8.0`; совместимость с ядром на .NET 10 проверяется прототипом после M0.

## Проверка
CI: `dotnet build` + `dotnet test` на ubuntu, windows, macos.
