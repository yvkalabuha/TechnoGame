# RR-0014 — Ресурсы, торговля, экспортный контроль

> Пометки: **[Факт]** — подтверждено источником; **[Предп.]** — предположение; **[Предл.]** — предложение. Ничего здесь не утверждено, кроме решений владельца в `docs/decisions/DECISIONS_LOG.md` (на них ссылки по номеру). Черновик волны 2 (PHASE F, `CONCEPT_EXPANSION_ANALYSIS.md` §4, направление 5). Опорные документы: `docs/research/RR-0010-supply-chains-clusters.md` (далее «RR10»), `docs/research/RR-0006-economy-industrial-capability.md` («RR6»), `docs/game-design/economy/economy-next-milestone.md` («ENM»), `docs/game-design/economy/E1-model.md`, `docs/architecture/LAYER_CONTRACT.md` v2.4 r10 («К»; правка 2026-11-14 по gate RR-0014), `docs/vision/CONCEPT_EXPANSION_v0.1.md` §6.5–6.6.

## Вопрос исследования
Как смоделировать природные ресурсы, торговлю и экспортный контроль так, чтобы каждая механика давала игроку **осмысленное решение** и **читаемое «почему нельзя»** (`why_not`), не ломая детерминизм L2 (ADR-0002), бюджет тика и уже принятые решения: #165 (экспортный контроль на E1.5 на существующих предметах), #168 (деньги в постоянных ценах 1945 года, без валют и инфляции), #193/#198 (сеть предприятий), #203 (три слоя видимости).

## Краткий вывод
- [Предл., граница принята из RR10 §5в] **RR10 владеет физикой** (баланс, потоки, запасы, мощность, делёж внутреннего дефицита, `why_not` по цепочке). **RR-0014 владеет рынком и политикой**: цены, сделки, пошлины, эмбарго, санкции, лицензии, оснастка, канал догоняющего, платёжный баланс. Интерфейс — **шлюз страны по CMP** (`import/export[country,cmp]`) и ворота `allowed(from,to,item)`. Рёбер «предприятие ↔ предприятие» через границу нет.
- [Предл.] `allowed(from,to,item) = ¬export_control ∧ ¬embargo ∧ licence_ok` — **только булева политика** из данных и решений. Деньги импортёра (`NO_MONEY`) и мощность перевозки (`NO_CAPACITY`) — **ограничения клиринга**, не ворота; цена берётся из снимка t−1, поэтому цикла внутри тика нет. [Факт: #165, ENM §2.7] На E1.5 живёт только первый член — `export_control(from,to,item)` над существующими предметами среза (лицензия, компонент, сплав); это **вырожденная форма** ворот.
- [Предл.] Предмет торговли в E3: CMP, **компоненты** (изделие без проекта игрока), лицензии, оснастка. Знание и готовые системы — вне E3 (ENM §2.5; владелец — RR-0008/разведка).
- [Предл.] Рынок — **цена как функция мирового баланса CMP** без ордербука, деньги — постоянные цены 1945 года (#168): «цена» есть относительный множитель к базовой `p0`, валют нет.
- [Предл.] Три категории доступности из CE §6.6 отображаются на режимы данных: `OPEN`, `LICENSE_REQUIRED` (≈ RESTRICTED), `DENIED` (≈ CLOSED); по блоку, эре и классу предмета. Товар, передача технологии и производственная лицензия — **разные ворота** (CE T6).
- [Предл.] Канал догоняющего `catch` (RR6 разногласие 1) получает множитель `access(owner,p) ∈ [0,1]`: без него скидка действует под полным эмбарго и контроль неэффективен. **Это критерий gate E1.5** (формула — §4).
- [Предл.] Эмбарго не считается дважды: потеря выручки идёт **только** через доход и `B_a` (E3); `g_shock` — лишь для событийных шоков без денежного канала (#172); на E1.5 они не складываются (§4).
- [Предп.] Стоимость: E1.5 — несколько обращений к таблице за месяц; E3 — двухуровневый клиринг через пулы блоков, O(число стран) на CMP ⇒ ~10⁴–3·10⁴ операций `Fx6` (≈ 3·10⁴ при 200 × 150), < 1 мс на месячный тик (§7). Главный риск — данные 1945 (двусторонние потоки под ADR-0009 недоступны), а не CPU.
- [Предл.] Ключевой тест на каждую механику: решение игрока + читаемая причина отказа (таблица §«Ключевой тест»). Механики без обоих — не берём.

### 2. Ресурсы
- [Предл., RR6 §4.9, CE §6.5] 10 природных категорий: уголь, нефть, газ, железная руда, медь, бокситы, уран, редкоземельные, лес, легирующие металлы (Ni, Cr, Mn, W). Мощность добычи — данные региона; **истощения нет в v1** (ENM §2.4).
- [Предл.] Единица ресурса — стоимостная (как у CMP, RR10 §5г): 1 ед. = 1 тыс. $1945 по базовой цене; тонны — только показ.
- Правило: ценность месторождения нулевая, пока процесс-потребитель не в `known_processes` (RR6). Новая технология создаёт спрос на ранее неважный ресурс **данными процессов** (входы `PRC`), а не отдельным механизмом (CE §6.5: «пластик, высокочистые вещества, полупроводники»).
- Нефть ≠ пластик: природный ресурс никогда не подменяет материал; суррогат — только явный флаг данных (прецедент `alloy_free`, #131), общий механизм E14 — OPTIONAL.
- Энергоресурсы в E1 — три вида (уголь, нефть-газ, гидро) по регионам с `loss` 3–10% и надбавкой за расстояние (E1-model §14.2, #171). [Предл., правило] **До E2 носители энергии в `RES` не входят**: энергия E1 — собственный баланс E1 и не торгуется. В E2 уголь и нефть-газ становятся `RES`, а энергия E1 потребляет их **как входы `PRC`** (через тот же мост RR10 §5г); торговля ими идёт через шлюз. Двойного учёта (E1-энергия и `RES`-спрос) нет: на E2 `G_rt` для угля и нефти-газа заменяется на выпуск `RES`.

### 3. Рынок (E3)
- [Предл., ENM §2.5; правка 2026-11-14 по gate] **Цена по компоненте связности.** Рынок CMP строится отдельно на каждой компоненте связности графа `allowed` по этому CMP (ожидается 2–4 блочных рынка); порядок поиска компонент — по id (подтвердить systems-architect). `price_m,K = p0_m·(1 + k_m·dev_m,K)`, `dev = clamp((D − S)/S, −c_lo, c_hi)`; **защита деления:** `S = 0 ⇒ dev = c_hi`; в `Fx6` сначала умножение, потом деление. Цена берётся из **снимка t−1** (прошлого месяца) — цикла «цена ↔ клиринг» внутри тика нет. Без `exp` и степеней.
- **Реальный выпуск и деньги.** Реальный выпуск и баланс (RR10) считаются в единицах `p0` (постоянные цены 1945, #168). `price_m` влияет **только на `B_a`**. `B_a` — месячный поток, **не накапливается** (долга нет, #168).
- **Спрос неэластичен** (v1): цена не бывает причиной отказа в сделке, поэтому причина `PRICE` из `why_not` **убрана** (решение автора из двух вариантов; альтернатива — явная кусочно-линейная скидка спроса — отклонена как лишний параметр). Нехватка денег — `NO_MONEY`.
- **Клиринг двухуровневый** (§7): внутри блоковой компоненты — пулы блоков, затем раздача странам; деньги импортёра делятся между CMP **до прохода** пропорционально спросу; делёж — floor-долями по весу предпочтения, остаток по id; RNG нет (#28).
- Платёжный баланс — **один агрегат на страну**: `B_a = Σ экспорт·price − Σ импорт·price` (месячный поток); отрицательный режет `s_prog` (ENM §2.5). Валют, курсов, долга нет (#168). Инвариант: `Σ_a B_a = 0` на компоненту (кроме помощи, §4).
- Контракты (CE §6.6): долгосрочная поставка «объём × цена × срок» между двумя странами. Решение: надёжность поставки против гибкости цены; рвётся эмбарго или событием. EXPERIMENTAL (после ворот E3).
- Торговые блоки: блок задаёт **режим по умолчанию** `allowed` и вес предпочтения; страны — члены блока на дату и эру (данные). Матрица «блок × блок × класс предмета» (~10×10×12) + список исключений, а **не** «страна × страна × предмет» (4·10⁴ × 12 ≈ 5·10⁵ ячеек).
- Транспорт: один коэффициент издержки (RR10 §5в); перерезанные пути и блокада — волна 3 (RR-0019).

### 4. Экспортный контроль, лицензии, оснастка, догоняющий
- [Факт: #165] **E1.5.** `export_control(from, to, item)` над существующими предметами среза; режимы `OPEN`, `LICENSE_REQUIRED`, `DENIED` по блоку и эре. Эффект на срез: отказ лицензии/компонента — корень `why_not` «контроль экспорта», а не «нет денег». Цена экспортёру: потеря `LicenceFlow`/`sale_income` и малый `g_shock` (≤ `ε_cap`). Gate E1.5: контрфактуры «блок с контролем / без» в Lab; серебряной пули нет (замещение через собственную культуру C-B остаётся).
- Предметы и каналы (разные ворота) [Предл.]:
| Предмет | Что передаётся | Куда влияет | Ворота |
|---|---|---|---|
| CMP, ресурс | материал | баланс RR10, `f_M` | `allowed` (товар) |
| компонент | изделие без проекта | `component_stock`, #62: силу даёт, `tech_lead` нет | `allowed` + допуск |
| производственная лицензия | право вести PRC | `ṽ` в культуре, `X½·(1 − l_lic)` (RR6); деньги — `LicenceFlow` | `allowed` (лицензия) + цена |
| оснастка | станки | `M` растёт, `H` нет (RR6 §4.14) | `allowed` (оснастка) |
| знание, готовые системы | — | — | вне E3 |
- **Канал `catch`; формула `access` на E1.5 (правка 2026-11-14 по gate).** `k_catch·catch·access(owner,p)`, где `access(owner,p) = max_{h ∈ holders(p)} [allowed(h → owner, p)]` — булево (или ступени по режиму: `OPEN` = 1, `LICENSE_REQUIRED` = ступень данных, `DENIED` = 0); `holders(p)` — акторы, у которых `p` освоен (`Mastered`). Остальные члены (специалисты, торговый объём, оснастка) — **FUTURE**. **Лицензия в `access` НЕ входит:** она действует через `ṽ` и `X½` (RR6, контракт §3, правило 5; двойной учёт и риск #158); в инварианты двойного учёта добавлена пара **«лицензия × catch»** (владелец — RR6, тест: при `access = 0` и выданной лицензии скидка `catch` равна 0, а `X½·(1 − l_lic)` действует). **Тест монотонности:** добавление держателя или смягчение режима не уменьшает `access`; `access ∈ [0,1]`. **Критерий gate E1.5:** без `access` контрфактура «блок с контролем» не покажет эффекта выше шума (абляция `k_catch = 0` — RR6 §8.3).
- [Предл.] Санкции = набор эмбарго; **механизм** здесь, **политика** (кто кого, когда) — RR-0012/RR-0016.
- **Эмбарго не считается дважды.** В E3 потеря выручки экспортёра идёт **только** через доход и `B_a` (экспорт падает ⇒ `B_a` падает). `g_shock` — только для событийных шоков без денежного канала (например, блокада порта, авария). На E1.5 (до `B_a`): потеря `LicenceFlow`/`sale_income` и малый `g_shock` (≤ `ε_cap`) **не складываются** сверх границы #172 — выбирается один канал на событие; Lab-проверка: суммарное снижение роста от одного эмбарго ≤ `ε_cap`.
- У жертвы включается замещение (рост собственного выпуска по C-B, снижение удельного расхода). Это прямое следствие истории (§5).
- **Пошлина (T17, E3).** Коэффициент `tariff_{to,item} ≥ 0` на цену импорта; не меняет реальный выпуск (в `p0`), а перераспределяет `B_a` (доход — у государства-импортёра, затраты — у покупателя); причина в `why_not`/UI — `TARIFF`.
- **Помощь (grant).** `grant(donor, recipient, amount)` без долга (E3, идея плана Маршалла): перевод в `B_a` и закупочную способность получателя, учитывается отдельной строкой баланса (`Σ B_a = 0` с учётом grant). Решение владельца (вопрос 5).

### 6. Видимость (#203) [Предл.]
Три слоя для торговли и контроля: (1) **показанное миру** — публичные эмбарго и режимы, торговая статистика с задержкой, видят все; (2) **публикуемое** — таблицы блоков и списки контроля (открытый слой, как FND/PRN), с задержкой; (3) **закрытое** — тайные поставки и обход через третьи страны, видит только разведка (RR-0017, волна 3), до неё скрыто. `why_not` игрока показывает причину **собственного** отказа полностью и причину чужого — на уровне видимого слоя. [Предл.] **Слой 3 в v1 пуст**, если обхода через третьих стран нет (вопрос 1, вариант «нет»): скрытых потоков не существует, поэтому пустота слоя — не ошибка; наполнение — только при утечке (`leak`) и разведке RR-0017.

### 7. Агрегация, тик, данные
| Уровень | Что | Объём | Частота |
|---|---|---|---|
| страна × CMP | шлюз: экспорт, импорт, цена | 200 × ~150 = 3·10⁴ | месяц |
| блок × блок × класс предмета | режим `allowed` по умолчанию | ~10 × 10 × ~12 ≈ 1200 | при смене режима |
| исключения | список `(from,to,item,режим)` | ≤ ~10³ | данные |
| страна | платёжный баланс (1 `Fx6`) | 200 | месяц |
Тик E3 (пересчитан по gate): **двухуровневый клиринг** — (1) внутри компоненты связности `allowed` по CMP агрегируются пулы блоков (спрос/предложение блока), (2) доля блока раздаётся странам по весу; на уровне 1 — O(блоки) ≈ 10, на уровне 2 — O(страны блока); деньги импортёра делятся между CMP **до прохода** пропорционально спросу. Итого O(число стран) на CMP ≈ 200 × 150 = 3·10⁴ операций `Fx6` (вместо ~3·10⁵ в первой редакции), < 0,5 мс [Предп.]; компоненты связности пересчитываются только при смене режима или эмбарго. E1.5 — O(число запросов `take_licence`/продаж) за месяц, пренебрежимо. Данные: PWT 11.0 и Maddison 2023 (CC BY, #168) — только макропоказатели; двусторонние потоки 1945 — недоступны под ADR-0009 (COW Trade/NMC: лицензия не указана, блокер, `economy-data-licences-1945.md`); **задача до данных E3:** подтвердить политику лицензии USGS (на странице набора заявления нет, ссылка отдавала 404) — экспертом по данным (research-scientist). Режимы блоков 1945–1991 — из PD-документов (FRUS) вручную, с источником.

### Проверка в Simulation Lab [Предл.]

## Разногласия
Gate 2026-11-14 (critic + advocate); итог — Orchestrator, вопросы — владельцу.
1. **`allowed` и деньги/транспорт.** Первая редакция включала `мощность ∧ деньги` в ворота — критик: цикл с ценой и смесь политики с клирингом. Принято: ворота только булевы, деньги и мощность — ограничения клиринга, цена из снимка t−1.
2. **`access` и лицензия.** Критик: лицензия в `access` — двойной учёт с `ṽ`/`X½` (#158). Принято: только `max` по держателям от `allowed`; лицензия не входит; добавлена пара «лицензия × catch» в инварианты. Нерешённое: форма ступеней по режиму — данные, калибровка Lab.
3. **Двойной счёт эмбарго.** Выручка идёт только через `B_a`, `g_shock` — только событийные шоки без денежного канала. На E1.5 один канал на событие (#172).
4. **Причина `PRICE`.** Спрос неэластичен ⇒ причина убрана; альтернатива (кусочно-линейная скидка спроса) отклонена автором как лишний параметр. Остаточное: возражение, что игрок хочет отказаться от дорогой сделки — решается пошлиной/квотой (T17), не ценой.
5. **Тик.** Первая оценка ~3·10⁵ операций пересчитана на 3·10⁴ через блоковые пулы; число проверить Lab-микротестом.
6. **Доминанта «DENIED всем вне блока».** Критерий добавлен в Lab; цена — потеря предпочтения нейтралов и выход из блока.
7. **Открыто:** асимметрия контроля (вопрос 3), утечка (вопрос 1) и слой 3 видимости (пуст в v1 без утечки) — решения владельца.

## Открытые вопросы
Вопросы владельцу (формулировка gate 2026-11-14; рекомендации автора — в скобках):
1. **Обход эмбарго:** (а) нет; (б) скалярная утечка `leak[neutral,item_class] ≤ ~0,1` с наценкой в E3, видна только в слое 3 (#203). [Предл.: (а) в E1.5; (б) на воротах E3 как абляция.]
2. **Отзыв лицензии:** (а) невозможен; (б′) прекращает будущие потоки, уже освоенные `H` и `M` остаются, отозвавший теряет доход. [Предл.: (б′) — не «обнуляет» навык, соответствует RR6 §4.14.]
3. **Кто задаёт контроль:** (а) умолчания блока из данных + асимметрия (ужесточать можно свободно, смягчать ниже нормы блока — только с трением); (б) умолчания блока, выход — только выходом из блока. [Предл.: (а).]
4. **Двусторонние потоки 1945:** (а) ручная матрица ~10 стран; (б) веса модели «блок × расстояние × колониальная связь», матрица — только якорь калибровки в Lab. [Предл.: (б) — меньше фальшивой точности (ADR-0009).]
5. **Помощь:** (а) `grant(donor, recipient, amount)` без долга в E3 (план Маршалла); (б) переводов нет. [Предл.: (а).]

7. systems-architect: порядок поиска компонент связности `allowed` по id; допустимость поправки контракта (ворота `allowed`, множитель `access`) в паре с RR6 «E1: граница»; контракт r10. Прежний п. 6 о поправке контракта сохраняется здесь.
