# ADR-0020 — Province storage, aggregation to regions and tick budget

> После ACCEPTED текст не меняется. Изменение решения — новый ADR с `supersedes`.
> Уровень: gate+research. Пункт 0.3 плана `development/milestones/MS-M1-economy-provinces-open-race.md`; снимает оговорку ADR-0016 §1 и требование ADR-0011 о регионах со смешанным владением. Ревизия 2 после gate: `docs/reviews/adr-0019-0020-{critic,advocate,reviewer}.md`, `docs/reviews/adr-0020-deepseek.md`.

## Краткий вывод
- [Предл.] Мир Kernel — несколько именованных таблиц: `actors` (строки заранее, колонка `active`), `regions`, `provinces` (провинции карты + территории без геометрии), `events` (`status`, `effective_tick`). Мир из одной таблицы хешируется прежними байтами.
- [Предл.] Владение хранится только в `provinces`. Атрибуция региона — **чистая функция** Core от `controller` провинций и весов `w_p`, мемо по версии таблицы `provinces` (кэш, не состояние). Хранимых колонок атрибуции нет.
- [Предл.] Экономика идёт **контролёру**. Регион с несколькими контролёрами — только из списка `mixed_regions.yaml` сценария; иначе граница события совпадает с границей региона (CI). Бюджет актора — `Apportion` выхода региона (точная сумма).
- [Предл.] Доля провинций в бюджете M1 — **≤ 10 мс** из резерва ADR-0016; CoW и хеш таблиц провинций — в `K_d`. Правило скорости — вопрос владельцу (K4 #333 против ступенчатого).

## Контекст
- [Факт: ADR-0011 §1, §3, §5, табл. классов] Провинции 2000–5000, регионы 150–250; `owner`/`controller` — `short`; `polities.yaml` — в `scenario_hash`, `map/*.yaml` — в `DataHash`, `map/*` запечатывается; класс B — «только владение, без геометрии» (Индия, колонии, кондоминиумы); центр Вены — совместная полития.
- [Факт: ADR-0016 §1, §3] Провинции не входят в полный масштаб; раздел: системы ≤ 100, `K_d` ≤ 50 (копия, swap, хеш), резерв 350 мс; правило `S + K_d + 19·P > 500` → ADR.
- [Факт: ADR-0017 п. 6] Кэш `LastHash` — пара `(version, hash)`, `Table.Version` растёт при swap открытых колонок и `Load`.
- [Факт: код, reviewer] Только `LongColumn`/`IntColumn`; хеш: `schema_version`, `n_rows`, колонки; `SliceWorld.SchemaFingerprint:403` пишет `i`/`l` по типу; `TickContext.Table`, `TickRunner._table`, `ChunkCountFor(Table.RowCount)` — одна таблица.
- [Факт: #312, #313, #325, #327, #328, #331, #333, #336–#343] Совместные политии; оккупация; события по дате; при превышении бюджета жертвуется скорость, пол 1 мес./3 с; K4 MS-M1 утверждён (#333): WARN → пол #331. **#338:** Тайвань — owner и controller ROC с 1945-10-25. **#337/#343:** восток Одера–Нейсе — owner DEU, controller POL/SUN, переход владения по договору 1950 (запасной — 1970).
- [Факт: `docs/game-design/scripted-events-conditions.md` §1, §4] Нужны `event_status`, `effective_date` в `StateHash`; `territories.yaml` для неевропейских наборов.

## Решение

### 1. Хранение и хеш
1. **Мир — список именованных таблиц** `World`. Система объявляет `ChunkTable` (по строкам которой режется на чанки) и свои колонки в любых таблицах.
2. **Правило записи между таблицами.** Один писатель на колонку (ADR-0019 п. 5). compute пишет только строки своего чанка своей `ChunkTable` в свои колонки; в строки других таблиц — только через буферы чанков, применяемые в своём merge в порядке чанков.
3. **`actors`:** строки всех политий, которые могут стать актором в сценарии (из `polities.yaml`: IND, PAK, IDN, FRG, GDR, …), создаются в t0; колонка `active` (`int`, 0/1) пишется только `ScenarioEventSystem`. Число строк постоянно → чанки и L2 не зависят от событий. Неактивные строки системы пропускают.
4. **`provinces`:** строка = провинция карты в ordinal-порядке `province_id`, затем территория без геометрии из `mods/core/map/territories.yaml` (`id`, `region`, `w`; `DataHash`, печать вместе с картой). Колонки `owner`, `controller` — `short`. Начальное владение — `owners.yaml` (`scenario_hash`). [Предп.] 2 × (5000 + ~300) × 2 Б ≈ 21 КБ — плотно, разреженное хранение не нужно до систем M2.
5. **`events`:** строка = событие сценария в порядке `(nominal_date, event_id)`; колонки `status` (`int`: `due|deferred|fired|alt_fired|skipped|disabled`) и `effective_tick` (`int`, −1 = нет). Пишет только `ScenarioEventSystem`. Срок отсрочки — функция `nominal_date`, окна и `effective_tick` предшественника, не колонка.
6. **`ShortColumn`** — новый тип Kernel (little-endian int16 в хеше). `SchemaFingerprint` — исчерпывающий `switch` по типу колонки (`s`/`i`/`l`), неизвестный тип — исключение.
7. **Хеш мира** (частично заменяет ADR-0017, формат). Одна таблица — байты как сейчас. Несколько таблиц: `int32 −1` (маркер), `int32 table_count`, затем по каждой таблице в порядке списка: имя (UTF-8, `int32` длина), `int32 schema_version`, `int32 n_rows`, `int32 n_cols`, колонки в порядке регистрации. SHA-256 и расписание ADR-0017 не меняются.
8. **Версия мира.** `World.Version = Σ Table.Version` (каждая версия монотонна → сумма меняется ровно тогда, когда меняется хоть одна таблица). Кэш `LastHash` — пара `(World.Version, hash)`; остальная семантика ADR-0017 п. 6 прежняя.

### 2. Атрибуция провинция → регион
9. **Функция, не состояние.** `Attribution.Of(provinces, statics)` — Core, чистая: для региона `r` пары `(c, share)` = `Apportion(1 000 000, w_p по контролёрам)`, пары по убыванию доли, затем по индексу политии. Число пар не ограничено (Вена: 4 сектора + центр = 5).
10. **Мемо.** Считается в post (один поток) при изменении версии `provinces`, при сборке мира и после `Load`; compute следующего тика читает его только на чтение. Это кэш, как `LastHash`: восстанавливается из таблиц, в хеш и сейв не входит (ADR-0013 п. 4 соблюдён). Любая будущая система, меняющая `controller` (война M2), не требует правки атрибуции.
11. **Веса — один путь.** `w_p` по умолчанию 1 для всех провинций и территорий; иные веса — только у регионов из `mods/core/scenarios/1945/mixed_regions.yaml` (`region`, `weights_source`, `as_of`, `licence`, `w_p > 0` у каждой провинции; `scenario_hash`). Запечатанный `regions.yaml` не меняется.
12. **Бюджет актора (#330):** для региона `r` с выходом `Y_r` — `Apportion(Y_r, share пар)` в порядке пар; часть совместной политии делится дальше `Apportion(part, econ_shares)` в порядке `members`. Σ бюджетов = Σ `Y_r` в raw точно. pull в compute актора, регионы по возрастанию индекса.
13. **Маркер смены для E1** — `events.effective_tick` (ADR-0019 п. 22); прежняя атрибуция, если нужна 2.9, хранится в колонках системы-владельца E1 (решение 2.9).

### 3. Регион с несколькими контролёрами
14. **CI выравнивания.** Для t0 и каждой даты таблицы событий: провинции, меняющие `controller`, — объединение целых регионов, у региона один контролёр, кроме `mixed_regions`. Нарушение — красный CI с перечнем.
15. **Покрытие поэтапных данных.** Событие, чьи провинции ещё не на карте (1.1 идёт параллельно с 1.6a), — предупреждение `pending_map`, а не ошибка, до заморозки карты; после заморозки — ошибка.
16. **Ожидаемый список** [Предп.; research-scientist, R3]: Берлин (4 сектора), Вена (4 сектора + центр), регионы, рассечённые зонами Германии и Австрии без географического раздела. Пенджаб, Бенгалия, Корея (38°), Индокитай (16°) — выравниваются разделением регионов (ADR-0011 класс A). R3 проверяет, что разделения держат 150–250 регионов.
17. **Нет источника весов** с PD/CC0/CC BY → регион делится по линии (правка карты до первого сохранения игрока, ADR-0013 п. 7); равные веса без источника запрещены.
18. Физическое состояние смешанного региона общее, атрибутируются выходы. [Предп.] Допуск: ≤ 10 регионов и ≤ 1 % населения мира в сумме — проверяет R3; иначе регионы делятся.
19. **Валидатор:** `mixed_regions` — источник, `as_of`, лицензия из белого списка, `w_p > 0` у всех провинций, у региона действительно > 1 контролёра хотя бы на одну дату; `econ_shares` у каждой `joint`, сумма 1 000 000; члены `joint` — политии-акторы, вложенные `joint` запрещены.

### 4. Атрибуция: controller, совместные и оккупированные политии
20. Экономика региона идёт **контролёру** (де-факто). DEU и KOR без правительства актором не являются — их регионы атрибутируются оккупантам. Пример: восток Одера–Нейсе до договора 1950 — owner DEU, controller POL/SUN, экономика у POL/SUN (#337, #343). Тайвань: controller ROC с t0, owner ROC с 1945-10-25 (#338). `owner` в M1 экономику не меняет.
21. Совместная полития (#312) может быть контролёром, не актор; раздел п. 12. Роспуск (`dissolve_joint`) — событие, меняющее `controller` провинций.

### 5. Бюджет тика (частично заменяет ADR-0016 §1, §3)
22. **Полный масштаб M1:** 200 акторов (строк — с запасом п. 3), 150–250 регионов, 2000–5000 провинций + территории, таблица событий.
23. **Раздел:** системы ≤ 100 мс; `K_d` ≤ 50 мс — **включая** CoW, swap и хеш всех таблиц; **провинции ≤ 10 мс** (`ScenarioEventSystem`, мемо атрибуции, проверки K9) — из резерва; остаток резерва — E1 и прочее. Правило `S + K_d + 19·P + провинции > 500` → ADR (расширение правила critic M4 ADR-0016).
24. Ожидание [Предп.]: ежедневная проверка `due/deferred` — мкс; мемо при смене — O(провинций) ≈ десятки мкс; итого < 1 мс/мес. Пересмотр доли — на gate M2 (война, логистика), каждая система провинций заявляет цену на провинцию-день до кода.
25. **Исходы K4** — как утверждено в MS-M1 (#333). [Предл.] p95 ≤ 500 при медиане > 400 — WARN. Правило скорости при WARN — вопрос 1.
26. Число провинций — не рычаг бюджета (#327). K4 — на фактической карте; справочно 5000 синтетических провинций с событием каждый день.

### 6. Инварианты K9 (не зависят от `HashEveryTick`)
27. Флаг `CheckInvariants` (execution-only, по умолчанию включён везде, цена — мкс): в t0, после `Load` и в post каждого тика, где версия `provinces` или `events` выросла — у провинции `owner`, `controller` — действующие индексы политий; у `joint` есть члены; `fired` события с `effective_tick` ≤ текущего; `active` актора согласован с событиями создания.
28. «Смена не из таблицы событий — ошибка» обеспечивается структурно: единственный писатель `owner`/`controller` в M1 — `ScenarioEventSystem` (архитектурный тест ADR-0019 п. 5).

### Частично заменяет
- **ADR-0016 §1:** «провинции не входят» → п. 22. **§3:** строка «провинции ≤ 10 мс», уточнение `K_d`, расширенное правило п. 23. §4 (исходы M0) не меняется; исходы M1 — K4 MS-M1.
- **ADR-0017 п. 6 и формат хеша:** заголовок мира из нескольких таблиц (п. 7), кэш по `World.Version` (п. 8). Байты одной таблицы и расписание — прежние.
- **ADR-0011:** «ячейка `(region, controller)` или столичная провинция» → функция п. 9 со списком `mixed_regions`. Новые файлы: `map/territories.yaml` (`DataHash`), `scenarios/1945/mixed_regions.yaml` и `econ_shares` в `polities.yaml` (`scenario_hash`).
- **ADR-0013:** формат по таблицам прежний; `save_format_version` растёт; мемо атрибуции не сохраняется.

## Рассмотренные альтернативы
| Альтернатива | Причина отказа |
|---|---|
| Провинции колонками в `actors` | ×200 памяти и хеша |
| Хранимые колонки атрибуции (ревизия 1) | Производное состояние, K9-равенство, привязка к одному писателю ломается в M2 |
| Ячейка `(region, controller)` с отдельным E1 | Строки E1 делятся при событиях, объём 2.9 растёт кратно |
| Весь регион — контролёру столичной провинции | Западный Берлин уходит SUN |
| Атрибуция по `owner` | DEU/KOR без правительства — экономика ничья; восток Одера–Нейсе — у DEU до 1950 |
| `mixed` в `regions.yaml` | Файл запечатан и географический; смешанность — свойство сценария |
| Добавление строк `actors` при событии | Меняет `n_rows`, чанки, L2 |
| `share × выход` в Fx6 | Σ бюджетов ≠ выходу (floor) |
| Уменьшать провинции при превышении | Запрещено #327 |

## Последствия
- **Плюсы:** один источник владения; атрибуция без состояния и годна для M2; сумма бюджетов точна; хеш различает наборы таблиц.
- **Минусы:** Kernel под несколько таблиц меняет API `ITickSystem` всех систем Core (R2); строки неактивных акторов в каждом тике; карта 1.1 зависит от таблицы событий через CI.
- **Обязательно:** один писатель на колонку; `Apportion` для любых разделов; `mixed_regions` с источником; `CheckInvariants` включён.

## Проверка
1. **Одна таблица:** golden M0 и `EXP-0002-det` (`824f4ded…`) без изменений.
2. **Golden-вектор** хеша мира из трёх таблиц (фиксированные байты); перестановка таблиц или имя другой → другой хеш; таблица с 0 строк; `ShortColumn`: байтовый путь = быстрый путь; `SchemaFingerprint` для `short`.
3. **L2:** четыре таблицы, threads 1/4/8/16 × ChunkSize 1/8/32, разные `ChunkTable`, `HashEveryTick` — хеш каждого дня равен; день активации актора и день двух событий `(date, event_id)`.
4. **Версия:** изменение только `provinces` сбрасывает кэш `LastHash`; день без события — версии `provinces`/`events` прежние; `Load`/`Next` другой таблицы внутри тика — исключение.
5. **Save/load** в день события и на следующий → тот же хеш; мемо после `Load` = мемо без сохранения.
6. **Атрибуция:** property — мемо = пересчёт с нуля после каждого события; сумма долей = 1 000 000; Σ бюджетов + доли `joint` = Σ выходов в raw; `joint` в смешанном регионе (`Apportion` в `Apportion`); смена только `owner` не меняет атрибуцию; роспуск `joint`.
7. **CI выравнивания** + отрицательный тест; `pending_map` до заморозки.
8. **Валидатор** п. 19; **K9** п. 27 при `HashEveryTick = false`.
9. **Бюджет:** K4 на фактической карте; 5000 синтетических провинций с событием каждый день; доля провинций по inclusive-профилю ≤ 10 мс.

## Вопросы владельцу (критичные первыми)
1. **Скорость при WARN K4.** (а) как утверждено (#333): сразу пол 1 мес./3 с; (б) [Предл.] ступенчато: 1 месяц за `max(1 с, 2·p95, 2,5·медиана)`, не медленнее 3 с — при p95 = 600 мс это 1,5 с, а не 3 с. Рекомендую (б); выбор (б) правит K4 MS-M1.
2. **Смешанные регионы.** [Предл.] (а) границы регионов совпадают с событиями (CI), кроме короткого списка (Берлин, Вена) с весами из источников; (б) строгое совпадение без исключений (Берлин и Вена — по 4–5 регионов). Рекомендую (а).
3. **Кому идёт экономика.** [Предл.] (а) контролёру: зоны Германии и Кореи — оккупантам, восток Одера–Нейсе — POL/SUN с 1945; (б) владельцу (у DEU и KOR экономика ничья). Рекомендую (а).
4. **Кондоминиумы.** [Предл.] (а) доля совместной политии делится поровну, если нет источника на иной раздел; (б) неравный раздел обязателен с источником, иначе событие/полития не вводится. Рекомендую (а).
